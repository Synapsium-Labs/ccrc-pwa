## Departures, by slug

- **`collect-moved-record-carries-leaf`** (granted by the coordinator). After the move, the quarantine record is the verb's authority. It carried only the witness identity, which every physical proof read: step 2, the move, re-prove (f), the removal's dev:ino, the putback, and the resume's slot and original-path checks. A released leaf has another identity, so the record now ends with an optional ` leaf=<dev>:<ino>:<btime>` on a released leaf only. `_ws_collect_record_read` exposes the physical identity (`_WS_QREC_PDEV`, `_PINO`, `_PBTIME`): the leaf's when present, else the witness's, so today's records read unchanged. The witness's compare-and-drop still compares the witness's own fields, and the resume token binds `leaf=`. An older ccd reads such a record as malformed, so it is `quarantine-kept`: fail-closed, and the operator's. Functions touched under that leave: `_ws_collect_reset`, `_ws_collect_record_write`, `_ws_collect_record_read`, `_ws_collect_fresh`, `_ws_collect_after_move`, `_ws_collect_putback`, `_ws_collect_finish` (the done line's `meas.witness moved-host` only), `_ws_collect_resume_eval` and `_ws_collect_resume`.
- **`collect-moved-token-binds-the-walk`** (granted by the coordinator). The moved token binds `newestCtimeNs` and `entries` as well as the fields the plan lists, as today's collect token does, so no consent is weaker than today's.
- **`ccd-ccd-has-no-committed-stamp`**. The plan's Global Constraints say to restamp `ccd/ccd` and check `node shared/mark.mjs --check ccd/ccd`. On `main`, `ccd/ccd` carries no committed stamp: its marker is written at install. `ccrc restamp ccd/ccd` therefore writes nothing and says so, and the check has no stamp to read. No restamp was made or needed.
- **`norecord-why-names-no-second-path`**. The detail already names the main checkout and the tree. `_ws_leaf_why_line` cuts at 300 bytes, and two more absolute paths would cut the remedy mid-path. So the "records another path" sentence names the remedy as `git -C <main> worktree repair <tree>`, "with the two named above", and each sentence names at most one more path (the admin directory). `_ws_reclaim_norecord_why` takes the workdir alone, as the plan's interface says. When the admin directory records the tree itself, it sets nothing; rung 8 cannot reach that shape, because `_ws_reclaim_no_record` holds it as unmeasured first.
- **`m4-case-stubs-the-leaf-device`**. The plan's hint for M4's case, "a mount at the leaf in the fixture table", does not exercise M4: M4 compares the leaf's `stat` device with the physical `~/.cc-tmp`'s, and a table line changes neither. A table mount at the leaf is refused later by the rows rule's `M` request, so M4's mutant would survive. The case stubs `_plat_devino` for the leaf's path alone, and M4's mutant then goes red.
- **`moved-host-owner-case-root-only`**. "Another user's directory at the id" needs a `chown`, so that case runs only as root (`it.runIf`). The link and file cases run everywhere.
- **`mountinfo-third-reader`** (claimed, and granted by the coordinator). The "two readers" case in `server/test/ccd-rows-rung-identity.test.ts` now pins three: `_ws_collect_mounts_clear`, `_ws_collect_moved_host` and the rows rung, all through the one seam. The one-literal case is unchanged.
- **`crash-before-the-move-is-state-changed`**. A crash before the move (`recorded`, `slotted`) resumes as `unmoved`. The verb then clears the slot and the record, keeps the witness and answers `state-changed`, as it does today. The next audit takes the leaf afresh, where the release is asked again, and the next verb collects it. A crash at `moved` completes in one resume.
