## What was built

- **The manifest** records `workdir`, `workdirReal` (`_ws_reclaim_resolve`'s `complete` answer, not opening with `//`,
  else `null`), `uuid`, and (fix round 1) `worktreeAdmin`: the name of git's admin directory for the tree under the
  common directory's `worktrees/`, from git's own reading of the tree's `.git` file, else `null`. A `.uuid` that does
  not read refuses the archive. Since fix round 2 (review 1521, F1) the name is recorded only when that admin
  directory names the tree back: its `gitdir` file (taken relative to the directory when git wrote it relative,
  `worktree.useRelativePaths`) reads `<dir>/.git` for a `<dir>` that resolves `complete`, through
  `_ws_reclaim_resolve`, to where the workdir resolved. A back-link that disagrees or cannot be read records `null`,
  which the arm holds on. Pinned with the review's chain (a `.git` crossed to another worktree's admin directory at
  archive time, then repaired, moved into the child with `git worktree move`, and the other worktree removed: the
  record is `null`, the row holds, and a CONTROL shows the crossed name would have placed it) and with the
  relative-paths form.
- **`_ws_reclaim_recorded_archive`**, asked third, holds A1 to A6 of spec §3.2 and sets `_WS_RECORDED_ARCH=1`. It reads
  the manifest with one python3 call that compares `id`, `uuid`, `branch`, `workdir` and `workdirReal` with the row's
  and hands back `worktreeAdmin` when it is one plain name. It shadows the record readers' globals and the resolver's.
- **A6, hardened in fix round 1 (review 1516, F1):** beside "git keeps no record at the row's path" and "no admin entry
  names `<w>/.git`", the arm holds while the admin directory the record names stands, or cannot be proven absent, and
  holds when the key is null, absent or not one plain name (fail closed, as D3 rules for older records). A tree
  relocated with its record following it (`git worktree move`, or `mv` then `git worktree repair` from the new place)
  keeps that directory's name while git names only the new path, so it holds; both relocations into a child's workspace
  are pinned, each with a CONTROL that git's removal of the relocated tree (which takes its admin directory) lets the
  record place the row again.
- **D5:** `_WS_RECORDED_ARCH` is reset beside GDIRS and IDS; `_ws_reclaim_owned` scans when it is set, and
  `_ws_reclaim_moved_check` runs, and reads each nested checkout's git directory, when it is set.
- **D3, as the operator ruled (item 37):** a record written before this change places nothing. The arm never reads the
  row's current `.workdir` in place of a missing field. The two live rows still need the operator's one-time act.
- **The advice:** three texts name `git -C $main worktree remove <path>`; `cmd_ws_rm`'s "worktree record not cleared"
  drops its prune clause.
