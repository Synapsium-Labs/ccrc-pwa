## What was built

- **ccd.** `_ws_held_by_put` and `_ws_held_by_doc`, beside the rows rung. The rung keeps `_WS_HELD_BY`, one
  `id<TAB>word<TAB>workspace` line per other row it puts in a not-asked bucket, reset on every call.
  `_WS_HELD_BY_RC` holds the rung's last answer and `_WS_HELD_BY_OWN` the child's own fault. The three documents
  print `heldBy` and `heldByOwn`, and the reclaim audit's `probe-unmeasured` line carries `meas.heldBy`. The
  outranking return clears the rows, and so does every call.
- **Server.** `server/src/cleanupHeldBy.ts` (L1, C4) holds `heldByOf` (the one reader, with five answers),
  `heldOnlyByListed`, `cleanupHeldByAct`, `cleanupHeldBy` (one item per row id, sorted, counts per lane, the first
  word in table order, the word's sentence), and `withCleanupHeldBy` (the status and the fold). The three lanes read
  `heldBy` off an unmeasured audit and keep the latest read on the entry they already keep for that subject. Every
  other answer clears it. `watch.ts` changes one line.
- **Console.** `heldByRowsWords.ts` (L1) holds `heldByRowsOf` (the one reader), `heldByRowControl` (the console's
  own check) and the words. `HeldByRows.tsx` renders one line per row through `AttentionList`, each
  with one control. A tap opens a `QuickConfirm` that names the row and says what will happen, and only the confirm
  acts. "Forget row" calls `api.forget` with the row id the server named. "Check again" sends nothing.
  `ChildReclaimBanner` renders it above `ExpiryAttention`.

## Departures, by slug

- `held-by-workspace-measured` (ruled, 15949): the fleet state cannot say "unreadable". The registry reader folds an
  unreadable `.workspace` to null, and `FleetSession.workspace` carries only that null. So ccd reads each named
  row's `workspace` field with `_reg_read` when it names the row. The heldBy entry gains
  `workspace: absent | present | unreadable`. An id ccd does not print reads `unreadable`. Forget is offered only
  when the word is gone-unrecorded AND ccd measured `absent` in every read that names the row AND the fleet state
  lists the row with `workspace: null`. An older entry without the key reads `null`, so it gets no forget (pinned).
- `forget-narrowed-to-non-workspace` (ruled option (b), 15943): this narrows the operator's table only where no
  door exists. A workspace row, a row whose field cannot be read, and a row missing from the fleet state each get
  "Check again". Their sentence says the tree is gone and that only a person removes the row, using R1's advice
  wording (recreate the tree with `git worktree add`, or remove the row by hand once its session has ended; where
  git still records it, the scoped `git -C <project> worktree remove <path>`; never a repo-wide prune).
- `check-again-reads-the-status` (ruled, 15949): there is no re-measure door and no GET of the coordination status.
  "Check again" re-reads the latest status the store already holds, sends nothing, and says the cleanup reads the
  row again on its next pass, about once a minute. It never implies it asked the server.
- `held-by-own`: the plan's interface has `heldOnlyByListed(read)`, but a read of ids alone cannot say "only". The
  documents print `heldByOwn` beside a `heldBy` array: true when the child's own buckets held it too. A missing key
  reads as own (fail safe), and such a child keeps its item.
- `fold-at-composition` (accepted with conditions, 15949): the fold is in `withCleanupHeldBy`, on the status's
  copies, not in `childReclaimAttention` and `expiryAttention`. The lanes' own lists, and so the feed's quiet check,
  see exactly what they saw before. That is pinned: `cleanup-held-by-fold.test.ts` holds the input unchanged, and
  both lanes' functions are characterized. One reader of the status does change: the archive page's run pins
  (`reclaimAttentionRunIds` over `currentCoord()`) no longer pin the runs of folded children. Those pins exist only
  so the banner can name a listed child's programme and wave, and a folded child is not listed. No push or stall
  notice reads either list.
- `held-by-id-placeholder`: a row id that is not one plain id (`[A-Za-z0-9._-]+`) is kept as `?` and printed as a
  null id. The server reads the whole read as malformed, so the child keeps its item. bash's `read` collapses an
  empty leading tab field, so the placeholder cannot be the empty string.
- `held-by-listing-failure`: when the registry cannot be listed, the rung answers rc 2 with no rows, so the documents
  print `heldBy: []`. That reads as `none`: no item, and no fold.
- `held-by-act-on-the-wire`: `CleanupHeldByItem.act` carries the server's decision, and L0 gains `CleanupHeldByAct`
  and `CLEANUP_HELD_BY_ACTS` (the wire-totality census asks for the list). The console still checks it
  (`heldByRowControl`).
- `meas-key-heldBy` (leave widened, 15951): `LifecycleMeas.heldBy` and its key-map entry. The census in
  `ccd-lifecycle-contain.test.ts` counts 39, the mirror's `journalparse.ts` reads the key, and the
  `lifecycle-wire.test.ts` fixtures carry it.
- `attention-line-control`: `AttentionLine` gains one optional `control`, and the "report, never a tap" headers of
  `AttentionList` and `ChildReclaimBanner` name the one exception.
- `lane-fields-optional`: `heldBy` is optional on the parsed reads, the outcomes and the three entries, so every
  existing literal compiles and an absent field means "no read yet". The expiry and collect steps set it through a
  wrapper on each existing step (`archivedExpiryLearned`, `archivedExpiryNextEntry`, `collectAfterAudit`), so it is
  set in one place per lane.
