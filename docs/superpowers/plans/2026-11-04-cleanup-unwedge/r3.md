## What was built

- **The hook.** A `prune` row, `pmatch`, beside `fmatch` (`GITPRE`, `GOPT`, `GITWT`, `GLAST`, `hdocs`, `qread`), read in
  all three modes on the command as written: `deny` (a child), `account` (every other session) and `class` (the
  classifier, and MCP strings as `fmatch` is). Both prefilters gain `*prune*`. The reason names
  `git -C <main> worktree remove <path>`, says a dry run (`-n`) is allowed, and names the file workaround
  (`git commit -F <file>`, `gh pr create --body-file <file>`) for text bash would still run. A deny already set is
  never replaced (the arm's existing guard).
- **How the row reads a command** (fix round 1, F6 and F3). Once the raw text names `prune` (its letters may be split
  by quotes, a backslash or a line continuation), it is read quote-aware, as bash reads it:
  - a quoted heredoc's body is dropped, and an unquoted one's is text but for its `$(…)` and backticks, unless the
    heredoc is fed to a shell (`bash <<'EOF'`, `sh -s <<EOF`, `cat <<'EOF' | sh`), which keeps it as code; with more
    than 16 heredoc lines the bodies are read as code;
  - a quoted span is one word of text, never a command boundary: its whitespace and separators become `_`, and an
    empty one standing alone stays a word (`git -C '' …`); a `$(…)` or a backtick inside double quotes stays code;
  - the string a `bash -c` (or `sh`, `zsh`, `dash`, `ksh`, `-lc` and the like) runs is read as code, one level deep;
  - then the command is split into simple commands on `;`, `&`, `|` and newlines, and one is refused whose program, at
    its head or after `$(`, `(`, a backtick or `{`, a shell keyword, assignments and a few wrappers, is `git`, bare or
    path-qualified, then git's global options, `worktree`, any flags and `prune`.
- **The dry run** (F1). Only git's own words after the matched `worktree … prune` are read, cut at `#`, `$(`, a backtick,
  `<` and `>`; the last of `-n`, `--dry-run` and `--no-dry-run` decides, as git does.
- **The global options** (F8, F10(b)). `--attr-source` joins `GOPT`; every option beyond the plan's six has a must-deny row.
- **The classifier.** `FORBIDDEN_PATTERNS` gains `{ why: 'git worktree prune', test: runsWorktreePrune }`, the same
  reading; the static-copy test holds the hook's class mode equal to it over both fixture lists, and deny mode answers
  the category for every must-deny row and for no must-allow row.
- **The advice.** `child-record-stale` names `git -C <main> worktree remove <path>`.
- **Main merged once** (F7), so `deviation-refs` reads the plan's high-water.

## Residuals

An accident guard, like the account arm, never a wall. These run past it:

- `bash -c` (or `eval`) with an assembled string, a script file, an alias or a shell function.
- A `$VAR` program (`G=git; $G worktree prune`): there is no `xmatch` row for it.
- `git gc`, and the automatic gc after many commands, prunes records older than `gc.worktreePruneExpire` (three months
  by default). R1 is what makes the reclaim independent of git's records for archived rows.
- A wrapper the grammar does not name, or one with an option value it does not read: `sudo -u <user> git …`,
  `timeout -s KILL 5 git …`, `env -u X git …`, `exec -a x git …`, and `xargs git worktree prune` or
  `find . -exec git worktree prune \;` (F10(f)).
- A redirection before the command (`2>/dev/null git worktree prune`, `</dev/null git …`; `2>&1 git …` splits at `&`),
  and a `case` arm after `)` (`case x in x) git worktree prune;; esac`) (F2).
- More than eight global options or four wrappers (the bounds `{0,8}` and `{0,4}`) (F10(b)).
- `pr$'u'ne` and `pr$"u"ne`: the deny and account prefilters strip quotes and backslashes but not the `$` before a
  quote, so no jq runs; the row itself reads them (F10(a)). The same gap exists on main for a forbidden verb split
  that way.
- A top-level payload over `APF_ACCT_STRIP_MAX` (8 KiB) that spells `prune` with quotes: its prefilter reads the text
  as written.
- Nested double quotes inside a `$(…)` inside double quotes are read one level only.
- The operator's own shell has no hook.

False denies, in the safe direction:

- Text bash would run: a backticked or `$(…)` mention inside double quotes or an unquoted heredoc, or a `bash -c`
  string. The reason names the file workaround.
- `git worktree prune --help` and `-h`, and bundled or abbreviated dry runs (`-nv`, `-vn`, `--dry`) (F10(c)).
- A `-n` after a redirection (`git worktree prune > out -n`), which git does receive but the cut does not read.
- More than 16 heredoc lines in one command: every body is read as code.
- Class mode reads MCP payloads, so a child's MCP issue or comment that mentions a backticked `git worktree prune`
  classifies as forbidden and cannot be routed for approval (F10(d)).

## Departures, by slug

- **`pmatch-beside-fmatch`.** The plan's interface names a row in `fmatch`; the row is its own definition, `pmatch`,
  asked after `fmatch` in each mode. Deny and account modes also run `fmatch` over `norm`'s form, which removes quotes,
  so a row inside `fmatch` would read quoted prose as code there (F6). `norm` stays where main has it.
- **`quote-aware-reading`.** The ruled reading of fix round 1; it reads `pr""une` and `pr\une` in every mode.
- **`dry-run-cut-at-redirections`.** The dry-run words are cut at every `<` and `>`, a superset of the ruled `>(` and
  `<(`, so a here-string's `-n` (`<<< -n`) does not count. It can only refuse more.
- **`heredoc-cap-16`.** With more than 16 heredoc lines the bodies are read as code, to keep the reading bounded.
- **`own-pr-body-checked-on-the-row`.** This PR's body, in its two inline shapes, is checked against the prune reason only
  (`own-pr-body.json`), because the account arm refuses it for another reason: the body names a backticked `env`, which
  that arm reads as printing the whole environment. That is main's behaviour and outside R3.
- **`timing-pin-is-a-ratio`.** The timing case bounds deny mode by the same payload without the row (1.25x) and class mode
  by `norm` (0.6x), both measured in the run, since absolute times differ between machines.
- **`command-position-and-wrappers`.** The plan's grammar names the program `git`; the row also requires it at a command
  position. Without it, `grep "git worktree prune" …` would be refused. Both kinds are on the must-allow list.
- **`more-global-options`.** `GOPT` reads `--namespace`, `--config-env`, `--attr-source`, `--exec-path`, `--paginate`,
  `-p`, `-P` and git's other flag-only global options beside the plan's six, each with a must-deny row.
- **`fixtures-are-string-lists`.** The fixture files are JSON arrays of Bash command strings, not `{tool, input}` rows
  as the account deny's are: every row is a Bash call.
- **`five-hook-suites`.** Step 6 names "the five hook suites above"; step 2 names four (`session-hook-prune-deny`,
  `-account-deny`, `-approval-deny`, `-merge-deny`). The fifth run here is `session-hook.test.ts`.
- **`ccd-advice-left-for-r1`.** `ccd/ccd` still names the repo-wide prune in four advice texts: the three the spec gives
  R1 and the `worktree record not cleared` refusal in `cmd_ws_rm`, which review 1479 (F9) routes to R1 as well. R3
  edits no `ccd/ccd` line. Until R1 lands, the hook refuses the command that ccd's advice names.
- **`classifier-red-measured-as-a-mutant`.** Each round's red was measured by running the new cases against the previous
  hook and classifier (round 0: main's; fix round 1: the tip `33e521e07`'s), after the change was written.
