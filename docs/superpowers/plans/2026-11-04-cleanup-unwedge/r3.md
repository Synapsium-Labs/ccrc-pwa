## Residuals

An accident guard, like the account arm, never a wall:

- `bash -c` (or `eval`) with an assembled string, a script file, an alias or a shell function run past it.
- A `$VAR` program (`G=git; $G worktree prune`): there is no `xmatch` row for it.
- `git gc`, and the automatic gc after many commands, prunes records older than `gc.worktreePruneExpire` (three months
  by default). R1 is what makes the reclaim independent of git's records for archived rows.
- A wrapper the grammar does not name, or one with an option value it does not read (`sudo -u <user> git …`).
- `pr""une`: the raw text names no `prune`, so the classifier and the hook's class mode miss it (the strict grammar
  escalates it to the operator); the deny and account modes read the `norm` form and refuse it.
- A top-level payload over `APF_ACCT_STRIP_MAX` (8 KiB) that spells `prune` with quotes: its prefilter reads the text
  as written.
- The operator's own shell has no hook.

A false deny, in the safe direction: text that holds a `git worktree prune` at a command position bash would not run,
such as a backticked or `$(…)`-wrapped one inside a quoted heredoc or a commit message, is refused. Write such text to
a file and pass the file.

## Departures, by slug

- **`norm-moves-above-fmatch`.** The plan's interface adds `def GITWT:` and an `fmatch` row; for the row to read the
  command as bash runs it in `class` mode (where the program runs `fmatch` on the raw text only), `norm`'s definition
  moves above `fmatch`. No other row changes.
- **`row-reads-norm-after-a-raw-prune`.** The classifier and the hook's class mode read the `norm` form only once the raw
  text names `prune`, which keeps a payload naming no `prune` from paying `norm`'s four substitutions; `pr""une` is
  the cost (Residuals).
- **`command-position-and-wrappers`.** The plan's grammar names the program `git`; the row also requires it at a command
  position (a segment's head, or after `$(`, `(`, a backtick or `{`, a shell keyword, assignments and the wrappers
  `sudo`, `env`, `command`, `exec`, `nohup`, `nice`, `time`, `timeout`, `bash`, `sh`, `zsh`, `dash`). Without it,
  `grep "git worktree prune" …` and `git commit -m "… git worktree prune …"` would be refused once `norm` removed
  their quotes. Both are on the must-allow list.
- **`more-global-options`.** `GOPT` reads `--namespace`, `--config-env`, `--exec-path`, `--paginate`, `-p`, `-P` and git's
  other flag-only global options beside the plan's six.
- **`fixtures-are-string-lists`.** The fixture files are JSON arrays of Bash command strings, not `{tool, input}` rows
  as the account deny's are: every row is a Bash call.
- **`five-hook-suites`.** Step 6 names "the five hook suites above"; step 2 names four (`session-hook-prune-deny`,
  `-account-deny`, `-approval-deny`, `-merge-deny`). The fifth run here is `session-hook.test.ts`.
- **`ccd-advice-left-for-r1`.** `ccd/ccd` still names the repo-wide prune in four advice texts: the three the spec gives
  R1 (`ccd/ccd:8387`, `8918`, `13563` on main) and a fourth it does not list, the `worktree record not cleared`
  refusal at `ccd/ccd:8506`. R3 edits no `ccd/ccd` line. `ccd-ws-audit.test.ts`'s `child-record-stale` case pins ccd's
  `detail` to `/worktree prune/`, so R1's text change meets that pin. Until R1 lands, the hook refuses the command
  that ccd's advice names.
- **`classifier-red-measured-as-a-mutant`.** Step 3's red was measured by running the new classifier cases against
  main's `approvalguard.ts` (mutant 6's state), after the row was written, with main's `wsaudit.ts` alongside for step 4.
