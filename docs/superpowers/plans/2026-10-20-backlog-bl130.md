# Backlog: CLAUDE.md states no README size; numeric line citations only fall (#558)

**GitHub issue:** #558 (ARCH-07 of the 2026-10-17 DDD/Clean/SOLID audit).

## Problem

Two pins required CLAUDE.md to restate README's line count: `oss-metadata.test.ts`
within 10% and `pools-prose.test.ts` within 100 lines. They capped nothing (README
grew from 743 lines to over 6,000 under them), the sentence was rewritten in about
twenty commits, and one of those turned main red (#440). Open PR #434 is
re-measuring it again.

Numeric line citations (`ccd:` plus a line number, `file.ts:` plus a line number)
rot as code moves, and their count was still rising.

## Fix

1. CLAUDE.md drops the README line count. Both pins are inverted: each asserts
   that CLAUDE.md states no README line count (D-5892). Both read one pattern,
   `server/test/readmeSizeClaim.ts`, which catches the count after README
   ("README.md (~6702 lines)") and before it ("the 6702-line README.md"), and
   returns only the offending phrase so a failure does not print the whole file.
2. `server/test/citations.test.ts` counts numeric line citations across the code
   and test files of the tree and fails when the count rises above its merge-day
   baseline. New code cites a symbol (`ccd#_ws_least_loaded`). Existing citations
   are rewritten when their file is touched; there is no bulk pass (D-5893).

## Tests

- `oss-metadata.test.ts` and `pools-prose.test.ts`: red against the old CLAUDE.md
  sentence and against a reversed "6702-line README" phrase, green once it
  carries no number.
- `citations.test.ts`: green at the baseline, red when one new `ccd:` line citation
  is added to a `server/test` file.

## Deviations and decisions

- **D-5892 (2026-10-20)** — CLAUDE.md states no README size, and both former size pins assert the absence. A size is not a rule, so README grows without a CLAUDE.md or test edit. This supersedes #434, which re-measures the figure.
- **D-5893 (2026-10-20)** — Numeric line citations are held by a downward-only ratchet in `citations.test.ts`. The corpus is every tracked or untracked-not-ignored code file outside `docs/` and `graphify-out/`, plus the extensionless executables under `ccd/`. Strings and comments are both counted, because telling them apart would need a parser per language and the ratchet only needs a stable count. The assertion is `<=` rather than an exact match, so removing a citation does not force an edit to the constant. Whoever removes some lowers it in the same commit.
  The constant was first 1584. Merging main before landing brought ten citations that were added while the PR waited, so it is 1594: the count on the day the ratchet lands, not the day it was written (D-5893).

Issued and unused: none.

### Found after landing: the ratchet's slack (#558)

No new number is issued; this revises D-5893 in place.

- **D-5893, revised (2026-10-20)**: the ratchet is exact. `<=` let removals go unrecorded. One commit took the count from 1594 to 1593 without lowering the constant. Two later commits lowered the constant to 1591 without matching the count. By then the tree held 1587, so four new citations passed before the fifth failed. The test now also fails when the count is below BASELINE, and its message names the new count to write. BASELINE is 1587, the count measured on main. This brings back the trade-off the original entry declined: a commit that removes citations has to edit the constant. That edit is the record that keeps the next added citation red.
  The count is a net figure, so replacing one citation with a new one in the same commit still passes. Telling which citation is which would need a list of locations, and a location list moves with every edit, so it is left out.
