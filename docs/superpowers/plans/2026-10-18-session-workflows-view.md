## Measured source (2026-10-18; Claude Code 2.1.203–2.1.302, a local session and the fleet box read-only, the 2.1.302 binary)

`S` is the session's transcript path without `.jsonl` (`<cfgDir>/projects/<slug>/<uuid>`).

| Path | Written | Read for |
|---|---|---|
| `S/subagents/workflows/<runId>/journal.jsonl` | appended: `launched` (2.1.265+), `started{key,agentId[,label,phase]}`, `result{key,agentId,result}`, `failed{key,agentId}` (2.1.251+). No timestamps. A retry is a new `started` with the same `key`. | done / failed / total, labels, phases |
| `…/agent-<agentId>.meta.json` | once, at the agent's start | its mtime is the agent's start; label/phase for pre-2.1.265 lines |
| `…/agent-<agentId>.jsonl` | the agent's transcript | the last non-zero `usage`: `input + cache_read + cache_creation` |
| `S/workflows/<runId>.json` | at a final status (`completed`/`failed`/`killed`), 5–35 ms after the end; rewritten if a resumed run ends again | a finished row: status, name, start, duration, `totalTokens`, agent states |
| `S/workflows/scripts/<name>-<runId>.js` | inline-script launches only | the name (filename prefix) and `meta.phases` |

How each fact maps (Claude Code 2.1.302's own computation in brackets):
- **total** = distinct journal keys [max(agentCount, agent entries); 111/112 runs equal]. Agents queued behind the concurrency cap are not on disk, so the disk total can trail the terminal's while they wait.
- **done / failed** = keys whose last line is `result` / `failed` [state `done` / `error`].
- **elapsed** = now − the first agent's start (its meta mtime); for a run resumed in place, the first agent after the old summary's mtime [now − startTime − paused; paused time is in memory only, so ccrc's elapsed can run ahead of a paused run's].
- **tokens** = Σ per key's latest agent of the input side of its latest usage line [Σ agent `tokens`: the same plus the first stream event's output count, +2..+24 tokens].
- **finished rows** drop 30 s after the end [`evictAfter = endTime + 30000`, measured in 2.1.302 only].
- **running vs finished** — two traps measured: a run with no summary is not necessarily running (169 orphans of dead or swapped sessions on the fleet, 3 live), and a run with one is not necessarily finished (a killed run resumed in place keeps its id and dir). The rule is D-5561's.

Sizes that bound the read (fleet): journals median 50 KB, p95 382 KB, max 2.7 MB; up to 292 run dirs in a session and 629 agents in a run; the last usage line a median 10 KB from an agent transcript's end, p95 53 KB.

The agent's read whitelist already admits these paths (`.claude*` under home), so the reader uses FleetIO's measured reads and needs no new op or exec verb.

## Design

- **L0 `shared/workflows.ts`**: `WorkflowView` (every count nullable, and null means *not measured*), `WORKFLOW_EVICT_MS`, `WORKFLOW_AGENTS_MAX`. **Wire:** `SessionStreamMsg` gains `{type:'workflows', workflows, unreadable?}` — additive, no `FLEET_PROTO` bump.
- **L1 `server/src/workflows/model.ts`**: pure — line framing over bytes with a bounded carry, the journal fold, usage tokens from a tail, `decideRun`, the running and summary rows, `selectRows`, `workflowsFrame`.
- **L3 `server/src/workflows/read.ts`**: `SessionWorkflows`, one per socket and session dir, caching offsets, folds and per-agent readings. Bounded per tick: the journal read from its last offset (at most 16 × 256 KB chunks per run), one 64 KB tail per agent whose size changed, a finished, dropped or interrupted run re-stat'ed only every 15th tick (staggered by run, so a session's quiet runs do not all re-stat on one tick; an undecided run waits the same while the process stays unmeasured), a long-finished run never read beyond two stats. **At most 24 agent reads per tick, spent in an order that starves no run:** first each running run's start (one meta stat, cached once known); then running agents' tails, a fair share per running run (`max(2, ⌊16 / runs⌋)`, the runs rotated across ticks when there are more than shares, and round-robin over each run's agents); then, with what is left and never less than 8, the one-time reads — labels for pre-2.1.265 lines and each done agent's last tokens, newest first. A done agent's read walks back from a tail with no usage line in up to 4 × 256 KB chunks before it is ruled unmeasurable; it is never read again after. (The first cut spent one shared budget on running tails first, and a run with 12+ agents writing every tick — or any run read after it — never got its start or its done agents' tokens.)
- **L4 `sessionws.ts`**: `checkWorkflows` beside `checkTasks` on the 2 s tick and the cold start, deduped on its JSON. `resolve()` keeps tmux's `sessionVerdict` (one `has-session`, as before) so `gone` and `unknown` stay apart, and carries the live file's `startedAt` as `Resolved.proc`.
- **PWA**: the store's `workflows`/`workflowsUnreadable`; `@ccrc/ui`'s `WorkflowStrip` on `CollapsibleStrip` (the shared strip chrome, the default 44 px tap floor) and `Meter` (Refined's bar, Instrument's LED segments), between the mail and the plan. Capped like the mail and task strips (`min(40vh, 320px)`). Collapsed: at most three lines, running ones first — name, bar, `done/total · elapsed · ↓ tokens`, a last word for a finished one — then `+N more — open for all`; the head counts every one. The lines are a list, one item per workflow, a running one saying `running` to a screen reader. Open: the summary steps aside and the rows are the one scroll body under the head; each workflow's detail starts with its own facts line, then phases in script order (the current one marked `now`), each agent's label and state, done agents behind a fold that toggles in place at the tap floor. A container query lines the rows into one grid (each line a subgrid row) where the strip is at least 560 px wide.
- **Instrument's inspector slot does not exist yet** (the skins W2 plan's S8/S12), so both skins use this same strip; moving it into the inspector is that plan's to do.
- **The card is unchanged.** It already says `working · N in background`, workflows counted (D-5231), and a workflow-specific card fact would need a per-session sweep of these directories on every fleet tick.

## Known limits

- **Retried agents' live tokens run low.** Claude Code's per-agent tokens accumulate across internal retries (a summary `attempt` above 1) that never reach the transcript, so a running row's `↓ N tokens` can read well under the terminal's for such a run (measured: 24 of 112 finished runs more than 1% off, all of them multi-attempt). Nothing marks it yet; the finished row corrects itself from the summary's `totalTokens`.
- **Paused time is not subtracted** from a running row's elapsed (§Measured source).

## Deviations found

### Issued 2026-10-18 and defined here

- **D-5560** — `session-workflows-view`: the session page lists the session's dynamic workflows, one line each with Claude Code's own facts (name, a bar, agents done of those scheduled so far, elapsed, `↓ N tokens`), and opens to each workflow's phases and every agent's label and state; a finished workflow stays 30 s (`WORKFLOW_EVICT_MS`, Claude Code 2.1.302's `evictAfter`) with its last word, `done`, `failed` or `stopped`. Read-only: no control starts, stops or changes a workflow. Every unmeasured fact is said — `progress unreadable`, `tokens unmeasured`, a `+` on a token floor, no elapsed clause without a measured start, `Workflow state unreadable` — and never drawn as a zero. The `workflows` frame is sent on change, and on connect whenever the session has a workflow directory (an empty list included); the one first read swallowed is a session dir that never had one. The PWA drops its rows on a `backlog` onto another transcript (and after a `rotated`, which forgets the file), and `sendBacklogAndTail` resets the frame's gate with every backlog, so rows from another session dir (a /clear, a swap, a reconnect onto another file) never outlive it; a reconnect onto the same transcript keeps the rows until the restated frame replaces them, so the strip neither unmounts nor collapses each time a phone foregrounds the PWA. A run carries at most `WORKFLOW_AGENTS_MAX` agents on the wire, running and failed first, and says how many it left out. The card is unchanged (D-5231 already counts workflows in `working · N in background`). Instrument has no inspector slot yet, so both skins draw the same strip.
- **D-5561** — `session-workflows-source`: the strip's source is the files Claude Code keeps under the session dir (§Measured source), read only under the session's resolved config dir. A run is FINISHED when its summary's mtime is at or after its journal's; otherwise INTERRUPTED when tmux proves the session gone, or when every write the reader knows of (the journal, a running agent's transcript) predates the live file's `startedAt`; UNDECIDED when the process could not be measured (tmux `unknown`, a pane pid or live file that did not read), and then the row last shown stands and a run never shown is not shown; otherwise RUNNING, however long since its last write (no recency timeout: a running workflow can go 30 min without one). Interrupted runs are not shown — whether Claude Code 2.1.302 draws one as a paused row after a restart was not observed. A missing runs directory is "no workflows" unless the hook's last fresh Stop listed a background `workflow` (D-5231's pair), and then it is unreadable: a build whose storage interface (2.1.287+) does not write these files must not read as "nothing running". Tokens are the input side of each key's latest agent's latest non-zero usage line, read from a 64 KB tail re-read only when the transcript's size changed; no usage line in the tail keeps the previous reading, and none ever is unmeasured; a done agent is read once more after it finished, walking back up to 4 × 256 KB past the tail. The per-tick read budget is spent in the order §Design gives, so no run's start, labels or done agents wait behind another run's busy agents. The run's start is its first agent's meta-file mtime (written once as it starts), or for a run resumed in place the first after the old summary's mtime.
- **D-5562** — `workflow-strip-census-entries`: the strip is a fourth `CollapsibleStrip` consumer, and `pwa/test/tap-targets.test.tsx`'s strip census (its own header: "a fourth strip is a one-line addition here") gains it — one `HEADS` row and one name — in a file open PR #627 also changes, which the skins plans freeze. The edit is two additive lines away from every hunk #627 changes there, measured to merge cleanly with #627's head (`git merge-tree`); if the operator rules the freeze binds this plan too, the PR waits for #627 and re-applies the two lines. Two other frozen files are NOT edited: the strip's two state hooks are data attributes (`data-current`, `data-stopped`, as `Meter` carries `data-band`) rather than computed modifier classes, which `design-system-boundary.test.ts`'s `OWNED` would have to list; and its head mark does not breathe as the task strip's does, because an opacity fade needs entries in `design/audit.mjs`'s registries. `contrast.test.ts` was run alone and is green, every new rule measured through the self-grounded `.workflow-strip` in all twelve themes.
