## What W4-3 built (Task 3, P7)

- **One flag, one declaration.** `COMMON_READ_OPTIONS` in `lib.mjs` holds the only read-option declaration of `--agents`, so `grep`, `describe`, `expand` and `tree` derive it, and `touched` will when it joins `READ_OPTIONS`. `parseReadArgs`' defaults carry `agents: false`. `parseGrepArgs` and `parseDescribeArgs` pass the flag over, as they pass the scope flags (a repeat is `bad-args`). `AG2` counts declarations, not files: a second read-option declaration in `lib.mjs` or in any other history module reds.
- **The scope carries it.** `decideScope`'s ok verdict has `agents: boolean` (from `flags.agents`, false when absent), in every scope kind. `cli.mjs` hands it to `transcriptsOf` and puts it on `rc.scope`, in both the tmux path and the headless path.
- **One spelling of "a main-thread transcript".** `recall.mjs`' `MAIN_TRANSCRIPTS` (`SELECT transcript_pk FROM transcripts WHERE agent_id = ''`) serves `transcriptsOf` and, through `mainOnlyAnd`, every select over `nodes`: `runTree`'s stored select, `resolveNodeInScope`'s partition, `scopePrefixes`, and `coveringLeaves` (its default arm). Under `--agents` no term is added, so those statements are the ones they were; without it a store with no subagent row selects what it always selected. One exception to "a default read prepares the statements it prepared before": `resolveNodeInScope`'s select now always carries the computed `main` column (results unchanged); `agentColumn`'s doc says so. Grep's referrer arms, the regex child's job, the header counts and lag, and expand's uuid and `--around` targets all read `rc.scope.transcriptPks`, so they follow `transcriptsOf` and needed no edit.
- **Out of scope, not absent.** A subagent node without `--agents` is a node outside the scope: `resolveNodeInScope` puts it in `outOfScope`, so an exact id answers exit 2 `out-of-scope` (never 3) from `describe`, `expand` and `grep --node`, and the prefix rule counts only the nodes the scope reads (Review Focus 5): a prefix unique without `--agents` is ambiguous with it. A message uuid held by a subagent transcript answers 2 the same way.
- **D-8175, the mark.** Under `--agents` only, a human line that names a subagent row carries ` agent:<agent_id>` right after the row's id and kind: `tree`'s node line, `describe`'s `node` line, `expand`'s entry and sidecar lead lines (after the uuid), `grep`'s hit line (leading it, since a hit line opens with its envelope) and `grep`'s `── leaf` group header. Each `--json` item that shows a row carries `agent_id`: the id for a subagent row, `null` for a main row. Without `--agents` no line and no item changes (no new key). The id is `displayToken` text, escaped as text in a line.
- **A page keeps its scope.** `--agents` rides `cli.mjs`' `scopeArgsOf` and `recall.mjs`' `scopeArgs` (the two spellings of a `next:` line's scope flags), and `grepKey` carries `agents: true` only under the flag, so a cursor minted under `--agents` is refused without it, and every earlier cursor keeps its key.
- **Not touched, by reason.** `describe`'s children list and `expand`'s lineage walk read a node the scope has already admitted. W4-2 keeps the chains apart (SA8: no parent mixes a subagent leaf with a main one), so a main node's children are all main; neither walk carries a term of its own. `coveringLeaves`' as-of-cut arm (reached only on the headless path) was given the same term, and fix round 1's case `F2 the as-of arm of coveringLeaves...` exercises it (mutant f2b).

## Relied-on invariants

- **Children and lineage carry no filter of their own.** `describe`'s child list (`childRowsOf`) and `expand`'s lineage walk (`expandLineage`) read only a node the scope admitted (`resolveNodeInScope`), and carry no `--agents` term. They rely on W4-2's derivation keeping subagent leaves on their own chain: derive's fan-in statements keep `agent_id = ''` (`epochTranscripts`; D-8168 and D-8169), and W4-2's SA8 (`history-derive.test.ts`) pins that no parent mixes main and subagent leaves, so no main parent has a subagent child, and a subagent parent's children are all subagent. If that ever fails, a main node's child list would name a subagent node without `--agents`.
- **The cut's epoch visibility reads every transcript.** lib's `asOfVisibleEpochsSql` looks at transcripts of any `agent_id` when it decides which epochs an as-of cut shows. It is left as it is: the cut's boundary must be a main one (`asOfCut` refuses a subagent boundary, `asof-invalid`), and a subagent cannot start before its parent's first row, so a subagent transcript never makes an epoch visible that the main thread's rows would not.
- **Describe's per-entry source lines carry no mark of their own.** The subagent node's own line above its `sources` list carries `agent:<agent_id>` (and its `--json` item `agent_id`), which meets D-8175: every source line belongs to that one node, so a mark on each would only repeat it.
