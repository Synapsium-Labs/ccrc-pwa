## What W4-2 built (Task 2, P2)

- `leafPolicy(agentId)` in `lib.mjs`, the one decider: `{ receipt: true }` for a main leaf (`''`), `{ receipt: false }` for any other agent key. `leafFields` asks it before `pickReceipt`, so a subagent leaf is never steered: its status is `not-requested`, reason `no-receipt` (SA7). Both callers of `leafFields`, `deriveOne` (through `todo`) and `refreshLeaf` (through its own boundary query), hand it the boundary's real `agent_id`.
- In `derive.mjs`, the boundary statements (`todo`, `firstTodo`, `lastBoundary`) and the file statement (`forkCandidates`) no longer filter `agent_id = ''`, so subagent boundaries are derived as leaves and a subagent transcript's fork counts are its own (SA27's `transcript_forked`).
- `epochTranscripts` stays main-only and `fanInLevels` gained no filter: the one guard of fan-in's level-0 slots, and of the card's lists, is that statement.
- D-8169 (`history-w4-main-gists-main-only`, licensed by the coordinator during the build, review M1): `priorGists` and `otherGists` join `transcripts` and read the session's main-transcript nodes only, so a main leaf's steered-gist check and a parent's node block never compare against a subagent leaf's gist. `nodes.transcript_pk` is NOT NULL and a parent carries its first child's, so the join drops no main node; W3-4's lower-rowid bound stays. Cases: `D-8169 leaf arm: a main leaf whose steered gist equals a subagent leaf's native gist stays ok (no carried-copy from another chain)` and `D-8169 node arm: a parent's node block whose gist equals a subagent leaf's native gist stays ok`.

## Statements the build found that the ledger should hold

- **SA27 keeps two `entry_variants` rows, not one.** The addendum's SA27 row says "one entry and one `entry_variants` row". The store's entry-conflict arm in `sweep.mjs` (B1's, unchanged) writes the entry's earlier body and the new body together, each its own row under `UNIQUE (entry_id, blob_id)`. So one message uuid with two bodies is one entry and two variant rows, one of them the entry's own blob. Nothing is dropped, which is the addendum's intent. The test pins the measured shape (the plan's rule: correct a differing outcome in the test, never in the plan). The addendum's SA27 row and the plan's Task 2 test block (`variantsOf(db, conflictUuid)` to be 1) still say one; their wording is the coordinator's to correct, and a ledger entry if it numbers one. This PR defines no number for it.
- **A subagent boundary stored below the leaves cursor by an armed W4-1-only build is never derived after W4-2, short of a rebuild** (review I1; the coordinator ruled (a), no rescan and no new state, 2026-11-10). The leaves cursor is a low-water mark over global `entry_id`s, and under W4-1 it moved past subagent boundaries stored between main ones. No node is armed, so no such boundary is stored anywhere today. The brief's "your widening inherits that backlog" reads, as built: W4-2 inherits the subagent boundaries stored above the cursor. The coordinator carries the rule into the arming runbook: no node is armed on a build without W4-2.
- **A waiting subagent boundary holds the leaves cursor, and main boundaries above it still derive in the same pass** (review M2). `firstTodo` now counts subagent boundaries too, so a subagent boundary that waits (its summary row not yet ingested, as under P5's 90% subagent pause) holds the cursor at the entry below it while it waits, and each pass rescans the boundaries above it (D-5024's cost). Nothing is lost: `todo` still walks every boundary above the cursor, so a main boundary above it derives in the same pass. Case: `M2: a subagent boundary that waits holds the leaves cursor below it, yet a main boundary above it derives in the same pass; a later pass derives the subagent leaf` (`history-derive.test.ts`); its mutant (the cursor's `top` always the last boundary) reds it.
- **A subagent leaf waits on its parent session's pending-receipt drain** (review M3). `deriveOne` holds a boundary while `ictx.pendingReceiptState` names its session uuid, and a subagent boundary carries its parent's uuid. A subagent leaf never takes a receipt, so the wait is needless but harmless: a later tick derives it.
- **SA9 is proved by two rows.** With the parent's main transcript absent from the store, both of `card.mjs`' filters (`cardStmts().transcript` and `measureStmts().leaves`) red under their mutants. With it present, a whole card step is compared against a main-only run (measure result, cursor, card/ and steer/ files, `card_*` and `steer_*` counters); only `measureStmts().leaves`' mutant reds it, because a present main copy masks `cardStmts().transcript`'s filter. `card.mjs` was changed only as a mutant, restored byte for byte and never committed.
- **Read verbs show subagent leaves until W4-3.** `deriveOne` indexes every leaf into `nodes_fts`, so on an armed node `grep` and `tree` show subagent leaves by default until W4-3's `--agents` lands. W4-3 filters nodes as well as entries. This matches the plan's recommendation to arm no node before W4-4.
