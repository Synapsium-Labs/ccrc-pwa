9. **The docs redactor (ARCH-67).** The docs helper (`ccd/ccd#_docs_py`, one python process per docs verb, on fd 3) carries `REDACT_RULES` inside its `docs-parity` block, a four-rule copy of `shared/docs.ts#DOCS_REDACT_RULES` held equal row by row by `docs-parity.test.ts`, and a `redact(s)` function with five direct sites, each **before** a cut, so a cut can never split a secret: `stderr_head`, `fetch_detail`, `failure_line`'s `detail` and its `stderrHead`, and `helper_failed_line`'s `detail`. **Two of those five fan out.** `stderr_head` has 18 direct call sites, and `os_head` (7 sites) is a call of it, so 25 sites reach it; `fetch_detail` has 1. With the three in `failure_line` and `helper_failed_line`, 29 call sites reach `redact`. Measured by enclosing function and by what catches the result:
   - **Inside answers that succeed.** `docs-index`: `discover`'s and `find_owner`'s `repo-unreadable` and `git-failed` Fails (`os_head` 3 sites and `stderr_head` 3, `rev-parse`'s among them) are caught by `index_row`'s first `except Fail` and become a row (`index_failed_row` writes no head). The Fails from `origin_url`, `for_each_ref`, `origin_head_target`, `counts_of` and `index_section_counts` are caught by `index_row`'s second `except Fail`, which discards the head and writes `repo-unreadable`. So a `docs-index` answer can redact one string per failing git call and print none of them. `docs-tree`'s drafts phase: `_holder_rc_detail` (from `trust_holder` and the worktree-list read), `trust_holder`'s two `os_head` calls, `_draft_rc_detail` (config, status, ls-files) and the `os_head('spawn', …)` in `snapshot` and `draft_phase` each build a drafts `detail` that the tree answer carries. `counts_of`'s Fail is caught in `_snapshot_once` and becomes `'base counts: ' + e.word`, which discards the head.
   - **Inside failure answers.** Every other site: `list_committed`, `tree_head_of_m` (2), `_pin_git`, `show_failed`, `tracked_oid`, `verb_fetch`'s `fetch_detail` and `stderr_head`, and the same discovery and git calls when `docs-tree`, `docs-show` or `docs-fetch` reaches them outside `index_row`. **A head is redacted twice on the way out:** in `stderr_head`, and again in `failure_line` (`stderrHead` is re-redacted, and `detail` is re-redacted and then cut).
   - **Consequences for a CLI.** "Call node once per docs verb" cannot be a single pass over the finished answer: the cut would come first. Spawning node once per redacted string would start node inside successful `docs-index` and `docs-tree` answers, once per failing git call, under the 12 s helper deadline. And a CLI failure that is not a `Fail` would escape `index_row` (it catches only `Fail`) and turn the whole `docs-index` into `helper-failed`. **The design C5h takes:** the helper starts **one** node process lazily, at its first redaction, and sends each string to it as one JSON line and reads one JSON line back. So there is at most one spawn per docs verb, none when nothing is redacted, and every redaction still comes before its cut, with no call site changed. A redactor failure is sticky and fails closed: the verb answers `helper-failed` with the fixed detail `redactor-failed`, never an unredacted string and never a partial index. That is a behaviour change, named in its own commit (C5h, Step 5).
   - **`helper_failed_line` calls `redact` too.** `run()`'s two handlers both call it, and its docstring says it "cannot fail". So a redactor that raises must not be called again from it. C5h gives it the fixed detail for the redactor's own failure, and it catches any raise of `redact`.
   - **The units.** `H.Sys` is subclassed with a `def spawn` override 31 times, in four files: `ccd-docs-tree.test.ts` 15, `ccd-docs-index.test.ts` 9, `ccd-docs-show.test.ts` 6 and `ccd-docs-fetch.test.ts` 1. Several answer every argv with a canned result, or read `argv[argv.index('-C') + 2]`, which raises `ValueError` on any argv without `-C`. So the redactor never goes through `self.spawn`: it has its own `Popen` seam (C5h). Units also make 36 direct calls of helper functions whose results hold a redacted string: `H.discover` 15, `H.trust_holder` 10, `H.draft_phase` 5, `H.enumerate_drafts_holder` 3, plus `H.stderr_head` 2 and `H.verb_fetch` 1. The eager design leaves every one of them a plain string. No ccd verb runs a `shared/*.mjs` file today; `ccd/ccd-usage-sweep` reads `shared/models.mjs` from the deployed tree (`${CCRC_TREE:-$HOME/ccrc}`), which is the one precedent. The front's python probe (`_docs_front`) answers `helper-unavailable` with `python-missing` or `python-too-old`, which the doctor words in `ccd/ccrc-doctor-checks#_check_docs`, not in `ccd/ccd`: its jq filter passes only those two details through (any other becomes `-`), its `case` arm words each, and its fail message and remedy say the helper "needs python3 3.8 or newer". Its rows are `server/test/ccrc-doctor-exposure.test.ts`'s `ccrc doctor: docs` block. ## Review focus (the failure modes most likely to bite)

1. **A token set that moved.** C5e's harvests are scoped by family: the reap family is every helper call outside the `COLLECT` and `LOOSE` regions, the collector family every call inside them. A scanner that now reads the whole file, or a call moved across a region marker, changes a set; C5d's literal lists catch it. Reviewers diff each set at base and tip.
2. **A guard gone blind.** Six guards, in six of the fifteen scanner files, stay green under a naive rename (§What the measurement found, item 3). Each must be re-pointed so its mutant still reds: a reap-family call added inside the swap slice or the lifecycle block (both lie outside the `COLLECT` and `LOOSE` regions, measured) must still red its "no reap-family call" row. The `WS-AUDIT-COLLECT` block lies inside the `COLLECT` region, so a reap-family call cannot be written there at all; its row is the containment fact instead, and its mutant moves the `COLLECT-BEGIN` marker. A re-point whose mutant cannot red, by construction, is itself a blind guard: reviewers ask of every re-pointed row what edit would red it.
3. **`return 1` lost.** `_ws_reap_leaf_ok` ends in `… || _reap_refuse …`, so its status is the helper's (the comment above `_reap_refuse` says so). `_ws_refuse` keeps `return 1`, and the comment moves with it.
4. **A token byte that changed.** C5f hands reap's fourteen facts to `_ws_reclaim_fingerprint` as `name=value` words in today's order. A reordered, renamed or added input changes every reap token: an audit taken before the deploy then reads `state-changed` once at the reap. The pin compares a literal token over fixed facts.
5. **A lock decline that changed.** C5g passes each verb's in-progress sentence verbatim; the flock-unavailable and lock-unopenable sentences are one text today and stay one. The decline answers at rc 0 with the document and the journal row, the locked function runs with the lock held, and the descriptor goes back on every path. `cmd_ws_restore`'s lock is not this wrapper (it dies on contention and holds the lock for the whole verb).
6. **A computed act no scanner can see.** Under C5g the act word reaches `_lc_refuse` and `_lc_emit` as `"$act"`. `ccd-refusal-v1.test.ts`'s "every call site names its token as a literal" counts only `_lc_refuse <literal-act>`, so a call with a computed act is invisible to it today. C5g extends the count to those calls and requires their tokens to be literal.
7. **Redaction after the cut.** C5h keeps every redaction before every `clip_utf8`. A node pass over the finished line would cut first.
8. **A fallback to a stale copy.** With no node or no CLI, the docs verb answers `helper-unavailable`; it never falls back to a python copy of the rules (spec §5.13).
9. **A node per string, or a raise that escapes.** C5h starts at most one redactor process per docs verb (the spawn-count rows), never through `self.spawn` (a unit's git stub must never see node's argv), and a redactor failure never escapes `run()`: `helper_failed_line` does not call the redactor again after its own failure, so the answer is still exactly one JSON line at rc 0. Nor does a raw `OSError` from the redactor's pipe (a node that exits before reading leaves python a `BrokenPipeError`): it becomes the sticky `RedactorFailed`, which is not an `OSError`, so the drafts phase's `except OSError` cannot swallow it into a drafts row that redacts again.
10. **A redactor that outlasts the runner.** The redactor's time is outside the verb's deadline, so it must be one per-verb budget inside the runner's margin (`docs-budget.test.ts`'s sum), bounded on the write side as well as the read side, and closed in `run()`'s `finally`. A per-call bound, a blocking write or a missing close lets the agent kill ccd mid-answer and orphan node in its own session.
11. **A `null` that now overwrites.** C5j's setter keeps three behaviours apart: a ready frame resets (any value, `null` included); a refresh writes only a non-null answer under the epoch it asked; local mode writes only a non-null answer. One "write if not null" rule for all three would keep a stale list across a reconnect to an older agent.
