# Programme ledgers: Goals and Waiting on you — Implementation Plan

> **For agentic workers:** one PR per task, in the order of §Landing order. To execute a task, REQUIRED SUB-SKILL: superpowers:subagent-driven-development, with superpowers:test-driven-development for every red-first step. Steps use checkbox (`- [ ]`) syntax. Workers do not edit this file's §Deviations found. A departure is named by slug in the task's report; the coordinator gives it a number from the block it issued at run-open. A worker never allocates.

**Goal:** Every programme gets a Goals pin and a Waiting-on-you list in the console, with one combined list across programmes, ticks that mail the owning coordinator, secrets pasted straight into a protected store, and Linear sign-in as a second way to give a credential.

**Architecture:** Pure vocabulary and deciders in one L0 module (`shared/ledgers.ts`), read by the server and the PWA alike. One coord.db migration adds the items, their history and the spec modifications, plus pin columns on `programs`. The coordinator writes through new box-token routes and `ccrc-api` verbs. The operator acts through session-gated routes, and a tick queues system mail in the same transaction. The PWA gains a combined list, an item view, a programme view and a chip on the programme box. Session questions join from the fleet frame's existing `attention` bucket, so nothing new is stored for them.

**Tech Stack:** TypeScript (ESM), Fastify, `node:sqlite` (`CoordStore`, synchronous), React and Zustand in `pwa/`, `@ccrc/ui` primitives, vitest (jsdom and the Chrome browser config), bash (`ccd/ccrc-api`, `ccd/session-hook.sh`).

**Spec:** `docs/superpowers/specs/2026-10-31-programme-ledgers-design.md` (approved 2026-11-01 "Approved with the rulings", D1 to D22). Prototype: `docs/superpowers/specs/2026-10-31-programme-ledgers-prototype.html` (branch `brainstorm/programme-ledgers`, shape only; its "as approved" Goals wording is superseded by D3).

## Global Constraints

- The repository is public: no private names in code, fixtures, commits, PRs or item text examples. Fixtures use `prog-a`, `lane-a`, `project-a`.
- Wire changes are additive only; `FLEET_PROTO` stays 1.
- `shared/*.ts` imports nothing, not even `node:*`.
- Decide in L1, act in L4. The transition table is the only place an item's move is decided.
- `coord.db` stays synchronous; no async wrapper over `CoordStore`.
- A secret value never appears in a response, mail, the feed, a log line, coord.db, the programme ledger or any session's reach (spec §5).
- Every new guard ships with a test that goes red when the guard is deleted (measured before and after, recorded in the PR).
- Copy rules: items speak to the operator in plain words; "Waiting on you", "Checking…", "Came back", "Recently cleared", "Changed since approval", "spec update pending", "ticked; coordinator not responding", "Nothing needs you. Waiting on: …" are the spec's exact labels.
- "Recently cleared" keeps 7 days (D13). Needed-by is `blocking | soon | later` (spec §3.2). A soon label is at most 40 characters.
- Heavy suites and typechecks run through `ccrc test`; single suites as `./node_modules/.bin/vitest run <file>` inside the package.

## Review Focus

1. **A tick when the programme has no coordinator any more** (last run closed between the list's render and the tick). Expected: refused `programme-ended` with a sentence telling the operator to dismiss instead; item unchanged. Pinned in PL4.
2. **A short secret** (under the masker's 20-character floor). Expected: stored, the answer says it could not be registered for masking, and the item says so in plain words; never a silent skip. Pinned in PL6.
3. **The same item ticked twice** (double tap, two tabs). Expected: the second tick is refused `not-open` and no second mail is queued. Pinned in PL4.
4. **A coordinator raises an item for a programme it does not claim**, or acts on another programme's item. Expected: refused `not-your-programme` after attribution, before any write. Pinned in PL3.
5. **A spec pin whose path is not under `docs/superpowers/specs/`** (or contains `..`). Expected: refused `bad-spec-path`; the PWA never builds a Docs link from an unchecked path. Pinned in PL3.
