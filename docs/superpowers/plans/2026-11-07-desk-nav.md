# Desk navigation in the top bar, and a shorter Docs head — Implementation Plan

> **For agentic workers:** one PR per task, run through this repository's coordinator, worker and reviewer flow (the desktop-polish programme); a worker extracts its task by its `### Task` heading. The two tasks own disjoint files, and §Landing order says which task waits for what. To execute a task, REQUIRED SUB-SKILL: superpowers:subagent-driven-development, with superpowers:test-driven-development for every red-first step. Steps use checkbox (`- [ ]`) syntax. Workers do not edit this file's §Deviations found. A departure is named by slug in the task's report; the coordinator gives it a number. A worker never allocates.

**Goal:** At a desk, Instrument's left rail moves into the top bar where the breadcrumb was, so the main pane gains 52 px at every desk width; and the Docs reader's desk head becomes one row plus one dense truth line, so a document's title rises from y = 382 to about y = 200 at 1280 × 800.

**Architecture:** Part A is a move inside Instrument's parts: the rail's door list (`RAIL_ITEMS`, from `DESK_PLACES` with Archive after Accounts) becomes `DESK_DOORS` in `TopBar.tsx`, which draws the one `<nav aria-label="Primary">` as Refined's `AppBar` does; the frame loses its rail slot and branch, the grid loses its first track, and `breadcrumb.ts` is deleted. Which door is current stays `topRouteOf`'s answer, which badge a door shows stays `placeBadge`'s, and every door stays `commandDoor('go-<id>')`. Part B restyles `DocsHead`'s full header into one row (back, crumbs, actions) over a dense `TruthLine`, and widens #2346's host-bar condition (`readerChromeFor`) from phones to every width, adding no second mechanism.

**Tech Stack:** TypeScript (ESM), React 19, `@ccrc/ui` (`Door`, `Icon`, `CountBadge`, `Wordmark`, `useMediaQuery`), CSS container queries, vitest (jsdom) and the Chrome browser config (`vitest.browser.config.ts`), `pwa/design/contrast-check.mjs`.

**Spec:** `docs/superpowers/specs/2026-11-06-desk-nav-design.md`, approved by the operator on 2026-11-07: items 62 (Part A as drawn), 63 (Part B as drawn) and 64 (this programme builds Part B after #2346's take-up wave lands), all as recommended. Mockup: `docs/superpowers/specs/2026-11-06-desk-nav-mockup.html`. Main measured at `db3241593`.

## Where the plan departs from the spec

- **`nav-holds-doors-only`**: the Primary nav wraps the wordmark door and the six doors; the command field, the bell, Settings and New session sit beside it in the bar, outside the landmark (spec "In short" lists them inside it). This is how Refined's `AppBar` draws its nav, and a palette opener, a toggle and an action are not navigation. Focus order is the spec's.
- **`settings-icon-door`**: Settings is an icon door with its tip at every width, not a labelled door from 1280, as Refined's gear is; it is current on `/settings` and its sections.
- **`home-door-follows-toprouteof`**: the wordmark door is current wherever `topRouteOf` answers Fleet, on `/` and on a session (spec §2.2 names `/`). One rule for every door; the session header still says which session.
- **`door-form-mounted`**: the word and the tip are mounted by `useMediaQuery(DOOR_WORDS_QUERY)`, never both in the DOM, so label-in-name measures what is shown (a hidden tip would put the full name and the count in the shown text).
- **`session-crumb-test-stays`**: spec §1 says `breadcrumb.ts`'s unit tests are a describe in `header.test.tsx`. That describe pins the session header's crumb, which §2.4 relies on; it stays, retitled. `breadcrumb.ts`'s own pins are `instrument-shell.test.tsx`'s top bar cases, rewritten.
- **`rail-browser-file-renamed`**: `instrument-rail.browser.test.ts` becomes `instrument-bar.browser.test.ts`, with `slowFirst.ts`'s key.
- **`docs-headers-is-not-the-head`**: spec §5 lists `docs-headers` among Part B's browser files; that file measures the docs response headers. Part B's figures live in `docs-compact-head` and `reader-frame`.
- **`aa-stays-the-librarys`**: spec §3.2 and §3.4 draw Aa in the head row. #2346's take-up keeps the reader's Aa as the library's own button at the frame's top right (its refinement (j): with the reader's settings on, the library always draws it, and a ccrc Aa could only duplicate it), so the desk row draws no Aa; it draws the frame bar's other tools, if Step 0 finds any.
- **`reader-chrome-at-every-width`**: `readerChromeFor` loses its width argument, since it answers the host bar everywhere; the take-up's width case and its mutant are rewritten.
- **`github-short-word`**: the row shows "GitHub" as spec §3.2 draws it; the link's name stays "View on GitHub".
- **`docs-line-h-in-tokens`**: the dense role is declared for both skins in `tokens.css` with a fine-pointer block, not in `skins.css`, which holds one skin's values (spec §3.2 points at `--row-h` as the pattern).
- **`open-committed-in-row`**: "Open committed version" (spec §3 lists three actions) keeps its place among the actions, in the row.
