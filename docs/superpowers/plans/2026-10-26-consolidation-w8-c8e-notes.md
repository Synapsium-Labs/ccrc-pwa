## Verdict

`server/src/accounts/ops.ts#localAccountOps` is **kept against `exec.ts`**: `realRunner` has no stdin, no explicit environment, no bound and no group kill, and the account op needs all four (the secret on stdin, D-5513; `{HOME, PATH, LANG}`, never `process.env`). The audit table is in the PR body. Against `agent/src/accountop.ts#makeAccountOpSpawn` it is the same algorithm with one measured difference: a group kill that throws other than ESRCH. The agent falls back to `child.kill(s)`; at the base the local arm did nothing. By OA-C8a (a) the local arm adopted the agent's fallback in a red-first behaviour commit. Then both bodies were folded into `shared/spawn.mjs#boundedStdinSpawn`, separate from `boundedSpawn`, because stdin, the environment, the TERM grace and the output cap all differ from it.

## Recorded choices (no number)

- **The rows went with their sites, one per move commit.** The two-way equality between `processSpawnSites()` and `PROCESS_SPAWNERS` reds a row as soon as its spawn site is gone. So each move commit deletes its own arm's row. The kernel's row `shared/spawn.mjs#boundedStdinSpawn` came in with the kernel (Step 4), and its reason names D-5513 and OA-C8a (a). Step 6 then pins the merged state: neither account-op key remains and the kernel row's reason names both. The end state is the plan's single row.
- **The non-ESRCH row is provoked through a `process.kill` spy.** It throws EPERM for a negative pid only, and every other call goes through to the real `process.kill`. Real children cannot produce that error under a fixture HOME. `child.kill` goes through the child's own handle, not `process.kill`, so the fallback reaches the real leader. The observable is whether the leader is dead within 1 s of the answer. Before: local `false`, agent `true`. After: both `true`. The answer word, `timeout`, is the same both before and after.
- **The behaviour commit is one commit.** In it, the local-arm row flips from `false` to `true`, and the run was red on the base body: 1 failed, 15 passed. With the fallback added it is green (16 passed). The PR body lists the red run.
- **`boundedStdinSpawn`'s unit rows are in `spawn-kernel.test.ts`**, as a second stub-host describe next to `boundedSpawn`'s, which is where C8c put that kernel's own rows.
- **`shared/spawn.d.mts` names its bytes `Uint8Array`, not `Buffer`.** A `Buffer` is a `Uint8Array`, so both wrappers type-check as they are, and the `.d.mts` names no Node global. That is the same reason C8c typed `signals` as `object`. The `StdinSpawnHost` and `SpawnedStdinChild` interfaces are written structurally, as `SpawnHost` and `SpawnedChild` are. The outcome type is `Exclude<AccountOpOutcome, { kind: 'refused' }>`, an `import type` from `agent-protocol.js`.
- **The local arm reads `timeoutOf(sub)` before the spawn instead of after it**, because the call now passes it as an option. `timeoutOf` is a pure lookup, either `ACCOUNT_SUB_TIMEOUT_MS[sub]` or a test's override. The bound timer is still armed after the spawn, inside the kernel.
- **The C8c census fixture's `BODY` slice now stops at `boundedSpawn`'s own closing brace** instead of the file's last one. The kernel now holds two functions, and the old slice would have pasted both into the "wrapper with the body" fixture. The rows that read it are unchanged and green.
- **The wire-name list** in `spawnKernelWireLiterals()` gains `GRACE` and `MAX_BYTES`, upper case only. That leaves `killGraceMs`, `maxOutputBytes` and C8c's `UPDATE_SPAWN_MAX_BUFFER` as non-matches. It went red first on a fixture kernel defining `KILL_GRACE_MS` and `OUTPUT_MAX_BYTES`.
