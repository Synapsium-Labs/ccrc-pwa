# ccrc Plan 2/3 — PWA Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `ccrc-pwa` — the mobile-first, native-feel installable web app that renders the fleet and drives sessions through ccrc-server's API.

**Architecture:** React + Vite SPA served by ccrc-server. All server state arrives over the two WebSocket streams (`/ws/fleet`, `/ws/session/:id`); all writes go through REST. A resilient WS client (offset resume, backoff, visibility resync) and two zustand stores are the spine; screens are thin renderers over them. Visual language comes from a dedicated design phase (frontend-design skill) that produces tokens before any screen is built.

**Tech Stack:** React 19, Vite, TypeScript strict, Tailwind CSS v4 + CSS custom-property tokens, zustand, react-virtuoso (bottom-anchored chat), react-markdown + remark-gfm, vaul (bottom sheets), framer-motion, @xterm/xterm + @xterm/addon-fit, vite-plugin-pwa, vitest + @testing-library/react + jsdom.

**Spec:** `docs/superpowers/specs/2026-07-20-ccrc-remote-control-app-design.md` — the **Design ambition**, **Usability principles**, and **Native-like bar** sections are binding acceptance criteria for every task here.

## Global Constraints

- Working dir: `infra/ccrc/pwa`. Types come from `infra/ccrc/shared/api.ts` — never redeclare `FleetSession`/`ChatEvent`/`Dialog`/`SessionStreamMsg` locally.
- Mobile-first: every screen designed at 390×844 first; desktop is the same layout with more air. All touch targets ≥44 px; safe-area insets via `env(safe-area-inset-*)`; inputs ≥16 px font (iOS zoom guard); `overscroll-behavior: contain` on scroll containers.
- Copy is jargon-free: "Move to another account" not "swap wrapper"; "account" labels are `team·max` (claude), `team·alt` (claude2), `team·b` (claude-corp), `gpt` — map in one module `src/lib/accounts.ts`.
- All motion respects `prefers-reduced-motion` (framer-motion `useReducedMotion` or CSS media query).
- Every screen implements loading (skeleton), empty, error, offline, and (where applicable) dead-session states — no unstyled fallbacks.
- Dev proxy: Vite dev server proxies `/api` and `/ws` to `http://127.0.0.1:7788` (ccrc-server running with `CCRC_HOME` pointed at a fixture tree from Plan 1).
- Commit after every task: `feat(ccrc-pwa): <what>`.
- The quality gate from the spec applies: "works but looks default" fails review.

export interface ReconnectingSocketOpts {
  url: () => string;                     // recomputed each (re)connect — carries fresh ?since=

### Task 4: Stores (fleet + session reducer)

**Files:**

- Test: `infra/ccrc/pwa/test/stores.test.ts`

**Interfaces:**
- Produces (`stores/fleet.ts`): zustand store `useFleetStore`: `{ sessions: FleetSession[]; conn: 'connecting'|'open'|'down'; notices: { id: number; message: string }[]; connect(): void; disconnect(): void; dismissNotice(id: number): void }` — `connect()` opens a ReconnectingSocket to `/ws/fleet`, applies `{type:'fleet'}` messages, appends `{type:'notice'}` messages.
- Produces (`stores/session.ts`): `useSessionStore(id)` factory backed by a `Map<string, StoreApi>`:

```ts
interface SessionState {
  events: ChatEvent[];            // deduped by uuid (tool_result keyed by toolId)
  offset: number; uuid: string | null;
  status: SessionStatus | null; statusUpdatedAt: number | null;
  dialog: Dialog | null;
  pending: { key: string; text: string; state: 'sending' | 'failed'; error?: string }[];  // optimistic sends
  conn: 'connecting' | 'open' | 'down';
  apply(msg: SessionStreamMsg): void;    // pure-ish reducer, exported separately for tests
  connect(): void; disconnect(): void;
  send(text: string, replaceDraft?: boolean): Promise<void>;   // optimistic: push pending → api.prompt → clear or mark failed
  retry(key: string): void; discard(key: string): void;
}
type SessionSnapshot = Pick<SessionState, 'events' | 'offset' | 'uuid' | 'status' | 'statusUpdatedAt' | 'dialog'> & { missingFile: string | null };
export function applySessionMsg(s: SessionSnapshot, msg: SessionStreamMsg): SessionSnapshot  // pure, unit-tested
```

- Reducer rules: `backlog` replaces events/uuid/offset; `events` appends (dedupe by uuid; a `tool_result` fills in the matching `tool_use`'s result slot in the UI model); `rotated` clears events + sets uuid, keeps a `system` divider event "Session context reset"; `dialog`/`dialog_cleared` set/clear `dialog`; `status` updates status fields. `connect()` builds `url()` with `?since=<uuid>:<offset>` when both known (resume without backlog).
- Optimistic sends: `send()` pushes `pending` with `state:'sending'`; on api success remove it when a matching `user` event with same text arrives via WS (or after 5 s fallback); on ApiError mark `failed` with the server error; a 409 draft-present surfaces `error:'draft-present'` + draft (Composer handles it in Task 7).

Optimistic path with mocked `api.prompt`: resolves → pending cleared on matching event; rejects with 409 → `failed` + draft captured.

- [ ] **Step 4: Run** — Expected: PASS.
