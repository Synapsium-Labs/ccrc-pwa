# Accounts connect A17: the write routes, step-up enforced, and the canary

**Goal:** plan Task A17 of `2026-10-18-accounts-connect.md` (spec §3.2, §3.3, §11, §13.1, §16; D-5511, D-5512, D-5513, D-5516; G11, G18). The server gets the first secret-bearing account routes: add a lane (with a pasted token), replace its token by paste, set its stated account and placement, remove or discard it (with the pre-check), and tick "I revoked it". Each runs through the account gate, with a step-up where spec §3.2 asks for one, the reconciling `AccountOps` wrapper and the box's A16 verbs. N6 and the as-built decisions are numbered D-7738 and D-7739 below.

**The OA1 record** (`2026-11-01-accounts-oa1-record.md`), read where this task touches it. G23 was not measured, so the removal ledger's vocabulary (`AT_PROVIDER_STATES`) has no `ended`: a sign-in lane's row reads `unmeasured`, as A16's box answers it, and a row that says `ended` is dropped, never relayed. D-5518's sign-in row is measured, and this task does not read it. §9, §3.3, the Codex device code and the setup-token code shape are not measured, and no route, word or answer here depends on any of them, so none of them is claimed.

**Before this change:** the box had A16's write subs, and `ccd caps` advertised `account-v2`, but no route ran them. A pasted secret had no way from the browser to the box. The argv builder also wrote no `--credential -` for `add` or `credential`, so a secret carried on stdin was refused `credential-required` by the verb (found by this task's canary, D-7739 (8)).

**Change:**
- `server/src/accounts/routes.ts`: the write routes, registered by `registerAccountRoutes` beside Check and the kill switch. `POST /api/accounts` (step-up), `POST /api/accounts/:id/credential` (step-up), `POST /api/accounts/:id/set`, `POST /api/accounts/:id/remove` (step-up for `remove` and `discard`, none for `check`) and `POST /api/accounts/revoke-ack` (N6). `routeOutcomeOf` maps the write verbs' codes to their words. The pure `discardVerdictOf`, `removedLedgerOf` and `removeCheckOf` decide and read what the routes answer.
- `server/src/accounts/egress.ts`: `maskHeld`, which masks a held secret's exact bytes and its base64 in every string of an answer.
- `server/src/server.ts`: the two new deps of the account routes, the lane state and kill-switch marker (`readLaneStates`) and the registry rows naming a lane (`accountSessionsOn`, one tagged `readRegistryMeasured` call).
- `shared/api.ts` (at the foot): `ACCOUNT_WRITE_REFUSALS`, the bodies and answers, and the removal ledger's vocabularies (`AT_PROVIDER_KINDS`, `AT_PROVIDER_STATES`, `AT_PROVIDER_PAGES`). `shared/refusal.ts` gives each new word its status.
- `shared/accounts.ts`: `laneStateOf` keeps `addedAt` and `enabledAt`, which discard's check reads, and `isLaneIdentity` is the one identity grammar, for the file's `identity` and for `set`'s stated account.
- `shared/account-argv.ts`: `add` and `credential` write `--credential=-` when the caller carries stdin, and never otherwise.

**Tests:**
- New: `server/test/account-routes-write.test.ts` (the real server, gate, step-up, reconcile wrapper with the real `reloadRoster`, and local arm, over a stub launcher that records its argv and stdin) and `server/test/account-canary.test.ts` (the real verb in a `laneStateFixture` HOME, through the local arm and through the real in-process agent, with a probe child that echoes the token on stderr; the same acts over a stub verb that echoes on stderr both the secret it is handed and the one the lane holds; and the shapeless key end to end).
- Extended: `server/test/auth-gate.test.ts` (`accounts/routes.ts`'s count 3 to 8, the totals 131 to 136 scanned and 128 to 133 HTTP, the gated count 85 to 90, `FLAG_AWARE` gains `POST /api/accounts/revoke-ack`), `server/src/auth/gate.ts`'s docstring count, `server/test/box-token-census.test.ts` (`ACCOUNT_DOORS` gains the five), `server/test/registry-refused-census.test.ts` (the new site), `agent/test/account-argv.test.ts`, `agent/test/account-op.test.ts` and `server/test/account-ops.test.ts` (`--credential=-`).

## Decisions

- **D-7738 (2026-11-01)** — `revoke-ack-route` (N6; accounts plan Tasks A17, A19): the `revoke-acknowledged` act (spec §3.6) had no route, and a removed lane has no `:id` left to post to. It is `POST /api/accounts/revoke-ack {laneId, kind}`, session-only and outside `/api/accounts/:id`, which writes one audit row with no value and calls no op. `laneId` is held to the roster's id grammar and need not be in the roster. `kind` is one of `AT_PROVIDER_KINDS`, the removal ledger's credential kinds, and the row's provider is derived from it. It runs no ccd verb, so it takes the gate with `cap: null` and joins `auth-gate.test.ts`'s `FLAG_AWARE`. It takes no step-up, because it records a tick and touches no secret. A row the audit did not write answers `unavailable`, never `{ok: true}`.
- **D-7739 (2026-11-01)** — `write-routes-as-built` (accounts plan Task A17; spec §3.2, §3.3, §6.2, §11, §13.1, §16): the as-built decisions of A17, and where it departs from the plan's wording.
  1. **The words.** `key-charset`, `confirm-mismatch` and `bad-stated` are 400. `not-discardable`, `lane-exists`, `config-dir-exists`, `live-sessions`, `sleeping-sessions`, `upstream`, `last-home-able`, `auth-in-progress`, `not-a-token-lane` and `duplicate-id` are 409. `token-unverified` is 503, `unreachable`'s status. The Linear routes' `key-rejected` (400) is reused, and so is `unmeasured` (502). Each verb code that the first wave's screens word crosses as the word of the same spelling. `live-sessions` and `sleeping-sessions` carry `sessions`, held to the registry id grammar and capped at 64. `config-dir-exists` carries `signedIn` only, never the identity the box read. Any other verb code rides A14's `lane-act-refused` with `verbCode`.
  2. **A retry finds the lane.** An add for an id the server's roster already holds answers `lane-exists` with that lane, before any op. After an add whose outcome was unknown, the reconcile's roster carries the lane if the box made it, so the operator's retry is told it exists rather than running into the verb's `duplicate-id` (spec §6.2's "never retries on its own into `duplicate-id`"). An add that ran and whose roster the server could not take (another fleet's) answers `outcome-unknown`, and the screen re-reads.
  3. **Remove's gate is taken twice.** It is taken first without the step-up, so the gate still runs before the body is read. Then, once the body names `remove` or `discard`, it is taken again with the step-up. `{mode: 'check'}` therefore never asks for a step-up. The pre-check writes no audit row, because it changes nothing. A dry-run answer off its grammar answers `outcome-unknown`.
  4. **Discard's route-side check** (`discardVerdictOf`) reads what the server can read: the lane-state file's `addedAt` and `enabledAt` (which `laneStateOf` now keeps), the kill-switch marker, and the registry rows whose `wrapper` or `home` names the lane. An unreadable lane-state file is no record of adding the lane. An unlistable registry answers `unmeasured`, never "no session". The rows the registry refuses (ids off its grammar) are not counted here, and the verb counts every row again under its lock. Upstream and a sign-in in flight are the verb's.
  5. **`set` takes no step-up in the first wave.** Its two fields, `stated` and `placement`, neither change a method nor raise a minted key's commitment, which are the only `set`s spec §3.2 steps up. `limit` and `limitReset` are A32's and answer `bad-request`. The stated account is held to `isLaneIdentity` (1 to 120 characters, not blank, nothing unprintable), the lane-state file's own identity grammar, and rides stdin as A16's `--stated=-`.
  6. **`credential` takes the paste form only.** `{method: 'mint'}` and `{retire}` are A32's, and N5's `{signOut}` is A20's, so all three answer `bad-request` here.
  7. **`add`'s body.** `provider`, `id`, `label` and `hue` are required strings. `method` and `placement` are optional strings, `credential` an optional string and `adopt` only `true`. Any other key (`limit`, `limitReset`, `expiresIn`, `models`) answers `bad-request`. The argv builder judges every value. The audit row names the method only when it is one of the provider's `connect` methods, because the audit refuses any other.
  8. **The builder writes `--credential=-`.** The verb reads a secret only behind `--credential -` (`_acct_read_credential`), and A8's builder wrote no such word, so every paste through a route was refused `credential-required`. A16's suites drove the verb directly and never saw it. The canary's first run found it. `add` and `credential` now write `--credential=-` whenever the caller carries stdin, and never otherwise, as `set` writes `--stated=-`. This file is outside the plan's Files list.
  9. **What the route masks.** `maskHeld` masks the held secret's exact bytes, its base64 (padded and unpadded) and its base64url in every string of a success answer and a refusal's extra fields, on top of the answer hook, which masks the shapes and the fingerprinted secrets. A pasted secret has no fingerprint row until the box's answer lands, and may have no shape. The route zeroes its own buffer of the secret's bytes once the op has answered. The JSON body's string itself is immutable, as spec §3.3 says.
  10. **The `compatible` case is a shapeless key pasted as an Anthropic token.** `compatible` is CLI-only (spec §13.2), and the builder refuses it as a route's provider. A token with no credential shape takes the same answer path, masked by its fingerprint alone, so the canary's end-to-end case pastes one through the route and the real agent. The masker's table is checked empty before the add and to hold the lane's row after it, so the mask comes from the answer and never from a planted row.
  11. **The canary's two stub children.** The real verb sends its probe child's stderr to `/dev/null` (`_acct_token_probe`), so a stub probe that echoes the token on stderr proves the verb's half, and no route-side mutant could reach that output. A second pair of cases replaces the verb itself with a stub that echoes on stderr the secret it is handed and the one the lane already holds. That is the child whose output a port or a route could relay, and the lane's own token is one the request does not hold, so `maskHeld` cannot hide such a relay. "The server's and agent's captured stdout and stderr" are read in-process: the server and the agent run in the test's process, and `process.stdout`, `process.stderr` and the console are captured for each case. The HOME is walked byte for byte, symlinks not followed and the database's WAL included, so the lane-state file, the status files, the mail and push stores and every coord.db table are covered by one walk, and every table is also read row by row.
  12. **The ledger's grammar.** `removed`, `kept` and `rehomed` are strings of 1 to 512 characters with no control byte, at most 128 of each. `atProvider` rows are held to `AT_PROVIDER_KINDS`, `AT_PROVIDER_STATES` (`still-valid`, `unmeasured`: no `ended`, the OA1 record) and `AT_PROVIDER_PAGES`. A removal that answered ok with no readable ledger answers `outcome-unknown`, and its row says `unknown`.
  13. **Overlap.** #2100 edits the same count lines in `auth-gate.test.ts` and `auth/gate.ts`, for other routes. The counts here are this branch's against `main`, and whichever of the two merges second re-adds the other's routes to them.
