Every defect is answered in the task named in §Review answers. Task 0 is done in the commits that add and revise this file.

**Operator rulings this plan builds on** (2026-10-17; the spec's §3 has them verbatim):
- only dispatched workspaces route to a coordinator; every session the operator creates is a coordinator (Tasks 9, 10);
- while a coordinator holds a child's question or prompt, the child shows a quiet "with coordinator" state and leaves Needs-you (Task 7);
- a daily digest of what coordinators decided in the operator's name, correctable by mail (Task 17);
- 180 s, late answer wins (Tasks 4, 6, 16);
- children's permission prompts: "Source fix + guarded rulings": the skill rule first (Task 1), then coordinator rulings with unknown commands escalated, rulings signed on the server box, and a child's own calls to the approval tools blocked (Tasks 11 to 16);
- deny rules for children only (Task 15);
- no trial week: switched on directly, with a kill switch (Task 16, Task M).

**Coordinator calls this plan builds on:** the first-sighting race, with a parent that is not live releasing at once (Task 5); late answer wins with `declined` (Task 4); one single-select question per call, agent first (Task 2), and the lane widened to the operator's own answer route (Task 8); the deadline and the ready-to-run command in the parent's mail (Task 6); the empty push body (Task 3); the digest at 07:00 UTC by default (Task 17); every operator-created path, the CLI included, is a coordinator (Tasks 9, 10); the threat model stated in the spec (§6.1).

The route's existence is the capability, and the version gate lives on the server (spec §6.9). So any mover in any order is safe, and this plan does not wait for working-state Task 9b.

## Global constraints

`CLAUDE.md` is the authority. This is its working subset for this plan.

- **Public repository.** Fixtures use neutral names: session ids `lane-a-project-a` and `project-a-quiet-basin` (child), `project-a-calm-mesa` (parent), `project-b-far-ridge` (a session in another project), wrappers `lane-a`/`lane-b`, agent ids such as `a0000000000000001`. No hostnames, accounts, project names, absolute home or scratch paths, emails, or anything read from a transcript. Guard-corpus commands are written for the corpus, never copied from a fleet transcript. A test signing key is generated in the test, never committed.
- **Hook payload fixtures copy a committed real shape.** A PreToolUse payload copies the key set of the PreToolUse events in `server/test/fixtures/delegation/2.1.280/agent-plain.json` (main: `session_id`, `transcript_path`, `cwd`, `prompt_id`, `permission_mode`, `effort`, `hook_event_name`, `tool_name`, `tool_input`, `tool_use_id`; a subagent's adds `agent_id`, `agent_type`). **No committed capture has a PermissionRequest yet.** Until Task 13 produces one (`server/test/fixtures/delegation/2.1.302/permission-main.json` and, if reproduced, `permission-subagent.json`, in the existing capture format), a PermissionRequest fixture is the PreToolUse key set with `tool_use_id` removed and `permission_suggestions` added, marked DERIVED with its source ([B]). Every such fixture is replaced by the captured shape in Task 14's PR.
- **Commands.** From inside the package, in the foreground, tool timeout at least 600000 ms, one suite process at a time: `./node_modules/.bin/vitest run --maxWorkers=2 test/<file>.test.ts`. Never bare `npx vitest`, never the full server suite. Typecheck with `./node_modules/.bin/tsc --noEmit -p .` in `server/` and `pwa/`. Every task also runs `single-definition`, `deviation-refs` (after `git fetch -q origin main`), `dtbd` and `topology-clean`, and `routes` when it touches a route.
- **Fixture HOMEs only.** Every `ccd` and hook test runs under `makeCcdHarness` (`server/test/ccdWsHelpers.ts`) with stubbed `tmux`, `systemctl`, `journalctl` and `ccrc-api`. Nothing in a test touches the live `$HOME`, tmux, `~/.cc-sessions`, `~/.cc-limits` or a `claude-session@*` unit.
- **The hook.** New marker and decision logic goes in the hook's tail, below `ccd/session-hook.sh:2900` (`marker-logic-in-the-tail`, D-3615); the PermissionRequest arm (≈:2920) only sets a flag the tail reads. The role card (Task 9) is a card emitter beside `_hook_hold_card` (≈:804), where every card lives. The approval-surface deny (Task 14) sits beside the role-skill deny (≈:3873, D-4934) and uses its deny printer. New hook tests go in new files with the harness copied from `server/test/session-hook-turnmark.test.ts`. The PostToolUse budget (p95 of 20 runs under 150 ms) holds; the PermissionRequest wait is not on that path.
- **`ccd/ccd` carries a generated marker** (`# ccrc:generated 1 sha256=…`, `shared/mark.mjs`). Re-stamp it after every edit and verify it independently; keep the executable mode.
- **No new `ccd` verbs.** `CLAUDE.md`'s Build 7 invariant "Zero new ccd verbs for coordination mutation" holds: no task adds a `ccd` verb or a `ccd` flag. Requests and rulings ride server routes through `ccrc-api` (new `ROUTES` rows, pinned by `ccrc-api-closed`). Task 15 changes what `ccd`'s spawn passes for a `.child` row (one `--settings` file); that is a spawn argument to Claude Code, not a verb.
- **Schema.** Every table or column change is a new entry appended to `MIGRATIONS` in `server/src/coord/schema.ts` (≈:63; earlier entries are frozen; `COORD_SCHEMA_VERSION = MIGRATIONS.length`, ≈:1383), never an edit in `db.ts`, which only applies them. If another in-flight branch takes the same slot, the later one renumbers on rebase (D-2410's rule, recorded at ≈:837). Each migration has its `coord-db` test: a database at the previous version migrates and keeps its rows.
- **Mutation discipline.** Every guard ships with a test that goes RED when the guard is deleted and when it is made wrong. Apply each mutant to the uncommitted change, run the named suite alone, record the red line in the PR, restore the file and compare it byte for byte.
- **Wire discipline.** New fields are additive and read through one reader each; absent means the old behaviour; `reviveFleetSession` computes each one. No new `SessionBucket` or `SessionLifecycle` member. `FLEET_PROTO` stays 1. A new refusal code joins its union and its map in `shared/api.ts`, never spelled at a call site.
- **Single definition.** Registered in `server/test/single-definition.test.ts`: `ASK_GRACE_MS` (already one home; Task 6 re-pins its value); `AskState`'s map with `declined` (Task 4); `tryHold` (Task 5); `askPushBody` (Task 3); `untrustedBlock` (Task 6); `answerableAsk` (Task 8); `SESSION_ROLE_MAP` (Task 10); `approvalClass`, its class map and `redactCommand` (Task 12); `APPROVAL_HOOK_WAIT_S`, `APPROVAL_HOOK_VERSIONS`, the ruling record's canonical form (`approvalRulingBytes`) and `CHILD_DENY_RULES` (Tasks 14, 15); `APPROVAL_STATE_MAP` and `APPROVAL_INPUT_RETENTION_DAYS` (Task 16); `DIGEST_HOUR_UTC` (Task 17). The hook's bash spellings (the forbidden match, the wait bound, the approval-surface pattern) and the Node verifier's canonical form are documented second copies, each held equal to the TypeScript one by a test that iterates over it.
- **SAFETY.** No session runs an operator act. Both kill switches are the operator's: `$REG/approvals-disabled` lives in `~/.cc-sessions`, so only the operator places it, by hand, under the SAFETY rule "NEVER touch tmux, `~/.cc-sessions`, `~/.cc-limits`, or `claude-session@*.service` directly"; the server box's `~/.ccrc/approvals-disabled` is placed by the operator on that box. No task adds a writer for either.
- **Branches and commits.** One PR per task (Task 11: two). Never push from a worker; the coordinator lands through the merge queue. End commit messages with the attribution trailer the run's system prompt gives.
- **Deviation ledger.** D-5289 to D-5302 are issued and defined once, in §Deviations found. No tracked file carries a concrete placeholder of the `D-TBD-<slug>` form (`dtbd.test.ts`).
