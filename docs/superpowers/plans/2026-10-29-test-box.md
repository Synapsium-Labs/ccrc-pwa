## Review focus (the failure modes most likely to bite)

1. **Scratch refs reaching `origin`.** The wrapper refuses a mirror URL equal to any of the clone's own remotes, and every push names explicit `refs/ccrc-test/<run-id>/*` destinations. A row pushes with a fixture whose `CCRC_TESTBOX_GIT_URL_BASE` equals `origin`'s URL and asserts nothing was sent (TB3).
2. **The session's index or tree touched.** The snapshot works on a copy of the index with `GIT_OPTIONAL_LOCKS=0` for the clean check. Rows compare the session's index bytes, `git stash list`, the worktree listing and every file's mtime before and after (TB3).
3. **A fleet secret leaving.** The run's environment is built from empty plus the allowlist; the session environment is never forwarded; the deny list runs before the push. TB4's runner row and TB8's env row print every name a fixture run sees.
4. **The fleet agent widened.** The `testbox` op adds no whitelist entry, no wire-supplied argv and no file read beyond the token file the settings name; its spawns are the fixed templates of D-7430. The service's systemd adapter lives under `agent/src/testbox/` and is imported by nothing the fleet agent's entry point loads; an import census reds the edge (TB4).
5. **A remote answer that differs from local.** The worker count, `TMPDIR` length, `CI`, the build outputs, the branch and `origin/main` each have a fixture row in TB3, TB4 or TB8; the parity check (TB14) is the last word.
6. **Carry-over.** Every run gets a fresh directory and a fresh checkout; the cleanup is a root unit outside the run's sandbox. The carry-over fixture (spec §2.3) runs in Part A against the seams and in Part B against real units (D-7431).

- **D-7424 (2026-10-29)** — `first-release-bootstrap` (spec §9): the box's first release is the fleet host's tag, fetched on the box and trusted on its transport checksum alone (the rule `install.sh`'s release mode applies), then placed by `deploy/testbox/install.sh` run from that extracted tree, never by `install.sh` or `ccrc install`, so the box gets no ccrc server, agent or user units; the installed tree is `<tools>/release/<tag>`, root's with no group or other write, named by the `<tools>/release/installed` link; the same installer puts the fleet host's node at `<tools>/current/node` and the server package's production dependencies beside the tree before any tool sync, so every later release, the first tool sync included, is verified by that tree's `verify-provenance.mjs` under that node.
- **D-7425 (2026-10-29)** — `node-sig-https-only` (spec §9): node's `SHASUMS256.txt` is fetched over HTTPS from `nodejs.org` and its `.sig` is not checked, because no code ships node's release keys; vendoring them is a follow-up, not part of this wave.

- **D-7430 (2026-10-29)** — `agent-op-fixed-spawns`: the agent unit reads no `ccrc.env`, so the `testbox` op reads the host keys by running `ccrc-test --testbox-knobs host`; that and the six version probes are fixed argv templates with no wire field, named in `agent/CLAUDE.md` as a fourth class of spawn outside the exec whitelist.

- **D-7446 (2026-10-29)** — `retirement-restore-isolated`: the retirement check's restore never boots the restored system; the scratch server starts in the provider's rescue system behind a firewall with no outbound and inbound ssh from the coordinator only, the restored disk is mounted read-only and checked without modifying it, and the server is deleted, so no second fleet, no tailnet identity clash and no use of the old box's credentials can happen.
- **D-7447 (2026-10-29)** — `fleet-volume-kept`: a server snapshot does not hold attached volumes, so the old box's fleet work volume is detached at the rebuild and kept unattached, labelled and deletion-protected, as half of the 30-day rollback source; a rollback restores the snapshot to a new server and attaches that volume, and OA-TB3 deletes both.
