# The update gate's elapsed time in its tests: a plain fake clock, ruled

- **D-7330 (2026-10-29)** — the update-gate rows W24-H2 and W24-H3 in `server/test/ccrc-update-flip-backups.test.ts` drive `_upd_gate` with a fake clock that is a PLAIN shell variable: the fixture runs `unset SECONDS; SECONDS=0` before the gate, so bash's wall-clock counting no longer adds to the 30 s steps the fixture probe takes. Before, the fixture assigned `SECONDS=$((SECONDS + 30))` on the special variable, which keeps counting real seconds after an assignment, and a second boundary inside the run made the gate report `after 121s` for a 120 s window. The rows keep their exact expected counts (90 for an unusable value, 120 as written), so a guard that slips to 90 still fails. A control row, W24-H4, makes the first probe really wait 1.1 s, so a wall-clock second boundary always falls inside the window, and asserts the report is still exactly 120. `ccd/ccrc` is unchanged: the gate keeps reading `$SECONDS` directly.
