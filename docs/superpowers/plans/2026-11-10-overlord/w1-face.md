# Overlord W1: the Overlord's face in the PWA Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to carry out this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

> **Execution status:** Draft piece of the Overlord programme's W1 plan, written against today's `main` (`cc6bcad17`). It
> defines no D-numbers: every decision below is a plain slug until the programme mints numbers.

**Goal:** Give the console its two characters, the Orb and the Dark Lord, with a mood that the PWA chooses from state it
already holds. The plan also adds a character choice in Settings that follows the person, the splash screen and its
wordmark, new app icons, and a count on the installed icon.

**Why:** The brand brief (#2618) draws the Overlord's face. It is drawn ahead of the Overlord itself, and most of it needs
no W1 machinery: art, tokens, a picker, a splash screen, icons and a badge. This plan ships that part now, so W1's
Overlord place (spec §4, C8) has a face ready to put on.

**Architecture:** One generator turns the 28 drawn SVGs into a data module and one stylesheet in `@ccrc/ui`. A data-driven
`Character` component draws any character in any mood, its colours read from tokens. An L1 decider in a new `pwa/src/face/`
directory chooses the mood from fleet-store fields. The character choice is one server row, with a device copy for the
first paint. The splash screen, the bar's face and the badge are L4 parts in the same directory. The existing icon
generator draws the new icons. Nothing here renames the product.

**Tech Stack:** TypeScript, React 19, Vite and VitePWA, Tailwind, `node:sqlite` (one coord.db table), vitest and jsdom,
the Storybook a11y addon, and zero-dependency Node scripts (`node:zlib` for PNG).

**Spec and brief:** `docs/design/briefs/2026-11-11-overlord-brand.md` (the brief, #2618), whose artwork is
`docs/design/overlord/svg/*.svg` and `docs/design/overlord/reference.html`. The plan also reads
`docs/superpowers/specs/2026-11-09-overlord-design.md` §4 (C8: the Overlord place is the home, from W1), §4.1 (each view is
composed from rows; an unmeasured reader says so) and §4.2 (attention is a budget; no new notification channel).

## Global Constraints

- **Colour comes from the tokens.** No hex value is written in any shipped `.ts`, `.tsx` or `.css` file this plan adds.
  The art maps to tokens exactly as the brief's table says. The only exceptions are the PNG icons, which the platform
  fixes in the Phosphor (dark) values, and which `icon-gen.mjs` reads from `tokens.css` rather than typing them.
- **No new palette.** No token is added, no theme is added or changed, and no contrast pair is added. `themes:check` and
  `theme-catalogue.test.ts` stay green untouched.
- **GLOW MEANS LIFE.** The characters never glow: no `filter`, `box-shadow` or `drop-shadow` on any character part.
- **Pixels stay whole.** The art is drawn at scale 1, 2 or 4 only (32, 64 or 128 CSS pixels), with
  `shape-rendering="crispEdges"`. Every animation is stepped (`steps(1)`, or `md-tear`'s `steps(6)` as drawn), never eased.
- **Reduced motion stills everything.** Under `prefers-reduced-motion: reduce` no character, wordmark or splash part
  animates. The still frame is each part's own base style (the mood's resting pose).
- **The fonts stay Geist and Geist Mono.** No new face ships (open question 2).
- **No rename.** The product's name strings stay `ccrc`: the manifest's `name` and `short_name`, `<title>`,
  `apple-mobile-web-app-title`, the push title fallback and the bars' `❯ ccrc`. The rename has its own plan.
- **No Overlord machinery.** Nothing here reads a designation, a generation or an Overlord row.
- **Test first.** Every step that adds behaviour writes its failing test and runs it red before the code.
- **Run tests through `ccrc test`**, from inside the package, in the foreground, with a timeout of at least 600000 ms:
  `cd pwa && ccrc test -- ./node_modules/.bin/vitest run test/<file>`. Never bare `npx vitest`.
- **One commit per task**, on the workspace branch, with the message the task gives. Push once, when the build is done.
- **Cite code by symbol or anchor** (`file.ts#symbol`), never by line number.
- **No private names.** Fixtures use neutral names (`lane-a`, `project-a`).
- **No D-numbers invented.** The slugs in "Deviations found" stand until the programme mints numbers.

## Review Focus

1. **A light theme turns the eye over.** The eye's white is `--ink-primary` and its pupil is `--bg-page`, so on a light
   palette the eye is dark with a light pupil. The brief asks for exactly this ("a character follows the palette and
   light/dark"), and `ink-primary / page` holds 4.5:1 in every palette, so the eye always reads. Task 1's test pins
   that every tone reads a token with a contrast row against the page, and Task 2's stories draw every mood under the
   a11y addon, whose toolbar walks the palettes. Task 11 screenshots Phosphor Daylight.
2. **Not heard yet is never calm.** Before the first fleet frame, or while a reader is `null`, the face must not say
   Sleeping or Happy. Task 5's rows "no fleet frame yet is Neutral" and "an unmeasured lane map changes nothing".
3. **Motion that never stops.** An infinite loop in a bar that is always on screen fails WCAG 2.2.2 (pause, stop, hide).
   The bar's face plays for 5 s after each change of mood, then holds its still frame. Reduced motion stills it at
   once. Task 8's rows "plays five seconds, then still" and "reduced motion is still from the start".
4. **A link that flaps.** The first connect (`conn: 'connecting'`, `linkLost: false`) is not Offline, and a remote
   fleet whose health has not answered yet is not Offline either. Task 5's Offline rows.
5. **A badge the platform refuses.** No `setAppBadge` (Firefox, an uninstalled tab), or a `NotAllowedError` (iOS
   without notification permission), must never throw or log on every frame, and "not heard yet" must leave the badge
   as it was. Task 10's rows.

## Deviations found

Each entry is a plain slug, for the programme to number. Each says what was decided and why.

- **art-is-generated, method** — the 28 SVGs become `ui/src/characters/art.ts` and one stylesheet through a generator
  with a `--check`, in the themes' way. The drawn files stay the source. Inline markup would hide its colours from the
  contrast and motion gates, which read `.css` only, and a second `dangerouslySetInnerHTML` is not wanted.
- **one-face-stylesheet, consolidation** — the 28 inline `<style>` blocks are one vocabulary (measured), so they become
  one generated sheet with `chr-*` names. The six inline `style` attributes become modifier classes.
- **shade-is-bg-page, open question 3** — the eyelid and rim shading is `--bg-page` at its drawn `fill-opacity` (0.22,
  0.3, 0.35). It is already that colour (`#0B0D0C`), so no value changes in Phosphor.
- **tears-are-acct-blue, open question 3** — the tears' `#2988FF` becomes `--acct-blue`, the one blue every palette
  defines, with a 4.5:1 row against the page.
- **light-theme-inverts-the-eye, scope** — on a light palette the eye is dark with a light pupil. That follows from the
  brief's table, and it keeps the eye's 4.5:1 pair.
- **choice-is-a-server-row, shape** — "saved per person" on a one-operator console is one coord.db row, with a device
  copy for the first paint. There is no per-person store to extend, and theme and skin are per device by design.
- **face-routes-outside-coord, shape** — `GET`/`POST /api/face` live in `server/src/face/routes.ts`. They are not a
  coordination write, so they are not in `SESSION_ONLY`, and they take the default session gate.
- **mood-lives-in-the-bar, placement** — until W1's Overlord place exists, the live face sits after the wordmark in the
  three bars. W1's place shows it larger.
- **mood-plays-five-seconds, accessibility** — the bar's face plays for 5 s after a change, then holds still

- **happy-from-merged-at, method** — Happy reads `pr.mergedAt` within 10 minutes, off the live fleet frame. The event

- **sad-is-waiting-without-a-question, method** — Alert is a session asking now. Sad is something else waiting on you
  (items, review caps, limit waits), until W1 can measure how long a wait has lasted.
- **afraid-and-laughing-wait, scope** — the decider never chooses Afraid (W3: approvals and holds) or Laughing (W1:
  review rounds per merge). Their art ships.
- **all-moods-ship, open question 4** — all fourteen moods' art ships at once, since it is generated at no extra cost;
  the decider's table decides what shows.
- **one-wordmark-two-marks, consolidation** — `Wordmark` gains the `overlord` mark rather than a second primitive. The
  bars keep `❯ ccrc` until the rename plan flips the default.
- **greeting-in-geist, open question 2** — the wordmark is Geist Mono at weight 800, and the greeting is Geist, not a
  serif. No font ships.
- **splash-on-installed-launch-only, scope** — the splash shows only in standalone display mode, at most 4 s, and
  never blocks a tap.
- **badge-counts-the-waiting-door, value** — the badge counts what the Waiting on you door counts (the one needs-you
  source), not only the sessions asking, so the count matches what the operator finds on opening the app.

- **icons-extend-icon-gen, consolidation** — the existing zero-dependency generator draws the new icons, reading the

- **notification-mood-icon-later, scope** — a mood's still frame as a push icon needs one PNG per mood and a mood in
