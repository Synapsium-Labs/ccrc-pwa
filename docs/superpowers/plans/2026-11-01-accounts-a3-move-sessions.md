## Decision

- **D-7736 (2026-11-01)** — `accounts-a3-move-sessions` (Task A3). "Move N sessions off" on a trouble card opens the Move sessions sheet, a client composition over `POST /api/sessions/:id/swap` that moves a lane's sessions one at a time, with the decisions below.

  1. **Where the button is.** Rate-limited's card leads with it (its first fix: rate-limited is not a fault, spec §4.1); Signed out's card offers it after the credential fix (§4.2). Expiring and Inconclusive offer no move. `TroubleCopy` carries `move: { from, primary } | null`, the card counts the sessions itself and shows no button when there are none, and it owns the sheet it opens. `AccountsScreen.tsx` is unchanged. The kill-switch row's and remove's pre-check entries (§4.5) arrive with A14 and A19, which open the same sheet.
  2. **Which sessions.** Every row on the lane that is not archived and that the server reads alive or asleep (`sessionsToMove`). An asleep session is listed so that it is named ("refused: asleep") rather than silently left behind; a dead or unknown pane has nothing to move. So the button can count one more than the card's effect sentence, which counts live sessions only ("3 sessions on it will fail their next turn"; "Move 4 sessions off" when one of four sleeps).
  3. **The target with several sessions.** The chooser is SwapSheet's own, exported unchanged as `SwapTargetChooser`, over SwapSheet's candidates (`pickableWrappers` minus the switched-off lanes). A lane is in "the same pool" only when it is eligible for every listed session's project; the default target is the least loaded of those by measured numbers (`leastLoaded`), and with none measured there is no default and Move waits for a pick. Every other lane sits behind the other-pools disclosure, and picking one is the explicit crossing: `crossPool` then rides only the moves whose own project the target crosses, so a session already in the target's pool never records a crossing. A default-target move whose project the route still refuses reads "refused: other pool".
  4. **Busy sessions and consent.** Each move is sent without consent, and the route's measured `409 session-busy` is the skip ("skipped: busy"). With "Also interrupt busy ones" ticked, that refusal is followed by the same move with `interrupt: true`, as SwapSheet's "swap anyway" does: consent only ever follows a turn the server measured, and no idle session's move carries it.
  5. **Outcome words, from codes only.** `moveOutcomeOf` (`accountWords.ts`) reads one table typed over the route codes: moved; skipped: busy; refused: asleep; refused: other pool; refused: status unreadable, pool unreadable, not in the registry, registry unreadable, bad session id, bad request, fleet host too old to cross pools. ccd's 502 (no code) reads "refused: the fleet host could not move it", a code this build does not know "refused: a reason this app does not know", and no answer at all "no answer: it may have moved", because the move may have happened. No response text (ccd's stderr, a pool name, an unknown code) reaches the sheet. A refusal never stops the sessions after it.
  6. **One at a time, and stopping.** Each swap is awaited before the next is sent. The progress line, a polite live region, reads "Moving 2 of 4" while the second is in flight (one answered), then "Done: 3 of 4 moved." The list is frozen when the move starts, so a moved session keeps its row and its word after the fleet frame takes it off the lane. "Stop after this one", and closing the sheet mid-move, end the move after the session in flight; the rows not sent read "not sent".
  7. **Files.** As the plan lists, plus three registrations the census suites ask for: the three new ink rules (`.move-project`, `.move-word`, `.move-progress`) are grounded on the sheet panel's `--bg-sheet` in `pwa/design/audit.mjs`'s `INHERITED_GROUNDS`, the two that read `--fs-meta` are registered in `pwa/test/role-census.test.ts`, and the list is `RESET_LIST`. SwapSheet's "every other account is switched off" sentence is exported as `ALL_SWITCHED_OFF`, so the two sheets share one spelling (`literal-census`).
  8. **Offline, nothing is sent** (spec §12.5, as reviewed). Offline is the fleet store's own reading, `conn` not `open` (a cold start from the snapshot reads `connecting`, which is no more live than a dropped link), never `navigator.onLine`. Opened offline, the sheet still lists the lane's sessions from what the page holds, says "You're offline: nothing will be sent until the server answers again." in a `role="status"` line, and Move is off, so no swap leaves the page; the line goes and Move comes back when the store reads `open`. A move under way stops when the store reads the link down between two moves, or when a swap gets no answer at all (`moveOutcomeOf`'s no-answer arm): that session keeps "no answer: it may have moved", the rest read "not sent", the line reads "Stopped: N of M moved.", and a `role="alert"` line says "The server stopped answering, so the rest were not sent." Before this, a dead link sent every remaining swap into it and every row read "no answer: it may have moved". A refusal is an answer, so it still never stops the sessions after it. **What is not here:** the spec's read-line ("Read 4 min ago") needs the time of the store's last good read, which the store does not hold today; that is Task A18's, with the screen's own offline sentence, as A2's offline row (D-7718) records.
