# Flows waves 1 and 1b: definitions, their store, their doors, the editor, and sharing

**Plan** · 2026-11-19 · Spec: `docs/superpowers/specs/2026-11-19-flows-design.md` (§4, §7, §8, §9, §10 waves 1 and 1b, §14.1).
Executor: the session that wrote the spec, inline. Nothing in this wave executes a flow.

## Acceptance

1. `shared/flows.ts` holds the model, its derived lists, `parseFlowDoc` (shape, on read) and `validateFlow` (§4's rules, at
   publish), each rule with a test that goes red when its check is deleted.
2. `ccrc@1` ships in `server/src/flows/templates.ts` and validates clean; the skeleton validates clean.
3. coord.db gains `flows` and `flow_versions` by a migration; `CoordStore` is their one writer; a row whose doc does not
   parse is answered `unreadable`, never absent; a published version is never rewritten.
4. The doors of spec §8 exist, session-gated, no box token, registered from `server/src/flows/routes.ts`, and the
   box-token census reads that file against a hand-kept `FLOW_DOORS` in both directions.
5. The PWA has a Flows screen reachable from the desk tabs, and on a phone from the palette's "Go to Flows": the operator's flows and the templates;
   "Use template" makes a copy; the editor shows the flow as a read-only diagram (desk) and an outline (every width), and
   edits a block's title, role, prompt, skill, gate and outcomes, adds a block after another, and points an outcome at a
   block; Validate lists problems; Publish refuses with them and otherwise makes the next version.
6. (1b, §14.1) A published version saves as a file (`shared/flows.ts#flowExportJson`); "Import a file" reads one as untrusted
   input (`readFlowFile`: the byte cap on its UTF-8 bytes, then JSON, then the shape check), refuses one that breaks the
   rules, shows every step's prompt, and makes a new flow's draft only on the operator's word. `POST /api/flows`'s `import`
   arm checks all three again and never makes a version.
7. Every guard suite the change can reach is green: rings/contexts tables, single-definition, census, anchors, typecheck.

## Deviations found

Numbers are issued by `POST /api/ledger/deviations`; this session could not reach it, so each is `D-TBD-<slug>` until issued.

- **D-TBD-flows-context-c5.** Spec draft placed Flows in a new context C12; built in C5 Coordination (its only consumer), so
  no context id, map row or boundary was added. Spec §7 and §11 updated.
- **D-TBD-flows-verify-step.** The protocol step `wave-done` is `verify`: `wave-done` is the worker's mail subject, spelled
  once (`shared/api.ts#WAVE_DONE_SUBJECT`, pinned by `single-definition/update-stall.test.ts`). Spec §4 updated.
- **D-TBD-flows-no-kind-hues.** Block kinds are told apart by their label and a locked block's dashed, matte shape, not by
  hue: kind colour tokens need generated palettes in every theme and the contrast gate, which wave 5's canvas takes on.
- **D-TBD-flows-diagram-read-only.** The diagram takes no input in wave 1; the outline selects a step and the diagram marks
  it. An interactive SVG block is a hand-drawn control the control census would hold, and the canvas wave replaces it.
- **D-TBD-flows-desk-place.** Flows is a desk place (`Place.phone: false`); the phone bar stays at its six doors, and a
  phone reaches Flows through the palette's "Go to Flows". The outline editor works at every width.
- **D-TBD-flows-get-unmasked.** The three Flows GETs are mask-exempt (`secret-mask.test.ts`): they answer operator-written
  text byte for byte, because the editor saves what it read; the engine wave's send to a session is the egress that masks.
- **D-TBD-flows-membership.** `parseFlowDoc` first tested membership with `in`, which admits `toString`; it uses list
  membership, with a test for each vocabulary.
- **D-TBD-flows-canonical-json.** A stored document is written in one canonical serialisation
  (`shared/flows.ts#canonicalFlowJson`): publish compares the stored draft with the document it validated, and a template's
  field order differs from the parser's, so a fresh copy would otherwise have been refused `superseded`.
