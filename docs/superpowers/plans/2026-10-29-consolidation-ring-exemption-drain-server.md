## Review focus (the failure modes most likely to bite)

1. **A drain that moves the edge instead of removing it.** Moving a value into a file that is itself outward of its importer swaps one exempt pair for a fresh one; so does a re-export from an L1 file of an L3 or L4 file. Reviewers run `serverRing` on every new file and read the "exactly the exemptions" row's output at the tip, not only its green.
2. **A default that keeps the edge.** `deps.port ?? nodeDelegationFilePort`, `= SHAPE_ONLY_MASKER` and `compare = timingSafeEqual` are runtime references: a port with an optional parameter whose default names the adapter still loads it. Each drained port is required, or its default is a value of the inner file's own ring.
3. **A changed identity.** `instanceof` across the codebase must see one class: `remote/client.ts` creates its errors from `remote/errors.ts`, never a second definition, and its re-export is the same binding (RS4's identity pin).
4. **A mint or match that changed.** The claim code stays 32 random bytes in base64url (43 characters), minted once per `issue`; the slot matcher stays constant-time over every slot (its `compare` call count pinned).
5. **A delegation file op that moved behaviour.** The node port's ENOENT answers (`readFile` and `openRead` give `null`), its modes (`0o600` files, `0o700` directories), and `fsyncDir` stay byte for byte; the journal-path census still lists every truncating call and every use of the port, by file.
6. **A masker swap.** `PushService` masks every payload before serialization from its construction on (the shape-only masker until `setMasker`); RS10's shape-only answer is the same text as `new SecretMasker().maskDeep` for every input in `secret-mask.test.ts`'s corpus.
7. **A stamp that lies.** The stamp's `size` is the set's count at the commit, and its `since` the commit's day; a rebase recounts it.
