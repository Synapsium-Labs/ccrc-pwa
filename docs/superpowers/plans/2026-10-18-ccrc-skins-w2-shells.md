## Global constraints

Every task's requirements include this section and the foundations plan's Global constraints, which bind unchanged (public repository, no root runner, the palette is generated, the bridge maps and never defines, the role census, a skin owns no colour, mutation discipline, the boundary tests, no new dependency, the deviation ledger, branch discipline, SAFETY). `CLAUDE.md` is the authority. W2 adds:

- **One data model.** A skin directory contributes layout only (spec §5.1). It imports shared modules: `stores/`, `lib/` (never `lib/api`), the components, pure modules and action hooks under `fleet/`, `session/`, `screens/` and `inspector/`, and `@ccrc/ui`. It never imports the other skin's directory and never calls the network (spec §5.2). A skin places a shared component; it never re-implements one. The element half of the identity guard (`skin-boundary.test.ts`, D-5094) enforces this from S4 on.
- **One branch on the skin.** `app.tsx` is the only caller of `useSkin()` in shared code. It hands the chosen set down through `SkinSetProvider`, and a shared screen renders the parts it is given (D-5469). No shared file compares a skin id, imports `SKIN_SETS`, or reads `data-skin`.
- **A door runs its command.** A shell control that performs a registry command is built with `commandDoor(id)` (S2b), never with a handler of its own. S17 reads `data-command` to prove every command has a door in both skins (D-5469, D-5477).
- **Icons are vendored as they are used.** A task that uses a lucide icon not yet in `ui/src/icons/lucide.ts` adds its name to `ui/design/make-icons.mjs`'s list and regenerates the file in the same PR (F8's rule).
- **What a switch preserves** (spec §5.4, D-5466): the route, the composer's typed text, an open sheet or dialog, the terminal drawer with its live connection, and an open command palette. From S2b on, `skin-switch.test.tsx` holds all five, and every later task that moves a shared element re-runs it. Scroll position may reset.
- **One instance per width.** Where a readout or a strip moves between places by width (the accounts gauges, the banners, the inspector's sections), exactly one instance is mounted at any width, chosen with `useMediaQuery`, as `app.tsx` does for the accounts strip today. A test per task asserts the count.
- **Every door has a word.** An icon-only control (the rail, the phone header's doors, the tab bar) carries an accessible name, and a visible label wherever the layout has room for one (the tab bar always; the rail in its tooltip and the shortcut sheet). Status keeps its glyph and its word (spec §3.1).
- **The tap floor holds in both skins.** Instrument's dense chrome (the 24px status bar, the 32px rows) is dense only under `@media (pointer: fine)`. On a coarse pointer every control is at least `--tap-min`, whatever the skin (spec §11 item 4).
- **The verification matrix, sixteen renders per changed view.** 360, 390, 1280 and 1920 wide × Refined and Instrument × dark (Phosphor & Ink) and light (Phosphor Daylight). A task that changes palette values adds Dracula and GitHub Light. Where a task names a breakpoint between those widths (900, 1600), it adds the width either side of it (899 and 900, 1599 and 1600). Screens are rendered in the app against a fixture `CCRC_HOME` **and** `HOME`, with Playwright (one browser at a time) or Storybook with `STORYBOOK_SKIN`. Each render checks: no horizontal page scroll, no page errors, no clipped or overlapping text, 44px targets under coarse emulation, and the identity core present. Screenshots are kept in a scratch directory outside the tree and never committed. The PR body carries the per-width × skin table (§Acceptance).
- **Load rules for local runs.** Every vitest run passes `--maxWorkers=2`; one suite process at a time; the full pwa suite at most once per task, with `--maxWorkers=3`; never the full server suite locally; each long command in its own foreground call with a timeout of at least 600000 ms.
- **Doc suites on every PR that edits a plan:** `deviation-refs` (after `git fetch origin main`), `dtbd`, `topology-clean` and `single-definition`, run from `server/`.

## Review focus (the failure modes most likely to bite)

1. **A switch that remounts.** Rendering the ladder inside a per-skin `Shell` component remounts it on every switch, which loses the composer's text, closes the sheets and drops the terminal's socket. The ladder sits at one fixed position in the shared frame (D-5466). Review any change to `ShellFrame`'s children, the keys on them, or where a flow's state lives.
2. **A second branch on the skin.** A `useSkin()` call, a skin-id comparison or a `SKIN_SETS` import in shared code forks behaviour. The `useSkin(` census (D-5094) and S2b's set census (D-5469) are the wall.
3. **Logic forked into a skin.** A skin component that computes a word, a status, a count or an action itself has forked the data model. Every derived value comes from a shared model or hook; a skin's file holds markup and its own class names.
4. **Colour in the structure channel that the gate cannot see.** Skin stylesheets are ordinary rules on `ref-*` and `ins-*` classes (spec §4.4). A rule whose ground the gate cannot recover reads as uncovered. It is never grandfathered; it gets its ground or its pair (S3, D-5478).
5. **Escape reaching through a new overlay.** Instrument's inspector overlay (S12) and the More sheet (S11) are new layers over a session. `SessionHeader`'s Escape listener interrupts a busy turn and never checks `defaultPrevented`. Each new layer stops Escape's propagation itself, as the palette does (D-5103).
6. **Density against touch.** A dense row, bar or rail outside `@media (pointer: fine)` fails the tap floor on a tablet that chose Instrument.
7. **Two instances of one readout.** Two accounts strips, two banner stacks or two task strips at one width double-poll and double-announce.
8. **A single key in a text field.** `T`, `H`, `I`, `N` and the fallback for ⌘J are single keys. They fire only outside text fields and with no modifier held (D-5103's rule), never inside the composer.
9. **"Unmeasured" read as "clean".** The integrity readout (S16) never shows an all-clear before a census has arrived (D-5104).
10. **The default flipped too early.** `preview: false` turns Instrument on for every desktop. It lands last, on its own (D-5479).

## Deviations and decisions

### Issued 2026-10-18 and defined here

`POST /api/ledger/deviations` issued this plan a block of fifteen, D-5466 to D-5479 and one more, 5480. Fourteen are defined here, once. The spec and the foundations plan are not edited: this plan cites their numbers (D-5093 to D-5104, and the foundations workers' D-5155 to D-5159 and D-5243 to D-5246 where it relies on them) and never redefines them.

- **D-5466** — `stable-shell-frame` (Tasks S2b, S7, S17): the skins supply the parts of one shared frame, and the ladder sits in it at one fixed, keyed position. This departs from spec §5.2's mechanism, `app.tsx` rendering `SKIN_SETS[useSkin()].Shell` with the ladder passed in as a slot.
  - **Why.** Two `Shell` components are two element types. React unmounts the whole subtree of an element whose type changes, so a switch would remount the ladder: the composer's text, every sheet the ladder owns and the terminal drawer's socket would all be lost, which is exactly what spec §5.4 says a switch keeps. S2b's suite is run against a planted literal mechanism and is red there: that is the measurement.
  - **The frame.** `ShellFrame` renders `app-shell` plus the set's `frameClass`, with six keyed children (`bar`, `nav`, `detail`, `inspector`, `status`, `phone-nav`); a `null` part is absent, and identity rides on the key, never the position. `detail`'s key is a constant, and it holds the `RenderBoundary` and the ladder.
  - **The routes.** `pwa/src/lib/routes.ts`'s `ROUTES` is the one route table, read by the ladder, the palette's Go-to commands, the breadcrumb and the parity test.
