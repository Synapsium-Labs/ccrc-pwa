## Global constraints

Every task's requirements include this section and the foundations plan's Global constraints, which bind unchanged (public repository, no root runner, the palette is generated, the bridge maps and never defines, the role census, a skin owns no colour, mutation discipline, the boundary tests, no new dependency, the deviation ledger, branch discipline, SAFETY). `CLAUDE.md` is the authority. W2 adds:

- **One data model.** A skin directory contributes layout only (spec §5.1). It imports shared modules: `stores/`, `lib/` (never `lib/api`), the components, pure modules and action hooks under `fleet/`, `session/`, `screens/` and `inspector/`, and `@ccrc/ui`. It never imports the other skin's directory and never calls the network (spec §5.2). A skin places a shared component; it never re-implements one. The element half of the identity guard (`skin-boundary.test.ts`, D-5094) enforces this from S4a on.
- **One branch on the skin.** `app.tsx` is the only caller of `useSkin()` in shared code. It hands the chosen set down through `SkinSetProvider`, and a shared screen renders the parts it is given (D-5469). No shared file compares a skin id, imports `SKIN_SETS`, or reads `data-skin`.
- **A door runs its command.** A shell control that performs a registry command is built with `commandDoor(id)` (S2b), never with a handler of its own; a fieldset whose choice is the command's argument (Switch layout, Switch theme) carries `doorMark(id)`, the attribute alone. A control that opens a per-row fleet flow (`openActions(id)`, `openPool`, `openArchiveAll`, `openReap`) is built with `actionDoor(id, fn)`, which adds `data-action`. S17 reads `data-command` and `data-action` to prove every command and every flow has a door in both skins (D-5469, D-5477). Which door each command gets, per skin and width class, is fixed in §The door table, and a task builds exactly the doors that table names for it.
- **Icons are vendored as they are used.** A task that uses a lucide icon not yet in `ui/src/icons/lucide.ts` adds its name to `ui/design/make-icons.mjs`'s list and regenerates the file in the same PR (F8's rule).
- **What a switch preserves** (spec §5.4, D-5466): the route, the composer's typed text, an open sheet or dialog (the swap sheet, New session, the ⋯ menu, the PR sheet, the history pane, the model or effort picker), the terminal drawer with its live connection, an open command palette, a toast in flight, keyboard focus (never dropped to `<body>`), and a reader following the bottom of a running turn (still following after the re-measure). From S2b on, `skin-switch.test.tsx` holds them, S2d adds the session's, and every later task that moves a shared element re-runs it. Other scroll positions may reset. A layer that a skin's own part owns (Instrument's quick-bar sheets and More sheet, its inspector overlay) closes on a switch only if it is registered in `SWITCH_CLOSES` (`skin-switch.test.tsx`) with its reason, asserted both ways: a registered layer that now survives is stale, and an unregistered one that closes is red.
- **One instance per width.** Where a readout or a strip moves between places by width (the accounts gauges, the banners, the inspector's sections), exactly one instance is mounted at any width, chosen with `useMediaQuery`, as `app.tsx` does for the accounts strip today. A test per task asserts the count. **Width-gated parts mount and unmount; they are never hidden by a media query in a skin stylesheet**, because jsdom applies no media queries and a CSS-hidden door would count as visible in every jsdom suite (`skin-boundary.test.ts` case (j), from S4a). The phone/desktop pane swap stays `shell.css`'s, shared, and S17's browser leg is what measures it.
- **One derived value, one function.** A count, a word or a status shown in more than one place is computed by one shared pure function that every place renders (`fleetSummary`, `sessionHeaderView`, `groupByStatus`, `toolSummary`, `SessionLine`'s words). A test that compares two readers' outputs is a sign of two implementations; the guard is a source scan that every place imports the one function.
- **Landmarks and focus order** (S2b): the `detail` child is the one `<main id="content">`; the bar is a `<header>`; each navigation (the app bar's tabs, the rail, the tab bar) is a `<nav aria-label=…>`; the fleet column is a `<section aria-label="Fleet">`; an inspector is an `<aside aria-label="Inspector">`; the status bar is a `<footer>` and not a live region (only the integrity readout announces, politely, when its state changes). A visually hidden "Skip to content" link is the frame's first focusable element. The DOM order of the keyed children is the focus order, and grid placement never reorders them visually against it.
- **Single-select is one choice.** A control where one option is chosen (Refined's filter rail, Instrument's status/project toggle) is a `role="radiogroup"` of radio-semantics buttons; Instrument's phone underline tabs are a `tablist` with `aria-selected`. A badged door's accessible name carries its count ("Inbox, 3 unread"). A label shown on hover is also shown on `:focus-visible`.
- **Motion is tokened.** Skin stylesheets animate only with `var(--dur-*)` and `var(--curve-*)`, never a literal duration, so the existing `prefers-reduced-motion` guard covers them (`skin-boundary.test.ts` case (i)). A scripted scroll goes through the shared `scrollBehavior()` (S15), which answers `'auto'` under `prefers-reduced-motion: reduce`.
- **The keyboard and the bottom edge** (S5, S11, S12): `useKeyboardInset`, `SessionScreen`'s `data-kb` and `--composer-h` (which `ToastHost` reads) are the existing machinery. A part fixed to the bottom edge publishes its height the way `--composer-h` is published (Instrument's tab bar as `--phone-nav-h`, removed on unmount), `ToastHost`'s offset is their sum, and every top-level screen's scroll region pads its bottom by `--phone-nav-h`. A bar above the composer (the quick bar) is not rendered while `data-kb="true"`.
- **Every door has a word.** An icon-only control (the rail, the phone header's doors, the tab bar) carries an accessible name, and a visible label wherever the layout has room for one (the tab bar always; the rail in its tooltip and the shortcut sheet). Status keeps its glyph and its word (spec §3.1).
- **The tap floor holds in both skins.** Instrument's dense chrome (the 24px status bar, the 32px rows) is dense only under `@media (pointer: fine)`. On a coarse pointer every control is at least `--tap-min`, whatever the skin (spec §11 item 4).
- **The verification matrix, sixteen renders per changed view, and spec §9's widths for a shell.** The floor for every rendered task is 360, 390, 1280 and 1920 wide × Refined and Instrument × dark (Phosphor & Ink) and light (Phosphor Daylight). A **shell task** (S4b to S12, S16, S17) renders at spec §9's full set, **360, 390, 438, 900, 1280, 1440, 1600 and 1920**, so the narrowest desktop and the 1600 boundary are measured, not inferred. A task that changes palette values adds Dracula and GitHub Light. Where a task names a breakpoint (900, 1600), it adds the width below it (899, 1599). At exactly 1600 every shell task checks no horizontal scroll with the rail or the inspector open, in both skins; the reading and log columns are `max-width: min(var(--measure-chat), 100%)`, never a fixed width. A task whose layout responds to motion adds a `prefers-reduced-motion: reduce` emulation pass. Screens are rendered in the app against a fixture `CCRC_HOME` **and** `HOME`, with Playwright (one browser at a time) or Storybook with `STORYBOOK_SKIN`. Each render checks: no horizontal page scroll, no page errors, no clipped or overlapping text, 44px targets under coarse emulation, and the identity core present. ## Review focus (the failure modes most likely to bite)

1. **A switch that remounts.** Rendering the ladder inside a per-skin `Shell` component remounts it on every switch, which loses the composer's text, closes the sheets and drops the terminal's socket. The ladder sits at one fixed position in the shared frame (D-5466). Review any change to `ShellFrame`'s children, the keys on them, or where a flow's state lives.
2. **A second branch on the skin.** A `useSkin()` call, a skin-id comparison or a `SKIN_SETS` import in shared code forks behaviour. The `useSkin(` census (D-5094) and S2b's set census (D-5469) are the wall.
3. **Logic forked into a skin.** A skin component that computes a word, a status, a count or an action itself has forked the data model. Every derived value comes from a shared model or hook; a skin's file holds markup and its own class names.
4. **Colour in the structure channel that the gate cannot see.** Skin stylesheets are ordinary rules on `ref-*` and `ins-*` classes (spec §4.4). A rule whose ground the gate cannot recover reads as uncovered. It is never grandfathered; it gets its ground or its pair (S3, D-5478).
5. **Escape reaching through a new overlay.** Instrument's inspector overlay (S12) and the More sheet (S11) are new layers over a session. The Escape interrupt (a window listener in `SessionHeader` on `main`, the shared `useEscapeInterrupt` from S2d) skips an event whose default is prevented and skips while any `[role="dialog"][data-state="open"]` is in the document (D-5235). So a new layer is safe only if it is built on the Radix layer that renders `role="dialog" data-state="open"` (as `Sheet` is), or its Escape handler calls `preventDefault()` and it receives Escape wherever focus is. A hand-made `aside` with a keydown handler is neither when focus is on the body. (The foundations plan's D-5103 text, "never checks `defaultPrevented`", predates D-5235; the palette's propagation stop is harmless and stays.)
6. **Density against touch.** A dense row, bar or rail outside `@media (pointer: fine)` fails the tap floor on a tablet that chose Instrument.
7. **Two instances of one readout.** Two accounts strips, two banner stacks or two task strips at one width double-poll and double-announce.
8. **A single key in a text field.** `T`, `H`, `I`, `n`, `G` and the fallback for ⌘J are single keys. They fire only outside text fields and with no modifier held (D-5103's rule), never inside the composer.
9. **"Unmeasured" read as "clean".** The integrity readout (S16) never shows an all-clear before a census has arrived (D-5104).
10. **The default flipped too early.** `preview: false` turns Instrument on for every desktop. It lands last, on its own (D-5479).
11. **A door jsdom can see and a person cannot.** jsdom applies no layout and no media queries, so a door inside the CSS-hidden fleet column, or under a `display:none` media query, passes every jsdom count. Visibility claims (S17 (a), (b), (d)) are measured in the real-browser leg; jsdom suites only count what is mounted, and width-gated parts mount by `useMediaQuery`.
12. **Behaviour owned by a part that a switch replaces.** State or an effect inside a skin's chrome (the ⋯ menu's open state, the Escape interrupt) is lost or forked on a switch. S2d lifts the session's, as S2a lifted the fleet's.
