# The test box, connected from the console — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task by task, with superpowers:test-driven-development for every red-first step. Steps use checkbox (`- [ ]`) syntax for tracking. Workers do not edit this file or its "Deviations found"; they name a departure in their report, and the coordinator folds it.

**Goal:** Any ccrc installer points ccrc at a prepared remote box and sets it up entirely from Settings › Automation › **Test box**: ccrc makes its own access key, pins the box's host key, checks the box, installs the test service from the fleet host's own verified release, pairs it with secrets it makes itself, runs parity from a button, and offers Settings, Repair, Replace, Disconnect and Apply release, each recorded in a ledger. The switch cannot be armed without a passing parity record.

**Architecture:** The server still never reaches the box. The page sends typed fields to session-only routes; the server checks them with one L0 contract (`shared/testbox-admin.ts`), gates them as account acts are gated, and sends one new fixed-template agent op, `testbox-admin`. The agent spawns `$HOME/.local/bin/ccrc testbox-admin <sub> --from agent` with argv from one shared builder. The verb, `ccd/ccrc-testbox-admin`, re-checks every field, runs `ssh` itself with a pinned host key, writes the fleet-side files atomically, and runs long acts (connect, repair, apply release, parity, apply when idle) as detached `systemd-run` units under a lock, with a state file the card reads. Fleet-side settings land in a ccrc-owned overlay, `~/.ccrc/testbox.env`, that ccrc's one reader learns. The box side reuses the root installer, which gains a same-tag re-apply and an unpair mode.

**Tech Stack:** bash (`ccd/`, `deploy/testbox/`), TypeScript (`shared/`, `agent/`, `server/`), Fastify, `node:sqlite` (`coord.db`), React (`pwa/`), vitest, the `pwa/browser` Chrome leg.

**Spec:** `docs/superpowers/specs/2026-11-07-test-box-connect-design.md`, approved 2026-11-10 (D-8166). Read it with this plan. Section numbers (§2.4), measurements (M17) and decisions (C9, T4) are the spec's. **Rulings:** `docs/superpowers/plans/2026-11-10-test-box-connect-ruled.md` (C1 to C16, all as recommended). **Built on:** `docs/superpowers/plans/2026-10-29-test-box.md` (TB0 to TB11 merged; this plan replaces the hand steps of TB12 to TB14 for any installer, which stay the recovery path).

**Base:** `origin/main` `b7dddef74`. Every symbol below was read on it. Line numbers are not given; each task's Step 0 re-reads the anchors it names, and code cites symbols, never lines.

**Names.** Tasks are **TC1** to **TC17** ("test box connect"); waves are **C1** to **C7**. Measured on `b7dddef74`: no `TC<n>` id exists under `docs/`, `ccd/`, `shared/`, `agent/src`, `server/src`, `pwa/src` or `deploy/`.

## What the measurement found

Read on `b7dddef74`. Each item names the task that acts on it.

1. **The verb has a home that does not grow `ccd/ccrc`.** `ccd/ccrc` and `ccd/ccd` are growth-listed at +40 net code lines (`server/test/growthCheck.ts`, `GROWTH_FILES`, `GROWTH_LIMIT = 40`), and every `ccd/lib/*.sh` is held too (`growthFiles`). `ccrc test` is one dispatch line, `test) exec bash "$CCRC_HERE/ccrc-test" "$@" ;;`, to its own file. `ccrc testbox-admin` takes the same shape: one line in `ccd/ccrc`'s verb `case`, the body in a new `ccd/ccrc-testbox-admin` that sources `ccd/ccrc` (for `_upd_resolve`, `_upd_fetch`, `_plat_*`, `_svc_run_detached`) and `ccd/testbox-knobs` (for `_tb_shape`, `_tb_load`), as `ccd/testbox-knobs` itself sources `ccd/ccrc`. New `ccd/` files ride the release tarball (`deploy/build-release.sh`'s `PATHSPEC` packs `ccd`). → TC3.
2. **One reader, one copy.** `_ccrc_knob` reads `$BOX_ENV_FILE` (`~/.ccrc/ccrc.env`) only and never the exposure overlay (its long comment). It is copied whole into the generated `ccd/lib/ccrc-settings.sh` (`deploy/gen-settings-lib.mjs`; `server/test/ccrc-settings-lib.test.ts` holds the two equal), which `ccd-testbox-times` sources, and `ccd/ccrc-doctor-checks` calls `_ccrc_knob CCRC_TESTBOX_URL '' file` itself. So the overlay goes into `_ccrc_knob`, for the sixteen fleet-host test box keys alone, and every reader learns it at once (spec §2.6, "the one reader, its generated library and the settings census"). → TC2.
3. **The box-settings wire needs no new word.** `BoxSettingSource` is `'environment' | 'file' | 'empty' | 'default'` (`shared/api.ts`). An overlay value reads `from: file` (it is a file ccrc reads), so the snapshot and the card take it with no skew. The four pairing keys are display class `is-set` already (`BOX_SETTINGS_TABLE` in `ccd/ccrc`), so D19 holds. → TC2.
4. **Box mode cannot meet the overlay.** The 28 box keys and the 16 fleet-host keys are disjoint (`_tb_host_table`, `_tb_box_table` in `ccd/testbox-knobs`), so an overlay keyed to the 16 is never read on the box. → TC2.
5. **The account op is the template.** `shared/account-argv.ts#buildAccountArgv` is the one builder both arms call; `agent/src/accountop.ts` is the bounded spawn port (`shared/spawn.mjs#boundedStdinSpawn`, explicit `{HOME, PATH, LANG}`, output cap, TERM then KILL); `agent/src/server.ts`'s `validateReq` builds once and `handleReq` builds again; `ready.ops` lists the op words; `agent/CLAUDE.md` names four wire-triggered spawn classes (`update`, `token-sync`, `account`, `testbox`). `testbox-admin` is the fifth, and needs **no stdin**: C1 puts no secret in the browser, so no secret crosses the wire at all (spec §2.3). → TC1, TC11.
6. **The gate is reusable as is.** `server/src/accounts/gate.ts`'s `AccountGate` takes `{cap, stepUp}` and refuses in a fixed order (auth off, insecure origin, not a session, cap absent, no recent step-up), minting an actor (`accounts/audit.ts#actorOf`). Cap words are advertised by `ccd caps` (`account-v1` in `ccd/ccd`'s caps printer; `ACCOUNT_CAPS` in `shared/api.ts`). → TC12 adds `testbox-admin-v1`.
7. **The ledger has a precedent.** `account_events` is migration 26 of `server/src/coord/schema.ts` (51 migrations on `b7dddef74`); its one writer, `AccountAudit.write`, refuses any value off its closed vocabularies, and a failed write is an answer. → TC12.
8. **The switch has no gate.** `POST /api/testbox/switch` (`server/src/coord/routes.ts`) takes `{on}` and runs `CCD_ARGV.testboxRemote`; `cmd_testbox_remote` in `ccd/ccd` writes or removes `$REG/testbox-remote-live`. → TC10, TC13.
9. **The installer re-runs, but not from where it is installed.** `deploy/testbox/install.sh` re-runs phase 5 when the box file's sha256 differs from the marker's, but phase 2 copies the staging tree to `<tools>/release/<tag>`, so run from the installed tree it would copy onto itself; and a different installed tag is refused (M3). It has no mode that removes the pairing (C6). → TC6.
10. **The push trusts `~/.ssh/known_hosts`.** `ccd/testbox-snap` exports `GIT_SSH_COMMAND="ssh -i <key> -o IdentitiesOnly=yes -o BatchMode=yes"` (M17). A box installed by hand before this plan has no pin file, so the pin options apply only when `~/.ccrc/testbox-known-hosts` exists. → TC5.
11. **Parity is an operator CLI with no scope default and no record.** `ccd/testbox-parity` needs `--pr`/`--rev`, runs two legs, prints `agree`/`DIFFERS`, exits 0/1/2 and writes nothing (M15). The fixtures of test box spec §6 (git state, socket, workers) are rows of its acceptance table and are not legs of the tool. → TC9.
12. **Lifecycle rows say nothing writes the pairing files.** `shared/lifecycle.ts` rows `testbox-token` and `testbox-push-key` (M18). → TC14.
13. **Where server files live.** `server/src/testbox.ts` and `testboxLane.ts` are context C2 Fleet Mutation in the ring map of `docs/superpowers/specs/2026-08-10-architecture-ddd-clean-solid.md`; a new top-level `server/src` file needs its row in the same PR (`server/test/rings/totality.test.ts`). The card lives in `pwa/src/fleet/` (C1, `fleet/**`), so new PWA files there need no map row. → TC12, TC15.
14. **The card's step-up.** `pwa/src/accounts/useStepUp.ts` and `ConfirmItsYou.tsx` are the accounts' passkey step-up. → TC15, TC16.

## Global constraints

- **Public repository.** Cite D-numbers and GitHub `#n` only. No tracker ids, hosts, addresses, account names, user names of anyone's box, emails or box names: prose says "the test box". Examples use `testbox.invalid`; fixtures use documentation-range addresses and neutral names (`repo-a`, `fleet-a`).
- **Machine-neutral, installer-usable.** No host, address, user, distribution, path of anyone's box or repository in code. Every value comes from the card, from a setting with a neutral default, or from the fleet host's own measurement. Everything the operator must do is a control on the card.
- **The server never reaches the box.** `ssh` stays in `FORBIDDEN_COMMANDS`; the agent's exec whitelist is unchanged; only the verb runs `ssh`, and every `ssh` it runs carries `-o UserKnownHostsFile=$HOME/.ccrc/testbox-known-hosts -o StrictHostKeyChecking=yes -o BatchMode=yes -o IdentitiesOnly=yes -o ConnectTimeout=<deadline>`.
- **Secrets.** The service token, the push key's private half and the access key's private half never appear in a page, a wire frame, argv, a log line, a phase file or the ledger. They are made on the fleet host by the verb. The token reaches the box on `ssh` stdin only.
- **One contract.** Field grammars, sub table, codes, phases and the parity decision live once in `shared/testbox-admin.ts` (L0). The bash verb's copies are held equal by tests that run both on one corpus.
- **Values.** Checked on the page, at the route (the L0 grammar), and by the verb (`_tb_shape`, `_tb_load`); refused, never defaulted. A write that would leave `ccrc.env`, the overlay or the box file in a state its reader refuses is refused before it lands.
- **Measured, never echoed.** Every route answers from the verb's re-read state; a long act's result is learned from the state file, never from the spawn's reply.
- **Wire additions are optional**, each with one PWA reader and a skew test in both directions. `FLEET_PROTO` and `TESTBOX_PROTO` are not bumped (spec §5.1: the admin `status` sub carries the card's reads; the `testbox` op is unchanged).
- **Recurring pins, re-run in every PR that touches their area:** `auth-gate.test.ts` counts and `server/src/auth/gate.ts` prose; `coord-pause-route.test.ts`'s `SESSION_ONLY`; `ccrc-api-closed.test.ts` counts and `ccd/ccrc-api` prose (new routes are console-only, no `ccrc-api` verb); `box-token-census.test.ts`; `coord-db.test.ts` migrations (main's `schema.ts` is authoritative: take the next free slot at landing and re-measure before merge); the settings census (`ccrc-settings-census.test.ts`: README's `**ccrc's own settings.**` paragraph names every setting; `deploy/ccrc.env.example`); Linux-only settings counts (derived by arithmetic, never retyped); `growth-check` waivers (`server/test/growth-exemptions.json`, only with a named ruling); poison containment in ccd tests (`ghContainedEnv` with systemd and tmux contained); `ccd-contexts.test.ts` rows for every new `ccd/ccd` function; `ccd-lib-load.test.ts` (tests read ccd through `ccdSource`); `consolidation-census.test.ts` (the `runCcd` not-ran arm first); `secret-mask.test.ts` (every GET route masked or exempt with a reason); `watcher-quiet-census.test.ts`; `dispatch-mutex-gate.test.ts`; `consolidation-path-guard.test.ts` (a diff touching `shared/switches.ts` or `server/src/notice.ts` touches no `pwa/`: no wave here touches either); `typecheck-tests.test.ts`; `pwa/test/refusal-literal-ratchet.test.ts` (refusals through `refusalText`); `pwa/test/control-census.test.ts`; `topology-clean.test.ts`; `deviation-refs.test.ts`.
