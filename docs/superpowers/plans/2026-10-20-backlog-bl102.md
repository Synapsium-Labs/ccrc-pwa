# Backlog bl102: the linked-worktree fold keeps what it could not measure

**Issue:** #530 (ARCH-08). **Size:** S. **Deploy class:** server lane only; no `ccd/`, `agent/` or `pwa/` byte, no wire change, no new `FleetIO` member.

## Problem

`listProjects` (`server/src/lifecycle.ts`) folds out a linked worktree, a workdir whose `.git` is a FILE. Its probe, `isLinkedWorktree`, decided that with `(await io.readdir(path.join(workdir, '.git'))) === null`. `readdir` answers null on ANY failure, so a remote readdir that timed out or failed read as "it is a file" and dropped a real project from both doors (the projects-root walk and the registry union). That contradicts the function's own contract: the probe only ever removes what it positively identified. #397 (path identity W1a) rewrote the registry half of `listProjects` but kept this line.

## Fix

`isLinkedWorktree` asks `lstatMeasured` on `<workdir>/.git`, which already exists on both adapters. Only a measured `regular` file condemns. A directory (`other`) is a main checkout and stays. A symlink stays, as the readdir probe kept one that pointed at a directory. A failed probe (`absent`, `unreadable`, `unmeasured`: a timeout, a permission error, an agent too old for the `lstat` op) keeps the project.

## Tests

`server/test/lifecycle-linked-worktree.test.ts`, each case through both doors:

1. A `.git` probe that times out keeps the project. Red at `origin/main` (both projects dropped).
2. A `.git` file is excluded.
3. A `.git` directory is included.
4. A `.git` symlink is kept.

Cases 2 to 4 pass at `origin/main` too. They are guards that kill the mutants which would trade case 1's fix for a wrong exclusion or inclusion.

## Deviations and decisions

### Issued for this work and defined here

- **D-5967** — `git-probe-keeps-unmeasured` (#530, ARCH-08): `isLinkedWorktree` excludes a workdir only when `lstatMeasured(<workdir>/.git)` measures a `regular` file; a directory, a symlink and every failed probe keep the project.
  - **Departs from the issue's proposal:** the issue also suggested reporting the unmeasured project. It is kept but not tagged: `ProjectRow` and `GET /api/projects` gain no field. The `registry` field that #397 added reports a whole half of the union; a per-row tag would be a new wire vocabulary, which the issue's own acceptance rules out.
  - **Known cost:** on a remote fleet whose agent predates the `lstat` op, every probe is `unmeasured`, so a linked worktree there is listed until the agent is updated. That is the fail-open direction the contract asks for: a spare row in the picker, never a lost project.
