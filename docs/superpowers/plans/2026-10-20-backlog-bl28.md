# Leaked test children: a timed-out spawn takes its whole tree, and a leak fails the run (#172, part 1)

GitHub issue: #172. This plan covers its first half only, the test suite's leaks. The second half (collecting a
dead session's background processes) is session-continuity work and is tracked on its own; a service that lives
outside this repository is not touched here.

## The problem

`spawnSync(…, { timeout })` kills only its direct child. When that child is a `bash -c` that has forked (a
`flock`, a `sleep`, a `git`), the grandchild runs on after the timeout: reparented, still in the suite's process
group, holding whatever it held. The reentrant-lock case in `server/test/ccrc-account.test.ts` exists for the run
where the second `_acct_marker_lock` waits on a lock its own process holds, and on each such red run it left one
`flock` behind. Measured: seven of them, about eleven days old, each holding a lock under a fixture directory the
test had already deleted, together pinning a workspace that could not be reclaimed until they were killed by hand.
Nothing in the suite noticed.

## The fix

1. **`server/test/spawnGroup.ts`, `spawnSyncGroup`** (D-5894): `spawnSync` with `detached: true` (libuv's
   setsid(); macOS has no setsid(1)), so the child leads its own process group. On a timeout the whole group is
   SIGKILLed. A child that returns on its own but leaves a member in its group makes the helper kill it and throw:
   the helper is the leak check for the groups it creates. A caller that strands a process ON PURPOSE (a fixture
   that removes a deadline to prove a backstop, a probe that wedges a platform tool) passes `{ strays: 'end' }`,
   and the helper ends the leftovers through the group it created and returns normally: the run's own handle,
   never a pid read back from a file (D-3533).
2. **`server/test/proc-leak.globalsetup.mjs`** (D-5894), wired as a second `globalSetup` in
   `server/vitest.config.ts`: setup records the members of vitest's own process group; teardown, after a 2 s
   grace, names every new member whose parent is neither vitest's main process nor a recorded one, with its age
   and its working directory (usually a fixture directory, which names the file that started it), and sets
   `process.exitCode = 1`. It signals nothing: a PID it observed is not a handle the run holds, and D-3533 rules
   that a globalSetup carries no signal authority (`ccrc-uninstall.test.ts` pins it, on Linux; the first cut of
   this check SIGKILLed what it named and that pin went red in CI). It does not throw, because a throw from a
   globalSetup teardown is printed and the run still exits 0 (measured on the pinned vitest 4).
3. **All seven timed spawns in `ccrc-account.test.ts`** move to `spawnSyncGroup`, the reentrant-lock case among
   them (D-5895 says why the rest of the suite's timed spawns are not converted in this change).
4. **The deadline-shim case strands its sleeper inside a group it holds** (D-5894). "the deadline shim's bash
   fallback does not hold its caller's pipe" orphans a `sleep 10` on purpose (the shim's fallback signals its
   watcher subshell, and the sleeper inside runs out its bound). The new check caught it. Its two runs now go
   through `sourceRun` with `strands` (`spawnSyncGroup` with `strays: 'end'`); the shim itself is unchanged.
5. **The leaks the check found on its first CI run**, each fixed in the test that made it (D-5894), each with the
   product code unchanged:
   - `ccd-account-auth.test.ts`, the two `noDeadline` cases on both arms (`sleep 300` ×4): the pump's backstop
     TERMs the pty wrapper and the mint under it runs on. `drive` runs in its own group, `strays: 'end'` only for
     `noDeadline`.
   - `ccgpt-runtime.test.ts`, the no-`timeout` build (`sleep 1200` ×2, `sleep 300`): the pure-bash deadline arm
     orphans its sleeper by design. The one runner leads its own group; `strands: true` on that case alone.
   - `ccrc-update.test.ts`, the `update.lock` holder (`sleep 60`): `flock` forks its command, and killing `flock`
     left the `sleep`. The holder is `detached` and the `finally` ends its group.
   - `platform-hazards.test.ts`, the BSD `grep -r` over a live FIFO (`grep` on the macOS probe): the case wedges
     grep on purpose and the timeout killed only `bash`. `bash()` runs in its own group with `strays: 'end'`.

## The tests

- `ccrc-account.test.ts`, "a wedged second acquisition is killed WITH its flock": it forces the wedge (the guard's
  variable is emptied between two `_acct_marker_lock` calls), asserts the call timed out, and asserts with `lsof`
  that no process holds the lock afterwards. Red with a plain `spawnSync` runner, which is origin/main's.
- `proc-leak.test.ts`: a nested real vitest under the leak check, over a fixture test that leaks a `sleep`, exits
  1, names the child, and leaves it dead; over a fixture that leaks nothing, it exits 0 and says nothing. The
  helper's four outcomes (timed out, returned with a leftover, returned with a declared stray, returned clean) are
  measured directly. The leaked child is asserted STILL ALIVE after the nested run: the check names it and never
  signals it (D-3533).
- The deadline-shim case, run on its own without its `finally`, fails the run and names `/bin/sleep 10`: the check
  on a real leak the suite already had.

## Deviations and decisions

### Issued for this work and defined here

- **D-5894** — `test-spawn-own-group` (#172 part 1): a test child that can fork and runs under a timeout is
  started by `spawnSyncGroup`, in a process group of its own, and the group is killed when the timeout fires; a
  case that strands a process on purpose declares it (`strays: 'end'`) and the group is ended when the call
  returns. The server suite's run fails (exit 1) when a process a test started in the suite's own process group
  is still alive at teardown; the check names each one with its age and working directory and signals none
  (D-3533: an observed PID is never a kill target). Blind spots, named in the globalSetup's header: a process
  that left the group (a detached child, a daemon in its own session, a tmux server) and an orphan whose new
  parent is a recorded member.
- **D-5895** — `test-spawn-own-group-scope`: only `ccrc-account.test.ts`'s seven timed spawns are converted here.
  About 120 more timed `spawnSync` calls sit in about 60 other files, several of them held by open pull requests
  that add timed spawns of their own, so a codemod or a pinned per-file census would collide with them. The
  run-level check (D-5894) already turns the measured failure shape, a forked grandchild of a timed-out spawn left
  in the suite's group, into a red run wherever it happens, so the remaining sites are converted file by file
  when a file is next touched, not in one sweep.

Issued and unused: none.
