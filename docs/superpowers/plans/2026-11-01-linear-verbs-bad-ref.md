# The `ccrc-api linear` verbs: a bad issue reference is refused locally as `bad-ref`

- **D-7685 (2026-11-01)** — `linear-verbs-bad-ref`: the Linear key design (#1444, spec §5.1) has `ccd/ccrc-api` check an issue reference against the identifier grammar `^[A-Za-z][A-Za-z0-9_]*-[0-9]{1,9}$` before anything is sent, and refuse any other shape locally with exit 2, but names no refusal word for it. The client answers `bad-ref` in its usual envelope, separate from `bad-id`: `bad-id` means a value SAFE_RE refuses, and `AAA12`, `AAA-` and `search` all pass SAFE_RE, so the two are different facts for the caller and one word for both would be the overloaded value the client's own `no-pane`/`bad-pane` pair avoids. The grammar's character classes are spelled out, never ranges, as `_api_server_cap` spells its own, because a range in a bash regex may collate non-ASCII letters under a UTF-8 locale. `server/test/ccrc-api-closed.test.ts` pins the word, the three shapes the spec names and four more (`-12`, `1AA-12`, a ten-digit number, `AAA-12-3`), and the two edges that pass (`A-1`, `a_B9-123456789`).
