## The gap

C38's `useHidingFollowsOpen` (`ui/src/primitives/sheet.tsx`) lifts the marks Radix made as a sheet turns closed, and
leaves alone the elements the page hid itself. It read those as the sheet opened, as
`[aria-hidden="true"]:not([data-aria-hidden])`: a hidden node with no Radix mark.

The `aria-hidden` package (read from its source, `aria-hidden/dist/es2015/index.js`) marks a node that is already hidden
as **uncontrolled**: it adds its `data-aria-hidden` mark and leaves the `aria-hidden` as it was. Its undo never removes
`aria-hidden` from an uncontrolled node. So when a dialog that is still mounted (closing, or open under this one) has
already marked an element the page hid itself, that element carries the mark when the next sheet opens. The next sheet
did not count it as the page's own, lifted it as it closed, and Radix's undo never put it back. It stayed announced for
good.

- **F2, no stack.** A sheet opens while the one before it is still in its exit (a menu sheet whose row closes it and
  opens the next in one commit). **Measured**, jsdom, `pwa/test/sheet-trap-hide.test.tsx`'s new row "a sheet opened while
  the previous one closes …". On `main`, a body-level `<div aria-hidden="true">` reads `null` once the second sheet
  closes (`the closing sheet lifted an element the page hid itself: expected null to be 'true'`). It still reads `null`
  after both sheets have unmounted (`… was left announced for good`, measured with that row's first assertion commented
  out). Load average 18.
- **F1, stacked.** Two confirms overlap over a sheet that holds a live region, so Radix marks the sheet's children,
  including an element the sheet hid itself. The `top.contains(node)` arm lifted it. **Measured**, jsdom, the new row "a
  confirm opened while another closes, over a sheet with a live region …". On `main`, the sheet's
  `<span aria-hidden="true">` reads `null` as the second confirm closes, and still `null` after both confirms have
  unmounted.

## The fix

The fix is at the owner, `useHidingFollowsOpen`, once. As the sheet opens, before its Radix marks anything, the sheet
reads every node already hidden: `[aria-hidden="true"]`, with or without a mark. It never lifts one of those, whoever hid
it. Only marks its own open added are lifted. The rest of C38's rule is unchanged: the topmost-open-dialog filter, the
reopen during the exit, and the focus guards. Departure `c40-lift-only-own-marks`.

- **Single-sheet callers with no overlapping exit** behave as before. With no other dialog mounted, the only hidden
  nodes at open are the page's own, the same set the old read took. **Inferred** from the code. The C38 rows pin it:
  `sheet-trap-hide.test.tsx` §1, all green (16 of 16 with the new rows), and `confirm-focus.browser.test.ts`.
- **Two, three and four deep** keep C38's rule. A confirm opening over a sheet finds the page already hidden by that
  sheet, so it never lifts the page; it lifts only its own mark over, or inside, the sheet under it. **Measured** at two
  and three deep: the two- and three-deep rows and the live-region row are green, and the three-deep row is now also
  asserted after the confirm unmounts (F3). Four deep is **inferred**: it is the same rule one level up.
- **What it gives up (inferred, not measured).** The read happens in the sheet's passive effect. A previous sheet that
  closes in the same commit lifts its own marks first only when it comes earlier in the tree. For the menu's hand-off,
  Chrome measured the page announced as the swap sheet closes (the F2 app row); for the other callers below the order
  is not measured. If a closing modal had not lifted yet, the new sheet
  would find the page hidden, take it as already hidden, and leave it hidden through its own exit. Examples are a sheet
  later in the tree, or the command palette, which is a vaul drawer but not a `Sheet`. That is `main`'s behaviour before
  C38, and nothing is left hidden for good: Radix's undo removes those marks at the unmount. The brief ruled that safety
  comes first.

**Where an element the page hid itself sits on a path Radix marks.** The `aria-hidden` package keeps visible the path to
the dialog and to every `[aria-live]` element (and `script`). It marks each sibling along those paths. It does not keep
`role="status"` or `role="alert"`; this was read from its source. So an element the page hid itself is at risk only when
it is a direct child of `body`, or a direct child of an ancestor of a live region. The app's live regions outside a sheet
are the code block's Copy label (`markdown.tsx`) and the reader lab. This was found by a code search, so it is
**inferred**.

**Measured** in Chrome, on the session screen at 390 (Refined) and at 1280 (Instrument), with a transcript holding a code
block, with the menu open:
- The menu marked the containers along the path to the Copy label: the skip link, the nav, the chat head, the code
  block's language label, `pre`, the paragraphs, the strips, the composer measure, the inspector or status bar, and the
  scrim.
- It marked **none** of the elements the page hid itself. Those are icons and glyphs inside the marked containers, never
  siblings on the path.

So F2 does not reach today's app with this transcript. A message that puts an `aria-hidden` element directly beside a
code block, or a body-level hidden element, would make it reachable (**inferred**). The browser row plants one such
element beside the code block to hold the fix in the real flow.
