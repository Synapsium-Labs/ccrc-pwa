## The gap

C38's `useHidingFollowsOpen` (`ui/src/primitives/sheet.tsx`) lifts the marks Radix made as a sheet turns closed, and
leaves alone the elements the page hid itself. It read those as the sheet opened, as
`[aria-hidden="true"]:not([data-aria-hidden])`: a hidden node with no Radix mark.

The `aria-hidden` package (read from its source, `aria-hidden/dist/es2015/index.js`) marks a node that is already hidden
as **uncontrolled**: it adds its `data-aria-hidden` mark and leaves the `aria-hidden` as it was. Its undo never removes
`aria-hidden` from an uncontrolled node. So when a dialog that is still mounted (closing, or open under this one) has
already marked an element the page hid itself, that element carries the mark when the next sheet opens. The next sheet
did not count it as the page's own, lifted it as it closed, and Radix's undo never put it back. It stayed announced for
good.

- **F2, no stack.** A sheet opens while the one before it is still in its exit: a menu sheet whose row closes it and
  opens the next in one commit. **Measured** in jsdom, `pwa/test/sheet-trap-hide.test.tsx`'s row "a sheet opened while
  the previous one closes …". On `main`, a body-level `<div aria-hidden="true">` reads `null` once the second sheet
  closes (`the closing sheet lifted an element the page hid itself: expected null to be 'true'`). It still reads `null`
  after both sheets have unmounted (`… was left announced for good`; measured with that row's first assertion commented
  out). Load average 18.
- **F1, stacked.** Two confirms overlap over a sheet that holds a live region, so Radix marks the sheet's children,
  including an element the sheet hid itself. The `top.contains(node)` arm lifted it. **Measured** in jsdom, the row "a
  confirm opened while another closes, over a sheet with a live region …". On `main`, the sheet's
  `<span aria-hidden="true">` reads `null` as the second confirm closes, and still `null` after both confirms have
  unmounted.

## The fix

The fix is at the owner, once: `useHidingFollowsOpen` (`ui/src/primitives/sheet.tsx`) and a record it reads,
`recordModalLayer` (`ui/src/lib/modal-layers.ts`, new). An element the page hid itself is never lifted, whatever modal
marked it; every other mark is lifted, whether it is this sheet's own or another modal's. The rest of C38's rule is
unchanged: the topmost-open-dialog filter, the reopen during the exit, and the focus guards. Departure
`c40-lift-only-own-marks`.

**The record (fix round 2, review 2334 F1 and F2).** Each modal layer records, as its panel mounts and before its own
Radix hiding runs, the elements the page hid itself:
- every hidden node that no modal has marked (C38's read);
- every node a layer still mounted recorded as the page's own.

The modal layers are `Sheet` and the command palette's vaul drawer, whose `Drawer.Content` now carries the record's ref.
They are the only Radix modal dialogs in `ui/src` and `pwa/src`: the popover is non-modal, and vaul is imported only by
the two. This was found by a code search, so it is **inferred**.

A page-hidden node that a modal marked was recorded as the page's by the first layer that saw it unmarked, and every
later layer takes that record in while that first layer is mounted. If the first layer unmounts first, the marked node
loses its mark (the undo removes the mark when no modal holds the node any more) and reads as unmarked again. So the
answer is what the page hid, whatever the tree order and whenever the read runs, as long as it runs before this layer's
own `hideOthers`. A layer is forgotten at the next record once its panel has left the document. Until then the record
holds the detached panel and its set, one entry per layer, as `readFor` did one per Sheet in round 1 (review 2334 F6).

**What the rounds before it read, and what each cost.**
- C38 read only the unmarked nodes, so a page-set node another modal had marked was lifted for good (reviews 2310 F2 and
  F1).
- The first build (277ef2d80) read every hidden node in the `open` effect. On the session screen the follow-up sheets
  are rendered before the menu sheet, and React runs passive effects in tree order. So the follow-up read while the
  menu's marks were still on, and kept the page hidden through its own exit. Review 2323 measured that window in
  Chromium at 335 ms at 390 and 140 ms at 1280, against 6 to 8 ms on `main`.
- Round 1 (b7dcaa09d) read every hidden node in the panel's ref. That fixed the tree order, but it still took a mark of
  another modal, still on the page at the panel's mount, for the page's own. Two such marks are measured below: the
  palette's, which never lifts its marks, and a sheet's closed under this one by code while this one stayed open
  (review 2334 F1 and F2). Each kept the page hidden through the sheet's exit.

**The read point.** The read runs in the panel's callback ref. Radix mounts a dialog's content at least one commit after
`open` turns true: its portal mounts first, and for a Root that mounted closed, its presence does too. So the ref runs
in a layout phase before Radix's own passive `hideOthers` marks anything for this layer. This ordering is **inferred**,
verified from the installed sources (React 19.3.1, react-dialog 1.3.1, react-portal 1.2.0, react-presence 1.1.11,
vaul 1.1.2, aria-hidden 1.2.6, review 2334). Its effect is **measured** in jsdom and in Chrome, below.

React's StrictMode (`pwa/src/main.tsx` renders the app in it) calls a newly mounted element's ref callback a second time
in development, after its effects (review 2334 F3). Round 1's `readFor` guarded that second call, and its comment named
the wrong cause, "a new callback identity". The record needs no guard: a second record takes in the first, so it can only
grow. The StrictMode rows below pin it.

**What changes and what does not.**
- **Every route measured** announces the page as the sheet closes, as `main` does, and never lifts an element the page
  hid itself. **Measured** in jsdom: the menu's hand-off in both tree orders and under StrictMode; the palette's hand-off
  in both tree orders, with the palette closing or gone; a layer an effect closes one commit after the sheet under it.
  **Measured** in Chrome: the menu's hand-off and the palette's, below.
- **Single-sheet callers with no overlapping exit** behave as before. With no other modal mounted, the record is C38's
  read. **Inferred** from the code. The C38 rows pin it: `sheet-trap-hide.test.tsx` §1's C38 rows and
  `confirm-focus.browser.test.ts`, all green.
- **Two, three and four deep** keep C38's rule: the topmost-open-dialog filter keeps the page and every dialog under the
  topmost one hidden. **Measured** at two and three deep, and the three-deep row is also asserted after the confirm
  unmounts (review 2310 F3). Four deep is **inferred**, the same rule one level up; review 2334's probe measured it on
  round 1.
- **No cost is known now.** Round 1's two disclosed costs are gone. A dialog open under this sheet that closes before it
  is the effect-driven row, green. The command palette is the palette rows, green in jsdom and in Chrome.

lifted the mark, because this sheet was the topmost open dialog under it. When both close in one commit, whichever lifts
second finds the mark already lifted. The arm is redundant with the topmost filter. **Inferred** from the code; M6
measured no row.

mounted, closing, when the swap sheet opens, and its marks are still on.

**Where an element the page hid itself sits on a path Radix marks.** The `aria-hidden` package keeps visible the path
to the dialog and to every `[aria-live]` element (and `script`), and it marks each sibling along those paths. It does
not keep `role="status"` or `role="alert"`. This was read from its source. So an element the page hid itself is at risk
only when it is a direct child of `body`, or a direct child of an ancestor of a live region.

The live regions in `pwa/src` outside a sheet were found by a code search, so this list is **inferred**:
- the code block's Copy label (`markdown.tsx`);
- the timers line (`session/TimersSection.tsx`), which the session screen renders too;
- `ResultLine` (`fleet/settingsText.ts`), under settings controls and in the home screen's halt banner;
- the highlight measure (`screens/HighlightMeasure.tsx`);
- the reader lab (`screens/ReaderLab.tsx`).

The others found sit inside sheets (`MoveSessionsSheet`, `WorkspaceNameField`).

**Measured** in Chrome on the session screen, at 390 (Refined) and 1280 (Instrument), with one transcript holding a code
block and no timers, with the menu open: the menu marked the containers along the path to the Copy label, and **none**
of the elements the page hid itself. So F2 is not reached on that page with that transcript. Another transcript, the
timers line, or a page with an `aria-hidden` element beside such a path is not measured.
