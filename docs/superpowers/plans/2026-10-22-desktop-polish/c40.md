Every claim below is labelled **measured** (a run whose result is quoted or summarised here) or **inferred** (read from

## The gap

C38's `useHidingFollowsOpen` (`ui/src/primitives/sheet.tsx`) lifts the marks Radix made as a sheet turns closed, and
leaves alone the elements the page hid itself. It read those as the sheet opened, as
`[aria-hidden="true"]:not([data-aria-hidden])`: a hidden node with no Radix mark.

The `aria-hidden` package (read from its source, `aria-hidden/dist/es2015/index.js`) marks a node that is already hidden
as **uncontrolled**: it adds its `data-aria-hidden` mark and leaves the `aria-hidden` as it was. Its undo never removes
`aria-hidden` from an uncontrolled node. So when a dialog that is still mounted (closing, or open under this one) has
already marked an element the page hid itself, that element carries the mark when the next sheet opens. The next sheet
did not count it as the page's own, lifted it as it closed, and Radix's undo never put it back. It stayed announced for
good.

- **F2, no stack.** A sheet opens while the one before it is still in its exit: a menu sheet whose row closes it and
  opens the next in one commit. **Measured** in jsdom, `pwa/test/sheet-trap-hide.test.tsx`'s row "a sheet opened while
  the previous one closes …". On `main`, a body-level `<div aria-hidden="true">` reads `null` once the second sheet
  closes (`the closing sheet lifted an element the page hid itself: expected null to be 'true'`). It still reads `null`
  after both sheets have unmounted (`… was left announced for good`; measured with that row's first assertion commented
  out). Load average 18.
- **F1, stacked.** Two confirms overlap over a sheet that holds a live region, so Radix marks the sheet's children,
  including an element the sheet hid itself. The `top.contains(node)` arm lifted it. **Measured** in jsdom, the row "a
  confirm opened while another closes, over a sheet with a live region …". On `main`, the sheet's
  `<span aria-hidden="true">` reads `null` as the second confirm closes, and still `null` after both confirms have
  unmounted.

## The fix

The fix is at the owner, `useHidingFollowsOpen`, once. The sheet reads every node already hidden, `[aria-hidden="true"]`
with or without a mark, and it never lifts one of those, whoever hid it. Only marks its own open added are lifted. The
rest of C38's rule is unchanged: the topmost-open-dialog filter, the reopen during the exit, and the focus guards.
Departure `c40-lift-only-own-marks`.

**Where the read happens (fix round 1, review 2323 F1).** The first build read in the sheet's `open` effect. React runs
passive effects in tree order, and on the session screen the follow-up sheets (swap, archive, terminal, history,
browser, the pickers, reap) are rendered before the menu sheet. So the follow-up's read ran while the menu's marks were
still on, and the menu's lift ran after it. The follow-up took the page's containers for already hidden and kept them
hidden through its own exit. Review 2323 measured that window in Chromium at 335 ms at 390 and 140 ms at 1280, against
6 to 8 ms on `main`.

The read now runs in the panel's callback ref at mount. Radix mounts a dialog's content one commit after `open` turns
true, because its portal mounts first. So the ref runs after the passive effects of the commit that opened the sheet,
where a sheet closing in that same commit lifts its marks, whichever comes first in the tree. It runs in the layout
phase, before Radix's own passive `hideOthers` marks anything for this sheet. The order is **inferred** from React's
and Radix's code. Its effect is **measured** in jsdom and in Chrome, below. A ref re-attached to the same element
(a new callback identity) reads nothing; only a newly mounted panel does.

- **Single-sheet callers with no overlapping exit** behave as before. With no other dialog mounted, the only hidden nodes
  at the panel's mount are the page's own, the same set the old read took. **Inferred** from the code. The C38 rows pin
  it: section 1's C38 rows of `sheet-trap-hide.test.tsx` and `confirm-focus.browser.test.ts`, all green.
- **The hand-off in either tree order** announces the page as the follow-up closes, as `main` does. **Measured**:
  - jsdom: "a sheet opened while the previous one closes" (closing sheet first in the tree) and "a sheet opened earlier
    in the tree than the one closing" (opening sheet first) are both green.
  - Chrome: the real session menu's hand-off. The follow-up sheet is earlier in the tree there, and the browser rows
    below are green.
- **Two, three and four deep** keep C38's rule. A confirm opening over a sheet finds the page already hidden by that
  sheet, so it never lifts the page; it lifts only its own mark over, or inside, the sheet under it. **Measured** at two
  and three deep: the two- and three-deep rows and the live-region row are green, and the three-deep row is also asserted
  after the confirm unmounts (F3). Four deep is **inferred**: it is the same rule one level up. Review 2323's probe
  measured it on the first build.
- **What it still gives up.** A dialog that hides the page and is still hiding it at this sheet's mount keeps it hidden
  through this sheet's exit. Two cases are known:
  - **A dialog open under this one that closes before it** (review 2323 F5). Sheet A is open; a sheet opens over it; A is
    closed by code while the top one stays open; then the top one closes. The page A had hidden was hidden at the top
    sheet's mount, so the top sheet never lifts it, and the page stays hidden through the top sheet's exit. **Measured**
    in jsdom with a probe row on this round's fix: red (`expected true to be false`). It is not kept in the suite,
    because it pins a cost, not a rule. Its reachability in the app is **inferred** rare: `SwapSheet` and
    `SessionActionsSheet` clear their confirms when the sheet under them closes.
  - **The command palette.** It is a vaul drawer, not a `Sheet`, so it never lifts its marks during its exit. A sheet it
    hands to finds the page hidden at its mount. **Inferred**, not measured.

  Both are `main`'s behaviour before C38, bounded by the exit. Nothing is left hidden for good: Radix's undo removes
  those marks at the unmount. The brief ruled that safety comes first.

second finds the mark already lifted. The arm is redundant with the topmost filter. **Inferred** from the code; M6

**Where an element the page hid itself sits on a path Radix marks.** The `aria-hidden` package keeps visible the path
to the dialog and to every `[aria-live]` element (and `script`), and it marks each sibling along those paths. It does
not keep `role="status"` or `role="alert"`. This was read from its source. So an element the page hid itself is at risk
only when it is a direct child of `body`, or a direct child of an ancestor of a live region.

The live regions in `pwa/src` outside a sheet were found by a code search, so this list is **inferred**:
- the code block's Copy label (`markdown.tsx`);
- the timers line (`session/TimersSection.tsx`), which the session screen renders too;
- `ResultLine` (`fleet/settingsText.ts`), under settings controls and in the home screen's halt banner;
- the highlight measure (`screens/HighlightMeasure.tsx`);
- the reader lab (`screens/ReaderLab.tsx`).

The others found sit inside sheets (`MoveSessionsSheet`, `WorkspaceNameField`).

**Measured** in Chrome on the session screen, at 390 (Refined) and 1280 (Instrument), with one transcript holding a code
block and no timers, with the menu open: the menu marked the containers along the path to the Copy label, and **none**
of the elements the page hid itself. So F2 is not reached on that page with that transcript. Another transcript, the
timers line, or a page with an `aria-hidden` element beside such a path is not measured.
