### Item 3: the second cause, found by CI

The pull request's full run on `6245d66df` (run 42673038502, attempt 2) failed F9 once more, on the same line:
`delegation pass slow: block=180001 cut=0 … flush=180001`. F9's own pass could not have written it: `closeDelegation()` had
aborted every pass of F9's watcher (its line would read `cut=1`) and refuses a new one. The line came from an EARLIER
case's watcher. No case in the file quieted its watcher, so a pass one case started could still be in its flush when F9
mocked `Date.now` forward by the grace. That flush then measured exactly 180 001 ms. The fixture's watcher is now
`quietAtTestEnd(…)`, so every case drains its own passes before the next case starts. F9 keeps its `closeDelegation()` for
the pass its own setup starts.

A scratch probe (never committed) put a case before F9 whose watcher holds its durable apply until `Date.now` reads F9's
mocked instant. On the old file that pass was released inside F9's window in 3 of 3 runs (CI's `flush=180001` exactly).
On the fixed file it was drained in its own case's teardown in 3 of 3. Unprobed, the file passed 20 of 20 runs under two
busy loops both before and after (the race needs CI's load). The before count for this cause is CI's: 1 of the 2 full runs
on this branch.
