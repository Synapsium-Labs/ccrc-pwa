# C7: the chat's rows are memoised, and markdown and highlighting are cached (D-6439)

The task note for the programme ledger (Task C7 of `docs/superpowers/plans/2026-10-22-desktop-polish.md`). The
coordinator folds it into the ledger; this file edits no ledger row.

## What changed

- `pwa/src/session/sameRow.ts` (L1, `import type` only). `sameTranscriptItem(a, b)` checks kind and key, then every
  own field by `Object.is`. Two fields are read off the item's event, so they are compared through `event` alone:
  `mail`'s `envelope` and `task`'s `notification`. A `tool-group`'s `entries` are compared element by element, by the
  same rule. `sameRowProps(a, b)` compares the item by `sameTranscriptItem` and every other prop by identity.
- `pwa/src/lib/highlightCache.ts` (L1, imports nothing): `createLru(maxEntries, maxWeight, weigh)`. It drops the least
  recently used entry first, never keeps an entry heavier than the weight bound, and has `clear()`.
- `ChatList.tsx`: `MeasuredItem` draws its row itself (`TranscriptRowView`) from the row's props, behind
  `memo(…, sameRowProps)`. This is the one row barrier. `computeItemKey` and `itemContent` are `useCallback`s.
- `MessageBubble` and `ChatMarkdown` are `memo`. Chat's remark plugins are one module constant.
- `markdown.tsx#boundedHighlight` takes its markup from a module-scope `createLru` (256 entries, 4,000,000 characters
  of markup), keyed by `lang` and `raw`. The cache is asked only after every bound has passed, so a refused block is
  never highlighted and never cached. The cache is shared by chat fences, T4a's tool wells (`ToolWellText`, which
  calls `boundedHighlight`) and the Docs reader's `CodeBlock`. T4a's routing is unchanged: the ANSI reader never
  highlights, and `ignoreIllegals` makes the markup a function of the pair.
- `SessionScreen.tsx`: `onRetry`, `onDiscard` and `onAnswer` are `useCallback`s. They are now at the screen's state
  block; the plan's ≈:621-625 had moved to ≈:644-657 by T1c and T3e.

## Departure (named for the coordinator to number)

`c7-reset-seam-for-call-counting-suites`. The cache outlives a test case, and two existing suites counted
`hljs.highlight` calls as a stand-in for "this block was highlighted":

- `markdown-bounds.test.tsx`'s `spyHighlight` answers `''`. The cache stored that answer for an 8,192-character ts
  block one case rendered, and the worker-path case on the same block then saw 0 calls.
- `docs-highlight-budget.test.tsx`'s `run()` asks whether hljs saw each block, and page G repeats page S's 48 fills.

Neither file is in C7's Files. The operator ruled on C7's structured ask: a reset seam. `markdown.tsx` exports
`resetHighlightCache()` (as `lib/seen.ts`'s `resetAcks` does). `markdown-bounds` calls it in `afterEach`,
`docs-highlight-budget` at the start of `run()`, and `markdown-highlight` in `afterEach`. No assertion changed.

## Residuals

- `renderToolWell(use)` returns a new function on every call, so `ToolCard`'s `renderWell` is not identity-stable. It
  is built inside the row, so the row barrier covers it, and C7 leaves it alone.
- The row barrier compares a field added to an item later by identity. That is the safe direction: at worst the row
  renders again.
- A suite that mocks `hljs.highlight` and does not call `resetHighlightCache()` can see a pair an earlier case cached.
  The three suites that count or mock it now reset it.
