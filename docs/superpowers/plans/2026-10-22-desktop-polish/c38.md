## Found while building

- **The first build broke a later open (fixed before any push).** It put the lifted marks back on every open, not only
  on a reopen during the exit. Once the panel has gone, Radix hides afresh a pass after the Sheet's effect, so a mark
  put back first read to Radix as the page's own, and Radix's undo never cleared it: the page stayed `aria-hidden` after
  the sheet's next close. `remove-sheet.browser.test.ts` caught it (16 rows timed out finding a button under a hidden
  root, **measured**; green on `main`). The fix puts marks back only while the panel is still mounted; the new browser
  row reds under the first build's code (M12). jsdom does not order Radix's hiding after the Sheet's effect as Chrome
  does, so this row lives in the browser leg only.
- **Stall watch's row about the keyboard preview** (`settings-screen.test.tsx`, "a cancelled confirm or a refused write
  leaves the full sentence on the checked level") went red when the focus first came back to the tapped radio: the
  preview follows the focused option. That is why a radio opener goes home to its group's checked radio (5 (b)).
- **Shadow lanes' browser row leaned on item 1.** On `main`, `live.isChecked()` could not find the radio while the page
  was `aria-hidden`, so the confirm had always gone by the row's "no dialog" check. With the page announced the radio is
  found at once, while the confirm still animates out, and the row saw it (8 views red, **measured**). The row now waits
  for the confirm to leave before its keyboard step; what it pins is unchanged. Departure
  `c38-shadow-lanes-row-waits-out-the-exit`.
