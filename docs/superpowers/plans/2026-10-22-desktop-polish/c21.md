# Task C21: a chat PR or commit opens the repository the message means, or stays text (D-8172)

Receipts for Task C21, 2026-11-10. The task's section and D-8172's definition are in the plan; the spec carries the rule as
R15 (`docs/superpowers/specs/2026-11-06-chat-reading-design.md`, section 6).

## What was chosen

- **Rule 1 is grammar.** `chatMarks.ts` recognises `owner/repo#n` as a `pr` mark with an optional `repo` field, written by the
  plugin as `MARK_ATTR.repo` (`data-mark-repo`) and read back by chat's `span` arm. It is tried only where a document path
  may start, so it is never the tail of a path or a host (`x/a/b#1`, `github.com/a/b#1`). The segment patterns
  (`GITHUB_OWNER_PATTERN`, `GITHUB_REPO_PATTERN`) are deliberately wider than the console's one GitHub grammar
  (`parseGithubRepo`), which alone decides whether a match is a repository. A match it refuses (`--a/b#1`) opens
  nothing. This keeps a single copy of the grammar: the literal census refused a second copy of `parseGithubRepo`'s
  repository pattern.
- **Rules 2 and 3a are one pure L1 module, `pwa/src/lib/chatRepoEvidence.ts`.** `messageRepos(text)` reads the whole raw
  message, including code spans, link targets and fenced code. It returns each repository named (`github.com/<o>/<r>...`
  or `<o>/<r>#n`), the repositories named per PR or issue number, and the commit addresses. It runs at render time:
  `ChatMarkdown` memoises it per text and provides it through `MessageReposContext`, and `linkify` reads it once per call.
  It is never in the parse worker's closure.
- **Rule 3b is one boolean, `ChatRefContext.runsElsewhere`.** `claimsRunElsewhere` (L1, in `chatRefs.ts`) asks
  `claimedRunsOf`, the existing coordinator-side reader, for the session's open runs. Any of them whose project has no
  `named` repository, or a different one, counts. So does every claimed open run before the projects read lands (what
  cannot be shown to be home is not home). `SessionScreen` selects it as one boolean from the fleet store, so a runs
  or projects frame that does not change the answer changes no context.
- **`refHref` takes the message's evidence as a required third argument**, so neither renderer can forget it. Repository
  comparison is by `repoKey`: `readRepo`'s owner and name (`parseGithubRepo` after one trailing-dot trim) in lower case, `.git` dropped.

## Fix round 1 (review 1758, ruled FIX)

- **F1.** The host match ignores case. An address shaped like a GitHub page whose owner or repository `parseGithubRepo`
  refuses (`github.com/o_o/r`, `github.com/o/-r`, `repo.git.git`) is an UNKNOWN repository: it is never linked to, and it
  counts as "another repository", so a bare name beside it stays text.
- **F2.** These name a repository too: the SSH form `git@github.com:o/r`, `api.github.com/repos/o/r`,
  `raw.githubusercontent.com/o/r`, `codeload.github.com/o/r`, and `gh … --repo o/r`, `--repo=o/r` or `-R o/r`, read up to
  the command's end at `;`, `&`, `|` or the line's end. Two of them are also evidence for a number:
  `api.github.com/repos/o/r/(pulls|issues)/n`, and a `gh pr|issue <verb> n` command with that flag. Prose such as
  `#12 in o/r` stays out.
- **F3, option (b).** A qualified name is refused when:
  - its repository ends in a `FILE_EXTENSIONS` entry (`chatMarks.ts`, defined once);
  - its owner or repository is all digits or one character;
  - both segments are upper case only.

  The evidence reader asks the same walk (`qualifiedNames`), so it refuses the same names. The review's link and stay-text
  lists are a table test. R15 states the residual: a prose pair such as `client/server#1` still links.
- **F4 and F5.** `readRepo` (`chatRepoEvidence.ts`) is the one reader that every address and every key is built from. It
  trims trailing dots once, with a linear backward scan; the quadratic `/\.+$/` replace is gone. Commit addresses are indexed
  once per message by their first seven characters, so a commit name asks only the addresses that share its prefix. Budget
  pins:
  - 800,000 dots: under 2 s;
  - 1 MiB of addresses: under 3 s;
  - 20,000 commit names against 20,000 addresses: under 3 s.
- **F6.** `wordBefore` and `wordAfter`, exported from `chatMarks.ts`, are the one boundary. The evidence reader takes
  qualified names from the grammar's own walk and ends a page's number or SHA at that boundary.
- **F7, recorded.** Rule 2's scope is one chat event: an address in one message is no evidence for a name in the next.
  R15 says so.
- **F8.** The spec now carries:
  - §4.1: the PR and commit rows, the grammar, and "a repository the code can tell is required";
  - §4.2: `refHref`'s home and its third argument, and `data-mark-repo`;
  - Figure 3: the message evidence and `runsElsewhere`;
  - R15, reworded, with the residual and the scope;
  - the Agreed list, which now includes R15.
- **F9.** The `www.` arm, two code spans naming two repositories, and a render-count test (another session's runs frame
  asks `refHref` zero times) are pinned. The dead code is gone: `named()`'s `.git` strip, `(?!\d)` and `home === null ||`.
  `claimsRunElsewhere` now reads `key === null || key !== home`, which is live only for a null home, and a decider test pins
  that case.

## Fix round 2 (review 1760, ruled FIX)

- **F7: one reader decides.** The F3 exceptions moved out of the grammar into `chatRepoEvidence.ts` (`qualifiedRepo`), and
  they are asked of the repository `readRepo` read, after its trim of trailing dots and `.git`. The grammar now recognises every
  `owner/repo#n` shape, and the one reader decides whether the chat can tell it. Rule 1 (`chatRefs.ts#repoPage`) and the
  evidence ask the same function. Side effect: `abc1234/x#5` is now a qualified name the chat cannot tell (text), where round 1
  read it as a commit.
- **F2 (a).** A qualified name the exceptions refuse is an UNKNOWN repository. It stays text, and so does its bare sibling:
  `config/app.yml#3 then #3` and `vercel/next.js#123 … #123` are text, while `vercel/nextjs#123 … #123` links both.
- **F3.** `FILE_EXTENSIONS` (a set, defined once, now in `chatRepoEvidence.ts`) gained the ruled list. §4.1 and R15 say
  "a listed file extension", and that a prose pair still links and may open a real but unrelated page.
- **F1: the `gh` reader is a small tokenizer** (`ghWords`, `ownWords`, `ghCommand`):
  - A command ends at a backtick, a line break, `;`, `&`, `|`, the next unquoted `gh` word, or a comma or full stop followed
    by a space.
  - It also ends at the first bare word past its positionals: `gh pr|issue <verb> <n>` has three and `gh api <path>` two.
    A word after a flag with no `=` is read as that flag's value. This bound is what ends `gh pr view 12 then cp -R o/r`,
    which no character does.
  - Quotes group a word, so `--body "see -R o/r"` holds no flag. A word that is exactly a quoted flag (`'-R'`) is that flag,
    as the shell passes it.
  - The LAST flag wins.
  - The number is the command's third positional, wherever its flags stand.
  - A flag reaches only its own command's number, and two commands naming two repositories for one number leave it text.
  - All seven reproductions are pinned, with `cp -R` and `grep -R`.
- **F4: the grammar reads a qualified name's boundary from the source.** `remarkChatMarks` receives the message's source
  (react-markdown and the parse worker both pass it). A qualified name at a text node's start or end is text where the source
  has a word character right before or after the node (`edgeQualified`). So under `_` or `__` neither reader counts it, and
  under `*` both do. Pinned through `ChatMarkdown` on the sync and worker paths, the after-side alone included
  (`_see owner-b/repo-b#12_`).
- **F5.** A letter, digit or `_` directly before a schemeless host names an unknown repository (text). The `égithub.com` pin
  changed to text, and CJK rows were added.
- **F6, partly.** Read now: `gh api repos/o/r/(pulls|issues)/n` with or without its leading slash (evidence), and
  `GH_REPO=o/r` (names a repository). The `gh` word starts at the shared boundary (`wordBefore`). Not read, and listed in R15:
  - a glued `-Ro/r`;
  - `gh repo clone o/r`;
  - a backslash continuation;
  - prose such as `#12 in o/r` or `In o/r, #12`;
  - `gitlab.com` and other hosts.
- **F8.** "Names another repository" is `namesOtherThan`: the set's size, the same cost for every bare name.
- **F9.** Commit addresses are kept once per (repository, SHA) inside each seven-character bucket.
- **F10.** The budget pins and their measured margins are listed under Measured below.
- **F11.** §4.2's sentence and Figure 3's tree node now carry `data-mark-repo`.
- **F12.**
  - The stale `chatMarks.ts` comment is fixed.
  - "Never a wrong repository" is gone from `chatRefs.ts` and the test header.
  - `GITHUB_OWNER_PATTERN`, `GITHUB_REPO_PATTERN`, `FILE_EXTENSIONS` and `SaidRepo` are no longer exported.
  - `HOST_START` is `(?<![.-])`.
  - `reposFor` takes `kind: 'pr' | 'commit'`, so the unreachable branch is gone.
  - The null-home term stays.
  - `server/test/single-definition/chat-marks.test.ts` now pins `FILE_EXTENSIONS`, `messageRepos`, `readRepo`,
    `qualifiedRepo` and `namesOtherThan` to `chatRepoEvidence.ts`, and `claimsRunElsewhere` to `chatRefs.ts`. It is the
    right home: that census already pins chat's recogniser and resolver, and these are the resolver's readers.

## The residual

Rule 1 follows GitHub's own `owner/repo#n` notation without checking that the repository exists. So a prose pair that is not
refused, such as `client/server#1`, `and/or#3` or `src/thing#12`, links to `github.com/<a>/<b>/issues/<n>`: a page that may
not exist, or a real but unrelated one.
