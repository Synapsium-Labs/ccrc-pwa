## The frame-cost harness

- **The initial-read oracle (review 952 F2).** Self-test case 1 now asserts that the event that released its held gate
  came after this request's `fulfil-start` (log order), with the two earlier `readA`s as a non-vacuity precondition.
  The early-arm mutant (the listener's arm removed) reds it on its own message. The old count assertion passed under
  that mutant.
- **Records on a failed attempt (advisory 1).** `frameCost` fills an optional `record` window by window, and a gate case
  keeps it through vitest's finish hook. So a rejected attempt and a vitest timeout both keep the windows measured
  before the failure. The body's `finally` ran too late on a timeout: a measured gate run lost its record that way.
- **The span (advisory 2).** Each window's wall span, from its first read to its second, is measured (`spans`, and
  `spanMs` in the record) with its wall-clock start (`atMs`), and the docs no longer say a window is "2 s".

## The A2 reds: explained by measurement, not by cause

- **The retained 2026-10-25 records.** Both failed cases change regime partway through: windows of 85-365 ms
  TaskDuration, then 2-17.6 s. A window's TaskDuration above 2000 ms cannot fit a 2 s span, so those spans ran far past
  their gap.
- **This run, with host pressure sampled each second.**
  - A gate case timed out (vitest's own 190 s) during an interval in which the fleet box's shared session memory sat at
    its limit. Memory full-stall ran 275-703 ms per second, and the box's load rose from 24 to 120.
  - Across two gate runs (M1 and M2), 132 windows ran 4-56 ms past a 2 s gap: M1's 74 windows ran 4.8-15.6 ms past it and
    M2's 58 ran 4.4-56.1 ms past it. M2 is the run in which the Instrument ceiling case, the third of its four gate
    cases, timed out; the 58 are the windows of its other three cases (the timed-out case has no record in that run).
- **The ruled change: the overrun refusal.** This run's structured ask was answered "Overrun refusal". A window whose
  span passes `gapMs + 1000` ms (`SPAN_SLACK_MS`) now fails the attempt as `window-overrun`, a named harness failure,
  never a cost figure. The overrun window is kept in the record. The refusal applies to every window, the idle one and
  the self-tests' included.
  - Pinned by two self-test cases: window 0 overrun, and the idle window overrun through `during(-1)`.
  - Their mutants are a bound that never trips, the throw before the record push, and the idle window skipped.
  - Threshold, frame counts, medians, gap, caps and budgets are unchanged.
  - Departure slug: `frame-cost-window-overrun`.

- **The reading, as correlation only.** The same deterministic work ran slower in the repeat that caught the spike, on
  a box whose CPU pressure was high, and the app's own tick and a poll's render also fell inside identical windows.
  Which of these moved the identical frames' median past 35% of the changing median was not measured, and no cause is
  established.
- **What it leaves.** The ratio case can red with no window overrun, as it did here while the box's CPU pressure was
  high. CI's runner is the arbiter.
