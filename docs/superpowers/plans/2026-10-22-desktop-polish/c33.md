## The guard

A new describe at the end of `server/test/deviation-refs.test.ts`, "every definition-shaped line is one the ledger
reads (Task C33)":

- **The shape** is `^- \*\*D-(\d+)\*\*`: a bullet whose bold closes right after the number, at column 0. It is narrower
  than the floor scan's `DEFINED` prefix, so bolded citations such as `- **D-149 sweep:**` and `- **D-1039..D-1045**`,
  which the corpus rows pin as citations, stay out.
- **Fence-aware without a second fence parser.** A candidate line is replaced by `- **D-N** — probe` with its own
  number, and the file is read again with `definitionsIn`. If that adds a definition of N, the line sits where the reader
  looks, and it is flagged. A line inside a fenced block adds nothing, so it is a quotation and is skipped.
- **`UNREAD_BASELINE`**, file to numbers, holds the lines other plans hold today. It is compared as a multiset in both
  directions: a line beyond it reds ("write the entry readable"), and a member that no longer stands unreadable reds ("delete
  it from the baseline"). So it may only shrink.

**Measured, red first.** With the guard committed and the plan not yet converted, the first case failed and listed the
112 numbers in `2026-10-22-desktop-polish.md`, and nothing else.

**Measured, with one entry put back.** On a throwaway local commit that restored `- **D-7257** - `, the case failed with
exactly `2026-10-22-desktop-polish.md: D-7257`. The commit was then dropped (`git reset --keep` to the tip before it).
