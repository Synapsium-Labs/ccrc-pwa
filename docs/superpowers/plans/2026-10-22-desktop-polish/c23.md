## What turns from a link to text

Each is a fail-safe cost of a ruling above:

- Item 1: a numberless command's flag is a candidate for every number, so `gh pr list -R owner-b/repo-b; gh pr view 13 -R
  owner-c/repo-c; #13` gives text where it opened owner-c. A flag naming the number's own repository leaves one
  (`… gh pr view 13 -R owner-b/repo-b; #13` opens owner-b).
- Item 3: `gh pr view 12 --title GH -R owner-b/repo-b and #12` was a correct owner-b link on main and is text now (the
  brief accepts this cost), and so is `gh pr view 12 -R owner-b/repo-b --title GH and #12`.
- Item 6: a commit address beside an unrelated net flag in a `gh` message gives text
  (`https://github.com/owner-b/repo-b/commit/1234567abc; gh pr list; cp -R owner-c/repo-c /x; 1234567abc`).
- Item 7: a value cut at the next flag that named home no longer opens home (`gh pr list; -R org-a/project-a.-R=…; #12`).

## What turns from text to a link

- Item 2 only: a continued command's flag is now its own, so `gh pr view --repo owner-b/repo-b \` then `12`, then `#12`,
  opens owner-b, as do C22's continuation rows (`gh pr view 12 \` then `--repo owner-b/repo-b`; `gh api \` then
  `repos/owner-b/repo-b/pulls/12`), which were text. Four existing pins changed from text to owner-b, each with a comment
  naming this ruling. Every such change in the fuzz is main's own answer once the continuation is read as a space.

## Departures

- `numberless-read-flags-too`: item 1 is read literally. A numberless command claims none of its repository flags, the ones
  it read as well as the ones it lost, because P2's shape (`gh pr merge -s 12 -R o/r`) reads its flag and has no number. The
  cost is the first "link to text" row above.
- `api-path-claim-unchanged`: a `gh api` path is no repository flag, so a path its command read stays that command's
  whether or not it gives a number (pinned; M17).
- `cut-number-always-unknown`: a cut command gives its number to an unknown repository even where it names none, unlike a
  command voided by an open quote, which is decided as if absent when it names none (C20's review 1766 F1 stands).
- `continuation-not-in-the-net`: the net's value reader does not skip a continuation (`-R \` then `o/r` on the next line
  names an unknown repository there). It only adds a repository the chat cannot tell, so it fails toward text, and the
  command reader reads the flag as its own.
