## F1: the shape and the fix

**The shape** (review 2343 F1, hand-traced against `aria-hidden` 1.2.6). The page hides a body-level node X. Layer A
mounts, records X as the page's own, and A's Radix marks X as uncontrolled: it adds `data-aria-hidden`, leaves the
page's `aria-hidden`, and its undo will never remove that attribute. The page then removes X's `aria-hidden` while A is
open. Layer B mounts while A is still mounted (the hand-off, in either tree order, or B over A with A then closed by
code). C40's record took X in from A's set as the page's own, B's Radix set `aria-hidden` on X again, B never lifted X
(it is the page's own), and the package kept A's uncontrolled flag, so its undo never removed the attribute. X stayed
hidden after every dialog had unmounted.

**The fix** (`ui/src/lib/modal-layers.ts`, `recordModalLayer`). A node inherited from another layer's record stays in
the new layer's page-own set only while it still carries `aria-hidden="true"` at the record. X, which the page un-hid,
is no longer the page's own to B, so B lifts it as it closes, like any other mark: it is announced through B's exit, and
after the unmount the package's undo has nothing to undo on it. **Measured**: the six F1 rows below.

**Why the C40 shapes still hold.** In every C40 shape the page never un-hides the node it hid, so at each record that
node still carries `aria-hidden="true"` (the page's own, kept as the package's uncontrolled node) and the filter keeps
it. The record's first part (hidden nodes no modal has marked) is unchanged, so a single sheet's record is C38's read as
before. **Measured**: all 25 C38 and C40 rows green with the fix, and C40's mutants R1 and M7 still red (below).
**Inferred** from the code: no caller changed; `graphify query` and C40's search name `sheet.tsx` and
`command-palette.tsx` as the record's only callers.

**One shape still open, and open before C40 too** (departure `c42-reverse-close-residual`). The page un-hides X while A
is open, B opens over A (A stays open, and B's Radix hides X again), B closes, then A closes. A recorded X as the page's
own at its mount, when it was, so A's close leaves it; the package's uncontrolled mark keeps the `aria-hidden` after both
unmount. **Measured** with a temporary probe (removed before commit), each run of it ending `{ during: 'true', after:
'true' }`: at C42's tip, at 6c2d705d2 (C40) and with f8251a39d's `sheet.tsx` (before C40), load 8.8 to 9.1. Telling the
page's re-hide of a node from a modal's needs more than the record holds, so it is left. No route in `pwa/src` or
`ui/src` reaches it (**inferred**, review 2343's refuter 2: no site toggles `aria-hidden` on a node `hideOthers` visits).

## F2: the prune

Removing `if (!known.isConnected) layers.delete(known)` kept sheet-trap-hide green at C40's tip (review 2343, lens 1).

**The brief's sequential shape no longer needs the prune** (departure `c42-prune-row-via-palette`). With F1's filter in,
sheet A, then the page un-hiding X, then sheet B: X carries no `aria-hidden` at B's record, so the filter leaves it out
whether or not the record still holds A. **Measured**: that shape as a temporary probe stayed green under mutant MF2
below (load 7.7).

**The row instead** goes through the palette: sheet A comes and goes while the page has X hidden, so A's record holds X;
the page un-hides X; the palette (which hides X, and never lifts its own marks) hands off to sheet B. At B's record X
carries the palette's `aria-hidden`, so only a record still holding the gone A takes X for the page's own. B must lift X
through its exit. **Measured**: the row is red with the prune removed (MF2), green with it.

## F3: the reopen

A live region keeps the palette's hiding on the page's children rather than the page; the page drops it while the
palette is open; the palette hands off to a sheet; the sheet closes, lifting the palette's marks on those children too;
the palette's exit ends, and its undo takes its marks off; a reopen during the sheet's exit put `aria-hidden` back on a
child no modal marked any more, which no close lifts and no undo removes. **Measured** red at 6c2d705d2 (`the sibling is
still hidden as the reopened sheet closes`, and after every unmount `a reopen left the sibling hidden with no mark, for
good`), as review 2343 measured on `main` before C40.

**The fix** (`ui/src/primitives/sheet.tsx`, `useHidingFollowsOpen`): a reopen puts back only the lifted nodes that still
carry `data-aria-hidden`. It fits in `sheet.tsx`, and it changes what a reopen hides in no C38 or C40 row: section 1's
first row (the reopen during the exit) and every other row stay green (**measured**). The sibling stays hidden while the
reopened sheet is open, through its parent, which a modal still marks (the row's control).
