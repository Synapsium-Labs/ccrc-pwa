## F1: the shape and the fix

**The shape** (review 2343 F1, hand-traced against `aria-hidden` 1.2.6). The page hides a body-level node X. Layer A
mounts, records X as the page's own, and A's Radix marks X as uncontrolled: it adds `data-aria-hidden`, leaves the
page's `aria-hidden`, and its undo will never remove that attribute. The page then un-hides X while A is open. Layer B
mounts while A is still mounted. C40's record took X in from A's set as the page's own, B's Radix set `aria-hidden` on X
again, B never lifted X, and the package kept A's uncontrolled flag, so its undo never removed the attribute. X stayed
hidden after every dialog had unmounted.

**The first build (296a56403)** left X out of B's set while X carried no `aria-hidden="true"` at B's record. Review 2353
measured where that was not enough (F1), each shape red at 296a56403 in this round's rows (**measured**, and again as
MF4 below at load 5.7):
- **StrictMode** (the app runs in it in development). B's second ref call comes after B's Radix undo, but A still
  counts X, so B's own `aria-hidden` on X survives that undo (review 2353 F8), X reads hidden at B's second record, and
  A's set still held it.
- **Three deep, with a layer held in its exit** (lens 1's S2). A's set still held X at C's record, which B's Radix had
  hidden again.
- **B over A, B closing before A** (round 1's departure `c42-reverse-close-residual`). A's set still held X, so A's close
  left it.

**The fix (fix round 1, review 2353's variant)** (`ui/src/lib/modal-layers.ts`, `recordModalLayer`). A node in a
still-mounted layer's record that no longer carries `aria-hidden="true"` is deleted from that record, and is not taken
into the new layer's. Each sheet holds its record's `Set` by reference, so the earlier layer no longer keeps X either:
whichever layer closes last lifts it, like any other mark. **Measured**: every F1, StrictMode, three-deep and
reverse-close row green (55 of 55).

**The rule the record now keeps.** A page's UN-hide during a layer is honoured. A hide the page makes DURING a layer
cannot be told from a modal's mark: the page's `aria-hidden` lands on one a layer already set, so the attributes alone
cannot separate them (**inferred**, review 2353's refuters 2a and 2c). It is lost, and the node ends announced.

**Why the C40 shapes still hold.** In every C40 shape the page never un-hides the node it hid, so at each record that
node still carries `aria-hidden="true"`. The delete never fires on it, and the filter keeps it. **Measured**: all 25 C38
and C40 rows green, and every never-un-hidden control (eight, with and without StrictMode) stays hidden. **Inferred**:
no caller changed; the only callers of `recordModalLayer` are `sheet.tsx` and `command-palette.tsx` (`graphify query`,
and review 2353's whole-branch pass).

  **Measured** by review 2353 (refuter 2b: true at the tip and with the variant). Not measured here.

## F2 and F4: the prune

Removing `if (!known.isConnected) layers.delete(known)` kept sheet-trap-hide green at C40's tip (review 2343, lens 1).

**The brief's sequential shape no longer needs the prune** (departure `c42-prune-row-via-palette`). With the first
build's filter, sheet A, then the page un-hiding X, then sheet B: X carries no `aria-hidden` at B's record, so it is left
out whether or not the record still holds A. **Measured** in round 1: that shape stayed green with the prune removed.

**Two rows.** Round 1's F2 row goes through the palette: sheet A comes and goes while the page has X hidden; the page
un-hides X; the palette (which hides X and never lifts its own marks) hands off to sheet B. Review 2353 F4's S15 row: the
page un-hides X while A is open, the palette opens over A, A is closed by code and leaves under the palette, and the
palette hands off to sheet B.

**Since the variant, no row tells the prune apart** (**measured**, the table below): MF2 (the prune removed) and ML1 (the
prune after the union) are each 0 red. The S15 row reds under ML1 together with MF4, and the F2 row under MF2 together
with MF4. **Inferred** why: the delete takes a node the page un-hid out of every set, a gone layer's included, at the
first record that sees it un-hidden, so a gone layer's set never holds such a node at a later record. So the prune is
now a bound on what the record retains (a gone panel and its set), not a correctness guard, and the coordinator's F4
ruling, a row red under ML1, cannot be met by a row. The coordinator, told, ruled: keep the prune as a retention bound,
keep both rows under their combined mutants, export nothing.

## F3: the reopen

A live region keeps the palette's hiding on the page's children rather than the page; the page drops it while the
palette is open; the palette hands off to a sheet; the sheet closes, lifting the palette's marks on those children too;
the palette's exit ends, and its undo takes its marks off; a reopen during the sheet's exit put `aria-hidden` back on a
child no modal marked any more, which no close lifts and no undo removes. **Measured** red at 6c2d705d2 and at
f8251a39d.

**The fix** (`ui/src/primitives/sheet.tsx`, `useHidingFollowsOpen`): a reopen puts back only the lifted nodes that still
carry `data-aria-hidden`. It changes what a reopen hides in no C38 or C40 row: section 1's first row (the reopen during
the exit) and every other row stay green (**measured**).
