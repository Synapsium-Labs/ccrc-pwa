### F5's budget, measured

Through `ccrc test`, the case alone (`-t`), at load 1.5 to 2.4. 12,000 lines each holding a commit address under one
shared seven-character prefix and the same SHA bare. Only the resolution of the 12,000 bare names is timed, not the read.

| Shape | Real code | Mutant: `main`'s `chatRepoEvidence.ts` | Bound |
|---|---|---|---|
| One repository, each bare full SHA | 10.1 to 10.8 ms | 4,161 and 4,492 ms | 500 ms |
| 12,000 repositories, each bare the shared prefix | 25.9 to 28.7 ms | 7,514 ms | 500 ms |

The bound is about 18 to 50 times the real time, and 8 to 15 times below the mutant.

### F3's cost pin

Five shapes of 1 MiB with no line break (`gh pr view 1 'a'; `, `gh -b "a" | `, `gh pr view 1 it's `, the same with a
line break, `gh '`): 59 to 113 ms each, against a 1,500 ms bound. The reading is linear by construction, and the pin
guards that: a closed quote's search reads up to the quote that closes it, which the word then consumes; a void quote's
search is never repeated, because the reader goes on past it. No mutant is separated by this pin. A version that looked
for the line's end past every quote over the whole text (each search to the text's end) ran 140 to 420 ms per shape:
2 to 4 times slower, which the bound does not catch. That design was dropped for the one above, so it is no mutant of
shipped code.

## Departures

- `hash-word-is-prose`: the value-flag list alone does not fix two of F1's four reproductions, `gh pr list -R o/r #12` and
  `gh pr create --repo o/r #12`, where `#12` is the third word and no flag precedes it. Review 1762's own first fix
  direction is used beside the list: an unquoted word starting with `#` is never a positional (a shell reads it as a
  comment). A quoted `'#12'` is still the command's number.
- `value-flag-list-extended`: the list adds `--header`, `-L`/`--limit`, `--reason`, `--state`, `--template`, `--input`
  and `--hostname` to the brief's. Without `--limit` and `--reason`, `gh pr list --limit 12 -R o/r` would make 12 the
  command's number and `gh issue close --reason completed 12 -R o/r` would lose its repository, both of which review 1762
  measured as right. Short forms that mean a boolean in another `gh` command (`-s`, `-m`, `-r`) are not added.
- `r15-records-the-new-reading`: R15's sentence on `gh` commands, and its "What names a repository", also state the F1,
  F3, F8 and F9 rules, so that the spec says what the code reads. The F6 sentence is the brief's.
- `no-stray-u0301`: review 1740 F4 and the brief say the comment carries a stray U+0301; the file holds none. The wording
  was garbled, and it is reworded.
- `d-8187-in-the-task-section`: the brief says to define D-8187 under the plan's "## Deviations found". The plan has no
  such heading; its tasks define their numbers in their own section, as C18, C19 and C21 do, and C20 does the same.
- `c21-r4-wording-kept`: review 1762 F6 also notes that `c21.md` calls the removed R4 check "dead code". That sentence is
  not in the brief's list, so it is left as it is.
