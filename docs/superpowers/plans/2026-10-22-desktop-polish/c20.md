### F5's budget, measured

Through `ccrc test`, the case alone (`-t`), at load 1.5 to 2.4. 12,000 lines each holding a commit address under one
shared seven-character prefix and the same SHA bare. Only the resolution of the 12,000 bare names is timed, not the read.

| Shape | Real code | Mutant: `main`'s `chatRepoEvidence.ts` | Bound |
|---|---|---|---|
| One repository, each bare full SHA | 10.1 to 10.8 ms | 4,161 and 4,492 ms | 500 ms |
| 12,000 repositories, each bare the shared prefix | 25.9 to 28.7 ms | 7,514 ms | 500 ms |

The bound is about 18 to 50 times the real time, and 8 to 15 times below the mutant.

### F3's cost pin

Five shapes of 1 MiB, four with no line break and one with a line break after each unit (`gh pr view 1 'a'; `,
`gh -b "a" | `, `gh pr view 1 it's `, the same with a line break, `gh '`): 59 to 113 ms each, against a 1,500 ms bound. The reading is linear by construction, and the pin
guards that: a closed quote's search reads up to the quote that closes it, which the word then consumes; a void quote's
search is never repeated, because the reader goes on past it. No mutant is separated by this pin. A version that looked
for the line's end past every quote over the whole text (each search to the text's end) ran 140 to 420 ms per shape:
2 to 4 times slower, which the bound does not catch. That design was dropped for the one above, so it is no mutant of
shipped code.

**The boolean list's source.** `gh` 2.103.3 (2026-10-26), read on this box from its own help. That is the `FLAGS` block
of `gh api --help`, and of `--help` for each of `pr view|checks|list|create|edit|comment|diff|close|reopen|ready|review|checkout|status`
and `pr merge`, and of `issue view|list|create|edit|comment|close|reopen`. A flag listed there with no value type is a
boolean. The `api` set is `api`'s booleans. The `other` set is every boolean of the `pr` and `issue` commands, minus any
flag that takes a value in another of them. That leaves out `-a`, `-c`, `-e`, `-m`, `-r`, `-s` and `--comment`, so they
take a value, which is the safer direction. `-i` is `--include` in `api` but `--interval` in `pr checks`, so it sits in
the `api` set only.

**What the shell reading costs.** Since an unquoted `#` word ends the command, `gh pr view #12 40 -R owner-b/repo-b; #40`
names nothing, and both bare names open home. That is what `main` gave (review 1766 F7 measured `main` at home), and what
a shell would run. A `-R` written after a `#` word is part of the comment.

**Equivalent forms removed.** The first form of the tokenizer also ended the command at a word's first character when that
word stood past the positionals. `close()` already decides the same at the word's end, and a mutant without that check
survived every row. So the check was removed, and the one rule (a bare word past the positionals ends the command) now
lives in `close()` alone.
