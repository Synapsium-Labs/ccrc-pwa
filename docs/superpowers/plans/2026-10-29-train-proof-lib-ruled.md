# The train-proof lane leaves ccd/ccd: ruled 2026-10-29

**Context.** #1797 (the train proof of a PR a merge train landed and closed,
D-7335, D-7362, D-7378, D-7381) grew `ccd/ccd` by 490 net code lines against
its merge-base and landed with the growth waiver
`server/test/growth-waivers/D-7362-ccd-ccd.json` (`maxDelta` 490). Its reason
was that every piece extends an existing owner and that a split would need a
digest-checked install of its own.

**Ruling (operator, 2026-10-29).** `ccd/ccd` must not grow that much. The train
proof and its prover move into a new sourced library, `ccd/lib/train-proof.sh`,
which is sourced, installed, censused and tested exactly as
`ccd/lib/disk-retention.sh` is. The move changes no behaviour, and the D-7362
waiver is deleted.

## Deviations found

- **D-7463 (2026-10-29)** — the train-proof lane moves to `ccd/lib/train-proof.sh`, ccd's second digest-pinned library, and the D-7362 growth waiver is deleted. Three regions move as they stood, each behind a `# @ccd-lib:<id>` pointer that `ccdSource()` puts back for every scanner. `trainpy` is `_pr_train_py`: `_pr_py`'s `train-refs` and `train-check` python modes, now their own fd-3 program, which `_pr_py` hands those two modes to with the same argv and stdin. `trainprove` is `cmd_pr_train_prove`. `trainrecord` holds the train budgets, the kept-proof and tried-record files with their readers and writer, `_pr_num_valid`, `_ws_train_record` and `_pr_train_proofs`. The body pins the file as `__CCD_LIB_TRAIN_SHA256=stamp-at-install`, which `ccd/ccd-entry-install.py` renders before the stamp, exactly as it renders `__CCD_LIB_SHA256`. `_ccd_lib_load` reads both files and checks both digests before it evaluates either, so one library that was not shipped refuses the start with neither run. Only a body whose every pin is a placeholder counts as a source checkout. The installer refuses a malformed file or a pin that does not match, and publishes the second library right after the first and before the body. `ccrc update` backs it up as `ccd-lib-train-proof.sh` (deploy.sh does too), and `ccrc uninstall` removes it by name. It appears in the install-tree fixture, the release tests, `CCD_LIB_FILES` (contexts, call graph, heredoc check) and `ccd/contexts.tsv`, where its ten rows move to the end in load order and `_pr_train_py`'s new row (C4) joins them. `_pr_train_py`'s python spells `PR_NUM` itself because it cannot share `_pr_py`'s, so the run-id census allows three spellings: one per python program plus `_child_runid_valid`. Measured with `growthCheck.ts`'s `codeLines`: `ccd/ccd` was 19,346 code lines before #1797 and 19,836 on main (+490). It is 19,502 here: −334 against main and +156 against #1797's base. The +156 that stays are hooks inside existing owners and do not move without a redesign: the `annotate`, `state`, `pick` and `bind` arms of `_pr_py`'s one python program, the reap's train rung and its four refusals (counted by the refusal census inside `_ws_reap_eval`), the queue word, the verbs' budget lines and the dispatcher. No waiver is needed, because this PR's own delta is negative. Rows: `ccd-lib-load.test.ts` (the second library loads, its pin is a placeholder, and tampering with, emptying or removing it refuses with neither library evaluated, sourced, executed and through the direct entry; so does one pin rendered beside the other unrendered), `ccd-entry-install.test.ts` (it is published after the first library and before the body, pinned under the stamp, republished alone after out-of-band drift, mode-repaired, and refused when malformed or mispinned), `install-census.test.ts` (both libraries declared, removed and backed up in order), plus the existing release, stamp, uninstall, ownership, deploy and agent entry rows extended to the second file.
