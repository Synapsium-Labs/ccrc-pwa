# A dispatch that never came back is abandoned by the server, ruled

- **D-7319 (2026-10-29)** — a run whose dispatch never came back is abandoned by the server through the one abandon arm, once it is proven dead, and its coordinator is mailed; Settings › Automation turns it off, seeded on.

**D-7319.** The operator ruled on 2026-10-29 that a run the fleet card draws as a phantom child, "spawn never completed" (`pwa/src/fleet/ProjectCard.tsx`, `PendingSpawn`, drawn while `dispatchWindow(run)` answers `stalled`), must be abandoned automatically and not left for the operator to abandon by hand. The ruling's requirements, and where each one is met:

| Requirement | How it is met |
|---|---|
| Reuse the existing Abandon act, never a second abandon path | `closeRun`'s abandon arm, reached only through `CoordRoutesHandle.withSweepAbandon` (the dead-coordinator lane's handle: `causedBy: 'sweep'`, the compare-and-set on `claimedBy`, a re-measure inside the arm). For a run with no session that arm makes no fleet act: one transaction closes the run `failed`, cancels the run's outstanding mail and releases its claims. `server/src/coord/abandonDeadDispatch.ts` writes no run state. |
| Abandon only when proven dead: stalled past a bound | `CCRC_DISPATCH_ABANDON_MS` (`server/src/config.ts`), default 900 000 ms (`DISPATCH_ABANDON_DEFAULT_MS`, `shared/dispatch-abandon.ts`); a value under `SPAWN_STALL_MS` is refused for the default. |
| No workspace exists for the run | `deadDispatchVerdict` (`server/src/coord/deadDispatch.ts`, L1) over one measured registry read: no row's `.child` marker names the run; no row of its project has an unreadable marker, an unmeasured identity, or the shape a cut-short `ws-add` leaves (a workspace with no marker, no hold and no spawn: `cmd_ws_add` writes the rows, then `.child`, then spawns the pane); no refused names; and the box marks its workspaces (no `child-omitted:` event on the run). |
| No `ws-add` or dispatch for it is still in flight | The stamp is at least the bound old, and the bound is at or above `SPAWN_STALL_MS`, which is at or above the 300 s `ws-add` ceiling the runner and the agent enforce, so the `ws-add` started at that stamp has returned or been killed (the agent does not kill an exec when its link drops, which is why the mutex alone is not the proof). The verdict is read again inside the coordination serialiser, which every dispatch holds from before its `ws-add` to after its bind; a retry restamps the run, so it reads in flight again. |
| Journal the act with its reason | After the commit: a run event `dispatch-abandoned:never-came-back started=<ms> bound=<ms>` beside the close's own `planned -> failed` row (`causedBy: sweep`). |
| Mail the run's coordinator | After the commit, through `queueSystemMail` (the server's own mail path), `dispatch-abandoned` from `operator` to `claimedBy`, naming the run and saying to dispatch again. Queued after the commit because the close parks every outstanding delivery of the run's mail. |
| A Settings › Automation switch row, default on | `dispatch_abandon_settings` (coord.db migration 33, seeded `on`), `GET`/`POST /api/coord/dispatch-abandon`, and the card "Dispatches that never came back" (`pwa/src/fleet/DispatchAbandonSection.tsx`) with On and Off, the collector's and the stall watch's conventions. Only an exact stored `on` arms it. `reclaim-paused` stops it too. |
| A late child must not be harmed | The run is never moved back: a dispatch that already returned never binds it, and a terminal run has no edge back. A child workspace that appears later carries `.child` naming a closed run, and child reclamation takes it under its existing rule for that case (`reclaim-paused` and `child-reclaim-disabled` still stop it). The coordinator, already mailed, opens a new run. The bound makes this residual. |
| Improve what exists first | A reason of the dead-coordinator lane's pass (`watch.ts`, `deadCoordinatorPass`), placed after the lane's switch and before every gate that is the crash's own (the journal's trust, the anchors, the breaker, shadow). No new timer, lane row or serialiser. |

**No `SWITCHES` row in this change.** `shared/switches.ts` is a file the consolidation W1a stream alone owns, and `consolidation-path-guard.test.ts` (D-5855) refuses a diff that touches it beside a `pwa/` path. This change carries the Settings card, so the switchboard row `dispatch-abandon-choice` (storage `dispatch_abandon_settings.choice`, default `on`, writer `POST /api/coord/dispatch-abandon`) lands in a server-only change after it. Nothing reads the act's arming through `SWITCHES`: the pass reads `CoordStore.dispatchAbandonSetting` directly.

**The bound was not measured from live dispatch durations.** Measuring them needs the server box's `coord.db` (`SELECT dispatchedAt - dispatchStartedAt FROM runs WHERE dispatchedAt IS NOT NULL AND dispatchStartedAt IS NOT NULL AND resumed = 0`), and this change was made without access to it. The default is set from the limits in the code instead: three times the `ws-add` ceiling and two and a half times the console's stalled threshold. The query above is the measurement to make before tuning `CCRC_DISPATCH_ABANDON_MS`.

**A programme's state.** When the abandoned run was its programme's only open run, the close sets `programs.state = 'abandoned'`, as the operator's abandon does. A new run opened under that programme is accepted (`openRun` refuses nothing on a programme's state), and the programme's state is not set back. That is today's behaviour of the operator's abandon, unchanged here.
