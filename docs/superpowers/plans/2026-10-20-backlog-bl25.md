# ws-rm keeps a shared branch: main, master, develop and origin/HEAD's target (#138) — Implementation Plan

**Issue:** #138, "ws-rm deletes the repo's shared main branch when a workspace has main checked out".

**Status:** one task, one PR. It changes `cmd_ws_rm` in `ccd/ccd` and adds tests to `server/test/ccd-ws-rm-attic.test.ts`.

## The problem

`ccd ws-rm` ends by running `git branch -d` on the branch git's worktree record says the workspace had checked out. `-d` refuses an unmerged branch, and that is its only protection. A workspace that had the repo's shared `main` checked out (its registry entry and git's record both said `main`), at an ancestor of `origin/main`, therefore lost the repo's local `main` at teardown: `-d` called it merged and printed `Deleted branch main`. Being merged protects unfinished work. It does not protect a branch whose value is its name. Whether the delete happened depended on unrelated state, because another worktree holding `main` would have made git refuse.

The registry could say `main` because `ws-rename --branch <old>` corrects the registry to whatever the worktree has checked out.

## The fix

Before the delete, `cmd_ws_rm` decides whether the branch is the workspace's own (D-5880). It is never own when it is `main`, `master` or `develop`, or when it is the branch `refs/remotes/origin/HEAD` points at, whatever the registry or git's record says. Such a branch is kept, and ws-rm prints `kept branch <name> (shared, not this workspace's own)`, so it is never kept silently. Every other branch goes through the existing path unchanged: the divergence note, then `git branch -d`, which still refuses an unmerged branch.

The change only narrows what ws-rm deletes. Nothing it kept before is now deleted. The ccd stamp is regenerated with `ccrc restamp`.

## Tests

`server/test/ccd-ws-rm-attic.test.ts`, describe "ws-rm never deletes a shared branch". The fixture pushes `main` so that it is an ancestor of `origin/main`, then moves the repo's own checkout off `main`. That is the state the issue measured.

1. The registry and git both name `main`. `refs/heads/main` survives and the kept line is printed. This is the acceptance test.
2. A `ws/` workspace switched its worktree onto `main`, and `origin/HEAD` is removed. Only the fixed list protects `main` here.
3. `origin/HEAD` points at `trunk`, a name not on the list, and the worktree is on `trunk`. Only the origin/HEAD comparison protects it.
4. The workspace's own merged `ws/` branch is still deleted, and no kept line is printed.

Red first: against `origin/main`, tests 1 to 3 fail. Test 1 prints `Deleted branch main` and the ref is gone. The existing ws-rm tests in `ccd-workspaces.test.ts` and `ccd-ws-reap.test.ts` stay green.

Mutation table, measured on a `git archive` copy with the stamp regenerated for each mutant:

| Mutant | Killed by |
|---|---|
| Drop main/master/develop from the list | test 2 |
| Drop the origin/HEAD comparison | test 3 |
| Drop the whole guard | tests 1, 2, 3 |
| Keep silently (no kept line) | tests 1, 2, 3 |
| Guard every branch | test 4 |

## Deviations and decisions

Issued 2026-10-20 to this fix, a block of two. D-5880 and D-5881 are defined here, once.

- **D-5880** — `ws-rm-keeps-shared-branches`: `cmd_ws_rm` never deletes `main`, `master`, `develop`, or the branch `origin/HEAD` points at. It keeps such a branch and prints `kept branch <name> (shared, not this workspace's own)` to stderr. The check comes before the registry-divergence note and the `git branch -d`, and it applies whether the name came from the registry or from git's worktree record. Pinned by tests 1 to 3 above.

- **D-5881** — `ws-rm-no-branch-shape-test` (a departure from the triage note): the triage note asked ws-rm to delete only a `ws/`-shaped branch whose registry name matches git's worktree record. Both halves would turn existing, intended behaviour red. ws-rename, ccd's own verb, gives a workspace's own branch any free name (`ccd-workspaces.test.ts`, "removes the RENAMED branch after ws-rename"). When the registry and git disagree, git's record is the name to delete (`ccd-workspaces.test.ts`, "trusts git over the registry when they disagree"). So the guard is a list of protected names, not a shape. **Known limit.** A shared branch that is not on the list and is not origin/HEAD's target, such as a release branch, can still be deleted when it is merged. That was the behaviour before this fix too. `git branch <name> origin/<name>` restores it.

Issued and unused: none.
