# The test box's tool sync: npm in a directory of its own version, and a hand-over on disk before the takeover exits

- **D-7560 (2026-10-30)** — `testbox-npm-per-version-and-durable-handover`: two rules of the tool sync (TB6, spec §2.10, D-7426, D-7559). (1) npm is installed into a directory of its own version, `<tools>/npm/<version>` (npm's package directory, placed whole in one rename and never changed after), and a set's `bin/npm` and `bin/npx` link into it; the sync never writes npm into node's prefix. So a sync that changes npm alone on the same node changes nothing under a run that resolved the old set, and a sync that fails after its npm step leaves `current`'s npm as it was. A sync prunes an npm directory once no kept set links it. The node prefix's `etc/npmrc` is written only when its lines differ, so a sync on the same node and proxy rewrites nothing; a changed registry proxy (a box setting) is written into the prefix at the next sync, as a setting change. The release's `server/` dependencies are installed with the new set's own `bin/`. (2) A takeover never exits while the queue is not on disk. Its hand-over is all or none: every queued run's file is written and fsync'd under a staging name, then all are renamed into `<root>/handover/` and the directory is fsync'd; a failure removes what that attempt wrote. A hand-over that fails is reported as the sync's failure (`tool sync failed (handover: <why>)`, so the box reads as degraded) and tried again on `CCRC_TESTBOX_PRISTINE_RETRY`'s delays with admissions still closed; a run submitted meanwhile queues and is handed over with the others. The next service removes a handed-over file only once it has queued that run: a file whose submit throws stays, and the service's timer tries it again; a file that does not read as a `run.submit`, or whose run the service refuses, moves to `<root>/handover/dropped/` beside a `<name>.reason` file. A submission's log directory is made before it is queued, so a submission that throws was never queued.
