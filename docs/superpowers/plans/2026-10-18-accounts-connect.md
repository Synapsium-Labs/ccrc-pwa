## Global constraints

Every task's requirements include this section. `CLAUDE.md` is the authority, and this is its working subset plus the spec's floors.

- **Public repository.** Every line, fixture, screenshot, commit message and PR body is public. Lanes are `lane-a` to `lane-f` (or the mockups' `work-max-1`-style names when a frame is cited), the email is `someone@example.invalid`, paths are `<suffix>`, `~/<suffix>` and `<projects-root>`, hosts are `<fleet-host>` and `<server-host>`. No hostname, IP, account, lane or login name, absolute home path, person's name or secret. `server/test/topology-clean.test.ts` stays green.
- **No real-shaped secret is ever written contiguously in a tracked file.** A fixture token is assembled at run time (`'sk-' + 'ant-oat01-' + 'x'.repeat(80)`, `'sk-' + 'or-v1-' + …`), so no scanner, push protection or reader mistakes a fixture for a credential. A canary is a fixed non-secret string such as `CANARY-<run-id>`.
- **Fixture HOMEs only.** No test runs `ccd`, `ccrc` or `ccd-account-auth` against the live `$HOME`: `makeCcdHarness(prefix)` (`server/test/ccdWsHelpers.ts`) and the `$TMPDIR/ccrc-testrun-*` parent. A stub `claude`, `codex`, `curl`, `systemd-run`, `launchctl`, `security`, `tmutil` or OpenRouter answers from first on `PATH` inside the fixture; nothing reaches a real provider from a test. `ghContainedEnv()` wherever a suite could reach `gh`.
- **Never touch the fleet or the controller box.** No task, test or step ssh-es to, deploys to, or reads from a live box. The box runs (OA1a, OA1b, OA2) and the VM check (OA3) are the operator's, from their own shell.
- **Never print a secret file's contents.** Existence is checked with `ls` or `stat`; a test reads a fixture secret only inside the fixture home, and asserts on its bytes without logging them.
- **The secret's one path (D-5513).** A secret is a component's local state in the sheet, one HTTPS POST under the session, one request's lifetime in the server, `stdinB64` on the `account` op, the verb's stdin, then a 0600 file. It is never echoed, stored in coord.db, put in browser storage, logged, mailed, pushed, put in the feed or carried on a websocket. Refusal text is built from codes only; no child program's output reaches the browser. Each task that adds a path a secret takes extends the canary (A17's suite) to it in the same PR.
- **The account gate (D-5511).** Every account route is session-only (not in `EXEMPT`, never a box token), answers `auth-off` while the gate is dark and `insecure-origin` on a plain-HTTP non-loopback `cfg.origin`, sends `Cache-Control: no-store`, and lives in a file that `auth-gate.test.ts`'s `ROUTES` scans. That sweep reads a fixed list of files (`server.ts`, `coord/routes.ts`, `update/routes.ts`, `token/routes.ts`, `docs/routes.ts`), so A14, which creates `server/src/accounts/routes.ts`, adds `...scanRoutes('accounts/routes.ts')` to `ROUTES` and the matching entry in `box-token-census.test.ts`, with its own per-file count pin. The step-up routes A5 adds to `server.ts` change that file's existing pin (`scanRoutes('server.ts').length`), so each route task updates the per-file count pin it changes as one serialized one-line edit, absorbed by merge. A route in a file the sweep does not scan is a defect the census cannot see (`CLAUDE.md`, the kickoff-route note).
- **The account spawn's environment is explicit.** Both arms of `AccountOps` (A7's local spawn and A8's agent op) give the `ccrc account` child exactly `{HOME, PATH, LANG}`, after `agent/src/tokensync.ts`'s `tokenSyncEnv`, and never `process.env`: the server's environment carries `CCRC_AGENT_TOKEN`, `CCRC_VAPID_PRIVATE` and `CCRC_HETZNER_TOKEN` (`~/.ccrc/ccrc.env`), and the agent's carries `CCRC_AGENT_TOKEN` (`~/.ccrc/agent.env`), and an inherited environment would reach every verb's `claude`, `codex`, `curl` and `jq` children.
- **The deny guard is an accident guard, and says so.** A9's rules and hook refuse the plain and path-qualified forms; a deliberate same-uid caller is not stopped, and no test or comment may claim otherwise (spec §3.1).
- **Wire discipline.** Frames and answers are additive; absence permits; one reader per field. `RosterWire` gains no secret-bearing field. `LaneWire` rides a separate `lanes` map that the offline snapshot never persists (G15).
- **Single definition.** The account sub union, every refusal code (with its HTTP status in `REFUSAL_STATUS`, D-5381), the cap words (N4), `ACCOUNT_DENY_RULES`, the method, placement, reset and expiry enums, the credential-shape mask patterns, the state words and their precedence each have one home, registered in `server/test/single-definition.test.ts` where a second copy could drift. No account-name list in any shipped source file.
- **Rings.** L0 `shared/*.ts` imports nothing. A policy (the state words, the ceiling arithmetic, the URL shape check, the step-up freshness) is a pure L1 function with no `fs`, fastify or `reply`. The `AccountOps` port is declared by its consumer (L2). An adapter never narrows a distinction it received: an absent lane-state file and an unreadable one are two answers, and "no check yet" is never rendered as Signed in.
- **Server logs** are `console.warn('ccrc-server: …')` with the op, sub and id only, never a body. `Fastify({logger:false})` stays.
- **Both skins, every width, every PWA PR.** The PR body carries the 16-cell matrix (§Acceptance): 360, 390, 1280 and 1920 × Refined and Instrument × Phosphor & Ink (dark) and Phosphor Daylight (light), against a fixture `CCRC_HOME` **and** `HOME` on a machine that runs no fleet. A desktop-only interim is not acceptable. A box or server task with no rendered surface writes "no UI" in all sixteen cells and names the task whose screen first shows its data.
- **Mutation discipline.** Every guard ships with a test that goes RED when the guard is deleted and when it is made wrong. Each task's table is RUN: apply the mutant, run the named suite alone, record the red line, restore with `git checkout -- <file>`. Never commit a mutant. "A comment is a request; a red suite is a mechanism."
- **No new dependency.** No task edits a `package.json` or a lockfile.
- **Deviation ledger.** This plan defines D-5511 to D-5522 and D-5552 to D-5558 (§Deviations and decisions). N1 to N7 are defined here by slug and take a number before the task that implements each is dispatched. No tracked file carries a `D-TBD-<slug>` placeholder (`dtbd.test.ts`), and 5559 is written bare.
- **Branch discipline.** One commit per task on the workspace's own branch. Absorb `main` only with `git merge`. Every commit leaves the suites it touches green.
- **SAFETY.** No task runs a forbidden `ccd` verb, touches tmux or a live fleet, or edits `~/.cc-sessions`, `~/.cc-limits` or a `claude-session@` unit outside a fixture. The private auth tmux server (`-L ccrc-auth-<id>`) is created only inside a fixture in tests. Real `launchctl` runs only under A36's triple gate.

## Review focus (the failure modes most likely to bite)

1. **A secret anywhere but its 0600 file.** Read every new path for a secret on argv, in a log line, an error sentence, an answer, a websocket frame, the store or browser storage. A17's canary is the wall; every later secret-bearing task extends it.
2. **The box token or a dark gate passing an account write.** The gate's `session` verdict is the only proof; review that no new route lands in `EXEMPT` or outside `server.ts`.
3. **Step-up that mints, rotates or crosses sessions.** A5's finish must stamp `assertedAt` on the requester's session only, keep `generation`, set no cookie, and refuse a challenge another session started.
4. **The status file trusted.** The URL, its host and the device code shown to the operator come from the server's validation (N2), and PKCE's URL from the op's answer, never from the file.
5. **argv that carries a secret or a free flag.** The agent builds argv from typed fields with the bounds in spec §13.2; `--force`, a path, a newline or a 65-character label is refused before spawn.
6. **A killed verb leaving a temp secret or a half lane, and a retry into `duplicate-id`.** Locks, TERM traps, the temp sweep and reconcile (D-5518); outcome unknown never retries on its own.
7. **Enable on a not-ready lane,** including a legacy lane before its backfill.
8. **The management key leaving its one reader and one destination,** or a browser path that raises the ceiling or installs the key (D-5554).
9. **Ceiling arithmetic.** daily × 31, weekly × 5, monthly and never × 1; a shorter reset is a raise; pending deletes count until OpenRouter stops listing them (D-5555).
10. **A launchd job in the operator's real gui domain.** Real `launchctl` only under A36's gate, with a run-unique label namespace and an `afterAll` bootout (D-5558).
11. **A sleeping session rehomed in silence** (N3): remove counts hibernated rows and says what waking them will do.
12. **"Unmeasured" read as clean.** No lane-state file is Not checked, an unreadable one is Inconclusive with its reason, and neither is ever Signed in.
13. **Instrument rows that overflow** the 340 px list column or the 360 px phone row (spec §12.2's width budget).

## Deviations and decisions

### Issued to this work and defined here

`POST /api/ledger/deviations` issued D-5511 to D-5522 for the Accounts design, and D-5552 to D-5558, with 5559 beside them, for its Q4, Q6 and Q10 designs. The spec cites them in its §18. Each is defined here, once, and later plans cite them and never redefine them.

- **D-5511** — `account-writes-operator-only` (Tasks A7, A12, A14, A17, A21, A29, A31, A33): every account route needs the gate's `session` verdict, an armed gate and an https or loopback `cfg.origin`. A box token is never accepted, so `ccrc-api`, every session and every coordinator get a 401 on the HTTP path. A dark gate refuses every account route with `auth-off`, with no loopback exception, because a dark loopback box is the default deployment. A plain-HTTP non-loopback origin refuses every write with `insecure-origin`, derived only from `cfg.origin` while the gate is armed, never from `Host`, `cfg.host` or `X-Forwarded-*`. One chokepoint, `accountGate` (`server/src/accounts/gate.ts`), applies all of this, plus `Cache-Control: no-store` and the cap word's refusing no-evidence polarity (`501 unsupported`). `GET /api/accounts` keeps today's answer for every reader and adds `lanes` and `connect` for the session verdict only. This guards the HTTP path only: same-uid processes on the fleet host are inside the trust boundary for secrets at rest.
- **D-5512** — `account-step-up` (Tasks A5, A6, A17, A21, A31, A33): adding a credential, starting a sign-in, rotating, changing a method, raising a minted key's monthly commitment, removing or discarding a lane, and removing the management key each need a step-up from the last five minutes **on the same session**. Step-up has its own routes (`POST /api/auth/step-up/start|finish|passphrase`), because the login doors mint a session. Finishing stamps `SessionRecord.assertedAt` on the requesting session only, mints nothing, sets no cookie and keeps `generation`. Challenges use the `step-up` purpose, bound to the requester's `idHash`. The passphrase arm is refused `passkey-enrolled` whenever a passkey is enrolled. `StepUpRateLimiter` is separate from `LoginRateLimiter`, and exhausting it locks that session's step-up (`step-up-locked`, an audit row). The PWA's **Confirm it's you** is an explicit button whose tap calls `navigator.credentials.get` before any `await`, and nothing is retried on its own. The Settings spec's D8 guard on passkey Revoke and Add uses these routes.
- **D-5513** — `account-secret-one-path` (Tasks A8, A10, A11, A16, A17, A18, A26, A28, A30, A32): a secret is typed once into a component's local state, sent once in an HTTPS POST, held by the server for that request with no reference kept, carried as `stdinB64` on the typed `account` op, and written by the verb as a 0600 file after the verb has refused control bytes and validated it. It is never echoed, stored in coord.db, put in browser storage, logged, mailed, pushed, put in the feed or carried on a websocket, and no child program's output reaches the browser. Keys born on the box (minted, PKCE) go from curl through `jq` to the temp file and never travel. `LimitCORE=0` on both units, and the `ccrc account` child's environment is exactly `{HOME, PATH, LANG}` on both arms. **Every server egress of session-derived text is masked** (`server/src/accounts/mask.ts`): the transcript, ask and drawer websockets (both drawer arms, at the `/ws/pty/:id` handler), pane history, the feed, run items, mail bodies and web-push titles and bodies. It masks the credential shapes in `CREDENTIAL_MASKS` (the whole `sk-ant-` family, refresh tokens included, OpenRouter keys, the generic `sk-` and JWT shapes, and the Codex gateway key), on decoded strings before serialization and across TUI row wraps, and every lane secret by exact bytes through a fingerprint that is `HMAC-SHA256(box token, "ccrc-secret-fp-v1\0" ‖ secret)`, computed on the box by the verbs (which hold both), answered by every secret-writing sub and by `roster --json`, kept in the server-only `secret_fingerprints` table with the token's generation (filled by `reloadRoster` from every answer), and re-keyed by a `roster` sub after a rotation, with the previous generation still matched until the re-key lands. A drawer chunk ending inside a candidate run holds it back for up to 50 ms. The exact-bytes check fails closed: a frame's runs are checked in chunks of 256, and past a hard ceiling the rest of the frame is replaced by a fixed too-large notice; no run is passed through unchecked. **Backups:** on darwin the verbs exclude `~/.cc-secrets` and `~/.ccrc/auth-scratch` from Time Machine, and `ccrc doctor` checks the exclusions and FileVault; on Linux, doctor states the operator's answer about provider-level backups and snapshots.
