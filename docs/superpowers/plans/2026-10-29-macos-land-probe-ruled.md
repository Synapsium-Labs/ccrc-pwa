# The land probe's tests on macOS: a portable lock holder and a portable child mask, ruled

- **D-7499 (2026-10-29)** — three `ccd-land-probe` rows failed on the post-merge macOS run while Linux stayed green, and in each one the test fixture, not the probe, was the part that only works on Linux. `ccd/ccd-land-probe` is unchanged. Two rows, `a held lock exits 0 quietly` (`server/test/ccd-land-probe.test.ts`) and `S1 reads no pause, takes no lock, and creates no file` (`server/test/ccd-land-probe-readonly.test.ts`), started their lock holder as `flock --no-fork <lock> sleep 30`. The flock that a macOS runner installs from Homebrew has no `--no-fork` (and no `-F`): it exits 64 with its usage text, so the lock was never held and the row failed at "the test never took the lock". Both rows now use `holdLandLock` from `server/test/ccdLandProbeFixture.ts`: one bash process opens the lock on fd 9, runs `flock 9`, then execs `sleep`. That keeps one pid that holds the descriptor, so SIGKILL still releases the lock and leaves no orphan. Both flock(1)s understand the descriptor form, and `server/test/updateRealBox.ts` already uses it. The "is it held" probe, `lockHeld`, answers true only on exit code 1, the conflict code of both flocks, so a missing or failing flock can no longer pass for a holder. The third row, `SIGTERM and SIGINT are blocked from the fork until the child is recorded, and the child itself does not inherit the block`, read the git wrapper's mask from `/proc/$$/status`. macOS has no `/proc`, so the log stayed empty. The wrapper now forks `python3 -I`, which prints its inherited `pthread_sigmask` as a JSON list (a blocked set is kept across fork and exec), and the row asserts that neither 2 nor 15 is in it. Measured red first on macOS (all three rows, as on CI) and green after the change, on macOS and in `node:22` as uid 1000. A mutant probe whose `child_signals` stops unblocking turns the mask row red on both platforms (`[2, 15]`). A mutant whose `flock -n 9 || exit 0` is gone turns the held-lock row red on macOS.
