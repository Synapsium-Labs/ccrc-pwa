## Global constraints

- **Public repository.** Every word in code, tests, commits and PR bodies is publishable: no host, address, account or lane name, project name, home path, email, private tracker id or run id from the box. Fixtures are neutral (`s-aaaa`, `programme-a`, run 7). Cite D-numbers, ARCH-NN and GitHub `#n`; never a private tracker id.
- **Account switching and the auto-swap are never blocked.** The lane reads no account figure and writes no swap marker; no task edits `_auto_swap_check`, `_swap_idle_gate`, `_swap_target`, `cmd_swap`, `swap-self` or the swap routes. A stop written by a swap is never E3s, and a swap's respawn never makes E5 or E4 (pinned in W2 and W5).
- **No herd restarts, no herd wakes.** A pass is `sweepDeadCoordinators`' own `CHILD_RECLAIM_SWEEP_MS` (60 s) throttle, read by reference, so R7 is at most 3 programmes acted on and at most one E1 warning a minute, lane-wide across every row and across a controller restart. The warning wakes a hibernated coordinator only through the mail sweep's hibernated gate, under `admitWake` (`WAKE_BURST` per `WAKE_WINDOW_MS`, read by reference, never a second literal). ## Review focus (the failure modes most likely to bite)

1. **A close of a live run.** E1 requires every open run of the programme to be `planned`, the programme quiet for 72 h on R4's full activity list, and a warning delivered at least 24 h earlier; E4 requires a `dead` verdict, not hibernated, and a stale heartbeat. Any reading that cannot be taken answers "not this pass" (R2). A diff where an unmeasured input acts is refused.
2. **The lane's own rows resetting its clock, or a gap counted as quiet.** R4 excludes `causedBy 'sweep'` rows and, once a warning is delivered, the coordinator's busy turns (the turn that reads the warning is not activity, departure `warning-turn-not-activity`); R5's anchors restart on a gap above `DEAD_COORDINATOR_GAP_MS`, a pause, maintenance or a backward clock step, so a restart after days closes nothing on its first pass.
3. **A fleet act on the wrong session.** R1 for every row, the crash row included: a `.child` marker naming a later run (`run.id < mark.runId`), a `none` marker (departure `none-marker-no-fleet-act`) or a null `sessionId` gives `fleetAct: 'none'` (the close proceeds, no `ccd` call, no `handOffChildReclaim`); an unreadable or unrecognised marker lists the run and never closes it. 4. **A late start lost, or a switch flipped mid-act.** The act runs on the one coordination mutex `dispatchRun`, `advance` and `closeRun` share, and `stillStuck(row)` re-checks state, `dispatchStartedAt`, `claimedBy`, activity, a listed registry, `reclaim-paused`, `coordinator-paused` and the row's own marker there, before and after the fleet act. No `gh`, `pr-state` or `ccd` call and no sleep runs inside the mutex (R6).
5. **Lost work.** From W1, for every row whose run has a `sessionId`: an open PR or unpushed commits (`pr-state`, the ws-audit `unpushed-commits` check, each read before the mutex and at most 5 minutes old at the act) refuse the close and list the run; an unmeasured reading refuses too. For a reused name the open-PR fact is read by the run's own `branch`, never `--session` (W2).
6. **A storm.** One warning a pass; close notices never wake (`wake = 'never'`) and never push; `expired:*` transitions and the lane's mail are record-only in `pushNewMail` and `pushNewRuns`; a shadow or hold feed row only when its outcome key changes, and one record-only feed row per programme per armed pass that acts; the only new push is one needs-you push per programme with a refused close under a gone coordinator, armed only, deduped durably.
7. **A coordinator never told, told twice, or woken.** `untold` rows are written in the close transaction and deleted in the notice's insert transaction; a crash between them still yields exactly one notice; a gone claimant gets no mail from W1 on (nothing parks `undeliverable`), and its rows drain to the heir when Resume or the reclaim door rewrites `claimedBy` (W2); a notice to a hibernated coordinator wakes nothing.
8. **A deliberate stop read as death.** E3s counts only a `stop` the journal attributes to a person's stop verb; a swap's, a supervisor's, an OOM policy's, a lane's or a maintenance stop never counts; hibernation is never "gone" for any row.
9. **A screen built twice, or a word that leaks.** W3 builds the programme card, screen and stepper once; P9 only places them. No card or header string equals `session.branch`, `session.workspace` or a run id, and none **contains** the slug when a title exists, at every width and in both skins; every card string appears in the header. One state→group record (`RUN_GROUP`) serves the ledger and the programme counts.
10. **A ratchet broken across the hall.** The feed's writer set stays two (`notify` and its archive pair, D-5859): the lane's rows go through `notify`, never a new `recordFeedEvent` site. `SWITCHES` gains marker rows only, each with no writer. `driftFindings`' suite is green unchanged after the move.
