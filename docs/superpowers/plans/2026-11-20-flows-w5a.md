# Flows wave 5a: move a step on the canvas

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** in the flow editor, a step is moved by dragging it on the diagram, or by focusing it and pressing the arrow keys;
the new place is part of the draft and saved with it.

**Spec:** `docs/superpowers/specs/2026-11-19-flows-design.md` §9, §10 item 5, §11 ("a drag-and-drop library is a dependency
decision worth its own measurement"). Builds on `plans/2026-11-20-flows-w4a.md` (branch `flows-w4`); this branch
(`flows-w5`) stacks on it.

## Decisions

1. **No library.** Moving one SVG group is pointer events and a transform; React already gives both. That keeps the
   dependency question of §11 for the part that may need it (connecting by dragging, 5b) and costs no bundle now.
2. **Keyboard first-class.** Each step is a focusable button when the diagram can move it: arrow keys move it one grid step
   (8 px), five with Shift; Enter, Space or a click selects it; the click a drag ends with selects nothing.
3. **Snapping and bounds live in the edit** (`flowEdits.ts#moveBlock`, L1): the grid is 8 px and a step never goes above or
   left of the canvas. A locked step moves too: placed, never edited (spec §4).
4. **Wave 5 splits.** 5a moves steps. 5b is connecting by dragging and live positions on the canvas (the dots wave 3a's
   read can now feed). Deviation `D-10016`.

## Tasks (as built)
