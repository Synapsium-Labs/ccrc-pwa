# Shadow lanes: the roster card's switch moves into Settings (worktree economy R-6, first row)

- **D-8274 (2026-11-11)** — the roster card is armed from Settings › Automation › Shadow lanes, one coord.db row per shadow lane behind `POST /api/coord/lane-arm`; the hand-made `coordinator-roster-card-live` marker is imported once at the upgrade and then retired.

**D-8274.** Spec `2026-10-28-worktree-economy-design.md` R-6 gives every switch that spec arms one Settings row, and puts the roster card (D4, #757) first in its order (R-5b: "Arm D4 first"). Before this change the operator armed the card only by touching `$REG/coordinator-roster-card-live` at a terminal on the fleet box. What R-6 asks, and where each part is met:

## Deviations found

- **The switchboard row lands in a server-only change after this one.** `consolidation-path-guard.test.ts` (D-5855) refuses a diff that touches `shared/switches.ts` beside a `pwa/` path, and this change carries the card. So `SWITCHES` keeps its `coordinator-roster-card-live` marker row (still `hand-only`: nothing in the tree writes it) with its old wording, and the setting row `coordinator-roster-card-choice` (storage `lane_arm_settings.choice`, default `shadow`, writer `POST /api/coord/lane-arm`) and the marker row's "retired" wording follow in a change that touches no `pwa/` path, as D-7319's row did. Nothing reads the card's arming through `SWITCHES`.
- **`ccrc doctor` does not yet report a leftover marker.** R-6 asks doctor to name a marker that still stands after the import, with the line that removes it. The card says it instead (the row's import line); the doctor check is a follow-up.
- **The wake arm reads the row on the box, through the hook, not in the server.** R-6 says R-5a's wake path ships behind this same switch. R-5a (D-8201) put the wake arm in the session hook's UserPromptSubmit, calling the same `_hook_roster_card` as the SessionStart arm, so the wake reads the row the same way: `"rosterCard":"live"` in the one `runs list` reply that function makes (`GET /api/runs`, filled from `CoordStore.laneArmSetting(ROSTER_CARD_LANE)` by `rosterCardFieldOf`). No server code reads the switch for the wake, and nothing reads the retired marker. The row's notes (`LANE_ARM_TEXT.rows['roster-card']`) name the wake too.
- **The switchboard's marker doc and D-8201's last sentence still say the marker arms the card.** `COORDINATOR_ROSTER_CARD_LIVE_MARKER`'s doc in `shared/switches.ts` (which names the wake arm) is reworded as retired in the server-only switchboard change above; D-8201's line carries a pointer to D-8274.
- **The confirm's facts carry no shadow-record counts.** The shadow record is a file on the fleet box that the hook appends to; the server has no read of it, so the sheet names the file and asks the operator to read it, and counts nothing.
