# The test box reads one config file, owned by root: ruled

- **D-7451 (2026-10-29)** — `testbox-box-config-file`: the test box plan (`docs/superpowers/plans/2026-10-29-test-box.md`, rev 1) said the box's installer reads "its `ccrc.env`" but never named the file, and ccrc's one settings reader cannot name it for the box. `_ccrc_knob` reads `BOX_ENV_FILE`, which `ccd/ccrc` sets to `$HOME/.ccrc/ccrc.env` when it is sourced (`ccd/ccrc#BOX_ENV_FILE`, measured on `origin/main` `d32509009`), and `_upd_release_base` reads `CCRC_RELEASE_BASE_URL` through it. On the box the root installer would have read root's home's file, the test service, running as its own user, that user's home's file, and the root tools unit root's file again for the release base, while the prepare, run, clean and install units read none. The box's units and its runs could then be built from different values. Ruled: the box has one config file, `/etc/ccrc-testbox/ccrc.env`, named once as `TB_BOX_ENV_FILE` in `ccd/testbox-knobs` and printed by `_tb_box_env_file`. It is owned by root, with mode 0640 and the service user's group, so the run users cannot read it. It holds no secret. The operator writes it before the first install, and the installer sets its group and mode and never writes a value into it. `_testbox_knobs box` binds `BOX_ENV_FILE` to that path for each `_ccrc_knob` call, in `file` mode, so neither the caller's home nor its environment is read. It refuses a file that is not a regular file, not owned by root, or writable by group or other. The four readers: the installer, as root, through `_testbox_knobs box`, which renders the unit drop-ins (slice limits, the proxy allow, the service's `User=`) and the users, directories and rule; the test service, as the service user, through `ccrc-test --testbox-knobs box` once at start; the tools unit, as root, which binds `BOX_ENV_FILE` to the path for `_upd_release_base` (read in `file` mode through `_tb_release_base` since rev 3, D-7457); and the prepare, run, clean and install units, which read no config file. The prepare, run, clean and install units carry no `EnvironmentFile=`, because one on a run unit would put the settings into a run environment that is built from empty plus the allowlist, and a unit property cannot be read from an environment file anyway; they take their values from the installer's drop-ins and the service's `specs/<k>`. A change to the file takes effect when the installer is re-run with the installed tag. The installer reloads and restarts only when the file's sha256 differs from the one its `installed` marker records. On the fleet host nothing changes: `_testbox_knobs host`, the wrapper and the agent op's `ccrc-test --testbox-knobs host` all run as the fleet user and read the same `~/.ccrc/ccrc.env`. TB7's `server/test/testbox-config-file.test.ts` holds that the four readers agree. It sets every box key in a fixture box file, other values in root's and the service user's fixture home files and in the environment, and checks that the drop-ins, the service's read, `specs/<k>` and the tools sync's release base all carry the box file's values, with one mutation per reader that reds it. A census fails on any `EnvironmentFile=` line under `deploy/testbox/`, and on any test box file that names `.ccrc/ccrc.env` or assigns `BOX_ENV_FILE` beyond the two bindings in `ccd/testbox-knobs` (box mode's and, since rev 3, `_tb_release_base`'s, D-7457). TB1's `testbox-knobs.test.ts` holds the box-mode reads and refusals, and TB7 now waits for TB1.
- **D-7456 (2026-10-29)** — `testbox-box-owner-seam`: D-7451's refusal of a box file not owned by root had no seam a test could use, since a test run as a non-root user (CI, and the docker runs) cannot make a root-owned file, so neither the accepting nor the refusing row could run (measured on `origin/main` `cc2a3b350`: `ccd/ccrc`'s stat wrappers read no owner). Ruled: `ccd/testbox-knobs` has one check of the box file, `_tb_box_file_ok <path>` (a regular file, not a symlink, owner equal to `_tb_box_owner_uid`, no group or other write), called by `_testbox_knobs box`, by `_tb_release_base` and by the installer's phase 1. `_tb_box_owner_uid` prints `0`, and only when `TB_FIXTURE_ROOT` is non-empty prints `TB_FIXTURE_OWNER_UID` (digits, else `0`); a `TB_FIXTURE_ROOT` that is relative or `/` is refused. Because `TB_BOX_ENV_FILE` is `${TB_FIXTURE_ROOT:-}/etc/ccrc-testbox/ccrc.env`, the override applies only to a file under the fixture root, and the real box file is always checked against root. `TB_FIXTURE_OWNER_UID` is read on one line of the tree, and no box unit or script under `deploy/testbox/` names a `TB_FIXTURE_` variable. TB1's `testbox-knobs.test.ts` runs the accepting row with `TB_FIXTURE_OWNER_UID=$(id -u)` and the refusing rows with it unset or another uid, with a mutation per arm, and TB6's and TB7's fixture runs set it.
- **D-7457 (2026-10-29)** — `testbox-tools-release-base-file`: D-7451 had the tools unit bind `BOX_ENV_FILE` and call `_upd_release_base`, but that reads `CCRC_RELEASE_BASE_URL` in environment mode (`ccd/ccrc:22109`, measured on `cc2a3b350`) and `_upd_resolve` reads it again itself (`:22183`), so a value in the unit's environment would have won over the box file. Ruled: the tools unit reads the box file the way box mode does. `_upd_release_base [file]` passes its optional mode to `_ccrc_knob` (one line, the default spelled once), and `ccd/testbox-knobs`' `_tb_release_base` runs `_tb_box_file_ok` and then `BOX_ENV_FILE="$TB_BOX_ENV_FILE" _upd_release_base file`, that is `_ccrc_knob CCRC_RELEASE_BASE_URL <default> file` against the same box file, and assigns the value to the script's `CCRC_RELEASE_BASE_URL` before `_upd_resolve`, so every read in the update path takes it. A refused file or an unmeasurable value fails the sync and changes nothing. `deploy/testbox/bin/tools-sync` assigns no `BOX_ENV_FILE`. `testbox-config-file.test.ts` row (d) holds that the tools unit, like the other three readers, carries the box file's value while the environment and root's home file name other hosts, with mutations for an environment-mode read and a skipped assignment.
