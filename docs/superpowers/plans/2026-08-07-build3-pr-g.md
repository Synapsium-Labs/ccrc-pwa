# Build 3 PR G Implementation Plan — accounts screen, placement honesty, dormant handshake

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The fleet's account state becomes a first-class screen; placement stops
routing sessions onto declared-dead or missing accounts; and the PWA↔server pair
gains the dormant protocol handshake that can one day block a stale client.

**Architecture:** All reads ride the existing `/api/accounts` + fleet-WS
pipelines — zero new routes, zero new whitelist grants. ccd gains one predicate
(`_account_ok`) consumed by both placement rules; the server mirrors only the
half it can honestly see (`disabled`), kept in lockstep by the shared
bash↔TS fixture harness. The handshake is a synchronous `hello` first frame on
`/ws/fleet` with both constants in `shared/`, inert until `FLEET_PROTO_MIN` is
raised.

**Tech Stack:** bash (ccd), TypeScript ESM (Fastify server, React PWA), vitest,
`makeCcdHarness` fixture-HOME harness.

**Spec:** `docs/superpowers/specs/2026-08-07-build3-riders-design.md` (riders
A, B, E). The code blocks below are shape-authoritative; where the harness or
neighboring idiom differs, **defer to the repo, not the plan** — read the
sibling tests first and adapt names. Never run destructive ccd verbs or touch
`~/.cc-sessions`/tmux; all ccd tests run inside `makeCcdHarness` fixture HOMEs.

## Global Constraints (from the spec, verbatim where quoted)

- "disabled excludes a lane as a *destination*; it never evacuates a session
  already there." Manual paths (`cmd_start`, `cmd_swap`, `cmd_prefer`) are
  unchanged.
- Pressure alone never refuses placement (the `all-pinned` fixture rule
  stands); only all-excluded-by-declaration refuses, and it refuses **before
  anything is created**.
- The server mirror filters `disabled` only — it cannot see `-x`; "ccd's
  refusal is the authority." Parity via `server/test/fixtures/leastLoaded.ts`
  run against BOTH implementations.
- Handshake: "absence permits" — no `hello` (older server) never blocks;
  blocking requires `hello.min > FLEET_PROTO`; a compatible later `hello`
  **clears** the block.
- `FLEET_PROTO = 1`, `FLEET_PROTO_MIN = 1`, invariant `MIN <= PROTO`
  test-pinned. Both live in `shared/api.ts` beside `PRESENCE_REFRESH_MS`.
- Band boundary: `crit` is `> 75` (DIRECTION.md), not `>= 75`. One writer:
  the screen imports `limitBand` from `LimitBar.tsx`.
- Rescue grep gains `Invalid API key` and `Please run /login` ONLY;
  `Select login method` stays out (it appears during intentional logins).
- Rollout: agent first (ccd ships), then server+PWA.

_lane_enabled() { [[ ! -f "$REG/$1-disabled" ]]; }   # operator kill-switch: touch/rm $REG/<w>-disabled
