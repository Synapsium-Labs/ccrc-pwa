## What changed

- **One list.** `ItemList` is one arm, `{ at: 'waiting', programme: string | null }`; `fromWord` writes `waiting` or
  `waiting:<slug>`; `listOfFromWord` reads an older page's `programme:<slug>` as the combined list filtered to that programme;
  `resolveList` is the one stale-list rule with no exception; `listGroups` has no programme arm; `knownProgrammes` is gone.
  `listPath` has one arm, `waitingPath(list.programme)`.
- **`waitingPath`** (`pwa/src/lib/routes.ts`, beside `programmePath`): the one builder of `/waiting` with its filter.
  `PROGRAMME_FILTER_QUERY` moved there with it.
- **The chip** opens `waitingPath(slug)`; its label reads `N waiting on you in <title>`. The title still opens the programme page.
- **The Goals page** (`ProgrammeScreen`) draws no list: Goals; a card headed "Waiting on you" holding either an
  `N waiting on you` link to `waitingPath(slug)` (the chip's own number, `programmeWaitingCount`) or, at zero, the waits-on
  sentence; and Stored secrets. Goals' modification links name the filtered list.
- **The filtered list's Recently cleared** holds that programme's items only (the Goals page lost its trail), with no
  programme named on each row; filtered to the sessions in no programme it draws none; unfiltered, as before.
- **The item's way back** always reads "Back to Waiting on you" and returns to the list it was opened from, filter included.
- **`sessionProgramme`** (`pwa/src/fleet/runWords.ts`): the one reader of a session's programme, the expression
  `questionRows` held inline; `questionRows` now asks it.
- **The Goals door**: `sessionHeaderView` gains an optional `programme` input and a `goals: { href } | null` output, decided
  once (`programmeIsOpenable`, then `programmePath`). `HeaderDoors` draws it first of the doors, as a keycap with the
  programme's own glyph (`workflow`, the one its box's kicker wears), named "Goals", with its word beside it from 900 like the
  other doors (`chat.css`). Both skins draw it, since both use `HeaderDoors`. `SessionScreen` passes
  `sessionProgramme(live, fleetRuns)`. No new wire field.

## Departures (slugs for the coordinator)

- `pl11-list-path-builder-in-routes`: the list's path builder is `waitingPath` in `lib/routes.ts`, not a second arm in
  `WaitingRoutes.tsx`: `ProgrammeBox` (fleet) cannot import `WaitingRoutes`, which imports `FleetScreen`, which draws the box.
  `PROGRAMME_FILTER_QUERY` moved with it (no other importer).
- `pl11-item-list-keeps-at`: `ItemList` keeps its `at: 'waiting'` field as a single arm, so every caller and the URL word read
  as before, and C4's additions to `WaitingScreen` and `ItemView` slot in unchanged.
- `pl11-stale-programme-view-exception-gone`: follow-up F3's exception (a real programme's view stays that view with no group)
  went with the view. An old `programme:<slug>` link to a programme with nothing on the list now settles on the combined list,
  as a stale filter always did.
- `pl11-cleared-trail-follows-the-filter`: D29's Goals page lists Goals, the waits-on sentence and Stored secrets, not the
  Recently cleared trail; to keep that trail reachable per programme, the filtered list draws the programme's cleared items
  only. This changes what the rail's filter shows for the trail (it showed every programme's).
- `pl11-back-names-waiting-on-you`: the item's way back no longer names a programme's title (that name was the programme
  list's); it reads "Back to Waiting on you" and keeps the filter.
- `pl11-goals-link-only-above-zero`: the Goals page's link is drawn only above zero; at zero the waits-on sentence stands in
  its place, as the spec's "its waits-on sentence" reads. The card's heading lost its count (`Waiting on you · N`), which the
  link now carries.
- `pl11-goals-item-links-filtered-list`: an item opened from Goals (a modification's "Open the item") steps along the filtered
  list and goes back to it, not to the Goals page.
- `pl11-chip-plain-count-kept`: a slug the programme route refuses keeps its plain count, no door, as before: an item opened
  from a list filtered to it could not carry that filter in its `?from=` (`listOfFromWord` reads slugs only).
- `pl11-goals-door-not-in-more-sheet`: the Goals door is not listed in the More sheet (a way out of the session, not an act on
  it; D30's "nothing else in the session's chrome changes"); `HeaderDoors`' comment says so.
- `pl11-goals-link-ghost-anchor`: the Goals page's link stands alone, so it is `GHOST_ANCHOR` on an anchor, not a `TextLink`
  (`tap-targets.test.tsx`'s rule).
- `pl11-claims-beyond-the-brief`: besides the brief's expected files, claimed and edited `pwa/src/fleet/runWords.ts`,
  `pwa/src/session/chat.css`, `pwa/src/screens/SessionScreen.tsx`, `pwa/src/lib/routes.ts`, `pwa/test/skin-switch.test.tsx`
  and `pwa/test/app.test.tsx`. No file was held by another programme.
