# Model classes follow new releases, the Anthropic arm — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Each wave (A2, A3, A4) is one PR, built on the
> dispatched workspace's own branch. Every test step follows superpowers:test-driven-development: the red test first,
> seen failing for the reason named, then the change, then green, then the task's mutation rows RUN, never read.
> Steps use checkbox (`- [ ]`) syntax for tracking. Workers do not edit this file: they write task notes in a new file
> under `docs/superpowers/plans/2026-11-18-model-class-advance-anthropic-arm/`, and the coordinator folds them in.

**Goal:** on an Anthropic lane, ccrc knows which model id each class alias resolves to, labels and effort follow it
when it moves, a class can be held on an id, and doctor names a home ccrc cannot read, all without ccrc ever
re-pinning a class or writing a home's `settings.json`.

**Architecture:** Claude Code's alias resolution is the source of truth (spec §2.5, amended 2026-11-18). One new pure
module, `shared/model-aliases.mjs`, parses Claude Code's catalogue cache and resolves each class's id from the lane's
own cache, else from the id a ccd launch reported. The models writer (`deploy/models-op.mjs`) writes the result to a
per-lane aliases file, hourly, under the lane lock, and admits holds on an Anthropic lane. ccd reads that file
through one cached reader in a new pinned library, `ccd/lib/model-aliases.sh`, to decide effort levels, a held id at
launch, an orphaned effort carried at launch, and an id change on a running session. The server's lane-models read
and the PWA's pickers and Models sheet read the same file through the `models` op.

**Tech Stack:**
- bare `node` `.mjs` modules with hand-written `.d.mts` declarations (`shared/`, `deploy/`);
- bash and jq (`ccd/ccd`, `ccd/lib/*.sh`, `ccd/ccrc`, `ccd/ccrc-doctor-checks`);
- the Fastify server (`server/src`) and the React PWA (`pwa/src`);
- vitest in `server/` and `pwa/`.

**Spec:** `docs/superpowers/specs/2026-10-13-model-class-auto-advance-design.md`, §2.5 as amended on 2026-11-18,
with §2.1 (D21), §2.6 (D17's Anthropic half), §2.7 (D19), §2.8 and §5. The route this plan executes is the Codex arm
plan's "Re-plan of 2026-11-16" (`docs/superpowers/plans/2026-10-15-model-class-auto-advance-codex-arm.md`), rows A2
to A4, with D-8683.

## Global Constraints

- **ccrc never re-pins an Anthropic class** and never writes a home's `settings.json` (spec §2.5, §2.5.7).
- **The one concrete id ccrc puts on an Anthropic launch is a held id**, only while a hold stands (§2.7, D24).
- **Every write of a lane's model files takes the lane-files lock** (`_models_lock_path`, `ccd/ccrc`), through
  `_models_node_locked` (D21). Readers take no lock.
- **Fail shut, and never stop a launch or a tick:** a file that cannot be read gives today's behaviour (class words,
  the haiku rule, the alias at launch), and doctor names it. Two conditions a caller handles differently never fold
  into one value: absent, unreadable and invalid are three answers.
- **Staleness:** a cache older than seven days by its own `fetchedAt` is stale (D25). Its own `staleAt` is ignored.
- **The four WARN names are fixed** (spec §2.8). The new `model-advance-blocked` cause words are exactly
  `alias-source-absent`, `alias-cache-stale`, `aliases-file-unreadable` and `aliases-file-invalid`.
- **No class word and no model id is spelled in shipped source** beyond what the census already allows: classes come
  from `CLASSES` (`shared/models.mjs`), family tokens from `FAMILY_TOKENS`, and ids from data. Test fixtures use
  invented ids (`claude-opus-9-1`, `claude-opus-9-2`, `claude-fable-9-1`), so no fixture goes stale at a release.
- **The repository is public.** Fixtures and notes use `lane-a`, `lane-b`, `home-a`; no real home, account, host or
  organisation id. A cache fixture never carries a credential-shaped name: files are named `tok-fixture-cc.json`.
- **Every test and typecheck runs through `ccrc test -- <command>`**, from inside its package.
- **Mixed-version safe at merge:** each wave is inert on a box whose other half runs the older build. A new key in a
  file an older build reads is additive; an older reader keeps it (`parseAdvance` keeps unknown keys).
- **Cite code by `#@anchor` or `file#symbol`**, never by line number. Every anchor below was measured on
  `origin/main` at `0c610c581` and on #2943's head `22e5a799c` on 2026-11-18; each wave's brief re-measures them.

## Review Focus

1. **A long-running session still on an older id** (one launched before a release and kept open, or one given an
   explicit older id). It must never become a lane's "seen in use" id. "Seen" takes the newest LAUNCH, by the spawn
   stamp, not the newest reading: Task A2.2's test "use takes the newest launch" pins that an old session that
   rendered last does not win, and Task A2.3's test "an effort apply is not a launch" pins that the launch time is
   never the `routeapplied` mtime.
2. **A home holding several cache files** (one per credential, one in each format). The newest current-format file
   wins and an older-format file is never a source (Task A2.1's test "several files"); when that newest file is
   stale, the class falls to use rather than to an older file (Task A2.2's test "stale own cache falls to use").
3. **A lane on a Claude Code build too old for its cache's target** (the Fable case, spec §2.5.8). The label must
   not name a model the lane cannot launch (Task A2.2's test "target needs a newer build").
4. **An unreadable advance or aliases file at launch.** The session launches on the alias, the tick does nothing,
   and one swap.log line says why, floored (Task A3.3's test "unreadable advance file launches").
5. **A hold released while sessions run held.** The released class's launch environment loses its key at the next
   spawn, and a running held session is not typed into (D19); `model-sessions-behind` then names it after a day
   (Task A3.5's test "release is not typed").

### Task A2.2: the resolver and the aliases file's format

**Files:**
- Modify: `shared/model-aliases.mjs`, `shared/model-aliases.d.mts`
- Test: `server/test/model-aliases-resolve.test.ts`, `server/test/model-aliases-file.test.ts`

**Interfaces:**

- Produces: `resolveAliases(input: ResolveInput): Aliases`, with

  `Seen = { class: ModelClass, id: string, launchedAt: string, readAt: string }` and
  `saved` the home's saved levels, model id to level (`modelSettings.<id>.effortLevel`).
- Produces: the file `Aliases = { v: 1, at: string, cache: { fetchedAt: string, format: 'current'|'older' } | { none: 'absent'|'unreadable'|'invalid' }, stale: boolean, classes: Record<ModelClass, AliasClass> }`,
  `AliasClass = { id: string|null, source: 'cache'|'use'|null, row: AliasRow|null, seenAt: string|null, orphaned: { id: string, level: string }|null }`.
- Produces: `parseAliases(json): Aliases` (throws `AliasesInvalid` with a `field`, `AdvanceInvalid`'s idiom),
  `serializeAliases(a): string`, `aliasesSourceCause(a): 'alias-source-absent'|'alias-cache-stale'|null`,
  `ALIASES_VERSION = 1`, `CACHE_STALE_AFTER_MS = 604_800_000`.

- [ ] **Step 1: Write the failing resolver tests**, one per rule of spec §2.5.2:
  - `own fresh cache wins` (source `cache`, the target id);
  - `stale own cache falls to use` (fetched 8 days before `nowMs`: source `use`, `stale: true`);
  - `older own cache falls to use` (`stale: true`);
  - `target needs a newer build falls to use` (`laneVersion` below the row's `minVersion`, compared part by part as
    integers);
  - `use takes the newest launch` (two `Seen` for one class: the later `launchedAt` wins, whatever `readAt`);
  - `use ignores a reading before its launch` (`readAt` earlier than `launchedAt` is dropped);
  - `use ignores another family` (a `Seen` whose id's `familyClassOf` is not its class is dropped);

  - `no source` (no own cache, no `seen`: every `id` null, `aliasesSourceCause` answers `alias-source-absent`);
  - `seenAt` is the newest `readAt` of a `Seen` with that class's current id, else null;
  - `orphaned` names a saved level under an older id of the class's family when `saved` has none under the current
    id, and is null when the current id has one. "Older" means another id of that family that is not the current id.
- [ ] **Step 2: Write the failing file tests:** a round trip through `serializeAliases` and `parseAliases`; each field
  refused by name; an unknown key kept; `v: 2` refused.
- [ ] **Step 3: Run both red** (`ccrc test -- ./node_modules/.bin/vitest run test/model-aliases-resolve.test.ts test/model-aliases-file.test.ts`).

## Deviations found

The departures from the re-plan of 2026-11-16 that this plan makes. Numbers are issued by the programme's
coordinator from its block and written here by the coordinator; until then each is named by slug.

- **`d18-source-own-cache-then-use`.** D18's source is the lane's own catalogue cache, then the id a ccd launch
  reported, with each id's row taken from any cache on the box that lists it (spec §2.5.2). D-8684's roster grouping
  is not built: A0 found no pair of cached homes in one organisation to check a grouping against, and the uncached
  homes record none. Cost if wrong: a home with no cache shows class words until a ccd launch on it is seen.
- **`anthropic-cache-stale-seven-days`.** A cache is stale after seven days by its `fetchedAt` (D25), not by its own
  `staleAt`, which lapses within the hour while Claude Code keeps launching over it. Cost if wrong: a cache between
  one hour and seven days old is trusted for labels.
- **`effort-carry-by-class-and-auto`.** "Effort carried across an id change" (D-8683) is ccd's class-keyed effort,
  plus a session-only carry of an orphaned saved level when the record says `auto` (D23); ccrc never rewrites the
  saved level. Cost if wrong: a launch outside ccd keeps losing a saved level, which the Models sheet names.
- **`anthropic-ops-admitted`.** On an Anthropic lane the models writer admits `rm` and the new `aliases-refresh`
  beside the re-plan's `hold`, `release` and `revert`, and a hold records `hold.model`. Cost if wrong: two more
  admitted ops on a lane kind that refused all but `show`.
- **`a3-measures-first`.** A3 opens with two throwaway-session measurements (Task A3.0) that choose between each
  mechanism and its named fallback. The re-plan named neither. Cost if wrong: A3 waits for the operator's go.
- **`effort-rule-both-kinds`.** The effort-level rule reads a Codex lane's registry and catalogue too (spec §2.5.4's
  own reason), though the re-plan placed A3 as "Anthropic ccd". Cost if wrong: a Codex lane's `haiku` class accepts a
  level its model lists.
