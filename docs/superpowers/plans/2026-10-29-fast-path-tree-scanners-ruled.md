# The fast pull-request path runs the whole-tree scanners: ruled

- **D-7455 (2026-10-29)** — the fast pull-request run (`.github/ci/fast-plan.mjs`) adds to its guard set every server test that lists a source tree itself — `server/src`, `shared`, `pwa/src`, `agent/src` or `ccd`, through `readdirSync`/`readdir`/`opendirSync`/`globSync`/`glob`, a walker the file defines, or a census helper's walker or scanner under `server/test/` (`scansSourceTree`) — when its file took at most `SCANNER_MAX_MS` (10 s) on the last full run, or has no measured duration. Before this, a whole-tree ratchet passed a pull request's run and failed only in the merge queue: `fleetio-contract.test.ts`'s plain `io.readdir(` ratchet walks `server/src` and reads every file as text, so vitest's import graph relates it to no change, and the guard rule (patterns, `TREE_READER`) did not name it. That ejection cost a queue slot and a re-run. The rule finds scanners by shape, not by name: a source root spelled as a literal (the directory itself, never a file or subdirectory under it, and never one joined onto a base that does not name the repository, so a fixture's `join(home, 'ccd')` is not the tree), a name bound to one (a `const` for the rest of its block, a loop or array callback for its body), and a lister called on it or handed to an iteration over roots. Comments are blanked first. Measured against the `testtimes` artifact of the 2026-10-29 main run: the guard set grows from 93 to 143 files (+50), from 431 s to 507 s of summed file time (+76 s), and the guard-only plan packs into 3 shards instead of 2. The cap leaves 8 scanners to the merge queue because the plan runs files, not cases, and each scan case sits inside a long fixture suite (17 s to 248 s a file, 674 s together): `ccrc-account`, `ccrc-install-graphify`, `coord-store`, `delegation-recovery`, `delegation-wave3.integration`, `lane-draft-never-blocks`, `mail-sweep` and `run-routes`. The step summary names each one that did not run. Moving each of those scan cases into a small file of its own would put it on the fast path with no change to this rule. `PIN_MAP_CARRIED` stays out of the guard set even when it scans.
