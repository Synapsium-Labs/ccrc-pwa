# Accounts connect A16: the box half of W2a

**Goal:** plan Task A16 of `2026-10-18-accounts-connect.md` (spec §3.3, §3.9, §6.3, §11, §13.3; G4, G5, G20; D-5513, D-5518). The fleet box gets the write subs the first PWA wave needs: an Anthropic token pasted or replaced is validated before anything is written, a re-added id does not inherit an old lane silently, `set` records a token lane's stated account and a lane's placement, and Remove gains its pre-check, Discard, the sleeping-session rule, the sign-in guard, the scratch sweep and the provider ledger. `ccd caps` advertises `account-v2` so the server offers them. OA1's record (`2026-11-01-accounts-oa1-record.md`) decides one branch: G23 was not measured, so a sign-in lane's ledger row says `unmeasured`. The numbers this task was gated on (N3, N4) and its as-built decisions are defined below.

**Before this change:** a pasted Anthropic token was written to `<id>-oauth.env` before anything checked it, so a mistyped token became a lane. The credential reader took stdin's first line only. `add` defaulted every config dir to `.claude-<id>` (so `claude-a` became `.claude-claude-a`) and provisioned into a config dir that already existed. No verb wrote a stated identity or changed `homeAble`. `remove` rehomed a hibernated row onto upstream, where it would wake, had no pre-check, no Discard and no guard against a sign-in in flight, left `~/.ccrc/auth-scratch/<id>`, and its answer said nothing about the provider. No box answer carried fingerprints, and `added` carried no `fleetIdentity`, so `reloadRoster` refused it.

**Change:**
- `ccd/ccrc`:
  - `_acct_read_credential` reads the whole of stdin, drops one trailing LF and refuses `key-charset` on any other C0 byte, DEL, a NUL or more than 8 KiB.
  - `_acct_token_probe`: one turn through the upstream launcher with the candidate as `CLAUDE_CODE_OAUTH_TOKEN` and a throwaway `CLAUDE_CONFIG_DIR` under `~/.ccrc/auth-scratch`, classified by the check's own classifier. `add` (paste and setup-token) and `credential` call it before any write, for every lane whose secret is `CLAUDE_CODE_OAUTH_TOKEN`.
  - `_acct_add_parse` takes `--adopt` and defaults the suffix by the G4 rule; `add` records `addedAt`; `enable` records `enabledAt`.
  - `_acct_live` also lists the rows on the lane that are asleep (`.hibernated`) or archived (`.archived`) and have no pane.
  - `remove` takes `--mode remove|discard`, `--dry-run` and `--rehome-sleeping`; runs the `pre-remove` gate after the live census; deletes `auth-scratch/<id>`; and passes the lane's kind to `removed` for the ledger.
  - `set --id [--stated -] [--placement overflow|full]` is a new sub.
- `deploy/account-op.mjs`:
  - `check-add` takes `--home` and `--adopt` and refuses `config-dir-exists` with what it measured; `defaultSuffixOf` is the suffix rule.
  - `pre-remove` measures the sign-in in flight and the lane state, answers the dry run and gates the removal; `set-placement` writes `homeAble`; `set-done` answers `set`.
  - `fingerprintsOf` computes D-5996's rows from the box token; `roster`, `added`, `rotated` (given `--file`), `removed` and `set-done` carry `fleetIdentity` and, with a token, `fingerprints`; `removed` carries `atProvider`.
  - `lane-state` takes `--identity -` (stdin), `--added-at` and `--enabled-at`.
- `ccd/ccd`: `cmd_caps` prints `account-v2`.
- `shared/account-argv.ts`: `remove`'s `mode` takes `check`, written `--dry-run`; `set`'s stated identity rides stdin as `--stated=-`, so the `stated` field is gone.
- `README.md` documents the validate-first read, `--adopt`, `set` and the new removal rules.

**Tests:**
- New: `server/test/ccrc-account-paste.test.ts`, `server/test/ccrc-account-remove-v2.test.ts`, `server/test/ccrc-account-set.test.ts`.
- Extended: `server/test/ccrc-account.test.ts` (the suffix rule, `config-dir-exists` and `--adopt`, `ccd caps`, and the cases that paste or replace an Anthropic token, which now plant an upstream launcher that answers the probe); `agent/test/account-argv.test.ts` (`--dry-run`, `--stated=-`); `server/test/account-ops.test.ts` (the stated identity on stdin); `server/test/ccdCapTokens.ts` (`account-v2` is a capability, not a verb); `ccrc-account-lane-state.test.ts` and `ccrc-account-lock.test.ts` (`addedAt` after `add`).
- Every new row was run red against `main`'s `ccd/ccrc` and `deploy/account-op.mjs` before it was run green.

## Decisions

- **D-7733 (2026-11-01)** — `remove-counts-sleeping-sessions` (N3; accounts plan Tasks A16, A19): `_acct_live` counted a session live only by its tmux pane, and `remove` rehomed every row naming the lane, so a hibernated session (D-5242) on a removed lane was rehomed onto upstream and woke there. `_acct_live` now also lists, by their files, the rows on the lane with no pane that are asleep (`.hibernated`) or archived (`.archived`), and `remove` refuses `sleeping-sessions` with the sleeping ids, after the live census and before anything is rehomed. The CLI's `--rehome-sleeping` keeps the old behaviour, and no route sends it (the argv builder has no field for it). Discard refuses a lane with a sleeping session too. A row is counted by its `.wrapper` field, as `_acct_live`'s live count is; a row whose `.home` alone names the lane is rehomed as before, because it does not run on the lane. An archived row is still rehomed onto upstream by a removal, as spec §11.2 says.
- **D-7734 (2026-11-01)** — `account-caps-per-wave` (N4; accounts plan Tasks A16, A20, A24, A26, A28, A30, A32): `ccd caps` prints `account-v2` from this task on, the word `ACCOUNT_CAPS` already names and `connect.accountOps` already reads (A12), for W2a's subs: paste validate-first, `credential` validate-first, `set`, and Remove's pre-check, Discard and gate. It is advertised after G1 (A13), G3 (A15) and G4, G5 and G20 (this task), and without G2 only, which is W2c's. Each later wave appends its own word to `ACCOUNT_CAPS` (`account-auth-v1`, `account-codex-v1`, `account-openrouter-v2`, `account-or-pkce-v1`, `account-or-management-v1`, `account-or-mint-v1`), so the door and each method narrow in place by the word they need. `account-v1` stays as the wave-1 marker. `account-v2` is a capability, not a verb, so it joins `CCD_CAPABILITY_TOKENS`.
- **D-7735 (2026-11-01)** — `box-w2a-as-built` (accounts plan Task A16; spec §3.3, §3.9, §6.3, §11, §13.2, §13.3): the as-built decisions of A16, and where it departs from the plan's wording.
  1. **What is validated first.** Every lane whose secret is `CLAUDE_CODE_OAUTH_TOKEN`: `add --method paste`, `add --method setup-token` with `--credential -`, and `credential`. OpenRouter's validation is A26's and a `compatible` key has no probe of its own, so neither changes here. The probe is the check's own command and classifier, run through the upstream launcher (the program every generated wrapper execs) with the candidate in its environment, a config dir created for it under `~/.ccrc/auth-scratch` (outside every agent read root, removed when the probe ends and by the TERM trap) and `~/.ccrc/probe` as its working directory. `ok` goes on; `auth-dead` refuses `key-rejected`; any other verdict (unreachable, a timeout, an answer the classifier cannot read) refuses `token-unverified`. Both are class 1 and come before any write, so nothing exists afterwards: no key file, temp, roster entry, marker, config dir or lane state. The probe spends one minimal turn, as `check` does.
  2. **The byte check.** `_acct_read_credential` reads the whole of stdin up to a bound, not its first line, so a value carrying a newline can no longer pass as its first line. One trailing LF is dropped, because that is what `echo` or `printf '%s\n'` into a pipe adds and the CLI has always taken it. Any other C0 byte (CR, TAB and NUL included), DEL, or more than 8 KiB refuses `key-charset` at class 2, for every provider and every caller of the reader. A NUL is detected because bash's NUL-delimited read stops at it.
  3. **`credential` keeps the old file and its check until the new token passes.** The probe runs before `--clear check` and before the write, so a refused replacement leaves the lane's state as it was, not Not checked.
  4. **Re-add safety (G4, G20).** The default suffix is `.claude-<id>`, or `.<id>` when the id already starts `claude-`; both halves spell it (`_acct_add_parse`, `defaultSuffixOf`), and the existing agreement case holds them equal. A suffix another roster entry holds is `suffix-collision`, as before. An existing `$HOME/<suffix>` refuses `config-dir-exists` (class 1) with `found: {signedIn, identity}`: signed in when its `.credentials.json` is there, and the account its `.claude.json` names in `oauthAccount.emailAddress` when that is printable, never a credential's bytes. `--adopt` proceeds onto it. The check runs in `check-add` when `--home` is given, which `add` always passes; a hand call without `--home` checks the roster only, as before.
  5. **"Never enabled" is recorded.** The lane state gains two box-only fields, `addedAt` (written by `add`, in the fresh write) and `enabledAt` (written by `enable`). The server's reader names neither and drops both. A lane is discardable only when `addedAt` is recorded and `enabledAt` is not, its marker holds it off, it is not upstream, and it has no live, sleeping or archived session. A lane added before this build has no `addedAt`, so it is never discardable, which costs it only Discard's skipped confirm.
  6. **A sign-in in flight** is `ccd-account-auth`'s status file, `~/.cc-sessions/.auth/<id>.json`, in `starting`, `url`, `waiting-code` or `exchanging`, written within 660 s (the attempt's `RuntimeMaxSec`, D-5515). A file a killed helper left in a live state past that is not an attempt, so it never blocks a removal for good. A20 adds the attempt id; this reads only the state and its time. `remove` refuses `auth-in-progress` before the sleeping rule and Discard's.
  7. **The pre-check.** `remove --dry-run` (the agent's `mode: 'check'`) runs before the lane lock, takes no lock and writes nothing, and answers `{ok, id, dryRun: true, live, sleeping, archived, upstream, otherHomeAble, authInProgress, discardable, at, fleetIdentity}`: `live` and `archived` are counts (`live` is `null` when tmux could not be asked), `sleeping` the ids, `otherHomeAble` the count of lanes still placeable without this one (`_acct_placeable`'s rule: home-able, an executable launcher, no marker). It refuses only what makes the question meaningless (a bad or unknown id).
  8. **The ledger.** `removed` answers `atProvider: [{kind, state, revokeAt}]` for the lane's credential kind, decided from the roster fields read before the drop: `anthropic-token` (`still-valid`, `claude-code-settings`), `anthropic-sign-in` (`unmeasured`, `claude-account-settings`), `openrouter-key` (`still-valid`, `openrouter-keys`), `api-key` (`still-valid`, no page), `codex` (`still-valid`, `chatgpt-settings`), and `[]` for a declared launcher. `revokeAt` is a word the sheet maps to its link; the box never answers a URL. The sign-in row follows OA1's G23 record: not measured, so `unmeasured`, never `ended` and never `still-valid`. A minted OpenRouter key's row is A32's.
  9. **`set`.** `--stated -` reads 1 to 120 printable characters from stdin (one trailing LF dropped), never from argv, because it names a person; `--stated <value>` and `--stated=<value>` refuse `stated-not-stdin`, and a control byte or an empty value `bad-stated`. It is written through the one lane-state writer as `identitySource: stated`, whose own rule refuses more than 120 characters. A sign-in lane refuses `not-a-token-lane`: its account is measured by `check`, and `enable`'s readiness reads that measured identity. **This departs from the A8 builder**, which wrote `--stated=<value>` on argv: `set`'s row now takes stdin and writes `--stated=-` when the caller carries it, so the stated identity rides `stdinB64` like a secret. `--placement full|overflow` writes `homeAble` under the placement lock, regenerates `accounts.sh`, and refuses `last-home-able` when taking the only placeable lane out. `--limit` and `--limit-reset` are A32's and still refused here.
  10. **The UI path.** The argv builder has no field for `--keep-credential` or `--rehome-sleeping`, so every removal the PWA sends deletes a token or key file and signs a sign-in lane out (`claude auth logout` in its config dir, then the `.credentials.json` removed), and refuses sleeping sessions. The builder's `remove` writes `--mode=remove|discard`, which the verb now parses, and `--dry-run` for `check`. `--delete-codex-auth` is A24's and still refused by the verb. The plan names `agent/src/accountop.ts` for the `--dry-run` spelling; since A8 the argv builder is `shared/account-argv.ts`, the one both `AccountOps` arms call (D-5622), so the change is there and the agent's op is unchanged.
  11. **Fingerprints.** The box computes D-5996's rows itself: the box token is `~/.cc-secrets/ccrc-mail.token` read by `extractToken`'s rule; each generated lane's secret is read (never sourced) from its secrets file's `export <VAR>=` line, unquoted from bash's `%q` or the setup-token capture's bare form, its trailing `=` stripped, and kept only between 20 and 8192 bytes. `gen` is `fingerprintGeneration`'s digest. `ccrc-account-paste.test.ts` holds the box's rows equal to `server/src/accounts/mask.ts`'s `fingerprintRow`. Every answer that carries the roster carries `fleetIdentity`, and `fingerprints` when the box has a token: `roster`, `added`, `rotated` (with `--file`, which `credential` passes), `removed` and `set`'s. A box with no token answers no `fingerprints`, rather than rows keyed with nothing. Codex lanes' secrets are A24's.
  12. **The growth check.** `ccd/ccrc` grows past the 40-line limit, so this PR adds the waiver `server/test/growth-waivers/D-7735-ccd-ccrc.json`. The decisions live in `deploy/account-op.mjs` where they can (the gate, the ledger, the suffix rule, the config-dir measurement, the fingerprints), and bash measures and orders the steps: the TERM trap, the locks, the tmux census and the probe's environment are bash's.
