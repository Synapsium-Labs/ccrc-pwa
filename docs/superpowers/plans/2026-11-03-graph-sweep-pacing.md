# Pacing the graph sweep

- **D-7876 (2026-11-03)** — the graph sweep is paced three ways, so a pass never starts in the second the previous one ended, never swaps without limit, and does not start while the host is thrashing. Measured on one fleet day: the sweep ran 27 times, each pass starting in the same second the previous one finished (`OnUnitActiveSec=15min` under passes that ran 15 to 92 minutes), two passes ended in timeouts, and the sweep's unit carried `MemorySwapMax=infinity`.
  1. **The timer counts from the end of the previous pass.** `deploy/systemd/ccd-graph-sweep.timer` uses `OnUnitInactiveSec=` in place of `OnUnitActiveSec=`, so the period (`CCRC_GRAPH_REFRESH_SECS`, default 15 minutes) is the minimum gap between passes. `_inst_graph_timer` renders the new key (its "exactly one … line" check names it), and `_check_graphify`'s unit-drift arm compares it, so a box whose installed timer still carries the old key is told to run `ccrc update`. ccrc's one timer-period reader, `_timer_period_s`, reads an `OnUnitInactiveSec=` cadence line with the same spellings as `OnUnitActiveSec=`, since the doctor's cadence helpers read the shipped graph timer through it.
  2. **A finite swap cap on the sweep's unit.** `deploy/systemd/ccd-graph-sweep.service` gets `MemorySwapMax=512M` beside its `MemoryMax=6G`. The builds run in `ccrctests.slice` under that slice's own caps; this caps the sweep's own git, jq and bookkeeping, so a pass that reaches its memory cap fails cleanly. The renderer touches only `TimeoutStartSec=`, so the installed unit carries the line byte for byte.
  3. **A pass under host pressure is deferred.** A new graph setting, `CCRC_GRAPH_PRESSURE_MAX` (a whole percentage, 0 to 100; default 60; 0 turns it off), read through `_graph_knobs` and validated by `ccd/graph-resolve` like every graph setting, and documented in `deploy/ccrc.env.example`, spec §5.4 and README. Once its settings are read, after the pass lock and the pause file (which keeps its precedence) and before the pin, the store, any fetch or any build, the sweep reads the host's PSI `some avg10` for memory and then CPU. Above the limit the pass ends with the new pass status `deferred-pressure`, its reason (the resource, the reading and the limit) in the census and on stderr, which is the unit's journal. The reading is ccrc's one pressure reader, `_psi_over <max> <knob>` in `ccd/ccrc`, moved there from `ccrc test`'s heavy queue (whose `_tpressure` now calls it), under the same `CCRC_PROC_ROOT` fixture seam. The default, 60, leaves an ordinary busy box alone: a stall on more than half of the last ten seconds is thrash, not load.
  4. **A run of deferred passes is one census entry.** The census keeps 10 passes, and every repository's backoff and budget order are read from the rows of the passes it keeps. A deferred pass that follows another replaces it, with `deferrals` counting the run and `deferred_since` keeping its first start, so a box under pressure for hours cannot push the earlier passes, and their rows, out of the census. No other pass status changes how the census is kept.
  5. **The doctor names the last pass.** Every `graphify` verdict line names the last pass's status and how long it ran (`finished - started`), for example `last pass ok in 42 s`, and a deferred pass's run and reason; a stamp that does not parse says the duration is unknown, and a box with no census says nothing. A deferral is reported, never a finding of its own.

  Not changed: the build path, the store layout and the backoff rules; the shallow-source checkout (D-7791); the pause file's precedence. The rows are in `server/test/graph-repo-sweep.test.ts` (the D-7876 describe, against a fixture `CCRC_PROC_ROOT`), `server/test/ccrc-install-graphify.test.ts`, `server/test/ccrc-doctor-graphify.test.ts`, `server/test/timer-period.test.ts`, `server/test/graph-knobs.test.ts` and `server/test/census-w8/cadence.test.ts`. The suites that run the real sweep (`graph-repo-sweep`, `graph-migrate`) point `CCRC_PROC_ROOT` at an empty fixture root, so the host they run on never defers a pass.
