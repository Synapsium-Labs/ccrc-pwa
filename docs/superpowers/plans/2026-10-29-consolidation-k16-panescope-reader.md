## What the measurement found

Measured on `b9f672354`; each item names its census (all in C5l), so a later task reads the same number.

1. **The marker has one writer and one reader, and both are in `ccd/ccd`.** `ccd/ccd#_panescope_record` (C2 in `ccd/contexts.tsv`, called once, from `_spawn_start`, "once per spawn, after the pane exists") reads the first pane's pid (`tmux list-panes … | head -1`), that pid's `/proc/<pid>/cgroup` line through the seam `_panescope_proc_root`, and writes the unit's basename through `_reg_set "$id" panescope "$unit"` when it is a `.scope` in the charset `[A-Za-z0-9@._:-]`; otherwise it removes a stale marker (`rm -f -- "$REG/$id.panescope"`). One body, two writes. `_reg_purge`'s suffix glob also removes the marker when a row is retired, as it removes every `$REG/<id>.<field>`; it names no field and is reported apart, not counted. The one reader is `ccd/ccd#_end_cause` (`_reg_get "$id" panescope`), called only from `_end_note_gone`, the supervise loop's `gone` exit, which asks the scope's journal for an OOM line in the last 120 s (D-5237). The suites that hold it are `server/test/ccd-restart-cause.test.ts` (24 cases; its `_spawn_start records the pane scope once` block holds the writer) and `server/test/ccd-spawn-split.test.ts` (the seam). Census: `panescopeReaders()` 1, `panescopeWriters()` 1.
2. **The cap does not read the marker, and could not without capping less.** `ccd/ccd-cap-scopes` is 67 lines, 10 of them code. Its whole decision: `for s in $(systemctl --user list-units --no-legend "tmux-spawn-*.scope" 2>/dev/null | awk '{print $1}')`; `cur=$(systemctl --user show "$s" -p MemoryMax --value 2>/dev/null || true)`; `[ "$cur" = "infinity" ] || continue`; `systemctl --user set-property --runtime "$s" MemoryHigh=8G MemoryMax=12G MemorySwapMax=2G TasksMax=4096 2>/dev/null && capped=$((capped+1))`; one line `capped N new pane scope(s)` when N > 0; `exit 0`. It caps **every** pane scope in **every** slice, which is the lesson of its own header: when D-307 moved the panes to a bare `app.slice`, this per-scope cap was "the one piece of the guardrail that did not have to change". A cap that took its set from the marker would leave uncapped: every pane but a session's first (`_panescope_record` reads `head -1`); every pane whose record found no scope (a pid already gone, an unreadable cgroup line); and every scope in the window between a pane's birth and the record. Each of those is a scope that can grow without bound. No test runs `ccd-cap-scopes`: the files that name it test its installation (`ccrc-install-tree.test.ts`'s byte-equality row, `ccrc-install-units.test.ts`, `ccrc-uninstall.test.ts`), its timer in the doctor (`ccrc-doctor-core.test.ts`), or cite its 12G in a comment (`ccd-tmux-server.test.ts`). Measured by running it against a stub `systemctl` on PATH on a scratch copy (then discarded): the argv and outcomes in C5l's table rows are what it did.
3. **The stop does not read the marker either, and must not.** `ccd/ccd-scope-sweep` (437 lines, 244 code) lists with `systemctl --user list-units --no-legend --plain 'tmux-spawn-*.scope'`, re-checks each name (`[[ "$u" == tmux-spawn-*.scope ]]`, so `ccrc-tmux-server.scope` never passes), keeps only units whose `Slice` is the session slice and whose `Description` parses, and judges a scope DEAD when none of its processes is a live pane of the server that launched it. Its targets are exactly the scopes whose pane is gone, and a pane is mostly gone because its session was reaped, which is when `_reg_purge` removes that session's marker. So a sweep that took its set from the marker would never see most of what it exists to find. `server/test/scope-sweep.test.ts` (1099 lines; 74 literal `it(` lines and six `it.each` tables, which vitest counts as **95 cases**: `Tests  95 passed (95)` measured on `5ed1acce9` as a non-root user, and `94 passed | 1 skipped (95)` as root, because of the one `it.skipIf(process.getuid?.() === 0)` case) pins every predicate, the shadow, the budget and the record.
4. **What the two acts do share is systemd's list of pane scopes, read with different filters on purpose.** The cap over-includes: every slice, no name re-check, no `Description` check, failing toward capping. The stop under-includes: the session slice only, ccd's server only, every unmeasurable value a `carry`, failing toward not stopping. That is the catalogue's "opposite safety direction" reason, the same one W5 recorded for the reap and reclaim attic pins (D-7074's sentence). The shared part is one pipeline, `systemctl --user list-units --no-legend [--plain] 'tmux-spawn-*.scope'`. Census: `paneScopeListers()` 4 sites in shipped programs, two that act (`ccd/ccd-cap-scopes`'s and `ccd/ccd-scope-sweep`'s top level) and two read-only (`ccd/ccrc-doctor-checks#_check_scopes`, `#_check_oom-policy`); `paneScopeActs()` 2 (the cap's `set-property --runtime`, the sweep's `stop --no-block`), no other `set-property` or pane-scope `stop` in `ccd/`.
5. **One measured gap in the cap, pinned and not fixed here.** Without `--plain`, `systemctl list-units --no-legend` prints the `●` glyph in the first column of a unit in the failed state, so the cap's `awk '{print $1}'` hands it `●`: measured, the script then asks `systemctl --user show ● -p MemoryMax --value` and never caps that line's unit. The sweep (`--plain`) and `ccd/ccd#_svc_list_sessions` (`--all --plain --no-legend … | awk '{print $1}'`) do not have this gap; the doctor's two listers read `--no-legend` without `--plain` and do. By systemd's unit model a failed scope has been stopped, so the gap has no memory consequence measured here; C5l pins today's behaviour as a named row, so any change to it is a visible diff. Under OA-C21 (b) it closes as a side effect (C5n).
6. **A comment the cap's tests must not believe.** The cap's loop comment says "An empty result means the unit vanished between list and show". The doctor's `_check_oom-policy` header records the opposite measurement: "`systemctl show` of a unit that is not loaded answers the manager's default", which for `MemoryMax` is `infinity`. So a vanished unit may reach `set-property`, which then fails and is not counted. C5l pins both answers (empty: no `set-property`; the default `infinity` with a failing `set-property`: not counted, silent, rc 0), so neither reading is assumed.
7. **The two units are already separate, as the Verdict requires.** `ccd-cap-scopes.timer` (`OnBootSec=45s`, `OnUnitActiveSec=60s`) and `ccd-scope-sweep.timer` (`OnActiveSec=2min`, `OnUnitActiveSec=60s`, with the comment "Its OWN timer, never ccd-cap-scopes'"); each service's `ExecStart` names its own script; neither unit file names the other's unit in an ordering or dependency directive; neither script runs the other. Nothing pins that today except the sweep's prose. C5l pins it.

## Review focus (the failure modes most likely to bite)

1. **A cap decision that moved.** The cap has six: what it lists (the glob, every slice, the first column), what it asks (`MemoryMax`, by unit name), what counts as uncapped (exactly `infinity`), what it sets (four properties, `--runtime`), what it counts (a successful `set-property` only) and how it ends (rc 0, silent unless it capped). Each has a table row and a mutant (C5l Step 4). Reviewers read every row of the cap verdict table at base and tip and ask of each mutant whether a weaker cap would still pass.
2. **A cap set narrowed by a filter that looks harmless.** A slice filter, a `Description` check, a name re-check stricter than the glob, or a marker lookup each reads like tidying, and each leaves some scope uncapped. The cross table's "another slice", "a second pane no marker names" and "a reaped session's dead scope" rows exist for this.
3. **A harness move that edits an assertion.** C5l Step 2 moves `scope-sweep.test.ts`'s fixture builders; if one `expect` line or `it` title differs, the move is refused.
4. **A stub that answers what the script assumes.** The `systemctl` stub honours the `list-units` pattern argument (so a widened glob is caught) and the `--plain` flag (so the `●` row is real), answers `show … -p MemoryMax --value` for the cap and the multi-`-p` form for the sweep, and models both answers for a vanished unit (item 6).
5. **Coupling by the back door** (C5n only). A generated copy must be bytes in each script, stamped; a `source` line, a shared runtime file or a call from one script into the other is refused.
