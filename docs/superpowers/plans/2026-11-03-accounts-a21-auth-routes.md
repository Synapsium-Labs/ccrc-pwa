# Accounts connect A21: the sign-in routes, the in-memory attempt, the URL allowlist and the sign-out act

**Goal:** plan Task A21 of `2026-10-18-accounts-connect.md` (spec §3.7, §3.8, §6.2, §9, §13.1, §13.2; D-5514, N2, N5; G17). The server gets the half of the sign-in the box half (A20) waits for: `POST /api/accounts/:id/auth/start`, `GET /api/accounts/:id/auth`, `POST …/auth/code` and `POST …/auth/cancel`, the attempt they share, kept in memory, N2's check of the helper's status file before the server answers it, `LaneWire.authAttempt`, and N5's sign-out act as `POST /api/accounts/:id/credential {signOut: true}`. OA1's record (`2026-11-01-accounts-oa1-record.md`) decides the allowlist: the `login` host and code shape are measured and read here; the setup-token code shape and the Codex host and device code are not, and D-7792 says what each one does until they are. The numbers this task was gated on (N2) and its as-built decisions are defined below.

**Before this change:** no route started, read, fed or cancelled a sign-in. The box could run one (A20), but only from its own shell; the connect sheet narrowed Mint and Sign in because the server's `ACCOUNT_CAPS` did not know `account-auth-v1`. `credential` had no field that became `--sign-out`.

**Change:**
- `server/src/accounts/attempts.ts` (new): the in-memory attempt store (`AuthAttempts`: one attempt per lane, `{attemptId, sessionIdHash, method, startedAt, expiresAt, node}` plus the last state read, whether its code went and whether it ended; an expiry timer per attempt on an injectable clock) and N2's pure verdict on the status file (`authStatusVerdictOf`).
- `server/src/accounts/routes.ts`: the four sign-in routes (`registerAccountAuthRoutes`), the `{signOut: true}` form of the credential route, and the verb codes the sign-in verbs answer (`bad-code`, `code-already-sent`, `no-auth-attempt`, `not-a-sign-in-lane`, and `auth-unsupported-here` with its reason).
- `server/src/accounts/gate.ts`: a pass also carries the session's whole `idHash` (`sessionIdHash`), the one input "the same session" needs.
- `server/src/server.ts`, `server/src/deps.ts`: one `AuthAttempts` per server (or the test's, `deps.authAttempts`), closed with the server; the status file read over the existing measured read (the agent's `read` op in remote mode); `GET /api/accounts` sets `LaneWire.authAttempt`.
- `shared/accounts.ts`: `AUTH_METHODS`, `AUTH_STATUS_STATES`, `AUTH_HELPER_BOUND_MS`, `AUTH_URL_HOSTS`, `AUTH_CODE_SHAPES`, `AUTH_USER_CODE_SHAPES`, `authUrlVerdict` and `authCodeShapeOk`.
- `shared/api.ts`: `ACCOUNT_CAPS` gains `account-auth-v1` (D-7750 (10)); appended at the foot: `ACCOUNT_AUTH_REFUSALS`, `AUTH_UNSUPPORTED_REASONS`, `LaneWire.authAttempt` (an interface merge), and the bodies and answers. `shared/refusal.ts`: the nine words and their statuses.
- `shared/account-argv.ts`: `credential` takes `signOut`, written `--sign-out`.

## Decisions

- **D-7792 (2026-11-01)** — `auth-url-allowlist` (N2; accounts plan Task A21; spec §3.8): what the operator is asked to open is validated by the server. `GET /api/accounts/:id/auth` answers the helper's status file only when it echoes the server's `attemptId`, names a state of the helper's vocabulary with an ISO `updatedAt`, and every `url` it carries is `https`, has no user name, password or explicit port, and names a host in the method's EXACT list (`AUTH_URL_HOSTS`, never a suffix); every `userCode` must match its method's shape. A URL is checked in every state, terminal ones included. Anything else ends the attempt (`auth-cancel` at the box, an `auth-url-untrusted` audit row, the attempt forgotten) and answers `auth-url-untrusted` with no URL. The answer's `url` is the parser's spelling and its `host` the parsed `hostname`, never the file's text. A read that fails is not a rewrite: it answers `unmeasured` and the attempt stands. **OA1b's record, applied:** `login` and `setup-token` are `claude.com` only (measured, `/cai/oauth/authorize`; the spec's `claude.ai` and `platform.claude.com` were not seen, so they are not listed). The `login` code is the measured shape (48 alphanumerics, `#`, 43 base64url characters). The setup-token code shape is pending, so it keeps the spec's provisional `^[A-Za-z0-9._#-]{8,512}$`, which both measured `login` samples match. The Codex host and `userCode` were not measured (the provider refused the request), so `openai-login` has no host and no device-code shape, and `auth/start` refuses it `method-unmeasured` before anything runs, rather than start a sign-in whose every URL the server would refuse; a box run that measures it adds the host and shape here. `openrouter-pkce` never reads a URL from the file (spec §3.8) and is its own wave's (`unsupported` here).
- **D-7793 (2026-11-01)** — `auth-routes-as-built` (accounts plan Task A21; spec §3.7, §6.2, §9, §13.1, §13.2; D-5514, N5): the as-built decisions of A21, and where it departs from the plan's wording.
  1. **The cap.** The four routes take the account gate on `account-auth-v1`, which `ACCOUNT_CAPS` now names (D-7750 (10)), so `connect.caps` offers it and the connect sheet stops narrowing Mint and Sign in; the sheet still runs only paste (`sheetRuns`), so those two read "needs an app update" at Continue until A22. `auth/start` steps up; `GET …/auth`, `auth/code` and `auth/cancel` do not (the step-up was taken at the start, spec §3.7).
  2. **The attempt.** The server generates the id (`randomBytes(16)`, 32 hex) and keeps it in memory with the starting session's whole `idHash`, which the account gate's pass now carries. `expiresAt` is `startedAt + 600 s`, measured before the op is sent: the helper publishes no provider expiry, so its 600 s bound is the earlier of the two, and the server's deadline is never later than the helper's. At `expiresAt` the store hands an attempt that has not ended to the routes, which issue `auth-cancel` with the server as the actor (`ccrc server`) and forget it; an attempt whose terminal state the server read is forgotten without a cancel. A second start while one is live refuses `auth-in-progress` before any op. A start whose outcome is unknown (a timeout, a lost answer, or an answer that does not name the attempt) keeps the attempt, so the sheet can poll it and the expiry cancels it, and its `outcome-unknown` carries `attemptId` and `expiresAt`.
  3. **The same session.** `auth/code` refuses a session other than the starter's with a new word, `not-your-attempt` (403), not `no-auth-attempt`: the operator is the one user (the single-user threat model), and the screen can then say the sign-in was started on another device. `auth/cancel` takes any signed-in session (it only stops something), but needs the attempt's id, which only the starter was answered.
  4. **The code.** Checked by its method's shape (`bad-code`, 400; nothing is sent and the attempt still takes a good code), then by the stdin bytes rule, then sent once on the op's stdin and zeroed when the op answers; masked out of every refusal's extras. One code per attempt: the server refuses a second `code-already-sent` before any op, and also after a send whose outcome is unknown. The audit row is `auth-code ok` or `auth-code refused <word>`, and carries no value.
  5. **The node.** The attempt records `fleetIdentity` at the start. Every later call refuses `node-changed` (409) when the node answering now differs, before any op, so a code never reaches another node; a start or a code whose answer names another node is refused too, and a start so refused is cancelled. A node change forgets the attempt.
  6. **`LaneWire.authAttempt`** is `{state, expiresAt, mine}` from the server's memory: the last state the server read (`starting` until the first poll, `exchanging` once the code went), on `GET /api/accounts` only, for the session verdict only.
  7. **The answer.** `GET …/auth` answers `{ok, state, url?, host?, userCode?, failure?, updatedAt, expiresAt}`: the URL and device code only in `url` and `waiting-code`, the states the operator acts on, and `failure` the helper's `error` on `failed` only when it is a plain word, never a sentence (spec §6.2's "the text comes only from the refusal code").
  8. **The sign-out (N5, D-7749).** `POST /api/accounts/:id/credential {signOut: true}` (step-up; no other key) runs `credential --sign-out` through the argv builder's new `signOut` field and answers `{ok, signOut: 'removed'|'absent', lane}`; its audit act is `credential`, since the closed act list has no sign-out of its own. Nothing is said about the provider: G23 is unmeasured.
  9. **The words.** `ACCOUNT_AUTH_REFUSALS`: `bad-code` 400, `not-your-attempt` 403, `code-already-sent`, `no-auth-attempt`, `auth-url-untrusted`, `method-unmeasured`, `node-changed` and `not-a-sign-in-lane` 409, `auth-unsupported-here` 501 with its `reason` from `AUTH_UNSUPPORTED_REASONS`. Every other verb code of the sign-in verbs (`auth-cancel-failed`, `auth-start-unanswered`, `auth-unmeasured`, `code-not-sent`, `method-not-supported`) rides `lane-act-refused` with `verbCode`. A cancel the box could not carry out leaves the attempt standing, so it can be cancelled again (D-7750 (8)).
