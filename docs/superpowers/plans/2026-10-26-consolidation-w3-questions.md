## Global constraints

The W0 plan's §Global constraints bind this plan: the public repository, SAFETY, no root runner, characterization discipline, counts measured and not argued, band routing and branch discipline. The W1a plan's rules for characterization commits, behaviour commits, the act-time re-read and the path guard bind it too. In addition:

- **Characterization first, red first, and never weaken a test.** Each PR's first commit is a characterization pin that is green against the old code (spec §5.1 rule 1, O9 (a)). Move commits change those suites only in their imports. A move commit that edits a characterization assertion is refused in review. **The named exceptions, and only these:**
  1. a test that reads a private watcher field (`heldAsks`, `heldApprovals`, `asksDisabled`, by cast);
  2. a literal source pin over text a task rewrites (a slice between two route registrations, a `tick` body match, a `sourceOfSymbol` over a moved method);
  3. an **inventory row that names a route path or its enclosing symbol**: a route census list or count (`routes.test.ts`'s canonical-id and `knownId` censuses, `auth-gate.test.ts`'s `scanRoutes` counts, `ROUTES.length`, the sorted `EXEMPT` keys and the box-token `gated` list), a lane count stated in number words (the census title in `auth-gate.test.ts`, `auth/gate.ts`'s EXEMPT reason 2 and its CSRF/origin note, `README.md`'s auth paragraph, all checked by `box-token-census.test.ts` against `COORD_LANES` and `ALL_LANES`), a prose census the code is checked against (`CLAUDE.md`'s box-token bullet), and a classified-site row whose enclosing symbol moves (`registry-refused-census.test.ts`'s `EXPECTED_SITES`).

  Each is edited in its own commit, and the commit asserts the same facts: a moved row keeps its reader and its word and changes only its file or enclosing symbol; a grown list or count grows by exactly the routes the same PR adds, and the commit message derives the new number from the old one; a prose census names the new routes in the commit that makes the code need them, never one without the other. The task's Files section lists every such file, and a worker who finds another one stops and reports it. Any other assertion edit in a move commit is refused in review.
- **One owner of question state per composition.** All question state (the hold carrier, `reseedLoaded`, `approvalInputs`) lives in an instance made by `coord/questions.ts#createQuestions(deps)`, never at module scope. `FleetWatcher` makes one in its constructor and exposes it read-only; `buildServer` uses `watcher.questions` when it is given a watcher, and makes its own otherwise, and passes that one instance to `registerCoordRoutes`. So the routes' door-ins and the watcher reach the same carrier in production (`index.ts` builds one watcher and hands it to `buildServer`), and two apps or two watchers in one vitest process share nothing. A single-definition row (Q3b) pins that `coord/questions.ts` declares no module-scope `let`, `Map`, `Set` or array. **Question state is held as closure locals of `createQuestions`** (a `const` or `let` declared inside the factory's body, which the returned members close over), never as class fields and never as properties of the returned object. That is the shape `census-w3/questions.ts#questionHoldCarriers` measures: it reads the bindings declared inside `createQuestions`, so a carrier held any other way would be invisible to it. ## Review focus (the failure modes most likely to bite)

1. **A swallowed question.** A deferred push that no carrier and no row can reach any more. The arms that guard against it are the missing-row push, the `unknown`-state push, the `answering` bound, the CAS-lost `held` keep, and `tryHold`'s compensation `staleAsk` after a half-committed mint. Each is a Q3a row.
2. **A push where there was none, or two.** A held question is recorded and never pushed until its window ends. A lapse pushes the mint's snapshot exactly once. A late answer replaces that push under the same tag. A cleared dialog pushes nothing.
3. **A principal that crossed.** No box-token request reaches the operator's arm, and no session-gated request reaches a claimant's arm. An alias decides nothing past its front ladder: it keeps today's auth calls, body read and id parse in today's order, then makes one call into a core.
4. **A changed word.** Every refusal string and code on every door, byte for byte.
5. **An unmeasurable read folded into an answer.** A store read that fails keeps today's direction on each path: the sweep retries, the operator's press goes through unrecorded, and a parent's answer refuses.
6. **A frame that changed for an old client.** The `ask` and `dialog` frames keep their send gates. `pairing` sits at the frame's top level, never inside `dialog`, so the old reducer's `{...s, dialog: msg.dialog}` carries nothing new.
7. **Two clocks merged.** The ask half keeps its 10 s throttle and its `primed` gate, and the approval half keeps running every tick, ungated, with its whole body inside `tick`'s synchronous turn. Neither half awaits the other: a slow or never-resolving `fleetFor` read in the ask half delays no approval lapse, no hook ceiling and no deferred push.
8. **State shared across instances.** A carrier or an input map at module scope would make every `buildServer` and `FleetWatcher` in one process share it, and a "restarted server" row would then pass on the previous app's input.
