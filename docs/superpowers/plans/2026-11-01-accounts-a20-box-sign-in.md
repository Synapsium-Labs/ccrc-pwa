# Accounts connect A20: the box half of the sign-in

**Goal:** plan Task A20 of `2026-10-18-accounts-connect.md` (spec §3.5, §3.7, §3.9, §6.2, §6.3, §9, §13.3; D-5514, D-5515, D-5518, N4, N5; G10, G17). The fleet box gets the sign-in the next PWA wave drives: `ccrc account auth-start`, `auth-code` and `auth-cancel` run `ccd-account-auth` as a detached transient unit, the pane methods take a pane on the lane's own tmux server, the code is relayed once and never onto an argv, a re-auth or a method switch is checked before it is installed, `ccrc account set --method` is the one writer of a lane's method, and `credential --sign-out` is N5's sign-out act. `ccd caps` advertises `account-auth-v1`. OA1's record (`2026-11-01-accounts-oa1-record.md`) decides four branches, stated in D-7750 (1). The number this task was gated on (N5) and its as-built decisions are defined below.

**Before this change:** no verb started a sign-in: `ccd-account-auth` ran in the operator's terminal or, for a pane method, in a `cc-auth-<id>` pane `ccd account-pane` made on the fleet's shared tmux server. A mint wrote its token straight into the lane's `<id>-oauth.env`, unchecked. No verb changed a lane's method, wrote `mintedAt` or signed a lane out without removing it. The Anthropic table's first method, and so `add`'s default, was `login`.

**Change:**
- `ccd/ccrc`:
  - `auth-start --id --method login|setup-token|openai-login --attempt <32 hex>` launches `systemd-run --user --unit=ccrc-auth-<id>-<attempt8> --collect -p RuntimeMaxSec=660 -p MemoryMax=512M -p StandardOutput=null ccd-account-auth <id> <method> --attempt <a>` and returns once the status file names the attempt. It refuses a macOS node (`auth-unsupported-here`, reason `darwin-arm-absent`) before anything is read or spawned, a sign-in already live (`auth-in-progress`), a method the lane's kind does not carry (`method-not-supported`), and `openrouter-pkce` (A28's).
  - `auth-code --id --attempt` byte-checks the code from stdin (`bad-code`), refuses an attempt the status file does not name (`no-auth-attempt`) and a second code (`code-already-sent`), and writes it once into the FIFO with the builtin `printf`.
  - `auth-cancel --id --attempt` stops the attempt's unit, a no-op for one that has ended, and kills the lane's private server and deletes its scratch when the attempt is the lane's last. A stop that fails refuses `auth-cancel-failed` and leaves all of it.
  - Both verbs export the user-bus defaults (`XDG_RUNTIME_DIR`, `DBUS_SESSION_BUS_ADDRESS`) before they ask the manager, through `_codex_bus_defaults` and `_svc_have_user_manager`; the stop is one function, `_acct_auth_stop`.
  - `set --method setup-token|login --attempt <a>` installs what that attempt left in `~/.ccrc/auth-scratch/<id>`, after its probe passes and under the lane lock: a re-mint through `credential`'s writer, a switch also through the roster, `accounts.sh` and the wrapper.
  - `credential --sign-out` (N5) runs `claude auth logout` in the lane's config dir and removes its `.credentials.json`.
  - `add --provider anthropic` with no `--method` is a mint (`setup-token`); with no `--credential` it writes the token lane with no key file yet. A paste through `credential` clears `mintedAt`. `remove` kills the lane's private tmux server with its scratch. `_acct_token_probe` also probes a sign-in, given its config dir.
- `ccd/ccd-account-auth`: `--attempt <a>`, echoed as `attemptId` into every status file; a pane method's unit copy makes its pane on `tmux -L ccrc-auth-<id> -f /dev/null`, waits for it and cleans up; in an attempt the minted token lands in `auth-scratch/<id>/minted.env` and a lane that holds a credential signs in into `auth-scratch/<id>/config`, and the helper hands either to `ccrc account set --method … --attempt` before it reaches `done`; every terminal state deletes `auth-scratch/<id>`, and a pane method's kills the private server by name.
- `ccd/ccd`: `cmd_caps` prints `account-auth-v1`; `cmd_account_pane` makes and cancels its pane on `-L ccrc-auth-<id> -f /dev/null`.
- `shared/providers.ts` and `deploy/account-op.mjs`: Anthropic's `connect` is `['setup-token', 'login', 'paste']`. `deploy/account-op.mjs` also gains `set-method`, `auth-live` and `auth-answer`, a `reason` on `refuse`, `--minted-at` and a repeatable `--clear` (now taking `mintedAt`) on `lane-state`, and `secretsFileOf`, the one template for a lane's secrets file.
- `README.md` documents the sign-in verbs, the private socket, the scratch, `set --method`, `--sign-out` and the new default.

**Tests:**
- New: `server/test/ccrc-account-auth-start.test.ts` (with the user-bus cases: the verbs run with only HOME, PATH and LANG, no manager answering, a cancel that cannot stop, an unanswered start), `server/test/ccd-account-auth-private-socket.test.ts`, `server/test/ccrc-account-method-switch.test.ts`, `server/test/ccrc-account-reauth.test.ts`, and their fixture `server/test/authAttemptFixture.ts` (recording stand-ins for `systemd-run`, `systemctl`, `tmux`, `script` and the upstream `claude`; both managers refuse with no `XDG_RUNTIME_DIR`, as the real ones do, and record the bus each call was given).
- Extended: `server/test/account-canary.test.ts` (every socket's scrollback, the private one included), `agent/test/whitelist.test.ts` (`auth-scratch` refused), `server/test/ccd-account-auth.test.ts` (the scratch config dir's spelling), `server/test/ccd-account-pane.test.ts` and `server/test/ccd-tmux-anchor.test.ts` (the private socket), `server/test/ccrc-account.test.ts` and `server/test/providers.test.ts` (Mint first; the login cases name `--method login`; the refusal-shape scan reads `_acct_refuse_reason`), `server/test/ccdCapTokens.ts` (`account-auth-v1` is a capability).

## Decisions

- **D-7749 (2026-11-01)** — `credential-sign-out` (N5; accounts plan Tasks A20, A21, A23): the sign-out act is `ccrc account credential --id <id> --sign-out`, `remove`'s own sign-out step for a lane that stays: under the lane lock, `claude auth logout` through the upstream launcher with `CLAUDE_CONFIG_DIR` set to that lane's config dir, bounded by the auth deadline, then its `.credentials.json` removed and verified gone. It runs only on a ccrc-generated Anthropic lane (`not-a-sign-in-lane` otherwise), takes no `--credential` (exit 2 if given), and answers `{ok, id, signOut: removed|absent, fleetIdentity}`; a lane with nothing signed in answers `absent` and runs no logout. A sign-in lane's last check is cleared with it; a token lane's is kept, because it measured the token, which stays. OA1 did not measure G23 or §9, so the answer says what was done on this box and nothing about the provider, and A23 keeps the danger confirm. The route (`POST /api/accounts/:id/credential {signOut: true}`) and its argv field are A21's.
- **D-7750 (2026-11-01)** — `box-sign-in-as-built` (accounts plan Task A20; spec §3.5, §3.7, §3.9, §6.2, §6.3, §9, §13.3; D-5514, D-5515, D-5518): the as-built decisions of A20, and where it departs from the plan's wording.
  1. **OA1's record, applied.** The `login` host and code shape were measured, and they are A21's to read: this verb byte-checks the code only (no C0 byte or DEL, 1 byte to 8 KiB), never its shape, so the pending setup-token shape gates nothing here. G23 and §9 were not measured: D-7749's answer names nothing at the provider. §3.3 was not measured and nothing here reads it. The Codex device code was not measured: `auth-start --method openai-login` runs the helper's existing Codex arm unchanged (it signs in where the lane's runtime keeps its auth), and its scratch arm is A24's.
  2. **The install runs in the unit, called by the helper; `auth-code` only relays.** The plan has `auth-code` validate the captured token "on `done`". But `auth-code` is what sends the code, so the exchange ends after it has answered, and every terminal state deletes the scratch that holds the credential. So the helper, the one process that sees the child succeed, calls `ccrc account set --method <m> --attempt <a>` before it publishes anything terminal. `set` refuses unless the status file names that attempt, probes the credential, and installs it under the lane lock. `done` therefore means "installed"; a refusal is `failed` with the refusal's code as its `error`, and no sentence of it. `auth-code` returns `{ok, id, attemptId, sent: true}` once the code is in the FIFO, and the server polls the status file from there.
  3. **Where each credential lands.** In an attempt, a mint always writes its token to `auth-scratch/<id>/minted.env` (0600, in a 0700 directory), and the install moves it into `<id>-oauth.env` through `credential`'s writer, with `mintedAt` written right after the rename, under the same lock. A `login` attempt signs in into `auth-scratch/<id>/config` when the lane already holds a credential (its `.credentials.json`, or a token: Sign in again and Switch to sign-in, the plan's two scratch cases); a fresh sign-in lane signs in where it lives, the path OA1a measured, because there is nothing there to keep. Outside an attempt (`ccd account-pane`, the wave-1 path) the mint writes the lane's file directly, as before, and its tests are unchanged.
  4. **The switches.** Sign-in → token: the token file is written first (inert, since no roster entry names it yet), then `set-method` sets `exec.secretsFile`, then `accounts.sh` and the wrappers are regenerated, then the lane state drops `check` and records `mintedAt`; `.credentials.json` stays until D-7749's sign-out. Token → sign-in: `.credentials.json` is copied beside the destination and renamed over it, then `set-method` drops `exec.secretsFile`, the projection and wrappers are regenerated, `<id>-oauth.env` is deleted, and the lane state drops `check` and `mintedAt`. Each probe runs before the first write, so a refused credential writes nothing.
  5. **The pane's two halves.** The unit runs the helper's OUTER copy: it publishes `starting` with the attempt, makes the pane on `tmux -L ccrc-auth-<id> -f /dev/null` running the helper's INNER copy (`CCRC_AUTH_IN_PANE=1`), waits for the session to end (bounded by the deadline plus twice the pump's grace) and cleans up. The inner copy is the status file's one writer while it lives; the outer writes only once the pane has gone and left no terminal state, or on its own trap. `-f /dev/null`: the lane's server reads no tmux.conf, so no fleet hook runs in it. `ccd account-pane` makes its pane on the same private socket with the same marker. `login` has no pane, so its terminal states delete the scratch and touch no tmux (`ccd-account-auth.test.ts` already pins that a login opens no tmux session).
  6. **The unit.** `-p StandardOutput=null`, because the helper's transcript carries the sign-in URL and no journal should keep it; stderr (the refusal sentences) stays. `--setenv=PATH=… --setenv=LANG=…` from the verb's own environment, which the agent's spawn makes exactly `{HOME, PATH, LANG}`, so the helper and its install find node, jq and flock. The lane lock's descriptor is closed for `systemd-run`, so no child holds it. A box with no `systemd-run` refuses `auth-unsupported-here` with reason `no-systemd-run`. **The user bus.** That spawn carries no `XDG_RUNTIME_DIR` and no `DBUS_SESSION_BUS_ADDRESS`, and `systemd-run --user` and `systemctl --user` from such a context find no manager, so both verbs first export `_inst_enable`'s pair (`/run/user/$UID` and its `bus`, through `_codex_bus_defaults`, kept when already set) and then ask `_svc_have_user_manager` (D-3483's probe); a box where no manager answers refuses `auth-unsupported-here` with reason `no-user-manager` before anything is launched. The launch stays a direct `systemd-run` rather than `_svc_run_detached`, whose argv is pinned and takes no `--unit` or properties. When the helper does not report in time, the start stops the unit through the same `_acct_auth_stop` as the cancel, and its `auth-start-unanswered` sentence says whether that stop happened or the unit runs on to its own 660 s bound. `auth-start` kills a stale private server and deletes a stale scratch before it launches, since no attempt is live: it refuses one that is by `pre-remove`'s rule (a live state written within 660 s), now also the `auth-live` op, and refuses `auth-unmeasured` when that op does not answer, failing closed.
  7. **The code.** `auth-code` reads stdin whole with the builtin `read` (a NUL is caught by the marker it leaves), refuses a terminal attempt, takes the lane lock, checks the FIFO is a FIFO this user owns (a regular file planted there would keep the code on disk), makes `code-sent` beside it with noclobber (O_EXCL, so of two racing sends one goes on), opens the FIFO read-write so the open never blocks, and writes with the builtin `printf`. A failed write removes the marker. The helper's FIFO cleanup removes `code-sent` too.
  8. **Cancel.** `auth-cancel` takes the lane lock, so it refuses `lane-busy` while an install is moving a credential rather than kill it mid-way; it stops `ccrc-auth-<id>-<attempt8>.service` (a no-op once it has ended, which systemctl answers as "not loaded", exit 5) and, when the status file names this attempt, kills the private server and deletes the scratch. **It fails closed:** when no manager answers or the stop fails for any other reason, it refuses `auth-cancel-failed` and leaves the unit, the private server and the scratch as they are, so a pipe arm's helper is never left running with its state cleared under it, able to take a code and install after a cancel the server believes happened. Cancelling again is safe. A darwin node, or a box with no `systemctl`, never started a unit, and answers `stopped: false`. It answers `{ok, id, attemptId, unit, stopped, state}`.
  9. **The default method.** `PROVIDERS.anthropic.connect` and `PROVIDER_CONNECT.anthropic` are `['setup-token', 'login', 'paste']`, so `ccrc account add --provider anthropic` with no `--method` mints rather than signs in, a CLI-visible change consistent with Q1. A setup-token `add` with no `--credential` writes the token lane with no key file (the wrapper sources it only when readable) and leaves it off, for `auth-start` to mint into; with `--credential -` it is a pasted token, validated first as before. The PWA's radio reads the same table, and Mint and Sign in stay narrowed until the server knows `account-auth-v1`.
  10. **The cap word.** `ccd caps` prints `account-auth-v1`, and the server's `ACCOUNT_CAPS` does not name it yet: A21 appends it with the routes that use it, so the connect sheet does not offer a Mint it cannot run (`accounts-route-lanes.test.ts` already pins that a word the server does not know is not offered).
  11. **`remove`** kills the private server only on a lane a sign-in ever ran on (its status file or scratch exists), so a removal of a lane with neither asks tmux nothing (`ccrc-account.test.ts` pins that).
  12. **The lane state.** `lane-state` takes `--minted-at` and a repeatable `--clear`, which now also takes `mintedAt`; `set --method setup-token` writes it and a paste (`credential`) clears it with `check`.
  13. **One template for the secrets file.** `secretsFileOf(id, provider)` in `deploy/account-op.mjs` is what `check-add` and `set-method` both write, so the three writers `ccd-account-auth.test.ts` pins stay three.
  14. **A refusal with a reason.** The `refuse` op takes an optional `--reason` word, printed beside the code; `_acct_refuse_reason` is its bash twin, which `ccrc-account.test.ts`'s refusal-shape scan now reads.
  15. **The fixture runs the Linux arm everywhere.** `authAttemptFixture.ts` sets `OSTYPE=linux-gnu` for the sign-in verbs, so a Mac developer runs the same branch CI does; a verb that does not launch a sign-in (an `add`, a switch's regeneration) runs the host's own arm (`HOST_OSTYPE`), since `ccrc` spells each platform's tools its own way.
  16. **The growth check.** `ccd/ccrc` grows past the 40-line limit, so this PR adds the waiver `server/test/growth-waivers/D-7750-ccd-ccrc.json`. The decisions live in `deploy/account-op.mjs` where they can (the method's roster write, the sign-in-in-flight rule, the answers, the lane-state fields), and bash measures and orders the steps.
