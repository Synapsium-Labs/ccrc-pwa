# Codex bridge, Stage 2: the bridge on the backend route — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Every test step follows
> superpowers:test-driven-development: the red test first, seen failing for the reason named, then the change, then
> green, then the task's mutation rows RUN (never read). Steps use checkbox (`- [ ]`) syntax for tracking. Each wave
> is one PR. Workers do not edit this file: the coordinator records rulings and measurements in it.

**Goal:** a Codex lane can run in `direct` mode, where one ccrc process on the lane's existing port, key and unit
answers Claude Code as an Anthropic endpoint and speaks the ChatGPT backend's Responses route itself, built from
finished items only, with no LiteLLM and no LiteLLM prompt, with Claude Code's own compaction working at the measured
window, and with `ccrc codex switch <id> litellm|direct` to move a lane between the two modes.

**Architecture:** the shim (`ccd/ccgpt-proxy.py`) keeps `litellm` mode byte for byte and gains a `direct` entry,
which imports a new stdlib package, `ccd/codexbridge/`, from the box's installed tree (D18, D19). Inside the package
three parts depend only on the one before (spec Figure 2): **inbound** turns an Anthropic request into a neutral
request, the **backend adapter** turns that into a Responses request and reads the HTTP answer, and the **reducer**
turns the upstream event stream into Anthropic events from `response.output_item.done` items alone. Beside them sit
the reasoning store (sqlite, 0600), the count estimator (D24) and a non-secret stats file, which the hourly models
refresh reads to lower a refused model's window (D25) and the doctor reads for drift names (D3). The credential is
Stage 1's library (`ccd/ccgpt-auth.py`): in `direct` mode the bridge is the lane's one refresher.

**Tech Stack:** Python 3.9+ standard library only (`http.client`, `http.server`, `json`, `sqlite3`, `ssl`,
`threading`, `hashlib`, `hmac`), run by the system `python3` in `direct` mode; bash (`ccd/ccrc`,
`ccd/ccrc-doctor-checks`); node `.mjs` (`deploy/models-op.mjs`, `deploy/account-op.mjs`, `shared/roster-json.mjs`)
and TypeScript (`shared/roster.ts`); vitest in `server/`, which spawns `python3 -I` drivers against an in-process fake
Responses backend and Stage 1's fake auth server; one scheduled GitHub workflow (`.github/`).

**Spec:** `docs/superpowers/specs/2026-10-15-codex-bridge-design.md` — §2.1 (the lane's shape), §2.2 (the backend
column), §2.3 (request translation), §2.4 (reply building), §2.5 (the reasoning store), §2.7 "What the bridge adds",
§2.8 (Stage 2), §2.9 D1, D3 and D4, §3 D9, D11-D14, D18-D20, D23-D25, D27, and §5 (the reducer and lane tests, the
first live step). The `siwc` adapter, the pinned rule (D21), consent (D22), the canary (D5, D26) and the trial are
Stage 3; retiring LiteLLM is Stage 4.

  directly). Every message request carries exactly `model, messages, system, tools, metadata, max_tokens, thinking,
  context_management, output_config, stream`; never `temperature`, `top_p`, `top_k`, `stop_sequences`,
  `tool_choice`. `context_management` is always `{"edits":[{"type":"clear_thinking_20251015","keep":"all"}]}`.
  `system[0]` is `x-anthropic-billing-header: cc_version=…;` whose three-hex suffix varies between requests.
  Mid-conversation `role:"system"` entries arrive inside `messages`, as a string, a block list or `[]`. Tools carry
  `defer_loading:true` for `DeferredToolPlaceholder` and for a tool ToolSearch loaded; a ToolSearch result carries a
  `tool_reference` block. `count_tokens` came only from a large Read's pre-check. `output_config.effort` was sent on
  every request (`high` for a GPT model id), and `max_tokens` is 32000 for a GPT model id.
- **Claude Code's reactions.** `pause_turn`: no continuation, the turn ends (exit 0). A mid-stream `error` with no
  `message_stop`: the same request is re-sent at once with `stream:false` (the only `stream:false` sender found).
  `prompt is too long: N tokens > M maximum`: compaction after at least one exchange; on a single exchange it refuses
  to compact. A 429 or 401 with no hint: full exponential backoff (2 retries on a lane, `CLAUDE_CODE_MAX_RETRIES=2`,
  `ccd/ccrc-codex:183`); with `x-should-retry: false`: no retry. A plain 400: three feature-degrade retries. 403: no
  retry. 529: gives up after 2 retries. Its match for overflow is loose: case-insensitive "prompt is too long" or
  "input is too long for requested model", N and M read by `prompt is too long[^0-9]*(\d+)\s*tokens?\s*>\s*(\d+)`.

## Global Constraints

- **The design, verbatim from the spec.** §2.1: "One process per lane, on loopback, guarded by the lane's existing
  gateway key." "Stdlib Python, run by the system `python3`. No virtual environment." "a flip stops one set of
  processes before starting the other, which is also the moment the credential's ownership passes between them."
  §2.4: "The reducer builds each Anthropic block only from the upstream's **finished** items". "Zeros in
  `message_start` and the real figures in `message_delta`". "A `ping` after 15 s of upstream silence". "An upstream
  idle timeout of 300 s, as in Codex. On restart the bridge stops taking requests and finishes the streams in
  flight." "Errors known before the stream starts become real HTTP statuses; errors mid-stream become an Anthropic
  `error` event with no `message_stop`." §2.5: "stdlib `sqlite3`, mode 0600", "14 days, and a size cap that evicts
  the oldest first". D23: "oldest-first eviction past 256 MB". D24: "seeded at 3.5 bytes per token, rounded up". D25:
  "A refusal at size R sets that model's window to R × 0.9, rounded down to 1k, through the hourly models refresh;
  never raises". D27: "Send `originator: ccrc`."
- **`litellm` mode is today's path exactly** (D18). With `CCGPT_BRIDGE` unset, `ccd/ccgpt-proxy.py` runs the same code
  it runs today: the only edit in that file is the `__main__` branch and the `_run_direct` function it calls. The
  shim's existing suite (`server/test/ccgpt-proxy.test.ts`) and the runtime probe's `SHIM_OUT` pin
  (`server/test/ccgpt-runtime.test.ts`) stay green with no assertion changed.
- **The package imports only the standard library and Stage 1's library**, which it loads by path
  (`CCRC_CODEX_AUTH_LIB`, `importlib.util.spec_from_file_location`, `sys.dont_write_bytecode = True`), never by
  `sys.path`. Python 3.9+:
  every module passes `ast.parse(src, feature_version=(3, 9))` (Task 1's census). `codexbridge/__init__.py` imports
  every module of the package at start (`load_all()`), so an update that rewrites the tree under a running bridge
  changes nothing it runs.
- **Retries have one owner: Claude Code.** The bridge never retries an upstream request, except exactly one retry
  after the library refreshed a token the upstream answered 401, and the bounded continuation of an
  `end_turn:false` reply (Task 8). Today LiteLLM retries 429, 403 and 5xx three times and cools a model down for
  5 s; the bridge does neither.
- **One definition of every name.** The bridge's file names (stats file, reasoning store, recordings directory) are
  spelled once, in `laneManifest` (`deploy/models-op.mjs`), copied into `lane.json` as `bridgeFiles`, and read from
  there by bash and Python. The `x-codex-` usage headers are stored by prefix, never by name, so the poller's five
  names stay spelled once (`ccd/ccgpt-usage.py`). The upstream error codes, the stop-reason table and the known drift
  names are module constants in the package. `server/test/single-definition.test.ts` gains the rows (Tasks 1, 10).
- **No body, token or content is ever logged, counted or written to a non-secret file.** The stats file holds counts,
  sizes, names (bounded by `NAME_RE = ^[A-Za-z0-9_.:/-]{1,64}$`, else `unrecognised`) and request ids (bounded as
  Stage 1's status file bounds them). The reasoning store holds encrypted reasoning items, 0600, and nothing else.
  A recording (Task 18) is raw upstream bytes, 0600, only while the operator's marker file exists.
- **Fixture HOMEs and fakes only; no test can reach a live endpoint.** Every bridge process in a test gets
  `CCGPT_BRIDGE_UPSTREAM_BASE` (a loopback `http://` URL, the only override the adapter accepts; a non-loopback value
  refuses at start) pointing at `fakeResponses` or, when the case needs no answer, at Stage 1's `CLOSED_AUTH_BASE`
  (`http://127.0.0.1:1`); and Stage 1's `CCRC_CODEX_AUTH_BASE`. `ghContainedEnv` and `containedSpawnOptions` set both
  defaults unless the caller names one (Task 7). A test that talks to an in-process server spawns asynchronously.
  Synthetic tokens are built at runtime (Stage 1's `syntheticJwt`), never written as literals.
- **Commands.** From `server/`, foreground, timeout at least 600000 ms, one file per command:
  `./node_modules/.bin/vitest run test/<file>.test.ts`. Never a bare `npx vitest`. vitest's per-test bound is 20 s
  on Linux, so every timer a case exercises is lowered through the driver's `consts` (Task 1), never waited out.
- **Mutation discipline.** Every guard ships with a row that goes red when the guard is removed or weakened. Run each
  row one at a time on the shipped file, restore it, prove the restore with `git diff --exit-code -- <file>`, and
  record `<row> → <n> failed (<titles>)` in the task's commit body; the counts below are predictions, measure them.
  Scratch notes go in `.superpowers/sdd/codex-bridge-s2/` (gitignored; check with `git check-ignore`).
- **Public repository.** Lanes are `lane-a`/`lane-b` in prose and the fixtures' own ids in tests, read by position.
  Model ids in tests are neutral (`model-6.1-alpha`, `model-6-beta`); no added line spells a real GPT model id. No
  hostnames other than the backend's public endpoint constant, no addresses, absolute home paths, account names or
  private project names. Fixture streams are synthetic: tiny prompts, `resp_`/`rs_`/`fc_`/`call_` ids of the form
  `<prefix>_fx<n>`, encrypted content `ENC-<n>`.
- **Upstream citations** are `openai/codex` paths at `092d3ac` (`rust-v0.162.1`), never a local copy.
- **Deviation numbers.** This plan writes only `D-TBD-<slug>` entries; the controller issues their numbers. A worker
  never calls the allocator: a further departure is written `D-TBD-<slug>` and named in the task's report.
- **A new WARN, inside the existing `codex` check only** (Task 17): R-O9 closed on 2026-10-19, so no soak gate
  allow-lists WARNs by name today; no new doctor check name is added.
- **Not touched:** the `siwc` route, ccd placement (D21), consent (D22), the canary (`deploy/models-canary.mjs`), the
  PWA, `agent/src/whitelist.ts`, `shared/api.ts`, `ccd/ccgpt-runtime` and its LiteLLM patch, the LiteLLM environment
  (kept for `litellm` lanes), Node floor `>=22.16.0`.
- Plan and spec prose at most 120 characters a line (code blocks and table rows exempt). Commit on the workspace's
  own branch, never a separate feature branch.

## Review Focus

Five conditions the spec implies and no rule above spells out, the most likely to bite first. Each has its test in
the task that owns the code.

1. **A long silent turn**: high-effort reasoning, or a compaction summary (GPT compactions take a median of 239 to
   271 s, spec §1.2), with no upstream event for minutes. Expected: a `ping` every 15 s of downstream silence, the
   summary's text forwarded live as it streams, no abort before the 300 s upstream idle bound, and the idle bound's
   error at 300 s of upstream silence, not at Claude Code's watchdog. Pinned in Task 8 ("pings through a silence,
   then the live text") with the timers lowered.
2. **A session that came from a Claude lane**: history holding Claude `thinking` blocks with Anthropic signatures,
   `redacted_thinking`, `toolu_` ids and `cache_control` everywhere. Expected: thinking and redacted thinking are
   dropped and counted, `toolu_` ids pass through as `call_id` unchanged, nothing is refused. Pinned in Task 2
   ("a history from a Claude lane translates").
3. **A restart or a switch landing while a stream is in flight** (a rollout's spine restart, `ccrc codex switch`).
   Expected: the bridge stops accepting, the in-flight stream finishes normally, and the process exits within
   `DRAIN_S`; a request arriving after the stop sees a refused connection, which Claude Code retries. Pinned in
   Task 8 ("SIGTERM drains the stream in flight").
4. **A connection that drops mid-block** (200 sent, a text block open, then EOF). Expected: the open block gets its
   `content_block_stop`, then one `error` event `api_error` and no `message_stop`; Claude Code's `stream:false`
   re-send is then answered by the fold. Pinned in Task 3 (fixture `synth2-drop-inside-live-text`) and Task 8
   ("the stream:false re-send after a mid-stream error is served").
5. **Both refreshers on one credential**: a `direct` lane whose LiteLLM tier was started by hand, or a switch
   interrupted between its stop and its start. Expected: `ccrc codex start` refuses `retired-tier-running` and never
   adopts it, `switch` re-measures before it starts, and the doctor FAILs the running retired tier. Pinned in
   Task 11 ("start refuses a running litellm tier on a direct lane"), Task 12 and Task 13.

## The bridge's contract (read this before any task)

Every task's Interfaces block refers to these names. The package is `codexbridge`, imported from the directory
named by `CCGPT_BRIDGE_DIR`'s parent.

**Environment of a `direct` process** (set by `_codex_start_tier <id> bridge`, Task 11; read once by
`server.config_from_env`): `CCGPT_BRIDGE=direct`, `CCGPT_ACCOUNT_ID`, `CCGPT_PROXY_PORT`, `CCGPT_LITELLM_PORT`
(still required by the shim's module-level reader, unused), `CCGPT_BRIDGE_DIR` (the tree's `ccd/codexbridge`),
`CCGPT_LANE_DIR` (`~/.ccrc/codex/<id>`), `CCRC_CODEX_AUTH_LIB` (`~/.local/bin/ccgpt-auth.py`), `CCGPT_CCRC_VERSION`
(the box's stamp, or `dev`), `CCGPT_CATALOGUE` (the lane's model catalogue, the path `ccd/ccrc` already builds),
`HOME`. The key, the authDir, the config dir and the bridge file names come from `lane.json` and `runtime.env` in
`CCGPT_LANE_DIR`, read at start. The key is parsed in process with
the launcher's grammar (`LITELLM_MASTER_KEY=sk-<48 lowercase hex>`, `ccd/ccrc-codex:163-179`), never sourced and
never put in the environment.

**Files in the lane directory**, named by `lane.json`'s `bridgeFiles` (Task 10): `stats` = `bridge.stats.json`
(0600, the bridge's only non-secret output), `store` = `reasoning.sqlite` (0600, plus sqlite's `-wal`/`-shm`),
`recordings` = `recordings/` (0700, written only while `record-streams` exists in the lane directory, Task 18).
Markers with no writer in the tree: `bridge-instructions` (send `system` as top-level `instructions`, D11's per-lane
switch) and `record-streams`.

**Routes** (Task 8): `POST /v1/messages` (with or without `?beta=true`), `POST /v1/messages/count_tokens`,
`GET /v1/models`, `GET /ccgpt/lane` (unchanged: `{"lane": <id>}`, no key). Every other path is 404 with an Anthropic
error body. Every route but `/ccgpt/lane` requires the key, as `x-api-key` or `Authorization: Bearer`, compared with
`hmac.compare_digest`; a missing or wrong key is 401 `authentication_error` with `x-should-retry: false`.

**The neutral request** (`inbound.NeutralRequest`, a `NamedTuple`): `model: str`, `developer: Optional[str]` (the
top-level system text, billing line removed), `items: List[dict]` (Responses input items, in order), `tools:
List[dict]`, `name_map: Dict[str, str]` (upstream name → Claude Code's name), `tool_choice: object`,

Every error keeps the upstream request id (`x-request-id`, else `request-id`) in the stats file and, with its code,
in the status file. A prompt-too-long 400 carries no `x-should-retry` header: the measured recovery used none.

**The commit point** (R17). The bridge holds the HTTP status line until the first of: the reducer releases its first
block event, a terminal event arrives, or `HOLD_S = 15.0` seconds pass. Before it, any failure is a real status;
after it, an `error` event. `message_start` is the first SSE event written at commit, carrying zero usage and the
**requested** model id.

**Stop reasons** (R13, `reducer.stop_reason`): a `tool_use` block emitted → `tool_use`; else the refusal flag →
`refusal`; `response.incomplete` `max_output_tokens` → `max_tokens`; `content_filter` → `refusal`; `interrupted`, and
any `end_turn: false`, → continuation (below); an unknown incomplete reason → an `api_error` failure; otherwise
`end_turn`. `pause_turn` is never emitted (D-TBD-end-turn-false-continues-in-bridge).

**Continuation.** A reply that ends with `end_turn: false` (or `interrupted`) and emitted no `tool_use` is continued
upstream inside the same Anthropic message: the bridge sends the same input plus that response's output items, at
most `CONTINUE_MAX = 3` times, renumbering block indexes; past the cap the message ends `end_turn` and the stats file
counts `continuation-cap`.

**Usage** (R15, `reducer.anthropic_usage`): `message_delta.usage` = `{input_tokens: max(0, input − cached −
cache_write), cache_read_input_tokens: cached, cache_creation_input_tokens: cache_write, output_tokens: output}`,
where `input` is the upstream `input_tokens`, `cached` its `input_tokens_details.cached_tokens` and `cache_write` its
`input_tokens_details.cache_write_tokens` (0 when absent). So the three input fields Claude Code sums equal the
upstream `input_tokens` exactly, and proactive compaction fires at the measured window minus 33k
(D-TBD-usage-sum-equals-upstream-input). On a continued message, the input fields come from the last response and
`output_tokens` is the sum.

## Operator runbook: the first live step, the flip, the watch (not tasks)

Nothing here is run by an agent unless the operator says so for that step. Wave 2 changes nothing until step 4.

**0. Offline rehearsal (an agent may run it; zero network).** In a fixture HOME, Claude Code's versioned binary is run
directly (never the `~/.local/bin` launcher, which sources a token file from `$HOME`), under `env -i` with a dummy
key, `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`, the lane's settings env block and `CLAUDE_CODE_MAX_RETRIES=2`,
against a fixture lane's bridge whose upstream is a fake Responses backend on loopback, with the fake also set as
`HTTPS_PROXY`/`HTTP_PROXY` (it must record zero CONNECT requests). Expected: a tool round trip; proactive compaction
at window − 33k with the fake's usage in `message_delta`; the prompt-too-long 400 after one exchange starting a
compaction; a 429 `billing_error` with `x-should-retry: false` ending the turn with one request; a `policy_blocked`
400 with one request; a mid-stream `error` followed by a served `stream:false` re-send; pings through a 60 s silence.
Any difference is reported before step 1.

**1. Choose the moment.** lane-b, the lane with more quota headroom (spec §2.8), at a quiet time; its build carries
waves 1 and 2; `ccrc doctor` is clean for it; its access token is fresh (`ccrc codex status lane-b --json | jq
.auth`), because the live probe never refreshes in `litellm` mode.

**2. The first live step: at most six tiny requests** (D27; spec §5). `touch ~/.ccrc/codex/lane-b/liveprobe-allowed`,
then `python3 -I ~/ccrc/ccd/codexbridge/liveprobe.py --lane lane-b --step <n>`, one at a time:
1. a one-word reply: `originator: ccrc` accepted, developer-first with no `instructions`, the usage fields, the
   response header names (`x-codex-*`, `openai-model`, `x-request-id`);
2. two parallel tool calls with `parallel_tool_calls: true` and top-level tools;
3. the round trip of step 2 with a `toolu_`-shaped id and the reasoning item replayed (with and without its `rs_`
   id, if step 3 is refused with it);
4. a request whose last item is a developer message after the user message (a turn's first request);
5. step 1 repeated with the same `session-id` and `prompt_cache_key`: `cached_tokens` and `cache_write_tokens`;
6. spare, for re-running one that failed for a reason not about the request.
Then `rm` the marker. If request 1 is refused for its originator or user agent, STOP: the lane stays on `litellm`
until the operator rules (D27). Scrub the recordings into the corpus (`record.py scrub`), in a reviewed
change.

**3. Read the answers against the plan's open questions** (tools at top level, the trailing developer item, the
reasoning id, the cache headers) and record them in this plan's Deviations or the Stage 3 plan.

**4. The flip.** `ccrc codex switch lane-b direct`. Verify: `ccrc codex status lane-b --json` reads `mode: direct`,
`tiers.bridge` running, `tiers.litellm` and `tiers.shim` not running; `ccrc doctor` keeps the `codex` check green;
a session's next turn answers; `bridge.stats.json` moves.

**5. The 7-day watch** (spec §2.8), with lane-b's own 7 days on `litellm` before the flip as the baseline:
- zero empty tool calls (`outcomes.emptyArguments` on calls whose arguments were non-empty upstream; and no session
  reporting an empty `tool_use` input);
- a 5xx rate (`outcomes.5xx` / requests) no worse than the baseline's (from `litellm.log`, counts only);
- a compaction rate (`outcomes.compactionRequests` / message requests) no worse than the baseline's;
- no credential incident: the status never reads `needs-signin` or `config-error` without a cause the operator
  knows, no `refresh_token_reused`, `lastRefreshAt` moving about every half token lifetime;
- no unexplained name in the doctor's WARN (Task 17) at the end of the week.
D25 may lower a model's window during the week; each lowering is in `ccrc models lane-b show --json`'s windows with
`source: "refusal"`, and the operator decides whether to keep it.

**6. Flip back** at any failed criterion, or at once on a credential incident: `ccrc codex switch lane-b litellm`.
The roster then reads as it did before the flip. **Before any rollback** to a build without the bridge, switch every
`direct` lane back first: the older build reads the running bridge as foreign and cannot stop it.

**7. After the week**: the result, the counters and the decision go in this plan's Deviations (or a ledger PR); lane-a
follows only by the operator's ruling, and LiteLLM's removal is Stage 4.

## Deviations found

Every entry is unnumbered: the controller issues the numbers and replaces each slug in this plan and in any code
comment that cites it. A further departure found while executing is written `D-TBD-<slug>` and named in the task's
report.

### D-TBD-end-turn-false-continues-in-bridge — `end_turn:false` is continued upstream, never `pause_turn`

- **Departs from:** spec §2.4, "A reply the model marks as not finished (`end_turn:false`) becomes `pause_turn`", and
  "an interruption a normal stop".
- **What changed:** a reply ending `end_turn:false`, or `response.incomplete` `interrupted`, with no `tool_use`, is
  continued upstream inside the same Anthropic message, at most 3 times (Task 8); `pause_turn` is never emitted.
- **Why:** measured: Claude Code 2.1.308 does not continue a `pause_turn` (one request, the turn ends, the partial text
  is the result). The Codex CLI continues itself (`core/src/session/turn.rs:2988-2990` @ `092d3ac`) and maps
  `interrupted` to `end_turn:false` (`codex-api/src/sse/responses.rs:418-455`), so the spec's two sentences collide.
- **Cost if wrong:** up to three more upstream requests for one reply, counted; an unbounded need ends `end_turn`.

### D-TBD-policy-refusal-is-policy-blocked — 400 `policy_blocked` with `x-should-retry: false`

- **Departs from:** spec §2.4, "Policy refusal | 400, not retried", which names no error type or header.
- **What changed:** `error.type` `policy_blocked`, header `x-should-retry: false`, before and after commit.
- **Why:** measured: a plain 400 makes Claude Code retry three times with features turned off; its embedded gateway
  contract names this shape.
- **Cost if wrong:** a client older than the contract may read `policy_blocked` as an unknown type; it still sees 400.

### D-TBD-usage-limit-is-billing-error — 429 `billing_error`, `retry-after`, `x-should-retry: false`

- **Departs from:** spec §2.4, "Usage limit (`…_usage_limit_exceeded`) | 429 `rate_limit_error`".
- **What changed:** the backend's code is `usage_limit_reached` (HTTP only) plus the quota codes; the answer is 429
  `billing_error`, `retry-after` from `resets_at`, `x-should-retry: false`; the status reads `limit-paused`.
- **Why:** measured: without the header Claude Code retries (2 on a lane, 10 by default, about 3 minutes); the
  embedded contract names `billing_error` for a plan limit and keeps `rate_limit_error` for throttling.
- **Cost if wrong:** a session fails its turn at once on a limit instead of after the retries; that is the intent.

### D-TBD-transient-rate-limit-row — throttling is a row of its own

- **Departs from:** spec §2.4's table, which has no row for `rate_limit_exceeded`, `slow_down` or another 429.
- **What changed:** 429 `rate_limit_error`, the upstream `retry-after` passed through, no `x-should-retry`, so Claude
  Code retries as it does for an Anthropic throttle.
- **Cost if wrong:** two retries a turn on a lane, as today.

### D-TBD-capability-rejected-token — an unmapped feature is `capability_rejected: <class>`

- **Departs from:** spec §2.4, "Unsupported capability | 400 naming the field".
- **What changed:** the message is `capability_rejected: <class>` from Claude Code's class table (`document_block`,
  `image_block`, `structured_outputs_unsupported`, …), with the field name after it; a server tool, which has no class,
  is a plain 400 naming its type with `x-should-retry: false`.
- **Why:** Claude Code self-heals only on those tokens; a field name alone gets the generic degrade retries.
- **Cost if wrong:** none on the backend route today: no such request was seen.

### D-TBD-overflow-n-and-m-are-estimates — where the prompt-too-long numbers come from

- **Departs from:** spec §2.4, which gives the text and not its numbers, and its "Claude Code 2.1.300 parses that
  text" (2.1.308's match is a loose substring, measured).
- **What changed:** `N` is the D24 estimate of the refused request, `M` the lower of the lane's window (its
  `CLAUDE_CODE_MAX_CONTEXT_TOKENS`) and `floor(0.9 N / 1000) × 1000`, so `N > M` always; the refusal is recorded at `N`
  for D25.
- **Why:** the backend's overflow message has no counts (`codex-api/src/sse/responses.rs:1137` @ `092d3ac`).
- **Cost if wrong:** Claude Code trims by the pair; an over-estimate drops more history before its summary.

### D-TBD-usage-sum-equals-upstream-input — `cache_write_tokens` is reported as cache creation

- **Departs from:** spec §2.4, "Input is reported net of cached tokens, and cached tokens as cache reads", which says
  nothing of cache writes.
- **What changed:** `input_tokens = input − cached − cache_write`, `cache_creation_input_tokens = cache_write`, so the
  three fields Claude Code sums equal the upstream `input_tokens`, and proactive compaction fires at window − 33k
  (measured threshold rule).
- **Cost if wrong:** if `cache_write_tokens` is not inside `input_tokens`, the count is low by it; the first live step
  reads a non-zero one (step 2.5).

### D-TBD-context-management-counted-not-applied — no `clear_tool_uses` in the bridge

- **Departs from:** spec §2.3, "`context_management` | applied by the bridge itself (`clear_tool_uses`)".
- **What changed:** every edit type is counted; none is applied.
- **Why:** measured: 74 of 74 requests carried only `clear_thinking_20251015` with `keep:"all"`, which removes
  nothing; `clear_tool_uses_20250919` is a flag-gated idle feature in 2.1.308.
- **Cost if wrong:** if that flag turns on, tool results are not cleared on a `direct` lane (LiteLLM polyfilled the
  edit); the doctor names the edit the first day it arrives.

### D-TBD-drift-counters-in-stats-file — D3's names go to the stats file

- **Departs from:** spec §2.9 D3, "They go to the status file".
- **What changed:** names, counts and the unexplained list live in `bridge.stats.json`; the status file keeps the
  credential's state, the code and the request id.
- **Why:** Stage 1's status file is written only under the credential's lock; counters updated on every request would
  hold that lock in the request path.
- **Cost if wrong:** one more non-secret file per lane, reaped with the lane.

### D-TBD-bridge-package-runs-from-the-tree — the package is imported from the installed tree

- **Departs from:** D18, "a stdlib package beside" the shim.
- **What changed:** the package stays at `<tree>/ccd/codexbridge/`; the shim, placed in `~/.local/bin`, imports it from
  there in `direct` mode, and the bridge's started record hashes it, so an update restarts a running bridge.
- **Why:** every placement path places single files (Stage 1's D-TBD-library-is-one-module); the tree is already the
  box's code (`ccrc` runs `deploy/models-op.mjs` from it, `ccd/ccrc:1326`), and on the release lane it is immutable.
- **Cost if wrong:** a `deploy.sh` push rewrites the tree in place; a running bridge imported everything at start.

### D-TBD-instructions-switch-is-a-marker — D11's per-lane switch

- **Departs from:** D11, which names a per-lane switch and no mechanism.
- **What changed:** a marker file, `bridge-instructions`, in the lane directory, with no writer in the tree; with it,
  `system` travels as `instructions` (Claude Code's text alone, never LiteLLM's prompt).
- **Cost if wrong:** the operator touches a file instead of a roster field; a later stage may promote it.

### D-TBD-first-lowering-capped-at-lane-window — D25 on a model with no entry

- **Departs from:** D25, "sets that model's window to R × 0.9 … never raises", read per entry.
- **What changed:** a first automatic entry is capped at the lane's current window, and a refusal older than an
  entry's `setAt` is ignored (Task 15).
- **Why:** with every other class model measured, an uncapped first entry would raise the lane from the 200k default;
  and an old refusal would undo a deliberate `set-window`.
- **Cost if wrong:** a window learned from a refusal can end below what the backend accepts; raising is `set-window`.

### D-TBD-library-third-status-writer — the bridge writes upstream states into the status file

- **Departs from:** Stage 1's contract: the status file "is written only under the lock, by `ensure_fresh` and
  `sign_in_device`".
- **What changed:** `record_upstream` (Task 6) is a third writer, under the same lock, merging only `state`
  (`limit-paused`, `ineligible`, and `ok` over them), `lastErrorCode` and `lastRequestId`.
- **Why:** spec §2.4 puts `limit-paused`, `ineligible` and the upstream request id in the lane's status.
- **Cost if wrong:** a two-second lock wait at most, best effort, after a reply is sent.

### D-TBD-canary-after-consent — no canary in Stage 2

- **Departs from:** D26 ("during the soak … the canary runs `ccrc codex switch <id> litellm`").
- **Why:** D5 runs the canary "under the lane's consent", which is D22, Stage 3; the 7-day watch's flip back is the
  operator's (runbook step 6).
- **Cost if wrong:** a bad day on lane-b is caught by the doctor and the operator, not by a canary.

### D-TBD-wire-watch-tested-on-synthetic-excerpts — D1's own test

- **Departs from:** D1, "Its own test checks that it reports the 0.162.0 move of `instructions` and the 0.155.0
  removal of the compaction endpoint", read as the real files.
- **What changed:** the test runs on short synthetic excerpts shaped like those two changes; the workflow reads the
  real files at run time.
- **Why:** tests run offline, and no upstream source is copied into this repository.
- **Cost if wrong:** a real-file shape the excerpts miss is found by the first real run, which opens an issue.
