# Codex bridge, Stage 2: the bridge on the backend route — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Every test step follows
> superpowers:test-driven-development: the red test first, seen failing for the reason named, then the change, then
> green, then the task's mutation rows RUN (never read). Steps use checkbox (`- [ ]`) syntax for tracking. Each wave
> is one PR. Workers do not edit this file: the coordinator records rulings and measurements in it.

**Goal:** a Codex lane can run in `direct` mode, where one ccrc process on the lane's existing port, key and unit
answers Claude Code as an Anthropic endpoint and speaks the ChatGPT backend's Responses route itself, built from
finished items only, with no LiteLLM and no LiteLLM prompt, with Claude Code's own compaction working at the measured
window, and with `ccrc codex switch <id> litellm|direct` to move a lane between the two modes.

**Architecture:** the shim (`ccd/ccgpt-proxy.py`) keeps `litellm` mode byte for byte and gains a `direct` entry,
which imports a new stdlib package, `ccd/codexbridge/`, from the box's installed tree (D18, D19). Inside the package
three parts depend only on the one before (spec Figure 2): **inbound** turns an Anthropic request into a neutral
request, the **backend adapter** turns that into a Responses request and reads the HTTP answer, and the **reducer**
turns the upstream event stream into Anthropic events from `response.output_item.done` items alone. Beside them sit
the reasoning store (sqlite, 0600), the count estimator (D24) and a non-secret stats file, which the hourly models
refresh reads to lower a refused model's window (D25) and the doctor reads for drift names (D3). The credential is
Stage 1's library (`ccd/ccgpt-auth.py`): in `direct` mode the bridge is the lane's one refresher.

**Tech Stack:** Python 3.9+ standard library only (`http.client`, `http.server`, `json`, `sqlite3`, `ssl`,
`threading`, `hashlib`, `hmac`), run by the system `python3` in `direct` mode; bash (`ccd/ccrc`,
`ccd/ccrc-doctor-checks`); node `.mjs` (`deploy/models-op.mjs`, `deploy/account-op.mjs`, `shared/roster-json.mjs`)
and TypeScript (`shared/roster.ts`); vitest in `server/`, which spawns `python3 -I` drivers against an in-process fake
Responses backend and Stage 1's fake auth server; one scheduled GitHub workflow (`.github/`).

**Spec:** `docs/superpowers/specs/2026-10-15-codex-bridge-design.md` — §2.1 (the lane's shape), §2.2 (the backend
column), §2.3 (request translation), §2.4 (reply building), §2.5 (the reasoning store), §2.7 "What the bridge adds",
§2.8 (Stage 2), §2.9 D1, D3 and D4, §3 D9, D11-D14, D18-D20, D23-D25, D27, and §5 (the reducer and lane tests, the
first live step). The `siwc` adapter, D2 (the SIWC docs fingerprint), the pinned rule (D21), consent (D22), the
canary (D5, D26) and the trial are Stage 3; retiring LiteLLM is Stage 4.

**Branch:** three PRs, one per wave, each cut from `origin/main` after the previous one merged. Every line number
below is at `11b7096d3`, the commit this plan was written against; where an anchor moved, find the quoted text, not

**What was measured to write this plan** (all offline, 2026-10-22; no request left the box, no credential was read):
- **Claude Code 2.1.308 against a local stub** (27 runs, 75 requests, fixture HOMEs, the versioned binary run
  directly). Every message request carries exactly `model, messages, system, tools, metadata, max_tokens, thinking,
  context_management, output_config, stream`; never `temperature`, `top_p`, `top_k`, `stop_sequences`,
  `tool_choice`. `context_management` is always `{"edits":[{"type":"clear_thinking_20251015","keep":"all"}]}`.
  `system[0]` is `x-anthropic-billing-header: cc_version=…;` whose three-hex suffix varies between requests.
  Mid-conversation `role:"system"` entries arrive inside `messages`, as a string, a block list or `[]`. Tools carry
  `defer_loading:true` for `DeferredToolPlaceholder` and for a tool ToolSearch loaded; a ToolSearch result carries a
  `tool_reference` block. `count_tokens` came only from a large Read's pre-check. `output_config.effort` was sent on
  every request (`high` for a GPT model id), and `max_tokens` is 32000 for a GPT model id.
- **Claude Code's reactions.** `pause_turn`: no continuation, the turn ends (exit 0). A mid-stream `error` with no
  `message_stop`: the same request is re-sent at once with `stream:false` (the only `stream:false` sender found).
  `prompt is too long: N tokens > M maximum`: compaction after at least one exchange; on a single exchange it refuses
  to compact. A 429 or 401 with no hint: full exponential backoff (2 retries on a lane, `CLAUDE_CODE_MAX_RETRIES=2`,
  `ccd/ccrc-codex:183`); with `x-should-retry: false`: no retry. A plain 400: three feature-degrade retries. 403: no
  retry. 529: gives up after 2 retries. Its match for overflow is loose: case-insensitive "prompt is too long" or
  "input is too long for requested model", N and M read by `prompt is too long[^0-9]*(\d+)\s*tokens?\s*>\s*(\d+)`.

## Global Constraints

- **The design, verbatim from the spec.** §2.1: "One process per lane, on loopback, guarded by the lane's existing
  gateway key." "Stdlib Python, run by the system `python3`. No virtual environment." "a flip stops one set of
  processes before starting the other, which is also the moment the credential's ownership passes between them."
  §2.4: "The reducer builds each Anthropic block only from the upstream's **finished** items". "Zeros in
  `message_start` and the real figures in `message_delta`". "A `ping` after 15 s of upstream silence". "An upstream
  idle timeout of 300 s, as in Codex. On restart the bridge stops taking requests and finishes the streams in
  flight." "Errors known before the stream starts become real HTTP statuses; errors mid-stream become an Anthropic
  `error` event with no `message_stop`." §2.5: "stdlib `sqlite3`, mode 0600", "14 days, and a size cap that evicts
  the oldest first". D23: "oldest-first eviction past 256 MB". D24: "seeded at 3.5 bytes per token, rounded up". D25:
  "A refusal at size R sets that model's window to R × 0.9, rounded down to 1k, through the hourly models refresh;
  never raises". D27: "Send `originator: ccrc`."
- **`litellm` mode is today's path exactly** (D18). With `CCGPT_BRIDGE` unset, `ccd/ccgpt-proxy.py` runs the same code
  it runs today: the only edit in that file is the `__main__` branch and the `_run_direct` function it calls. The
  shim's existing suite (`server/test/ccgpt-proxy.test.ts`) and the runtime probe's `SHIM_OUT` pin
  (`server/test/ccgpt-runtime.test.ts`) stay green with no assertion changed.
- **The package imports only the standard library and Stage 1's library**, which it loads by path
  (`CCRC_CODEX_AUTH_LIB`, `importlib.util.spec_from_file_location`, `sys.dont_write_bytecode = True`), never by
  `sys.path`. Python 3.9+:
  every module passes `ast.parse(src, feature_version=(3, 9))` and Stage 1's PEP 604 walk (no `X | Y` in an
  annotation or an `isinstance` call), and imports only names in a fixed allowlist of the standard-library modules
  the package uses (Task 1's census; `sys.stdlib_module_names` exists only from 3.10). A socket timeout is caught as
  `socket.timeout` (an `OSError` that is not `TimeoutError` on 3.9). Every entry that imports the package (the shim's
  direct entry, the test driver, Task 18's two CLIs) sets `sys.dont_write_bytecode = True` first: `-I` implies `-E`,
  so `PYTHONDONTWRITEBYTECODE` is ignored and an import would write `__pycache__` into the tree.
  `codexbridge/__init__.py` imports every module of the package at start (`load_all()`), so an update that rewrites
  the tree under a running bridge changes nothing it runs.
- **Retries have one owner: Claude Code.** The bridge never retries an upstream request, except exactly one retry
  after the library refreshed a token the upstream answered 401 (never for a token issued within `FRESH_TOKEN_S`,
  which a refresh cannot cure), and the bounded continuation of an
  `end_turn:false` reply (Task 8). Today LiteLLM retries 429, 403 and 5xx three times and cools a model down for
  5 s; the bridge does neither.
- **One definition of every name.** The bridge's file names (stats file, reasoning store, recordings directory) are
  spelled once, in `laneManifest` (`deploy/models-op.mjs`), copied into `lane.json` as `bridgeFiles`, and read from
  there by bash and Python. The `x-codex-` usage headers are stored by prefix, never by name, so the poller's five
  names stay spelled once (`ccd/ccgpt-usage.py`). The upstream error codes, the stop-reason table and the known drift
  names are module constants in the package. `server/test/single-definition.test.ts` gains the rows (Tasks 1, 10).
- **No body, token or content is ever logged, counted or written to a non-secret file.** The stats file holds counts,
  sizes, names (bounded by `NAME_RE = ^[A-Za-z0-9_.:/-]{1,64}$`, else `unrecognised`) and request ids (bounded as
  Stage 1's status file bounds them). A response header's value is never counted: the one exception, the media
  type, is counted as the name `content-type:<type before ";", lower-cased>` under `NAME_RE`. The reasoning store
  holds encrypted reasoning items under hashed keys, 0600, and nothing else. A recording (Task 18) is raw upstream
  bytes, 0600, only while the operator's marker file exists. The direct handler catches every exception itself and
  logs only `ccgpt-proxy: direct: <exception class> <bounded code>`, never `str(e)` or a traceback, so socketserver's
  `handle_error` never prints one (an `http.client` header error formats the header value with `%r`).
- **Fixture HOMEs and fakes only; no test can reach a live endpoint.** Every bridge process in a test gets
  `CCGPT_BRIDGE_UPSTREAM_BASE` (a loopback `http://` URL, the only override the adapter accepts; a non-loopback value
  refuses at start) pointing at `fakeResponses` or, when the case needs no answer, at Stage 1's `CLOSED_AUTH_BASE`
  (`http://127.0.0.1:1`); and Stage 1's `CCRC_CODEX_AUTH_BASE`. `ghContainedEnv` and `containedSpawnOptions` set both
  defaults unless the caller names one (Task 7). A tier's environment is the manager's plus its pairs, never the
  caller's (`_svc_run_supervised`, `ccd/ccrc:1218-1222`; the nohup arm starts from `env -i`), so a bridge started
  through `ccrc codex start` or `switch` gets both only because `_codex_start_tier`'s bridge arm forwards each as a
  pair when the caller has it set (Task 11); on a live box neither is set and nothing is forwarded. A test that talks
  to an in-process server spawns asynchronously.
  Synthetic tokens are built at runtime (Stage 1's `syntheticJwt`), never written as literals.
- **Commands.** From `server/`, foreground, timeout at least 600000 ms, one file per command:
  `./node_modules/.bin/vitest run test/<file>.test.ts`. Never a bare `npx vitest`. vitest's per-test bound is 20 s
  on Linux, so every timer a case exercises is lowered through the driver's `consts` (Task 1), never waited out.
- **Mutation discipline.** Every guard ships with a row that goes red when the guard is removed or weakened. Run each
  row one at a time on the shipped file, restore it, prove the restore with `git diff --exit-code -- <file>`, and
  record `<row> → <n> failed (<titles>)` in the task's commit body; the counts below are predictions, measure them.
  Scratch notes go in `.superpowers/sdd/codex-bridge-s2/` (gitignored; check with `git check-ignore`).
- **Public repository.** Lanes are `lane-a`/`lane-b` in prose and the fixtures' own ids in tests, read by position.
  Model ids in tests are neutral (`model-6.1-alpha`, `model-6-beta`); no added line spells a real GPT model id. No
  hostnames other than the backend's public endpoint constant, no addresses, absolute home paths, account names or
  private project names. Fixture streams are synthetic: tiny prompts, `resp_`/`rs_`/`fc_`/`call_` ids of the form
  `<prefix>_fx<n>`, encrypted content `ENC-<n>`.
- **Upstream citations** are `openai/codex` paths at `092d3ac` (`rust-v0.162.1`), never a local copy.
- **Deviation numbers.** This plan writes only `D-TBD-<slug>` entries; the controller issues their numbers. A worker
  never calls the allocator: a further departure is written `D-TBD-<slug>` and named in the task's report.
- **Two new WARNs, inside the existing `codex` check only**: the bridge tier's stale row (Task 13, the twin of
  today's shim-stale WARN, `server/test/ccrc-doctor.test.ts:12475`) and the drift row (Task 17). R-O9 closed on
  2026-10-19, so no soak gate allow-lists WARNs by name today; no new doctor check name is added.
- **Not touched:** the `siwc` route, ccd placement (D21), consent (D22), the canary's request and reader
  (`deploy/models-canary.mjs`: only its lane probe changes, Task 11b), the PWA, `agent/src/whitelist.ts`,
  `shared/api.ts`, `ccd/ccgpt-runtime` and its LiteLLM patch, the LiteLLM environment (kept for `litellm` lanes), Node

## Review Focus

Five conditions the spec implies and no rule above spells out, the most likely to bite first. Each has its test in
the task that owns the code.

1. **A long silent turn**: high-effort reasoning, or a compaction summary (GPT compactions take a median of 239 to
   271 s, spec §1.2), with no upstream event for minutes. Expected: a `ping` every 15 s of downstream silence, the
   summary's text forwarded live as it streams, no abort before the 300 s upstream idle bound, and the idle bound's
   error at 300 s of upstream silence, not at Claude Code's watchdog. Pinned in Task 8 ("pings through a silence,
   then the live text") with the timers lowered.
2. **A session that came from a Claude lane**: history holding Claude `thinking` blocks with Anthropic signatures,
   `redacted_thinking`, `toolu_` ids and `cache_control` everywhere. Expected: thinking and redacted thinking are
   dropped and counted, `toolu_` ids pass through as `call_id` unchanged, nothing is refused. Pinned in Task 2
   ("a history from a Claude lane translates").
3. **A restart or a switch landing while a stream is in flight** (a rollout's spine restart, `ccrc codex switch`).
   Expected: the bridge closes its listener, a stream that finishes within `DRAIN_S = 5.0` s ends normally, every
   stream still open at `DRAIN_S` gets one `error` event `api_error` (so Claude Code re-sends it), and the process
   exits; every stop path waits at least `DRAIN_S + STOP_MARGIN_S` (10 s) before a KILL. **What this costs, said
   plainly:** the bridge runs under the shim's unit, so a restart is stop, then start, and between the listener's
   close and the new process's bind nothing listens. Claude Code on a lane retries twice, at about 0.6 s and 1.1 s
   (`stub.md` run 24, a 429; a refused connection is assumed to retry on the same schedule, unmeasured), so a request
   that arrives, or a cut stream's re-send that lands, more than about 1.7 s before the new bind fails its turn.
   `DRAIN_S` is kept short so that window is seconds, not a minute. Pinned in Task 8 ("SIGTERM: a short stream
   finishes, a long one gets api_error at DRAIN_S, a new connection is refused") and Task 11 (the stop waits).
4. **A connection that drops mid-block** (200 sent, a text block open, then EOF). Expected: the open block gets its
   `content_block_stop`, then one `error` event `api_error` and no `message_stop`; Claude Code's `stream:false`
   re-send is then answered by the fold. Pinned in Task 3 (fixture `synth2-drop-inside-live-text`) and Task 8
   ("the stream:false re-send after a mid-stream error is served").
5. **Both refreshers on one credential**: a `direct` lane whose LiteLLM tier was started by hand, or a switch
   interrupted between its stop and its start. Expected: `ccrc codex start` refuses `retired-tier-running` and never
   adopts it, `switch` re-measures before it starts, and the doctor FAILs the running retired tier. Pinned in
   Task 11 ("start refuses a running litellm tier on a direct lane"), Task 12 and Task 13.

`classify_http` reads the body's `error.code` (and `error.type`) BEFORE the HTTP status, so a code's row wins over its status's row (`slow_down` and
`server_is_overloaded` both arrive as 503). `login-failed`, Stage 1's ninth word, is raised only by `sign_in_device`, which the bridge never calls; an
`AuthError` whose word is in neither set is the 401 row. Every error keeps the upstream request id (`x-request-id`, else `request-id`) in the stats
file and, with its code, in the status file, except when `record_upstream`'s lock is not taken or no credential is present: then the library answers
None and no request id reaches the stats file (D-6827). A prompt-too-long 400 carries no `x-should-retry` header: the measured recovery used none.

**The commit point** (R17). The bridge holds the HTTP status line until the first of: the reducer releases its first
block event, a NON-failure terminal event arrives (`completed`, or `incomplete` with a known reason), or `HOLD_S =
15.0` seconds pass. A failed terminal (`response.failed`, a top-level `error`, a truncation) with no block released
stays pre-commit and is answered as a real status. The `HOLD_S` clock starts when the upstream response head
arrives, never at request receipt: the key check, the token (a lock wait included), the upstream request, a 401's
refresh and its one retry all run before it, so their failures are always real statuses. Before the commit point,
any failure is a real status; after it, an `error` event. `message_start` is the first SSE event written at commit,
carrying zero usage and the **requested** model id.

**Stop reasons** (R13, `reducer.stop_reason`): a `tool_use` block emitted → `tool_use`; else the refusal flag →
`refusal`; `response.incomplete` `max_output_tokens` → `max_tokens`; `content_filter` → `refusal`; `interrupted`, and
any `end_turn: false`, → continuation (below); an unknown incomplete reason → an `api_error` failure; otherwise
`end_turn`. `pause_turn` is never emitted (D-6410).

**Continuation.** A reply that ends with `end_turn: false` (or `interrupted`) and emitted no `tool_use` is continued
upstream inside the same Anthropic message: the bridge sends the same input plus that response's output items, at
most `CONTINUE_MAX = 3` times, renumbering block indexes; past the cap the message ends `end_turn` and the stats file
counts `continuation-cap`.

**Usage** (R15, `reducer.anthropic_usage`): `message_delta.usage` = `{input_tokens: max(0, input − cached −
cache_write), cache_read_input_tokens: cached, cache_creation_input_tokens: cache_write, output_tokens: output}`,
where `input` is the upstream `input_tokens`, `cached` its `input_tokens_details.cached_tokens` and `cache_write` its
`input_tokens_details.cache_write_tokens` (0 when absent). So the three input fields Claude Code sums equal the
upstream `input_tokens` exactly, and proactive compaction fires at the measured window minus 33k
(D-6416). On a continued message, the input fields come from the last response and
`output_tokens` is the sum.

- **The drain** (SIGTERM; D-6429). Open streams are kept in a lock-guarded registry with an in-flight
  counter. The signal handler only sets `stopping` and starts a thread that calls `httpd.shutdown()` (a
  `ThreadingHTTPServer`'s `serve_forever` cannot be shut down from its own thread, and its handler threads are
  daemon threads, so leaving them to the interpreter's exit would drop them). When `serve_forever` returns on the
  main thread: `httpd.server_close()` (new connections are refused from here, which is up to one poll interval
  after the signal: `serve_forever` notices the shutdown at its next poll, every 0.5 s by default, and until
  `server_close` the listening socket keeps accepting into its backlog), wait on the counter up to `DRAIN_S`,

  stats file, return 0. Claude Code re-sends a cut stream as `stream:false` at once (`stub.md` runs 06/07), and that

## Deviations found

### D-6410 — `end_turn:false` is continued upstream, never `pause_turn`

- **Departs from:** spec §2.4, "A reply the model marks as not finished (`end_turn:false`) becomes `pause_turn`", and
  "an interruption a normal stop".
- **What changed:** a reply ending `end_turn:false`, or `response.incomplete` `interrupted`, with no `tool_use`, is
  continued upstream inside the same Anthropic message, at most 3 times (Task 8); `pause_turn` is never emitted.
- **Why:** measured: Claude Code 2.1.308 does not continue a `pause_turn` (one request, the turn ends, the partial text
  is the result). The Codex CLI continues itself (`core/src/session/turn.rs:2988-2990` @ `092d3ac`) and maps
  `interrupted` to `end_turn:false` (`codex-api/src/sse/responses.rs:418-455`), so the spec's two sentences collide.
- **Cost if wrong:** up to three more upstream requests for one reply, counted; an unbounded need ends `end_turn`.

### D-6411 — 400 `policy_blocked` with `x-should-retry: false`

- **Departs from:** spec §2.4, "Policy refusal | 400, not retried", which names no error type or header.
- **What changed:** `error.type` `policy_blocked`, header `x-should-retry: false`, before and after commit.
- **Why:** measured: a plain 400 makes Claude Code retry three times with features turned off; its embedded gateway
  contract names this shape.
- **Cost if wrong:** a client older than the contract may read `policy_blocked` as an unknown type; it still sees 400.

### D-6412 — 429 `billing_error`, `retry-after`, `x-should-retry: false`

- **Departs from:** spec §2.4, "Usage limit (`…_usage_limit_exceeded`) | 429 `rate_limit_error`".
- **What changed:** the backend's code is `usage_limit_reached` (HTTP only) plus the quota codes; the answer is 429
  `billing_error`, `retry-after` from `resets_at`, `x-should-retry: false`; the status reads `limit-paused`.
- **Why:** measured: without the header Claude Code retries (2 on a lane, 10 by default, about 3 minutes); the
  embedded contract names `billing_error` for a plan limit and keeps `rate_limit_error` for throttling.
- **Cost if wrong:** a session fails its turn at once on a limit instead of after the retries; that is the intent.

### D-6413 — throttling is a row of its own

- **Departs from:** spec §2.4's table, which has no row for `rate_limit_exceeded`, `slow_down` or another 429.
- **What changed:** 429 `rate_limit_error`, the upstream `retry-after` passed through, no `x-should-retry`, so Claude
  Code retries as it does for an Anthropic throttle. `slow_down` arrives as an HTTP 503 and is read by its code.
- **Why:** Claude Code 2.1.308's embedded gateway contract keeps `rate_limit_error` for throttling and gives
  `billing_error` to a plan limit; a throttle is worth a retry, a plan limit is not.
- **Cost if wrong:** two retries a turn on a lane, as today.

### D-6414 — an unmapped feature is `capability_rejected: <class>`
