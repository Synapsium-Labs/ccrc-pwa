# Cleanup un-wedge — Implementation Plan

> **For agentic workers:** one PR per task. The four tasks can be built at once; three of them edit `ccd/ccd`, so they land one at a time in the order of §Landing order. To execute a task, REQUIRED SUB-SKILL: superpowers:subagent-driven-development, with superpowers:test-driven-development for every red-first step. Steps use checkbox (`- [ ]`) syntax. Workers do not edit this file's §Deviations found. A departure is named by slug in the task's report; the coordinator gives it a number. A worker never allocates.

**Goal:** Automatic cleanup of finished children works again and stays working. An archived row whose tree is gone is placed from its archive record; ccd and the console name the rows that hold cleanup, once each; the session hook refuses a repo-wide `git worktree prune`; the collector takes a temp root a box move left, and explains the rows git forgot.

**Architecture:** The proofs live in ccd (the anti-corruption layer), in the rows rung's one helper (`_ws_reclaim_recorded`) and the collector's one evaluation (`_ws_collect_eval`), so the audit, the verb's locked recomputation and the tail ask them the same way. ccd reports holding rows as data (`heldBy`); the server reads it through one L1 reader and decides the console's items in one L1 decider; L4 lanes and `watch.ts` only carry it. The hook's deny is one new category in the existing forbidden-match program, mirrored in the classifier.

**Tech Stack:** bash (`ccd/ccd`, `ccd/session-hook.sh`, jq 1.6+ with Oniguruma), TypeScript (ESM), `node:sqlite` (`CoordStore`, synchronous), React in `pwa/`, vitest.

**Spec:** `docs/superpowers/specs/2026-11-04-cleanup-unwedge-design.md` (D1 to D13; D3, D6 and D12 are Open). Main measured at `08e3b290a`.

## Global Constraints

- The repository is public: no private names in code, fixtures, commits or PRs. Fixtures use `project-a`, `row-a`, `row-b`, `lane-a`.
- **SAFETY.** Tests use fixture HOMEs only (`makeCcdHarness`, `server/test/ccdWsHelpers.ts`), never the live `$HOME`. No task runs `ccd` against the live host, and no task runs `ws-reclaim`, `ws-expire`, `ws-collect`, `ws-orphan` or any other `ws-*` verb outside a fixture HOME. Every new condition can only refuse or hold; none may turn a refusal or an unmeasured answer into a pass.
- No re-proof is weakened: every token is minted by the audit and re-proved inside the verb's lock, and a new arm is asked the same way at the audit, the locked recomputation and the tail.
- No new ccd verb, no new exec grant, no new refusal word. `no-worktree-record`, `witness-mismatch`, `containment-unproven` and `probe-unmeasured` keep their meanings.
- Wire changes are additive only; `FLEET_PROTO` stays 1. A new field is read through one reader, and its absence means today's behaviour.
- `shared/*.ts` imports nothing, not even `node:*`.
- Decide in L1, act in L4. `heldByOf` and `cleanupHeldBy` are pure; lanes and `watch.ts` call them in one line each.
- No overloaded null: `heldBy` absent (older ccd), `null` (rung not reached), `[]` (rung ran, no row held), rows, and malformed are five different answers.
- `ccd/ccd` carries a generated stamp on line 2. After every edit, `~/.local/bin/ccrc restamp ccd/ccd`, then confirm `node shared/mark.mjs --check ccd/ccd` exits 0 and exactly one line begins `# ccrc:generated`. `server/test/ownership.test.ts` is a gate for every `ccd/ccd` PR.
- Every new ccd function gets one row in `ccd/contexts.tsv` (context C4); `server/test/ccd-contexts.test.ts` is a gate.
- Every new guard ships with a test that goes red when the guard is deleted (the mutants listed per task), measured before and after and recorded in the PR. Restore a mutant from a saved copy (sha checked), never `git checkout`.
- Growth-listed files (`ccd/ccd`, `ccd/session-hook.sh`, `server/src/watch.ts`) grow only as far as the check allows: run `GROWTH_CHECK=armed` before the first push.
- No `D-7999` to `D-8002` reference in shipped source until this plan is on `main`; use the task name in comments until then.
- Gates run through `ccrc test`, one at a time: `~/.local/bin/ccrc test --heavy -- ./node_modules/.bin/vitest run <file>` from inside the package. Never two heavy runs at once. Known load flakes (CLAUDE.md) are re-run alone before calling a break.
- Every merge of main into a task branch is "merge main once, never a rebase". On a `ccd/ccd` stamp conflict take either side of line 2 only, resolve the rest as source, then restamp.
- Mail before every push and wave-done: a queued ruling can change a step.

## Review Focus

1. **A gone row placed wrongly.** The archive arm must hold whenever its record is unreadable, a link, older than this change, or disagrees with the row in `id`, `uuid`, `branch`, `workdir` or `workdirReal`, and whenever git still records the tree. Expected: `unres` as today. Pinned in R1 (`ccd-reclaim-archive-arm.test.ts`, one case per condition).
2. **A moved archived tree inside the child.** A tree moved into the child after its record was pruned must hold the child at the ladder and at the tail. Expected: unmeasured at rung 9, and `_ws_reclaim_owned` scans. Pinned in R1 ("an archived sibling's tree moved inside the child keeps the child").
3. **`heldBy` read as "nothing holds".** An older ccd's document has no `heldBy`; a malformed one is not `[]`. Expected: no item from either, and the per-child items stay unfolded. Pinned in R2 (`cleanup-held-by.test.ts`).
4. **The prune deny over-reaching.** A dry run, `git worktree list`, `git worktree remove <path>`, `git remote prune` and `git fetch --prune` must pass. Pinned in R3 (`fixtures/prune-deny/must-allow.json`).
5. **The collector's release taking the wrong directory.** A witness device this host mounts, a major-0 device, an unreadable table, a leaf on another device, a leaf born before the witness, a link and Darwin must all keep `witness-mismatch` or answer unmeasured. Pinned in R4 (`ccd-collect-box-move.test.ts`).

## Landing order

All four start at once. They land **R3 → R1 → R4 → R2**:

- **R3 first.** It shares no file, and it stops the accident that caused the wedge from happening again.
- **R1 next.** It is the durable fix. It also changes the `ccd/ccd` advice texts that R3's deny would otherwise contradict.
- **R4, then R2.** Each edits `ccd/ccd`, so each merges main once after the one before it lands (restamp, a narrow re-gate of its own files, CI as the arbiter for the rest), never a rebase. R4 is smaller and lands before R2. R2's `heldBy` sits beside R1's arm in `_ws_reclaim_workdir_shared`; its worker reads R1's merged hunk before writing its own.
- Nothing else that touches `ccd/ccd` merges between a task's merge of main and its own merge.
- Rollout is the operator's, through the update control plane, fleet box first. After R1 is live, the operator's one-time act on `row-a` and `row-b` (spec §10) is what un-wedges the box, since their records predate R1.
