# Flows wave 4a: an attested gate, reported with its evidence

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** the outcome door (wave 3b) also takes the outcome of an `attested` gate, which must carry its evidence; the server
records who attested what, and runs nothing (spec §5: "`attested` is the honest name for 'a command passes'").

**Spec:** `docs/superpowers/specs/2026-11-19-flows-design.md` §5, §10 item 4. Builds on `plans/2026-11-20-flows-w3b.md`
(branch `flows-w3b`); this branch (`flows-w4`) stacks on it.

## Decisions

1. **Wave 4 splits.** 4a is the attested gate, which needs nothing but the outcome door. 4b is `approval` (raises a
   Waiting-on-you item and passes on the operator's tick) and `pr-state` (reads the PR phase ccrc measures): both act or read
   beyond the flow store, so they get their own plan. Deviation `D-10015`.
2. **Evidence is required and bounded**: one to `EVIDENCE_MAX` (2000) characters, else `400`. An instruction or skill
   block's outcome records `evidence` NULL whatever the body says.
3. **Migration 127** (written as 113; renumbered to 126 when the stack was rebased onto `main` on 2026-11-24, and to 127 the same
   day after the coordinator advisor took 123) adds `flow_outcomes.evidence`; re-measured before the push.

## Tasks (as built)

   (`the server measures it`). Cases in `flows-outcome-route.test.ts`: accepted with evidence, refused without it and over
   the cap, NULL evidence for a skill block.
2. Migration 127; `recordFlowOutcome` writes the column; `coord-db` and `run-close-switch` follow.
