# The test box's tool sync, as built: departures from the plan's sketch

- **D-7553 (2026-10-30)** — `testbox-tools-sync-departures`: TB6 of `docs/superpowers/plans/2026-10-29-test-box.md` (D-7408) is built with five departures from the plan's sketch, none of which changes what the box verifies or installs. (1) The service's side is two files, not one: `agent/src/testbox/tools.ts` (L1) holds every decision the plan names (the sync state, the backoff on `CCRC_TESTBOX_PRISTINE_RETRY`, the no-op, the sets kept for live runs, the takeover, the rebuild after a node change), and `agent/src/testbox/toolsync.ts` (L4) is its driver, which writes `specs/tools`, starts `ccrc-testbox-tools.service` through the system manager and reads the unit's report; an L1 file cannot act. (2) `service.ts` keeps its one-line budget: the `tools.sync` line in `FRAME_HANDLERS` reaches the driver by a literal dynamic `import('./toolsync.js')` (the import census follows it), and the driver is attached to the service by the entry point. The status answer a connection is sent carries the sync's state through `toolsync.ts#statusOf`, the service's own answer with the sync's reason put first, which is where `status.ts#degradedReasons` puts it. The box's measured versions fill the status through the service's existing `tools` dependency. (3) The takeover (D-7426) closes admissions through the run limit the entry point hands the service, which the driver sets to 0 once a sync has replaced the release; it then waits for the service's runs to end and exits 0. Runs still queued are lost with the process, as with any service restart; the wrapper's lost-run handling (TB8) covers them. (4) In step 6 the new tool set and the verified release tree, with its `server/` production dependencies, are both made complete before `<tools>/current` and then `<tools>/release/installed` are each switched in one rename, so a failure in any step, `npm ci` included, leaves both names as they were (spec §2.10: a failed sync leaves `current` and the installed release on the previous set). `<tools>/current` is a link to a set directory under `<tools>/sets/`, since a rename cannot replace a non-empty directory; TB7's bootstrap lays out its first set the same way. (5) The node and Chrome download hosts are fixed in the root script, so the service user can choose versions but not where root downloads from; the tests reach fixture servers for those two names through root's fixture `~/.curlrc` (`connect-to` and a fixture CA), and a containment row proves the redirect before any other row runs. The script names no `TB_FIXTURE_` variable and no test box setting.
