## Review focus (the failure modes most likely to bite)

1. **Pane text sneaking back.** A fallback that reaches for `Dialog.title`, `body`, `raw` or a scraped label "just for this case" on an AskUserQuestion. `askSource` is the wall; review every branch that renders without calling it.
2. **A second envelope source with its own staleness.** T1a keeps the envelope on the session stream only. A change that widens `HOOKSTATE_FRESH_MS`, or keeps aged envelopes in the fleet card, the push body, the hold or `answerAsk`'s read, widens the key-based answer gate. Rejected.
3. **Escape declining a question.** Today the modal makes `useEscapeInterrupt` stand down. Inline (T1c) there is no open dialog, so an Escape from the composer, or from the card, would send Escape to the pane and decline the pending question. The interrupt must stand down while an inline ask is mounted, and the card's own Escape must be prevented.
4. **The composer moving.** The inline card is a new keyed sibling; the composer's key and order never change (D-5466). `skin-switch.test.tsx` keeps its typed text across a skin switch with an inline ask up.
5. **Focus theft.** An inline ask arriving while the operator types must not pull focus from the composer.
6. **One instance per width.** At the desk the ask is inline and no `Sheet` is mounted; on a phone the sheet and no card. One test per width class counts both.
