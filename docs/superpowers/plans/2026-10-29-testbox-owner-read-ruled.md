# The test box file's owner is read without a stat dispatch: ruled

- **D-7527 (2026-10-30)** — `testbox-owner-read-portable`: the test box plan (`docs/superpowers/plans/2026-10-29-test-box.md`, Task TB1, D-7456) has `_tb_uid <path>` read the box file's owner with `stat -c %u`, or `stat -f %u` under `CCD_OS=darwin`, "as `ccd/ccrc`'s `_plat_*` wrappers dispatch". Building TB1 on `origin/main` `4dcbbe272` found that `server/test/macos-platform.test.ts` (the standing GNU-spelling sweep over every shebang'd file in `ccd/`) refuses a `stat -c`/`stat -f` spelling anywhere outside the platform block of `ccd/ccrc` and `ccd/ccd`, and TB1 may change no other line of `ccd/ccrc` than `CCRC_SETTINGS`, so it cannot add an owner wrapper there. Ruled, as built: `_tb_uid` reads the third field of `LC_ALL=C ls -nd -- <path>`, the numeric owner on GNU and BSD alike, and refuses an answer that is not digits, so the owner check needs no platform dispatch and the sweep keeps scanning the file whole. The seam is unchanged: `_tb_box_file_ok` is still the one owner check, comparing `_tb_uid`'s answer with `_tb_box_owner_uid`, and every D-7456 row (the accepting row with `TB_FIXTURE_OWNER_UID=$(id -u)`, the refusals with it unset or another uid, and the two mutations) runs against it. An owner wrapper in the platform block, if a later task wants one, is that task's `ccd/ccrc` edit.
