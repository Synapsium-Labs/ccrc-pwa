## For S2 (what the getters and the row event really do)

- `row:<id>` fires when a row's record JSON or its pane verdict changes, and when the row leaves the listing. A
  supervised live row's record carries `supervisedAt`, which ccd's supervise loop restamps about every 30 s. So a live
  row fires `row:<id>` about every 30 s even when nothing a reader cares about has changed. A cold row never fires,
  because it is a copy of the last read.
- `currentRowFacts(id)` answers null for every row on a tick whose tmux listing failed. The per-row fallback measured
  the verdict inside `assembleFleet` and does not publish it.

## For the measurement pass

- The times arm roughly doubles the registry listing frame: about 25 to 30 bytes per name, so about 350 KB more per
  answer at 12,900 names, every 2 s. The agent also makes one `lstat` per entry per tick. This is derived, not measured.
  In return, a quiet tick's registry read falls to one request. Read the link's `readdir` round trip and the agent box's
  load before and after the agent carries `readdir-mtimes`. The times arm runs about 12.9k `lstat` calls per tick in

## Departures (by slug)

- **readdir-times-optional-member.** `FleetIO.readdirWithTimesMeasured` is optional on the interface. About 94 test
  fakes implement `FleetIO`, and a required member would break each one. Its absence means names-only keys, which is
  today's behaviour. The remote arm sends `times` only when the agent's `ready.ops` names `readdir-mtimes`.
- **registry-read-names-its-cold-rows.** `RegistryRead` gains `cold` beside the plan's `reused`. `cold` is the subset
  taken under `rowTemperature`'s cold rule. A hot row reused by key (the times arm) is still hot for hook states, usage
  and pane captures. Without `cold`, the tick plan would have to derive temperature a second time.
- **usage-tasks-stay-before-the-frame.** The usage and tasks lanes stay ahead of `assembleFleet`. Both already run on
  their own clocks, so they rarely cost the frame anything. A usage lane run reads every hot row, and a cold row
  whose entry was last read 30 s or more ago (`usageReadIds`, the lane's own wall clock); a cold row's entry is carried
  forward only while it was read within the last 30 s. The 30 s is the bound on the age of a carried entry; a change
  shows at the next usage lane run, at most 60 s later (the lane's cadence). At that cadence every cold row is
  already 30 s old at each run, so the carry saves no usage reads in production; it applies to a run kicked earlier.
  The `registry` phase includes the wait for the tmux verdicts; the `listing` phase is timed from the start of the ask. The plan's Interfaces do not list either lane after the frame, and Step 0's pins stay
  unchanged.
- **listing-name-may-hold-spaces.** The listing row pattern is `^(.+) ([01]) (\d+) (\d+)$`, not the plan's
  `^(\S+) …`. The three numeric fields still anchor every line. One tmux session on the box named with a space (an
  operator's own session, say) would otherwise fail every listing and send every tick down the per-row fallback.
- **unclean-read-evicts-the-cached-row.** `RegistryRowCache.put` of an unclean record removes the id's entry rather
  than only refusing to store it. Otherwise an older clean entry could make the row cold right after a fresh unclean
  read. A row that `buildRecord` drops is evicted the same way, through `RegistryRowCache.delete`, which the plan's
  interface does not list.
- **local-io-lists-names-only.** `localIO` does not implement `readdirWithTimesMeasured`, though the plan said it
  would. Test fakes spread `...localIO` and override `readdir`, for example to make the registry unlistable. With the
  member inherited, the tick's cached read would list the real filesystem past the fake. Local mode keeps names-only
  keys, so cold rows still skip; only hot-row reuse is lost there. A contract test pins the absence.
- **snapshot-writer-stats-the-file.** `SnapshotWriter` makes one `stat` of the cache file each tick, so a file deleted
  or rewritten under it is noticed and written again. Main made one `loadSnapshot` read each tick, so this is still
  cheaper. After a tick that skipped the write, the next clean tick writes even when the sessions are unchanged, which
  matches what main did on that tick. One `fleetws.test.ts` assertion changed: it expected a rewrite on an unchanged
  tick after a purge, and writing only on change removes that rewrite. The guard it protects still holds: after a
  purge the cache is not frozen at the old high-water mark.
- **frame-guard-through-change-latch.** Moving the fleet emit reshaped its byte-equality guard, and the
  `single-definition/advance-switches` census then failed. The guard now goes through `changeLatch`, which is still
  byte equality on the frame's JSON.
- **listing-decoder-lives-in-tickplan.** `verdictFromListing` and `pidFromListing`, with the `PaneListing` type they
  read, live in `tickPlan.ts` (L1), and `exec.ts` re-exports them. `exec.ts` keeps the format string, the decoder of
  tmux's text (`parsePaneListing`) and `Tmux.listPanes`, so the format and its decoder live only there (`tickPlan.ts` keeps two log strings and `tmuxName`). In `exec.ts`, those two
  readers made `fleet.ts` and `tickPlan.ts` load an L3 adapter at runtime, which `rings/outward-edges` refuses.
- **registry-read-waits-for-the-listing.** The registry read awaits the tmux listing before its per-row decisions,
  because the verdict is an input to the cold rule. So a slow tmux now holds `readRegistryMeasured`, and the lanes
  behind it, where main ran them before its first tmux call. The wait is bounded in both modes by the same timer:
  `PANE_LISTING_DEADLINE_MS` (10 s, inside `Tmux.listPanes`, which serves local and remote alike; remotely it starts
  before the frame is sent and fires at or before the agent's own deadline). Past it, the listing reads as failed,
  every row is hot and the tick asks each row the old way. That per-row fallback in a local mode still goes through
  `realRunner`, which has no deadline, so a hung local tmux still holds the tick under `ticking`, as on main; the
  deadline buys only that the registry read and the lanes behind it run once before the hang.
- **clean-means-no-unreadable-field.** `isCleanRecord` is wider than the plan's three conditions (unmeasured, lifecycle
  unmeasured, hold unreadable): spec §2.1 governs ("no unmeasured or unreadable field"). It also refuses an unreadable
  project or branch read, an unreadable route field, the substrate and strand unreadable markers, and an unreadable
  child, deny-settings or child-shell mark. A measured absence (a main checkout's missing `.branch`) stays clean, and
  `namedByOperator` cannot be told apart from an unreadable read, so it has no clause. A hot row reused by key is
  re-read every 30 s (`hotRowReuse` takes `nowMs`), so a one-off failed read cannot stick while the key never changes.
  A plain field (`.archived`, `.prphase`, `.workspace` and the like) that reads `unreadable` still folds to null as on
  main, but `buildRecord` now marks the record (`plainFieldUnreadable`, server-side only, never on a wire type) and
  `isCleanRecord` refuses it, so the cache never stores such a record. The plain read goes through `fieldMeasured`
  (one request, as before), and the old `field()` helper is gone.
- **an-empty-listing-is-no-listing.** An exit-0 answer with no pane line is `ok: false` (`tmux listed no panes`), not
  a listing of zero sessions. A running tmux server always has a session (with none it exits 1, "no server running"),
  so an empty listing proves nothing, and the tick falls back to the per-row calls, which is today's behaviour. The
  plan read empty stdout as zero sessions; many test fakes answer every tmux call with exit 0 and no output, and under
  that reading every row was gone and no pane was captured.
- **snapshot-purge-test-names-its-predicate.** `persistFleetSnapshot` imports `isRegistryId` and calls it, instead of
  taking it as a parameter, so `watch.ts` no longer names it. The id-argv census now lists `fleetstate.ts` among its
  gate files in place of `watch.ts`: the purge test is the one place that vets an id there.
- **clean-predicate-lives-with-the-record.** `isCleanRecord` moved from `rowTemperature.ts` to `registry.ts`, the
  record's writer and the owner of its vocabulary (`HOLD_UNREADABLE`, `SUBSTRATE_UNREADABLE`, `STRANDED_UNREADABLE`).
  The widened predicate reads `projectEvidence`, and the core-vocab census allows that field one reader outside the
  writer. `rowTemperature.ts` re-exports it, and `registryRowCache.ts` imports it from `registry.ts`. A pure move.
- **verdicts-may-be-a-promise.** `RegistryReadOpts.verdicts` may be a Promise of the function, where the plan types a
  function. `readRegistryMeasured` awaits it after the registry's own listing, so the tmux listing and the registry
  listing run together.
