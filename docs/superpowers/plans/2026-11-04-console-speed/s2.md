## Departures

- `fleetrowsusable-not-reexpressed`: `lifecycle.ts` stays out of S2 (the coordinator's ruling). `fleetRowsUsable` is
  unchanged, and `served-read.test.ts` pins that it and `servedFromWatcher` answer the same over one table.
- `older-hidden-reads-the-window`: the release window would make Settings' "N older releases are not offered here"
  count only what the window kept. `pwa/src/screens/updates.tsx` reads `releasesTotal` to restore it, and its
  absence keeps today's arithmetic.
- `release-window-keeps-dev-rollback`: the plan's rule 4 keeps three older Stable releases per installed tag. The
  window also keeps three older releases of any channel per installed tag (a Dev fleet's Roll back list), each
  installed tag's own row (the Running row), the newest three non-withdrawn Stable releases (an unmeasured
  Stable fleet's list), and every release a node refused (rule 6, commit fae482253: the refusal is shown on its row).
- `beat-needs-a-session-store-arm`: the `beat` member of `SessionStreamMsg` needs one `case 'beat': return s;` in
  `pwa/src/stores/session.ts`, whose switch is exhaustive (`satisfies never`). That file was outside the split.
- `before-without-limit-refused`: `GET /api/runs?closed=1&before=N` with no `limit` answers 400, where `before` was
  ignored before. A cursor with no page size is malformed, and no caller sends one. So does `GET /api/runs?limit=N`
  without `closed=1` (pinned in `runs-page`, "limit 0, 501…"): a page of the archive is only asked with it, and no
  caller sends one either (`pwa/src`, `ccd`, the skills and `ccrc-api` searched).
- `attribution-edge-in-one-commit`: the D10 edge (a row retired mid-read answers `unknown-sender`) follows from
  `readSessionRecord` itself, so it shares the code change's commit, whose body names it.
- `runs-page-ring-follows-the-store`: the plan's file table puts `coord/runsPage.ts` in L3, but `coord/store.ts`,
  whose delegate imports it, is L1 by its facts, so a declared L3 made an outward edge (`outward-edges.test.ts`). The

- `updates-section-passes-the-total`: `pwa/src/screens/settings/UpdatesSection.tsx`, outside the split, passes
  `releasesTotal` to the window (one line).

- `run-pages-merge-in-run-words`: the pure merge of the archive's pages (`RunPagesView`, `mergeFirstRunPage`,
  `appendOlderRunPage`) lives in `pwa/src/fleet/runWords.ts`, outside the split, the L1 owner of the board's run
  decisions, so `useColdRuns.ts` decides nothing.

- `stream-status-follows-the-listing`: with a watcher, a chat stream re-resolves on `row:<id>`, a rotation or the
  30 s backstop (D8). S1's row signature carries no live status, so a working-to-idle flip fired no event and the chat

- `runs-page-type-spelled-once`: `api.runsPage` returns `RunsPageAnswer` (review 1464, N1; two lines of
  `pwa/src/lib/api.ts` under leave).

- `served-age-untyped-on-two-answers`: `ageMs` reaches the `GET /api/projects` and `GET /api/fleet` answers, but

- `run-pages-keep-recently-closed`: page one of the run archive also carries every closed run that closed at or after

- **F1, the mechanism now.** `operatorActRoute` (`servedRead.ts`) names an operator act: every route under
  `/api/accounts/` of any method, every write to `/api/accounts`, and `POST /api/projects/:project/pool`.
  - An `onRoute` hook in `server.ts` wraps each such route's handler. The act counts in when its handler starts and
    counts out, with a stamp, at the later of two moments: the handler settling and the response closing.
  - An act the client aborts therefore stays in flight until the box has answered the handler. An act still in flight
    counts as ending now.
  - `takenAfter` hands a route the watcher's measurement only when that tick began after the last act ended:
    - the limits of `GET /api/accounts`;
    - both halves of `GET /api/projects`;
    - the pools read beside `/api/fleet`'s listing.
  - One mechanism in one place. The sign-in's status read keeps its stamp because it is an act route.
- **The residual no stamp can fix.** An act whose op ends `outcome-unknown` (a timeout, a lost link or too much output)
  has ended for the server when its handler answers. If the agent writes after that, a tick between the answer and the
  write is served until the next tick, 2 to 3 s.
- **A2.** A refusal inside a handler counts, since the box may have acted. An act the auth gate refuses never reaches
  the handler, ran nothing, and is not counted.
