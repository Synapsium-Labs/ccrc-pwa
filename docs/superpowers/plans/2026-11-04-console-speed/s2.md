## Departures

- `fleetrowsusable-not-reexpressed`: `lifecycle.ts` stays out of S2 (the coordinator's ruling). `fleetRowsUsable` is
  unchanged, and `served-read.test.ts` pins that it and `servedFromWatcher` answer the same over one table.
- `older-hidden-reads-the-window`: the release window would make Settings' "N older releases are not offered here"
  count only what the window kept. `pwa/src/screens/updates.tsx` reads `releasesTotal` to restore it, and its
  absence keeps today's arithmetic.
- `release-window-keeps-dev-rollback`: the plan's rule 4 keeps three older Stable releases per installed tag. The
  window also keeps three older releases of any channel per installed tag (a Dev fleet's Roll back list), each
  installed tag's own row (the Running row), the newest three non-withdrawn Stable releases (an unmeasured
  Stable fleet's list), and every release a node refused (rule 6, commit fae482253: the refusal is shown on its row).
- `beat-needs-a-session-store-arm`: the `beat` member of `SessionStreamMsg` needs one `case 'beat': return s;` in
  `pwa/src/stores/session.ts`, whose switch is exhaustive (`satisfies never`). That file was outside the split.
- `before-without-limit-refused`: `GET /api/runs?closed=1&before=N` with no `limit` answers 400, where `before` was
  ignored before. A cursor with no page size is malformed, and no caller sends one. So does `GET /api/runs?limit=N`
  without `closed=1` (pinned in `runs-page`, "limit 0, 501…"): a page of the archive is only asked with it, and no
  caller sends one either (`pwa/src`, `ccd`, the skills and `ccrc-api` searched).
- `attribution-edge-in-one-commit`: the D10 edge (a row retired mid-read answers `unknown-sender`) follows from
  `readSessionRecord` itself, so it shares the code change's commit, whose body names it.
- `runs-page-ring-follows-the-store`: the plan's file table puts `coord/runsPage.ts` in L3, but `coord/store.ts`,
  whose delegate imports it, is L1 by its facts, so a declared L3 made an outward edge (`outward-edges.test.ts`). The
  file declares no ring, and its ring follows its facts: its one importer is L1, so the plan's L3 was wrong.
- `updates-section-passes-the-total`: `pwa/src/screens/settings/UpdatesSection.tsx`, outside the split, passes
  `releasesTotal` to the window (one line).

- `run-pages-merge-in-run-words`: the pure merge of the archive's pages (`RunPagesView`, `mergeFirstRunPage`,
  `appendOlderRunPage`) lives in `pwa/src/fleet/runWords.ts`, outside the split, the L1 owner of the board's run
  decisions, so `useColdRuns.ts` decides nothing.

- `stream-status-follows-the-listing`: with a watcher, a chat stream re-resolves on `row:<id>`, a rotation or the
  30 s backstop (D8). S1's row signature carries no live status, so a working-to-idle flip fired no event and the chat
  header could lag the fleet card by up to 30 s. D8 justified its triggers by swaps and rotations, never by status, and
  the card and the header are two renderings of one measurement (`server/src/fleet.ts`, `server/src/sessionws.ts`). So the stream compares its row's `status`
  and `statusUpdatedAt` in the watcher's in-memory listing every 2 s and runs `tick()` only when either changed: no
  extra I/O, S1's files untouched (the coordinator's ruling).
- `server-ts-session-stream-watcher`: leave for one changed line in `server/src/server.ts`, the `watcher` argument to
  `SessionStream` in the `/ws/session/:id` handler.
- `runs-page-type-spelled-once`: `api.runsPage` returns `RunsPageAnswer` (review 1464, N1; two lines of
  `pwa/src/lib/api.ts` under leave).

- `served-age-untyped-on-two-answers`: `ageMs` reaches the `GET /api/projects` and `GET /api/fleet` answers, but
  neither answer has a named type in `shared/api.ts`: each is an object literal built in its route in
  `server/src/server.ts` (`app.get('/api/projects', …)` and `app.get('/api/fleet', …)`). `ageMs` is typed only where
  the routes build it. A follow-up gives both answers a named type in `shared/api.ts`.

- `run-pages-keep-recently-closed`: page one of the run archive also carries every closed run that closed at or after
  the page's oldest close. Otherwise a long-lived run (an old id) that just closed sat on neither Active nor Finished
  until the operator paged back to it. `nextBefore` stays id-based. Follow-up: the extra rows have no cap, so a mass
  close after the page's oldest close rides page one.
- `run-pages-pin-reads-the-attention-list`: the run pages pin the closed runs the reclaim banner names, by reading the
  coord frame's attention list in `server/src/coord/routes.ts` (spec §2.2). A §5.9 guard
  (`child-reclaim-verdict-readers.test.ts`, case (e)) bars any reader of that list. Spec §5.9 bars a reclaim
  decision from reading the published verdicts, and this read only chooses which rows are sent, so the guard names
  it as the one presentation reader, with a control that it stands once (the coordinator's ruling).

- **F1, the mechanism.** The act routes mark the served limits stale. An `onSend` hook in `server.ts` stamps when the
  handler of an account act ended: every route under `/api/accounts/` of any method, and every write to
  `/api/accounts` (`accountActRoute`, `servedRead.ts`). It stamps before the answer leaves, so the app's refresh can
  only arrive after it. `takenAfter` then hands `GET /api/accounts` and `GET /api/projects` the watcher's limits only
  when that tick began after the stamp (`listedAt`, taken before the tick reads the limits). Until such a tick lands,
  both routes read for themselves. A refused act counts too, since the box may have acted. The sign-in's status read
  (`GET …/auth`) counts because that is where the server sees a sign-in end. `lanesWire` taking `disabled` from its own
  read was not chosen: `accounts[].disabled` and `authDead`, the answer a dark gate's reader gets, come from the same
  served limits.
- **F2.** `onRowChanged` keeps its event as `rerun` (before `start()` arms the stream, or while a tick is in flight).
  `tick()` drops a poll or the backstop that finds a tick in flight, as the base did.
- **F3.** Both arms of `/api/fleet` read one predicate, `linkDown` (remote mode, a fleet state, not connected), so
  local mode keeps serving. The pin names a fixture snapshot path: `testDeps` names none, and the default is under
  the real home.
- **F13.** The listener order changes no behaviour, because the `/ws/fleet` handler is synchronous between the two lines
  (the review measured no leak path), so only the unref has a red-first pin.
- **F12.** `POST /api/mail` and its ack still read the whole registry, and still answer `registry-unmeasurable` for a
  row retired between two listings mid-read, where the attribution lanes now answer `unknown-sender`. Carrying D10
  into the ingress is a follow-up.
