# The test service's seams the spec left open: ruled

- **D-7501 (2026-10-29)** — `testbox-service-seams`: building TB4 of the test box plan (`docs/superpowers/plans/2026-10-29-test-box.md`, D-7406) on `origin/main` `5877c9fea` found six things the spec and the plan do not name. Ruled, as built: (1) the service's listen address and token file are two more box keys, `CCRC_TESTBOX_LISTEN` (`host:port`, the tailnet address; no default, so a box without it refuses to start) and `CCRC_TESTBOX_SERVICE_TOKEN_FILE` (the service user's 0600 token file), read by `agent/src/testbox/config.ts` from the box-mode printer like every other key; TB1's printer adds both, and (6)'s third, so its box key count is 25 + 3. (2) `shared/testbox.ts` has no status request frame, so the service answers a client's `hello` with its `StatusAnswer`, as the fleet agent answers with its ready frame; a client that wants only the status closes after it. (3) The prepare unit says why it failed on its last stderr line, in `TESTBOX_FALLBACK`'s words; the system manager writes the prepare unit's output to `out/<k>/prepare.stdout` and `out/<k>/prepare.stderr` and the run unit's to `out/<k>/stdout` and `out/<k>/stderr`, the names TB7's units use. The clean unit writes its report word (`ok`, `missing`, `oversized`, `not-regular`) to `results/<run-id>/report.status` beside the copied report. (4) A session's `--maxWorkers` lower than `CCRC_TESTBOX_WORKERS` is kept, and then the three worker names carry the same lower count, so the flag and the names never disagree. (5) Queue positions are decided (`agent/src/testbox/queue.ts#positions`) but `TESTBOX_PROTO` 1 has no frame that carries them to a waiting client; the task that builds the client (TB8) adds it, additively, and a submission the box will not run is refused by closing the connection with code 1008 and the reason. (6) Spec §2.2 lets a unit end by timing out but names no bound: the box key `CCRC_TESTBOX_UNIT_MAX` (a duration, default `1h` for TB1's table) is the longest a prepare, run, clean or install unit may run, TB7 sets each unit's `RuntimeMaxSec=` from it, and the service's `systemctl start --wait` and mirror git run under it. Every process the service starts goes through the one bounded spawner, `shared/spawn.mjs#boundedSpawn` (`agent/src/testbox/exec.ts`), so the spawner audit gains no row; the short calls (the settings printer, `systemctl show` and `stop`, the reflink probe) take `UPDATE_SPAWN_TIMEOUT_MS`, the bound the agent gives its launcher calls.
