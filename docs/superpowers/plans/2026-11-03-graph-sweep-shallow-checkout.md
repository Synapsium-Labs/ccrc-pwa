# The graph store's checkout of a shallow source

- **D-7791 (2026-11-03)** — the graph sweep's store checkout borrows the source's objects through an alternates line written after `git init`, and never uses `git clone --shared`. For a local source that is shallow, `git clone` leaves its local path and clones over upload-pack, where `--shared` does nothing: no `objects/info/alternates` is written, only the objects of the source's branch heads are copied, and the clone exits 0. The sweep's source ref, `refs/remotes/origin/main`, is not a branch head, so its commit was never in the copy, and the copy never sees a later fetch. On the fleet box every shallow source therefore failed each pass at setup ("cannot move the store's checkout"), and each copy duplicated the source's objects. `_gs_prepare` now (1) makes the checkout with `git init -q` and `git symbolic-ref HEAD refs/heads/graph-store` (not `init -b`, which needs git 2.28) plus `<common dir>/objects` in its alternates; (2) mirrors `<common dir>/shallow` into the checkout's `.git/shallow` on every pass, or removes it when the source is full; (3) makes the checkout again when none of its alternates lines resolves to the common dir's objects, so a broken copy left by an earlier pass is replaced on the first pass after deploy, with no manual step, and its copied objects are freed; and (4) puts git's first error line in the row's reason when the checkout cannot move, through ccd/ccrc's `_upd_redact`, the one log-line redactor. A checkout that already borrows from its source is kept as it is, including one the old `git clone --shared` made from a full source. Spec §2.2 of `docs/superpowers/specs/2026-10-28-graphify-shared-graphs-design.md` records the change; the rows are in `server/test/graph-repo-sweep.test.ts` (the D-7791 describe).
