## Problem 2: which contract the engine's entry has (decided)

**The entry reads the source it is handed; it never resolves a repository-relative path.** The CLI stays #1660's
argv, with its third argument renamed from `<ccd>` to `<source>`:

```
node shared/hook-helpers.mjs --write|--check|--restamp <target> <source> | --regions
```

- `<source>` is the region's source file, and **the caller chooses it**: `ccrc restamp` from `--regions`' third column
  (below), a test by naming `ccd/ccd` or `ccd/ccrc`. The module states no root, because nothing in it resolves
  `source` against one; the two places that do resolve it say their root: `cmd_restamp` resolves against the target's
  own tree (`$dir/..`, the tree it already takes the module from), and the census against its own `root` argument
  (`REPO` by default, a planted tree in a FIXTURE).
- **`row.source` is still read by the entry**, as an identity check, so it is not a dead field there: before reading
  either file, the entry compares the last `/`-separated segment of `<source>` with the last segment of the target
  row's `source` (`ccd` for the hook and auth-dead rows, `ccrc` for the log-line row; `--write` and `--check` on a file
  with no region use the hook row, as today, and `--restamp` on such a file still prints `nothere` with no check). A mismatch writes nothing and exits 2 with one stderr line,
  `hook-helpers: <target> carries the <label> region, whose source is <row.source>; <source> is not that file`. The
  segment is cut with `lastIndexOf('/')`, never `node:path` (the carve-out). The check is by basename and not by the
  whole `ccd/<name>` suffix because `_restamp_hook_note` passes a file it only knows is named `ccd`; every caller
  measured in item 2 passes the right basename, so the check changes no existing call's output.
- **`row.source`'s readers are therefore three, each with a row and a mutant:** `--regions` (the `--regions` row), the
  entry's identity check (the CLI identity row), and the census (its FIXTURE row). The sketch's "the entry reads each
  row's own `source` file itself, never `ccd/ccd` by default" is withdrawn; its other half ("`cmd_restamp` uses the
  third column to choose the file it passes") is the contract.
- The sketch's CONTROL row ("a row whose `source` file is absent makes `--check` exit non-zero naming the path") holds
  as today's behaviour, pinned, not changed: an absent `<source>` is the uncaught `ENOENT`, exit 1, stderr naming the
  path. Changing that error path is not part of this task.

**`--regions` prints three columns,** `detect\tlabel\tsource`, `source` the row's repository-relative path. Its one
reader changes in the same commit:

- `ccd/ccrc#_restamp_region_of` reads `IFS=$'\t' read -r detect label source`, and for the row whose `detect` the file
  carries prints `label`, a tab, and `${source:-ccd/ccd}`. The default is for a two-column module (a target tree whose
  `shared/hook-helpers.mjs` predates C5i), where every region's source was `ccd/ccd`; it keeps restamp working on such
  a tree exactly as today.
- `ccd/ccrc#cmd_restamp` splits that at the first tab into `what` (the label, as today) and `source`, and resolves
  `srcfile` as `$dir/${source#ccd/}` when `source` is `ccd/<name>` with no further `/` and no `..`; any other
  `source` leaves `srcfile` empty. It then refuses, writing nothing, when `$hooks` or `$srcfile` is missing, with
  today's sentence and the file it lacks:
  `restamp: $f carries generated $what, but its own tree lacks $hooks or ${srcfile:-$source}; restamp it from a full
  checkout (the tree holding both ccd/ and shared/). Nothing was written.` For the hook and auth-dead rows `srcfile` is
  `$dir/ccd`, so their refusal text is byte-identical to today's. The sketch's per-region wording ("carries a generated
  log-line redactor") is dropped: one template, the label `log-line redactor`, no branch per region.
- `_restamp_hook_region "$hooks" "$f" "$srcfile"` replaces `… "$ccdsrc"`. The `case` that refuses `ccd/ccd` (stamped at
  install time) and `_restamp_hook_note` are unchanged.
