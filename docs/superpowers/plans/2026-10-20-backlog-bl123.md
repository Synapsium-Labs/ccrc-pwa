# Backlog: drain the outward-edge imports (ARCH-05, #551)

A short plan for one backlog item. GitHub issue: #551, `[ARCH-05] Drain the outward-edge exemptions (constants, rundefs tx split, PWA helpers)`.

## Problem

A policy file becomes impure through what it imports.

- **Server.** `coord/rundefs.ts` opened with `import { tx } from './db.js'`. Five coordination policy files import something from it: `childReclaim.ts`, `close.ts`, `kickoff.ts`, `expireArchived.ts` and `collectTempRoot.ts`. Most of them want only a marker constant, but each one had a runtime path to `node:sqlite`. Pure values were also read through adapters:
  - `NODE_ID_RE` came through `coord/store.ts`, in `token/link.ts`, `token/door.ts`, `token/driver.ts`, `update/inventory.ts` and `accounts/audit.ts`.
  - `UNMEASURED` came from `exec.ts`, which spawns processes, in `lifecycle.ts`.
  - `configDirFor` came from `config.ts`, which imports `coord/db.ts`, in `turnverdict.ts`.
- **PWA.** Six imports ran from a feature directory into a screen. `fleet/sessionFacts.ts` and `session/reapWords.ts` took `humanBytes` from `screens/ArchiveScreen.tsx`. Three fleet files took the settings words and the result line from `screens/settingsText.ts`. `fleet/WhatsNewSheet.tsx` took `releaseDate` from `screens/updates.tsx`. On top of that, `ApiError` lived in the fetch adapter `lib/api.ts`, and `timeOf` lived in the `MessageBubble.tsx` component.

## Fix

- **Server (D-5896).**
  - `rundefs.ts` keeps its pure half. The mail writes that run under `tx` move to `coord/rundefsTx.ts`: `queueSystemMail`, `insertSystemMailTx` and `queueStallNotice`.
  - `tx` moves to `coord/tx.ts`, which takes `node:sqlite` as a type only. `db.ts` re-exports it.
  - `NODE_ID_RE` readers import it from `shared/agent-protocol.ts`, where it is defined.
  - `UNMEASURED` moves to `server/src/unmeasured.ts`, and `configDirFor` to `server/src/configDir.ts`. Their old modules re-export them.
- **PWA (D-5897).**
  - `ApiError` moves to `lib/apiError.ts`, and `lib/api.ts` re-exports it.
  - `humanBytes`, `timeOf`, `releaseDate` and `isPlaceableInstant` move to `lib/format.ts`, which imports nothing. `fleet/useUpdatesView.ts` re-exports `isPlaceableInstant`.
  - `settingsText.ts` moves from `screens/` to `fleet/`, beside the two Settings sections that already live there.

## Tests

- `server/test/coord-policy-rings.test.ts` walks the runtime import graph. tsc elides type-only imports, so the walk skips them. The test asserts that the five policy files, `rundefs.ts`, `rundefsTx.ts` and `tx.ts` have no path to `node:sqlite`. It also asserts that each constant's readers no longer import the adapter. Its controls prove that the walk finds `node:sqlite` from `db.ts`, `store.ts` and `routes.ts`.
- `pwa/test/screens-back-edges.test.ts` asserts that `fleet/` → `screens/` and `session/` → `screens/` are both empty. Type imports count. It also asserts that `lib/format.ts` and `lib/apiError.ts` import nothing, and that `lib/api.ts` re-exports the same `ApiError` class.
- Two existing pins follow the move:
  - The coord ring's `HANDLE_HOLDERS` in `single-definition.test.ts` loses `rundefs.ts` and gains `rundefsTx.ts` and `tx.ts`.
  - The claim door's import allowlist in `token-claim-route.test.ts` loses its `../coord/store.js` entry.

## Deviations and decisions

### Issued for this work and defined here

- **D-5896** — `policy-files-off-the-db-adapter` (ARCH-05, #551, server): `coord/rundefs.ts` is split into a pure half and `rundefsTx.ts` (the three mail writes under `tx`), `tx` itself moves to `coord/tx.ts` (it needs only the handle's `exec` and takes `node:sqlite` as a type; `db.ts` re-exports it), so `childReclaim.ts`, `close.ts`, `kickoff.ts`, `expireArchived.ts` and `collectTempRoot.ts` have no runtime path to `node:sqlite`; `NODE_ID_RE` readers import it from `shared/agent-protocol.ts` rather than through `coord/store.ts`, `UNMEASURED` moves to `server/src/unmeasured.ts` and `configDirFor` to `server/src/configDir.ts`, each re-exported from its old module. `close.ts` and `kickoff.ts` still queue mail; the handle reaches them from the store they are handed, not from their imports. The proposal's `defaultSessionsPath` stays in `auth/sessions.ts`: `config.ts` imports `coord/db.ts` for `defaultCoordDbPath` anyway, so moving it alone purifies nothing.
- **D-5897** — `pwa-features-import-no-screen` (ARCH-05, #551, PWA): `ApiError` moves to `lib/apiError.ts` and `humanBytes`, `timeOf`, `releaseDate` and `isPlaceableInstant` to `lib/format.ts`, both leaves that import nothing, with `lib/api.ts` and `fleet/useUpdatesView.ts` re-exporting what they held so no screen changes its import; `settingsText.ts` moves from `screens/` to `fleet/`, its three screen readers changing one specifier each. The fleet and session back-edges into `screens/` go from 6 to 0. The proposal's `isLocalDivider` and `nodeVersion` moves are not in this change: neither is a back-edge into `screens/`.

The three readers now import from the new leaves, and the three entries are deleted. This continues D-5896 and issues no new number.
