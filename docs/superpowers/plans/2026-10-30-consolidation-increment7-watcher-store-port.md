## Review focus (the failure modes most likely to bite)

1. **A census rule that under-counts.** If the walk misses a path (a thunk, a carrier object, a class field, a typed slot), its rows stay green while the watcher still reaches the whole store. The CONTROL rows (WP1) hold each rule on a fixture, and the reviewer reads the census's per-unit output at the tip, not only its green.
2. **A port that grows to fit.** Adding a member to `WatcherCoordMember` to make a task compile is wrong unless the census shows the member reached. The reach row reds a member nothing reaches; the reviewer reads the member diff of `coord/ports.ts` in every PR (expected: empty after WP2, apart from §In flight's one).
3. **A second member list.** A `Pick<CoordStore, …>` on a chain function, or a new `*Port` interface over the store or over `Deps`, is the banned pass (§Global constraints, One port).
4. **An emit change.** Any change to what `tsc` emits from `server/src` (with comments removed) is a behaviour change this plan does not allow; the emit diff must be empty in every PR.
5. **A test fake that no longer matches.** Tests that hand the watcher a fake store typed `as unknown as CoordStore` keep compiling (a `CoordStore` is assignable to the port); a test that reads a member outside the port off the watcher's deps would fail `tsc -p test/tsconfig.tests.json` at WP10. Step 0 of WP10 lists any.
6. **A dispatcher left whole.** After WP9, the only whole values in scope are the dispatchers' `this.deps.coord` reads, each handed straight to a port parameter (a port entry); WP10's rows hold the port-entry count and the whole reach at 0.
7. **The scanner's TypeScript drifting from the build's.** The census type-checks with TypeScript 6 while the server builds with TypeScript 7; a program the scanner cannot type would make the census read wrong types. WP1's row "the program type-checks under the scanner's parser" reds on any diagnostic.
