## What this plan refines in the spec (measured at `e66ca6ac`)

None of these changes what the spec promises. Each is a mechanism the spec leaves open, or a fact about the tree the spec does not state.

1. **The spike runs first, on a standalone harness.** Spec §10 runs the O6 spike on a preview build "before stage 1 merges". Task 1 runs it before any product code, on a page that mounts the product's own `Sheet` and keyboard inset around an off-screen xterm, so its outcome can shape Tasks 9 and 12 instead of reworking them. Task 14 re-runs its rows on the PR's preview build. Both of the spec's conditions hold, earlier.
2. **Two kinds of screen fixture.** Hand-built synthetic screens (Task 5) let the re-wrap tests go red first without waiting for the rig, and cover shapes the six recorded scenarios do not (unbreakable tokens, CJK, the exit notice, a numbered reply that is not a menu, a non-Claude-Code screen). The rig-recorded pairs (Task 6) prove the shapes against real Claude Code. Where the two disagree, the recorded pair wins and the builder follows.
3. **One residue scanner.** The recorded fixtures are JSON in a `<claude-version>/` directory, the layout `server/test/delegation-rig/sanitize.mjs --scan` already checks fail-closed by allowlist. The drawer rig records under `/rig/...` paths, so nothing is ever rewritten: a run with residue is refused whole. No second sanitiser is written.
4. **`paneOptionRows` is not "the run holding the cursor" on every screen.** With no `❯` on a numbered row it falls back to the lowest run at the shallowest digit column (its own comment, `dialog.ts`). So `menuSnapshot` (Task 16) answers `null` unless exactly one row is `selected`. Spec §5.5's "finds the run holding the cursor" is that condition.
5. **The 1b gate reads the store's `dialog`, never its `ask`.** `dialog` is the server's scraped verdict: `parseDialog` answers non-null only for a menu. `ask` is a hook envelope; it says a question exists, not that the pane shows a menu.
6. **The wave-3 promises are wider than the spec's one citation.** At `e66ca6ac` (a case-insensitive `wave 3` census, Task 0 Step 4), these still promise the drawer's wave 3:
   - in stage 1's scope: `PINNED_WINDOW_*`'s docstring (Task 2); and in Task 13, the `/ws/pty/:id` latch comment in `server/src/server.ts`, `PaneProbe`'s and `PaneHistoryReply`'s docstrings in `shared/api.ts`, `WIN_SIZE_CAP`'s note in `server/src/ccdargv.ts` and one comment in `server/test/single-definition.test.ts`. The drawer's own comments in `TerminalDrawer.tsx` and `consoleFit.ts` name no wave 3 (the census finds none there), but they describe the panning and the glass-following client that D-5005 ends, so Task 13 rewrites them too;
   - left to stage 2's B0, which edits `ccd/ccd` anyway and is AGENT-FIRST: `cmd_caps`'s comment above `echo win-size-v1` ("The server gates the un-pin on …"), `cmd_win_size`'s "Wave 3's `sizer.unpin` keys on this exit code", and `_auto_compact_check`'s "the extension is named for wave 3 rather than taken here";
   - left to stage 2 with a work item attached: `agent/src/whitelist.ts`'s note on the `win-size` grant says the `/ws/pty/:id` handler validates `:id` nowhere and that "Wave 3's own plan lists validating `:id` as work it will do". With wave 3 superseded, that item has no owner. Stage 1 adds no route and leaves it; stage 2's B1 rewrites the route (`drawer.ts`) and takes it, with the note (§Stage 2).

   `ccdargv.ts`'s `winSize` builder note describes wave 2 accurately and stays.
7. **F1's carriers stay.** `pane-history-route.test.ts` holds `server/src/server.ts`, `pwa/src/session/TerminalDrawer.tsx` (in `historyScrollback`'s docstring) and `server/src/exec.ts` to F1's measurement (`MEASURED`), and its reach test holds `shared/api.ts`. No rewrite here removes the `resize-window -x 43 … 1853 … history_size … 9460` paragraph from any of them.
8. **Tests that pin a resize frame are inverted, not deleted.** `terminal.test.tsx`'s "a refit that changes the grid sends {type:"resize"}", `terminal-scrollback.test.tsx`'s resize-frame case (≈:556–562), and every `clientGrid` read in `console-window-fit.test.tsx` and `console-window-fit-xterm.test.tsx` assert the opposite after Task 4. D-5005 is exactly that reversal.
9. **`DrawerTerm.fit()` goes.** `fitToWindow`'s two fallbacks to `t.fit()` (a host with no layout, and an unmeasurable glass) become "keep the current view", `chooseView`'s `null` arm.
10. **Where `TermInput` appears.** Spec §5.4 says the field is "shown by default on a coarse pointer" and that the grid view is "unchanged". Read together: the field belongs to the wrapped view (default on a coarse pointer, and on a fine one only if Task 1's gate fails). The grid view keeps xterm's own textarea and today's quick keys, plus a guarded `^C`.
11. **The wrapped view's paste needs a guard of its own.** On a fine pointer the off-screen xterm takes the keyboard, and with it the clipboard. xterm 6.0.0's `paste()` (`src/browser/Clipboard.ts`) brackets text without removing an end marker inside it, so a paste there would break I5. Task 12 takes the paste at the host's capture phase and frames it as the field does. The grid view's paste is P3.

## Global Constraints

Every task's requirements include this section. `CLAUDE.md` is the authority; this is its working subset.

- **Public repository.** Every line, fixture, commit message and PR body is public. Fixtures are SYNTHETIC: hand-built (Task 5) or recorded from the rig (Task 6) with neutral names (`project-a`, `lane-a`), never captured from a live session. No hostnames, accounts, absolute home paths or people's names. `topology-clean.test.ts` stays green.
- **No root runner.** Run cd'd into a package: `cd pwa && ./node_modules/.bin/vitest run test/<file>`; `cd server && ./node_modules/.bin/vitest run test/<file>`. **Never bare `npx vitest`.** Suites run in the FOREGROUND with a timeout of at least 600000 ms. A `CLAUDE.md` load flake is re-run alone before it is called a break.
- **Rings.** `shared/*.ts` imports NOTHING (the PWA bundles it). The pure modules under `pwa/src/session/` import no React and touch no DOM, so their tests need no jsdom.
- **Single definition.** A constant, a table of key bytes, a palette or a parser has one home. `server/test/single-definition.test.ts` fails the build on a second copy of a registered definition, and 1b registers the moved parsers there. `KEY_SEQ` is the one table of key bytes; the grid's quick keys derive from it. The 16-colour palette moves out of `glass()` into one constant that both the terminal and the wrapped view read.
- **Wire discipline.** No frame, field or route is added in stage 1 or 1b. `FLEET_PROTO` stays 1. The drawer keeps sending `{type:'input'}` and nothing else.
- **jsdom has no layout, no `matchMedia` and no `visualViewport`.** Tests stub them, as `console-window-fit-xterm.test.tsx` already stubs xterm's measuring element. The coarse-pointer read goes through the existing `useMediaQuery('(pointer: coarse)')`.
- **CSS scans.** `contrast.test.ts` and `pr-keycap-css.test.ts` read the stylesheets. New styles use the existing tokens (`--tap-min`, `--sp-*`, the well's ink and background) and no raw colour.
- **Pane output reaches the DOM as text.** No `innerHTML` and no `dangerouslySetInnerHTML` anywhere in the wrapped view. A cell's style maps to a closed set of CSS properties. A link the pane prints (OSC 8) is shown as text, never as an anchor.
- **Mutation discipline.** Every guard ships with a test that goes RED when the guard is deleted, AND when it is made wrong. Each task's mutation table is RUN, before and after, never read: apply the mutant, run the named suite alone, record the red line, restore with `git checkout -- <file>`. Never commit a mutant. "A comment is a request; a red suite is a mechanism."
- **Comment guards.** `pane-history-route.test.ts`'s `FALSIFIED` scan reds any source comment saying tmux never reflows (or does not reflow); its `MEASURED` list holds three files to F1's measurement (Refinement 7). Rewritten comments say what the design does, and never restate the falsified claim.
- **Deviation ledger.** Numbers are ISSUED by `POST /api/ledger/deviations`, never chosen. A worker never allocates: it names a departure by slug in its wave-done, and the coordinator allocates and defines it in §Deviations found. No tracked file carries a concrete `D-TBD-<slug>` (`dtbd.test.ts`).
- **Branch discipline.** One commit per task on the workspace's own branch, never a separate feature branch. Absorb `main` only with `git merge`. Every commit leaves the suites it touches green.
- **SAFETY.** Nothing here runs ccd, touches the live tmux server, or reads a live pane. The real-tmux suite and the rig use a private `-L` socket only, and the rig runs in a throwaway container.
- **Commands are approval-free:** reads, git, grep, node, vitest, `gh` reads. Never `pkill` or `killall`. Subagents never send mail and never load a role skill; only the worker sends the wave-done.

## Review Focus (the failure modes most likely to bite)

1. **A resize frame sneaking back.** Any frame other than `input` re-opens panning. Task 4 removes `resize` from `sendFrame`'s type, so the compiler refuses one, and a behaviour test pins it across every refit trigger.
2. **The model and the server reading different screens.** 1b's taps are safe only because the model's 50 rows ARE `capture-pane -p`'s rows (W6). Task 7 measures that on every recorded fixture.
3. **A key chosen from the wrapped geometry.** Invariant I5: what is sent is sanitised literal text, a named key, or a menu delta from the 220-column model. A visual-row index must never become an arrow count, and a description row is never a tap target.
4. **A false menu, or an Enter on the wrong row.** A reply quoting `1. …`/`2. …` is not a menu: taps need the store's `dialog` AND a selected row in the model. **Select ⏎** sends `\r` only while the model's cursor rests on the tapped option (Task 16).
5. **Paste as keystrokes.** `\e[201~` inside pasted text must never reach a frame, through the field (Task 12) or through the off-screen terminal (Refinement 11).
6. **Storage that throws.** Private windows, previews and thumbnail capture throw on `localStorage`; the view chip must still render and choose (Task 9).
7. **Fixture residue.** A recorded byte stream is the likeliest place for a path, a hostname or a clock to slip into a public tree (Task 6).

## Interfaces (canonical)

```ts
// shared/api.ts — beside PINNED_WINDOW_COLS / PINNED_WINDOW_ROWS (Task 2)
export const TMUX_STATUS_ROWS = 1;

// pwa/src/session/TerminalDrawer.tsx — the reshaped seam (Task 4; tests inject it)
export interface DrawerTerm {
  write(data: string): void;
  onData(cb: (data: string) => void): void;
  onWheel(cb: (ev: WheelEvent) => boolean): void;
  /** Fix the grid at exactly this size (`term.resize`). Never follows a host. Replaces `fit()`. */
  pin(cols: number, rows: number): void;
  /** Unchanged contract: measures, never resizes the live grid. null when not open or not measurable. */
  propose(px: number): { cols: number; rows: number } | null;
  /** Render at this type size. Moves no grid (it is pinned), so it returns nothing. */
  setFontSize(px: number): void;
  /** Open into this host, once. A later call is a no-op: the host moves, the terminal does not. */
  open(host: HTMLElement): void;
  isOpen(): boolean;
  /** The window's rows as styled cells (Task 7): readModel over the active buffer, the status
   *  row excluded (term.rows − TMUX_STATUS_ROWS rows). Every reader of the screen reads this. */
  model(): ModelRow[];
  /** tmux's status row, for the grid's display only; nothing decides on it. */
  statusRow(): ModelRow;
  /** Fires after parsed writes (xterm's onWriteParsed); returns the unsubscribe. */
  onParsed(cb: () => void): () => void;
  focus(): void;
  dispose(): void;
}
export type MakeTerm = () => DrawerTerm;   // was (host) => DrawerTerm: opening is now the drawer's choice

// pwa/src/session/drawerView.ts (Task 9)
export type DrawerViewKind = 'grid' | 'wrapped';
/** null means "not measured yet: keep `current`". It is never read as 'grid'. */
export function chooseView(fit: ConsoleFit | null, override: DrawerViewKind | null,
```
