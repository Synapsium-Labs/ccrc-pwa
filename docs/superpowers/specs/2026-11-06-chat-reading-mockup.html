The worker is fine; two of its background wait loops can never finish, because each waits on a condition that can never come true.

  • PID 1286235 runs until ! pgrep -f "mutate.py", waiting until no process matches "mutate.py". Its own command line contains "mutate.py", so pgrep always finds the loop itself.
  • PID 1259080 waits for a line in a mutants file and also has ! pgrep -f "r3b/mutate.py" in its condition, so it is stuck the same way.

While they run, the worker never goes idle, so the fleet holds its mail. Ending them doesn't touch the worker's code or branch; they are only wait loops.

Why I can't do it. Killing another session's processes is an operator act under the coordinator rules, so it has to be you.

What to do (either one):

  • run ! kill 1259080 1286235; or
  • open tmux pane cc-project-a-backup-guard and stop those two background tasks from its task list.
