Path identity design

Spec · 20 Oct 2026 · 14 min read
In shortA path names one document at one ref, so a link means the same thing on every checkout.

Today a reader can reach the same file by two paths, and each one answers with its own copy.

▶ Play⤢Copy
Figure 1. How a link resolves to one copy.

The resolver answers once, and the answer carries the ref it read.

After: ⋯ open

What the truth line and the actions row held, one row each. A draft or branch view adds its rows here; banners stay inline.

What moves where

  • Back + crumbs (two lines, about 70 px) become one 44 px row: ‹, then a two-line label in the same row (section in 11 px mono, file name in 14 px, both ellipsised). The full path is the menu's first row; '…' crumb expansion is dropped on a phone.
  • Truth line (about 106 px): ref, short commit, how the ref was chosen, source, size go to the ⋯ menu's first row with Copy commit. Freshness becomes a dot on ⋯ (green fresh, amber stale or failed); its refresh tap is a menu row.
  • Actions row (44 px, more when it wraps): Share and Export become 44 px icon buttons on the head row; View on GitHub, 'GitHub's copy may differ' and Open committed version go to the menu.
  • Padding: .docs-screen top padding 8 → 0 and the 12 px gap to the leaf → 4 on a phone with the reader shown.
  • 'Formatting…' overlays the frame host instead of taking a line, so the frame no longer jumps 28 px when ready.
  • Banners (drafts, caveats) stay inline above the frame: they are warnings, and a menu would hide them.
  • Library chrome is untouched: 8 body margin + 48 bar + 29 gap = 85 px, the bar still hides on scroll down. No library release needed.
  • Desktop (900 px and up) keeps today's head.

Code: DocsHead.tsx gains a phone branch (one row plus a menu component), docs.css phone rules, and a small 'more' menu with its own tests. A draft view still adds its banners. With a library option for the 29 px bar gap and the body margin (held release), 133 could drop to about 100.

What the user loses

  • The ref and commit are no longer visible at a glance; one tap on ⋯ to see what is being read. The dot only says fresh or stale, not which ref.
  • A branch or draft view looks the same as main in the head; only the banners (kept) and the menu say so. A small 'branch' or 'draft' tag next to the section name could fix this at no height cost.
  • Export's visible states ('Export (plain view)', 'Formatting…', 'Updating to…') shrink to an icon with a disabled look; the words move to the accessible name and to the menu row, so a sighted user must open ⋯ to learn why it is greyed out.
  • View on GitHub costs one extra tap.
  • The file name is usually clipped (about 30 of 40 to 57 characters fit); the title below names the document anyway.
  • Two stacked tool rows remain (console 44 + library 48); this variant does not merge them.
