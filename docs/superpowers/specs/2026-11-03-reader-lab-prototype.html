Reader lab (prototype)

A proposal for W8b: one console page that runs the Docs reader's phone checks, E17 and E18 from the rich-docs spec, on whatever phone opens it. This is a static mockup. Nothing here runs, and every number on it is an example.

Why a page. E17 and E18 must run on your phone's browser engine. They need a busy-loop frame, a planted hostile frame and a cookie probe, and none of that can be put in an ordinary doc. Today the only alternative is you running developer tools on the phone. With the page, you open one link, tap Start, wait about two minutes, then copy the result and send it to me.

The page, on a phone

It lives under Settings, beside "Measure highlighting" (/settings/reader-lab, also on the command palette as "Go to Settings › Reader lab"). Like that page, it stores nothing, sends nothing and writes no clipboard; you select the result yourself.

What it would cost

  • Where it lands: W8b, beside the W8a residue. It is a page plus a small test-only server door that counts which lab requests carried the session. The door is off unless the page is open and the request carries a per-run nonce. That door is the one part that needs a security review.
  • Size: about the size of the highlighting measurement page (one screen, one driver, fixtures), plus the planted frames the browser tests already have, reused.
  • Beside it: CI also runs the same batteries on Playwright's WebKit and Firefox as proxies. They catch engine differences early, but they are not your phone, so they do not replace E18's retirement-gate run.
  • If you would rather not have the page: E17 and E18 stay manual. You would run developer tools on the phone with a fixture page from me, which is slow and easy to get wrong.

What you would do

  1. Open Settings › Reader lab on the phone you read on.
  2. Tap Start and keep the app in front for about two minutes.
  3. Tap Select result, copy, and send it to me. Repeat on any other phone or browser you use.
