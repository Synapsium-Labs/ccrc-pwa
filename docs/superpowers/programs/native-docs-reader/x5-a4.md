# Task X5 A4: `ccrc expose artifacts` and doctor

The task note for native Docs reader wave 53 (X5 wave A4, run 3968). It is what the ledger should learn from this wave. The design is `docs/superpowers/specs/2026-11-19-native-docs-html-artifacts-design.md` (§2.3 to §2.5 and §10), and its leaf plan is `docs/superpowers/plans/2026-11-19-native-docs-html-artifacts.md`. That plan's Results section, "Wave A4", gives what was measured and every mutation row.

## In short

- **What landed.** The operator's side of the artifact tier, with no page served yet:
  - `ccrc expose artifacts` names the two artifact origins beside a console exposure: two DuckDNS labels at a prompt, or `--artifact-origin` and `--content-origin` on a byo box, and `--off`. It writes the three keys into the exposure file, and the Caddyfile's log block and second site block.
  - Every console arm carries the keys on a re-run, or drops them and says so.
  - Doctor's `artifacts` check judges the keys, finds the second block, and asks the loopback listener once per name. `name` resolves every host of its list.
- **One rule, two languages.** `ccd/ccrc` carries a pure-bash mirror of `server/src/artifacts/policy.ts`'s site rule and config decision. Both are run against one table, `server/test/fixtures/artifact-site-rule.json`: the TypeScript by `artifacts-config.test.ts`, the bash by `ccrc-expose-artifacts.test.ts`. So the arm and doctor never write or bless a set the server would turn off at boot.
- **The tier never stands alone.** The only writer of the three keys refuses unless a named console exposure with sign-in armed already stands, and doctor FAILs by name on keys beside an address or beside a sign-in that is not whole.
- **Beside the local sign-in verb (#3405).** The verb gives the same answers before and after the tier is added, on Linux and with the Mac switch. Expose's hint that points at `ccrc auth off` is not said when an artifact key is among the keys it found.
- **Deviations.** D-9137 is the growth waiver for the two `ccd` files (224 and 100 net code lines after review 4022's fix round), one number and two files. D-9138 is unused, and it is returned.

## Choices made in the wave, for the ledger

| Choice | Why |
|---|---|
| The mirror is kept whole in `ccd/ccrc`, the loopback pair included, with no separate sourced file | The coordinator's ruling. Doctor's check table is sourced by `ccrc`, so both readers reach one copy. |
| The carry derives the DuckDNS list's extra hosts from the two artifact origins | The plan had it read them back from `CCRC_DDNS_DOMAIN`. Reading the origins keeps one fact, and the bytes are the same. |
| Doctor reads the keys from the exposure file only, not through `_box_unit_env` | The plan's words. A set placed by hand in `ccrc.env` reads as unset there. Expose's shadow refusal names it, because the three keys joined that refusal's list. |
| A `CCRC_PORT` that is set and not plain digits (1 to 65535, no leading zero) is refused: the arm writes nothing, doctor FAILs by name, and a console arm's re-run, which asks the same reader, drops the artifact keys and says why (read from the code; no case of its own). Only unset or empty is the default, 7788 | `config.ts` reads it with `Number()`, so `07790` is 7790 there, and a bash reader that guessed otherwise wrote a set the server turned off (review 4022 F1). The coordinator ruled a refusal rather than a second copy of that parse. A value with spaces around it is refused too, because `_box_env_value` does not trim. |
| Artifact keys beside a console origin that is an address FAIL in doctor, as they do beside `CCRC_EXPOSE_MODE=ip` | Review 4022 F2: the same hand-made state had two verdicts. |
| Where the stored artifact port is the trouble, the arm and doctor say to run `ccrc expose artifacts --off` first | The arm has no port flag, so a bare re-run keeps the stored port (review 4022 L2-F1). |
| The mirror runs under `local LC_ALL=C` | Found by review's differential fuzz: under a UTF-8 locale, `[a-z]` matched non-ASCII letters, which the server refuses. |
| Doctor's probe is `curl -q --noproxy '*'`, with a Host header per name | Found by review: an operator's `~/.curlrc` or proxy would otherwise answer for the listener. |
| The `ccrc auth off` hint gains a condition, not new words | `ccrc auth off` never removes an artifact key, so its re-run would refuse again. The holder of the verb saw the hunk and had no objection. |
| An artifact key carried by a unit drop-in does not make `ccrc auth` refuse | The listener binds `127.0.0.1` in code whatever the keys say, and the site rule never reads `CCRC_AUTH`. So the verb's list of keys a unit source may not carry stays as it is. |

## Carries

- **A stale Caddyfile after a hand delete** (the coordinator ruled it out of scope). The exposure file's header says to delete it to go dark. Doing so takes the artifact keys with it, but leaves the generated Caddyfile and its system copy with both site blocks and the log block, as it already leaves the console's block. Caddy then answers 502 for the two artifact names. Closing it is a change to how a console exposure is taken down.
- **The missing-subcommand line** still reads `(duckdns|byo|ip|status)`, because an existing test pins it. A later edit may add `artifacts` there with that test.
- **Left for later by the coordinator (review 4022):** re-checking the bind and the host's shape when the arm reads values back from the exposure file; a doctor WARN when an artifact name resolves to none of this box's addresses; a port flag for the arm, which a console on 7790 needs (the default artifact port is 7790, and the arm refuses a set where the two are equal).
- **The equality case's reach.** On Linux, every later read of the sign-in verb sits behind its reach refusal, so the case sees only what the reach reader reads. On a Mac it sees only that the early refusal comes first. This cannot be avoided, because the tier exists only on an exposed box.
