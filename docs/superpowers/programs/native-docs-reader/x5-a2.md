# Task X5 A2: the capability store, the scope read and the mint doors

The task note for native Docs reader wave 52 (X5 wave A2, run 3967). It is what the ledger should learn from this wave. The design is `docs/superpowers/specs/2026-11-19-native-docs-html-artifacts-design.md`, and its leaf plan is `docs/superpowers/plans/2026-11-19-native-docs-html-artifacts.md`. That plan's Results section, "Wave A2", gives what was measured and every mutation row.

## In short

- **What landed.** A signed-in console session can ask the server for a time-limited, unguessable link to one HTML page of the docs, list its live links, and revoke them:
  - a session's liveness asked by its id, read-only (`SessionStore.livenessOf`);
  - the in-memory capability store: the token kept only as its sha256, an idle hour, 12 hours absolute (2 over drafts), bound to the minting session through a port that reads the passphrase's generation on every call, 32 live a box and 16 a session;
  - five doors in the docs plugin: the availability and list read, the scope read, the mint, Revoke and Revoke all.

  Nothing is served through such a link yet (wave A3), and nothing changes on screen (wave A5). No exempt class, box-token door, migration, `ccd` verb or agent grant was added.
- **The A1 review's items.** The listener's early answers' bodies are asserted; the console's fence refuses a bracketed artifact host; the artifact instance answers during shutdown through its own hook; the A1 fix round's mutation table is relabelled; and `CLAIM_CODE_RE` is now a re-export of the capability token's grammar.
- **Deviations.** D-9135 (the content door's store members and bytes port land with A3.3, their consumer; `drafts` is counted by the store; the view's manifest is a read-only face) and D-9136 (the mint's tree read is a closure over the console's own tree read in `docs/routes.ts`, not an adapter in `ccdsource.ts`). Both numbers of the reserve are used; none is returned.
- **The counts**, derived from the tree merged with `main` at `87c64a957a` (after another programme's #3456): `docs/routes.ts` registers 20; the gate's scanned routes 339, HTTP 336, gated 218, exempt 118. `DOCS_DOORS` has twenty doors, and the two new GETs are exempt rows in the secret-mask inventory. The real-table header walk (`docs-headers.test.ts`) covers the five doors.
- **The held files.** `server.ts` took the exact hunks its holder approved (a packet against `main` `595d9c5c0f`); the gate's count files were edited after #3456 merged and released them.

## Choices made in the wave, for the ledger

| Choice | Why |
|---|---|
| The two new GETs are exempt in the secret-mask inventory, not in `MASKED_GET_ROUTES` | They answer repository content (paths, a short commit, a branch) and random ids, like the other docs reads; the mint, a POST, is masked, which is why it draws again. |
| The mint draws its token again while the whole answer would be altered by the mask, at most 8 times, else `unmeasured` | The plan names the URL; the whole answer also holds the id, which Revoke needs byte for byte. |
| `ArtifactMintAsk.pin` is a `DocListPin`, and the scope query spells a stat-pinned draft with `stat` in place of `fp` | So the m3 carry's stat-pinned draft can be asked at all, and is refused `draft-too-large` before the pin parser. |
| Revoke all ends every capability on the box | One operator; the spec's "Revoke all" in Page details and the Docs index. |
| `livenessOf` accepts only the 64 lower-case hex digits the store writes | `rowOf` decodes hex in either case, so an id would otherwise have two spellings. |

## Carries

- **For A3 (from the first items' review).** With the framework's 503 on closing turned off, a request that arrives while the artifact instance closes runs its routes. In A2 they answer the fixed 404. Once A3 fills them, their dependencies may already be closing, so such a request would get the fixed 500. That is safe, but A3 should say so or answer such requests itself.
- **For A3.** `ArtifactRouteDeps` is not extended (D-9135): A3.3 adds `store` and `now` with its first consumer, and decides `ArtifactBytes`' placement by D-9136's rule (a closure over the docs lane in L4, not an L3 adapter that books nothing).
- **The store reads the wall clock** it is given, as the session store does: a clock stepped backward lengthens a capability's life by the step.
- **A busy docs lane is `unmeasured`** (502) on the scope read and the mint, as the plan words it, so the launch sheet (A5) cannot tell "try again" from a failed read. A5 may want the lane's `docs-busy` passed through.
- **A repeated scope query key** answers its value's word (`bad-commit`, `bad-project`), not `bad-query` `repeated` as the file route's parser does. A parity gap only.
- **`docs/policy.ts`' private `own` and `isRecord`** are exported under the names `docsOwn` and `isDocsRecord`, because the single-definition scan counts those two names as privately declared in many files. A later consolidation of those helpers can retire the aliases.
- **A process slip.** The first A2.3 implementer wrote two source edits with in-place stream edits, then redid both with the file tools; the committed bytes came from the file tools and were reviewed. Recorded in the plan's Results.
- **The whole tests typecheck** (`test/tsconfig.tests.json`) could not finish on the fleet box (the test slice's memory cap). Every changed test file was typechecked under a config that extends it and includes those files; the hosted run covers the rest.
