# Task X5 A1: artifact names, the site rule, the second listener and the host fences

The task note for native Docs reader wave 49 (X5 wave A1, run 3923). It is what the ledger should learn from this wave. The design is `docs/superpowers/specs/2026-11-19-native-docs-html-artifacts-design.md`, and its leaf plan is `docs/superpowers/plans/2026-11-19-native-docs-html-artifacts.md`. That plan's Results section, "Wave A1", gives what was measured and every mutation row.

## In short

- **What landed.** The ground for HTML artifacts, with no page served yet:
  - the L0 vocabulary;
  - the one decision whether the tier is on;
  - a second Fastify listener on loopback that answers a fixed 404 for everything;
  - a fence on each listener that refuses the other's host names.

  Nothing in the console changes for the operator. No route was added to the gated instance, and no exempt class, migration, `ccd` verb, setting or box-token door.
- **The grammar moves.** `CAPABILITY_TOKEN_RE` and `isCapabilityToken` now live in `shared/capabilityToken.ts`, and `shared/docsReview.ts` re-exports them as `REVIEW_TOKEN_RE` and `isReviewToken`. `isExactHttpsHost` and `isExactHttpsOrigin` live in `shared/httpsOrigin.ts`, and the mockup policy re-exports them as `isMockupHost` and `isMockupOrigin`. X3's and the mockup policy's tests ran unchanged before and after.
- **Deviations.** D-8786 is carried out (X2's spec, ten passages). Reserve numbers 9113 and 9114 are unused, and both are returned.

## Choices made in the wave, for the ledger

The plan left these open. Each is argued in `server/src/artifacts/policy.ts` and has its own test.

| Choice | Why |
|---|---|
| `CCRC_EXPOSE_MODE=ip` is `off/by-address` whatever keys stand | The ip arm writes no keys (spec §2.4). A hand-added set beside an address fails shut. |
| Beside a `http://localhost:<p>` console, only `http://127.0.0.1:<p>` artifact origins, never https ones | Spec §2.3: loopback is for development and the browser suite only. |
| A host a browser reads as an address is refused, and a console reached by address is `by-address` | Found by the A1.2 review. `https://10.0.0.01` beside a console at `https://10.0.0.1` passed the string checks, but a browser serializes it as the console's origin. |
| A port is accepted only as a browser writes it: no leading zero, no explicit `:443`, and a loopback origin not on the console's port | Found by the A1.2 review. `https://h` beside `https://h:0443` would be one origin for the wrapper and the page, which undoes §2.2. |
| The two fences read `Host` differently. The artifact side allows its two hosts exactly (`hostMatches`: lower-cased, one trailing dot dropped, the port as written). The console side refuses an artifact host in any port spelling (`namesArtifactHost`), unless that host was configured with a port, as the loopback pair is | An allow list fails shut, and a refusal list must refuse too much. Found by the A1.3 security review: with one shared exact match, `<content-host>:443` reached the console's routes, while a proxy's host matcher ignores the port. |
| Fastify's own 400 (bad escape) and 414 (over-long parameter), and Node's socket-level 400 and 431, are answered with fixed words and the hardening headers | They come before any hook. Fastify's echoed the request path, token included. |
| The no-shared-policy scan is a new file, `server/test/single-definition/docs-artifact-tiers.test.ts` | The docs area files were held by the P4 worker. |

## Carries

- **X2 spec, §4.8.** Three headings outside D-8786's quoted text still read as before the C3 ruling:
  - "What stays standalone-only under C3's recommendation";
  - its table's "Under the recommendation" column;
  - "The widening, priced, not designed (C3's alternative)", whose paragraph now ends by saying the design exists.

  They were not edited, because D-8786 lists exactly what it changes. A later ledger edit may reword them under a number of its own.
- **One more copy of the 43-character grammar.** `shared/agent-protocol.ts` has `CLAIM_CODE_RE = /^[A-Za-z0-9_-]{43}$/` (the box-token claim code, from the box-token lifecycle), which is the same grammar. It was outside this wave's files. Folding it into `shared/capabilityToken.ts`, or recording why it is different, is a follow-up.
- **MIME charset.** `ARTIFACT_MIME` carries bare types (`text/html` with no charset), as spec §5 lists them. A3 decides the `Content-Type` value it sends.
- **Tests typecheck.** The whole `test/tsconfig.tests.json` typecheck could not finish on the fleet box: the test slice's memory cap killed it. The changed test files were typechecked under a narrower config. The hosted run's typecheck covers the rest.
- **Nits from the A1.3 security review, left in held files.** Each is in a hunk its holder approved word for word, so changing it here would go past that approval. A later wave can fix them:
  - The comment in `server.ts` says the console fence is added "before every other" `onRequest` hook. The websocket and multipart plugins' hooks run before it, though neither ever answers. It does run before the reader lab counter and the gate.
  - The `OWN_ERROR_HANDLER` reason in `secret-mask.test.ts` says "the fixed 500 page", but the body is fixed plain text.
  - In `index.ts`, `cfg.artifact.state === 'on'` beside `app.artifactServer !== null` is redundant.
- **The console echoes a malformed escape.** Before any hook, the console's own default 400 for a bad percent-escape repeats the path. That is `main`'s behaviour, and nothing is logged. But if a Caddyfile misroutes `/c/<token>/%zz`, its token would show in that body. A `frameworkErrors` on the console instance is a follow-up for A3, the wave that first serves tokens.
- **A process slip.** One implementer appended to `policy.ts` with a shell heredoc instead of the file tools. The content is what was asked, and it was reviewed and mutation-tested like the rest.
