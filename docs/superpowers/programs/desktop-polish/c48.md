# Task C48: the fleet list drops every delegation row (D-8782)

The task note for desktop polish Task C48. The operator's words, 2026-11-19, on C46: "the number of subagents in a session
is noise at this point on the left panel. It's information useful only inside the session running them." After C46 and C47
took the counts off a session's row, a screenshot showed the rows themselves still nested under a session ("workflow · not
confirmed", "agent · not confirmed", one per helper), and the operator called that the same noise. The brief first kept
worktree rows and unowned rows; a scope change the same day ("Yeah I want them out too") took them out as well, so the
fleet list draws no delegation row at all. Every claim below is labelled **measured** (a command was run and its result
seen) or **inferred** (read from the code or the ruling only). "Here" is this task's branch, cut from `origin/main` at
0b96bd0dc. Fix round 1 answers review 2864, which read the first tip (25cacbc6e): its findings F1 to F9 are named where
each is met.

## In short

- The fleet list (the left panel on desktop, the session list on a phone) draws no delegation row: not a session's
  subagent or workflow, not a worktree, not an unowned tree, not the foot's region of activities whose session is listed
  nowhere ("Delegated work, session not listed", **gone in fix round 1, review 2864 F1**: it was a delegation group header
  with delegation rows), and no `offline-coordinator` or `unowned` group header. Session rows, spawn rows and the programme
  tree are unchanged (**measured**: the C48 cases in `fleet-screen.test.tsx` send a frame of activities, a worktree, an unowned
  tree and an activity whose parent is listed nowhere, and an offline one with words this build has never heard of, and read
  the whole fleet list; the card's session row is the positive control; the real-Chrome file asserts the same at three widths,
  both skins and both palettes).
- The row kinds `activity`, `lease`, `unowned` and `delegation-group` have no producer, so they are gone: `FleetRow` is a
  session or a spawn; `delegationPass`, `CardDelegation`, rules 6 to 11 of `nestFleet`, `fleetTree`'s routing of the frame to
  cards and `unplacedActivities` are removed, and `nestFleet(sessions, runs)` and `fleetTree(sessions, projects, runs, acks)`
  take no frame (**measured**: the pwa compile check is green with the kinds removed from the union, so no consumer is left
  reading one).
- A fold line and a programme box's footer named `delegated` and `worktrees`. Both words went with their rows, so the
  fold counts workers only and folds from two workers (**measured**: `rollup.test.ts` W4-U25, `fleet-rollup-render.test.tsx`
  W4-U31 and `project-card.test.tsx`).
- The worktree rows MOVED, by the coordinator's ruling (mail 26931): a session's own details list its worktrees with the same
  words and the same three controls (Keep worktree, Attach to…, Not delegated), through the same doors and refusals. The row's
  view is `session/SessionWorktrees.tsx` and the controls' view `fleet/WorktreeControls.tsx` (lifted out of `ProjectCard`; only
  the focus heading changed). The one reader of the frame for leases is `leasesStartedBy`, beside `activitiesStartedBy`;
  `sessionWorktrees.ts` adds the two labels a row names, read in `SessionScreen` as one primitive key so a fleet frame that
  changes no lease and no label re-renders nothing.
- STAYS: the session's own details, with `N delegated` and its list of every activity (**measured**:
  `card-header-facts.test.tsx` passes unchanged, and `delegation-words.test.ts` reads an agent and a workflow through
  `activitiesStartedBy` and `delegatedChip`); Settings › Automation › "Worktrees left behind"; and everything on the wire and
  the server.

## Where an operator sees them now (the coordinator asked)

- **Activities (subagents, workflows):** in the session's own details (`N delegated`), for a session the list carries. For an
  activity whose session is listed nowhere: **nowhere**, since the foot's region went (F1).
- **A session's worktrees (leases):** in that session's own details, with the three controls: on its coordinator's page AND on
  its via-worker's (the fleet list drew one row; this is deliberate, so each holder can act). A lease whose path is a listed
  session's workdir is not drawn, as at `main` (review 2864 F5; see below). **An offline coordinator's page** lists the leases
  it held while it is still a row of the fleet store, archived or offline included (**measured**:
  `session-screen-worktrees.test.tsx` SW-S2 opens the real `SessionScreen` for an archived coordinator whose lease the frame
  files under the offline group, and reads the lease and its controls; it goes red when the screen passes another id to
  `leasesStartedBy`).
- **Unowned work, leases with no listed session, and the unowned tree's Not delegated door:** nowhere in the PWA after this PR.
  A lease whose parent and worker are both absent from the fleet store has no session page (review 2864 F2), so it joins
  unowned work. **Measured**: the only readers of `delegation.unowned` in `pwa/src` were the card rows removed here (and the
  store's envelope check). The coordinator ruled (fix round 1) that unowned work, those leases and the unlisted activities
  get a home in the Archive section that C49's helpers-panel design builds; until then they have none. No code change here. The
  server's door is untouched.
