# Task C48: the fleet list drops subagent and workflow rows (D-8782)

The task note for desktop polish Task C48. The operator's words, 2026-11-19, on C46: "the number of subagents in a session
is noise at this point on the left panel. It's information useful only inside the session running them." After C46 and C47
took the counts off a session's row, a screenshot showed the rows themselves still nested under a session ("workflow · not
confirmed", "agent · not confirmed", one per helper), and the operator called that the same noise. Every claim below is
labelled **measured** (a command was run and its result seen) or **inferred** (read from the code or the ruling only).
"Here" is this task's branch, cut from `origin/main` at 0b96bd0dc.

## In short

- The fleet list (the left panel on desktop, the session list on a phone) draws no row for a session's subagents or
  workflows: not under a listed parent, and not in the `offline-coordinator` group. A group header whose only members were
  activities is not drawn (**measured**: `c48-fleet-list-no-activity-rows.test.tsx`, six cases).
- The `activity` row kind has no producer, so it is gone: `FleetRow`, `fleetRowKey`, the card's view, the group-member
  arm and the rollup's delegated-row type no longer name it, and `CardDelegation` has no `activities` field (**measured**:
  the pwa compile check is green with the kind removed from the union, so no consumer is left reading it).
- A fold line and a programme box's footer said `delegated` and `worktrees`. With no activity row there is nothing for
  `delegated` to name, so the line says `worktrees` alone, and only when a worktree row is among the folded children
  (**measured**: `rollup.test.ts` W4-U25 and W4-U25b, `fleet-rollup-render.test.tsx` W4-U31, W4-U31b and W4-U31c).
- A coordinator with one worker and any number of activities no longer folds: the fold needs two worker children or two
  worktree children, and activities are neither (**measured**: W4-U25).
- STAYS: worktree rows and their controls, unowned rows and the two groups' headers while a member exists, session rows,
  spawn rows and the programme tree; the session's own details, with `N delegated` and its list of every activity
  (**measured**: `card-header-facts.test.tsx` passes unchanged, and the new file's last case reads the same frame through
  `activitiesStartedBy` and `delegatedChip`; **inferred** that `SessionDetails` itself draws as before, from its being
  untouched).
- NOT TOUCHED, and the ruling did not name it: the fleet foot's region of activities whose parent is not in the fleet list
  (`unplacedActivities`, `FleetCards.tsx`'s `UnlistedWork`). It is a closed region at the foot of the list, not a row nested
  under a session, so it is left as it was; the coordinator may rule it separately (**inferred** from the ruling's words,
  "rows still nested under a session").
