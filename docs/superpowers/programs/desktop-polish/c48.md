# Task C48: the fleet list drops every delegation row (D-8782)

The task note for desktop polish Task C48. The operator's words, 2026-11-19, on C46: "the number of subagents in a session
is noise at this point on the left panel. It's information useful only inside the session running them." After C46 and C47
took the counts off a session's row, a screenshot showed the rows themselves still nested under a session ("workflow · not
confirmed", "agent · not confirmed", one per helper), and the operator called that the same noise. The brief first kept
worktree rows and unowned rows; a scope change the same day ("Yeah I want them out too") took them out as well, so the
fleet list draws no delegation row at all. Every claim below is labelled **measured** (a command was run and its result
seen) or **inferred** (read from the code or the ruling only). "Here" is this task's branch, cut from `origin/main` at
0b96bd0dc.

## In short

- The fleet list (the left panel on desktop, the session list on a phone) draws no delegation row: not a session's
  subagent or workflow, not a worktree, not an unowned tree, and no `offline-coordinator` or `unowned` group header. Session
  rows, spawn rows and the programme tree are unchanged (**measured**: the two C48 cases in `fleet-screen.test.tsx`, which
  send a frame of activities, a worktree and an unowned tree, and an offline one with words this build has never heard of,
  and read the whole fleet list; the card's session row is the positive control).
- The row kinds `activity`, `lease`, `unowned` and `delegation-group` have no producer, so they are gone: `FleetRow` is a
  session or a spawn; `delegationPass`, `CardDelegation`, rules 6 to 11 of `nestFleet` and `fleetTree`'s routing of the frame
  to cards are removed, and `nestFleet(sessions, runs)` and `fleetTree(sessions, projects, runs, acks)` take no frame
  (**measured**: the pwa compile check is green with the kinds removed from the union, so no consumer is left reading one).
- A fold line and a programme box's footer named `delegated` and `worktrees`. Both words went with their rows, so the
  fold counts workers only and folds from two workers (**measured**: `rollup.test.ts` W4-U25, `fleet-rollup-render.test.tsx`
  W4-U31 and `project-card.test.tsx`).
- The worktree rows MOVED, by the coordinator's ruling (mail 26931): a session's own details list its worktrees with the same
  words and the same three controls (Keep worktree, Attach to…, Not delegated), through the same doors and refusals. The row's
  view is `session/SessionWorktrees.tsx` and the controls' view `fleet/WorktreeControls.tsx` (lifted out of `ProjectCard`; only
  the focus heading changed: the section's heading, or the details region when the last row leaves). The one reader of the frame
  for leases is `leasesStartedBy`, beside `activitiesStartedBy`; `sessionWorktrees.ts` adds the two labels a row names, read in
  `SessionScreen` as one primitive key so a fleet frame that changes no label re-renders nothing. An offline coordinator's own
  page lists the leases it held (**measured**: `session-details-worktrees.test.tsx`).
- STAYS: the session's own details, with `N delegated` and its list of every activity (**measured**:
  `card-header-facts.test.tsx` passes unchanged, and `delegation-words.test.ts` reads an agent and a workflow through
  `activitiesStartedBy` and `delegatedChip`); the fleet foot's region of activities whose parent is not in the fleet list
  (`unplacedActivities`, `UnlistedWork` in `FleetCards.tsx`), which the ruling did not name; Settings › Automation ›
  "Worktrees left behind"; and everything on the wire and the server.

## Where an operator sees them now (the coordinator asked)

- **Activities (subagents, workflows):** in the session's own details (`N delegated`), and, for a session the list does not
  carry, in the region at the foot of the list (**measured**: `SessionScreen` reads the frame through `activitiesStartedBy`;
  the region is `unplacedActivities`).
- **A session's worktrees (leases):** in that session's own details, with the three controls. At `main` the details listed
  activities only (**measured**: nothing under `pwa/src/session/` drew a lease), so this PR adds the list there, as the
  coordinator ruled. Settings › Automation › "Worktrees left behind" is a different, read-only list.
- **Unowned work and its Not delegated door:** nowhere in the PWA after this PR, until a follow-up gives them a place.
  **Measured**: the only readers of `delegation.unowned` in `pwa/src` were the card rows removed here (and the store's
  envelope check). The coordinator raises the follow-up. The server's door is untouched.
