# Task C50: a coordinator badge, and no Programme word beside the programme icon (D-8817)

Task note for the desktop-polish programme (plan `docs/superpowers/plans/2026-10-22-desktop-polish.md`, section C50). Each
claim is labelled **measured** (a command or a real Chrome showed it) or **inferred** (reasoned, not shown).

## The operator's words (2026-11-19)

1. "We don't need to write the word "Programme" when we use the programme icon and colours and also the wave timer."
2. "instead of writing the word "coordinator" let's come up with a badge to give to the workspace"

## What changed

- The programme box header draws no visible "Programme"; the icon is an image named "Programme". The middot that only separated the
  word from the title is gone too. **Measured** in real Chrome: the kicker's text is the title, the waiting chip, Spec and the
  waves count only.
- A coordinator's fleet row and its session header draw one `RoleBadge` (`@ccrc/ui`, the new vendored `network` icon): accessible
  name "coordinator", the role title on hover, no visible word. **Measured**: 16 px square, empty text, `aria-label="coordinator"`,
  at 360 and 1280 px in Refined and Instrument, in the dark (Phosphor) and the light theme.
- The badge is the programme's hue inside its box and the quiet secondary ink elsewhere, so the session header's badge has no hue.
  **Measured** in Chrome: inside the box its computed colour equals the box's `--prog-cyan` (dark `rgb(111, 214, 234)`, light
  `rgb(10, 99, 119)`), at 10.73:1 (dark) and 6.85:1 (light) on the coordinator band's ground.
- The command palette's entries keep the word (`session-entries.test.ts` passes unchanged).
- `ROLE_CELL_CHARS` is 3 characters and the separator, not eleven. **Inferred**: a 16 px icon is about 2.4 characters of the meta
  line's mono face at `--fs-2xs`, so 3; no real-Chrome measure of the longest branch a row can fit was taken beyond the geometry
  case passing at 360, 390, 1280, 1470 and 1920 px.
- The programme page's kicker stays: no icon sits beside it, so it is the page's only cue. **Inferred** from reading
  `ProgrammeScreen.tsx` and its stylesheet; the operator's note names the icon and the colours beside the word.

## What CI found after the first push, and the fix round (measured)

The first push's fast run was red in two files my import search had not found, and CodeQL raised one alert on my own test:

- `role-census.test.ts` ("every non-story primitive is classified"): the new `role-badge.tsx` was in neither registry. It is now in
  `NOT_ROLE_BEARING`, with the reason that its size is the 16 px icon's own and it carries no text.
- `older-server-render.test.tsx` compares the current render of an older server's frames to a recorded base, byte for byte, less
  the head-only additions it declares. The coordinator's role cell was declared as the word; it is now declared as the badge
  (`ROLE_CELL`, `ROLE_ONLY_LINE`), and the programme kicker's change is declared too: the head's icon wrapper is unwrapped, and the
  base's word, middot and icon class are removed, on the base side.
- CodeQL `js/incomplete-sanitization` on `coordinator-badge.test.tsx`: a helper turned a selector into a pattern without escaping
  the backslash. It now finds the rule by its text (`indexOf`), so no selector becomes a pattern; the stylesheet cases still red when a
  rule is deleted (the earlier mutation check holds for the new reader: a missing rule reads `null`).

All three files pass alone after the fix. **Inferred** lesson: a search for importers of the touched modules does not find a test
that renders the whole fleet from recorded markup, or a census of a directory a new file lands in; the brief named the role census.
