## The coordinator's three conditions (delivery 29257)

1. **The dry run's journal read is bounded, and measured.** **Sourced:** F4's read of the retained journal runs OUTSIDE
   the applier's queue, so nothing the watcher applies waits for it; it is cut at `DELEGATION_BACKFILL_SCAN_MS`, 120 s,
   by the injected clock, and past the bound (or on a read that refuses) the count is unmeasured (`reportedScan: cut`),
   never partial. Inside the queue the dry run reads only the list file and decides the plan.
   **Measured** on this box (2026-11-21, load 3.2), on a fixture journal of the live shape (the spec's Table 3 mix: per
   agent a Start, 22 of its own tool events, a Stop and a final notification; 847 bytes a record): 200,000 records,
   161.6 MiB, read and keyed in 4.2 s, about 47,000 records a second (38 MiB/s, warm page cache). So the bound reads
   several million records, more than the journal's retained set is expected to hold (**inferred** from Table 3: about
   500,000 journaled agent events a week). **Measured:** the plan over a checkpoint of the live size (31,189 activity
   rows, 2,389 open, 300 parents) takes 3.4 ms. **So the watcher waits at worst**, for the dry run, the list file's read
   and those few milliseconds; for the pass, the same plus one `commitLocked` (the encode and write every commit makes);
   for the undo, one `commitLocked`.
2. **What the operator sees when the count moved:** 409 `count-changed`, with `report` (the count the pass would close
   now, by kind and age) and `detail`: "the pass would close N, not M: read the dry run again". Pinned by RT-5 and B-D4.
3. **CLAUDE.md:** one sentence beside the other doors', naming the door, its gate and the pass's refusal while sign-in is
   dark.
